# Ngày 23: Sửa lịch sử phiên bản đã commit Phần 5 (rebase 2)

Trong bài viết trước, chúng ta đã thảo luận rằng Rebase được dùng để "chỉ định lại phiên bản cơ sở" cho hai branch hiện có. Sau khi thực thi Rebase, nó cũng thay đổi điểm bắt đầu của branch gốc (điểm rẽ nhánh được di chuyển), gây ra thay đổi trong đồ thị phiên bản. Tuy nhiên, Rebase có thể làm được nhiều hơn thế - nó còn có thể được dùng để sửa đổi thông tin phiên bản của bất kỳ phiên bản nào trên một đường branch cụ thể.

Bài viết này tiếp tục khám phá `git rebase`, đi sâu vào các kỹ thuật nâng cao và quy trình làm việc thực tế để sử dụng rebase hiệu quả, bao gồm việc sửa đổi thông tin commit trên một branch.

## Các kỹ thuật Interactive Rebase nâng cao

### Tách một Commit

Để tách một commit thành nhiều commit:

```
git rebase -i HEAD~3

# Mark the commit to split with "edit"
# When Git stops at that commit:
git reset HEAD^
git add file1
git commit -m "First part"
git add file2
git commit -m "Second part"
git rebase --continue
```

### Kết hợp và sắp xếp lại

Bạn có thể vừa sắp xếp lại vừa kết hợp các commit trong một thao tác:

```
git rebase -i HEAD~5

# In the editor:
pick abc123 Feature A
squash def456 Fix for A
pick jkl012 Feature C  # Moved before B
pick ghi789 Feature B  # Moved after C
fixup mno345 Typo fix for B
```

## Rebase với Exec

Chạy một lệnh sau mỗi commit trong quá trình rebase:

```
git rebase -i --exec "npm test" HEAD~5
```

Thao tác này chạy `npm test` sau khi áp dụng mỗi commit, giúp bạn tìm ra commit nào đã làm hỏng kiểm thử.

## Rebase lên một Commit cụ thể

Thay vì tên branch, bạn có thể rebase lên một commit cụ thể:

```
git rebase --onto <new-base-commit> <old-base-commit> <branch>
```

Ví dụ trường hợp sử dụng - loại bỏ các commit ở giữa lịch sử:

```
# Remove commits between B and D
#     A---B---C---D---E feature
# Becomes:
#     A---B---D'---E' feature

git rebase --onto B D feature
```

## Rebase với các tùy chọn Strategy

Sử dụng các chiến lược merge trong quá trình rebase:

```
# Always prefer our version in conflicts
git rebase -X ours main

# Always prefer their version
git rebase -X theirs main
```

## Bảo toàn Merge Commit

Theo mặc định, rebase làm phẳng các merge commit. Để bảo toàn chúng:

```
git rebase -p main
# or
git rebase --preserve-merges main
```

Lưu ý: `-p` đã lỗi thời; hãy dùng `--rebase-merges` thay thế:

```
git rebase --rebase-merges main
```

## Rebase với Fork-Point

Tự động tìm điểm rẽ nhánh (fork point):

```
git rebase --fork-point main
```

Điều này hữu ích khi remote branch đã bị force-push.

## Quy trình: Giữ Feature Branch luôn cập nhật

Quy trình phổ biến để giữ feature branch của bạn luôn cập nhật với main:

```
# On feature branch
git fetch origin
git rebase origin/main

# Or in one command
git pull --rebase origin main
```

## Quy trình: Chuẩn bị cho Pull Request

Dọn dẹp các commit của bạn trước khi tạo pull request:

```
# 1. Interactive rebase to clean history
git rebase -i main

# 2. Squash fixup commits, reword messages
# 3. Force push to update your branch
git push -f origin feature-branch
```

## Quy trình: Cập nhật sau Code Review

Sau khi nhận phản hồi từ code review:

```
# Make changes
git add .
git commit --fixup <original-commit>

# Rebase with autosquash
git rebase -i --autosquash main

# Force push the updated branch
git push -f origin feature-branch
```

## Xử lý Force Push

Khi ai đó force-push một branch mà bạn đang làm việc:

```
# Fetch the updated branch
git fetch origin

# Rebase your work onto the new history
git rebase --onto origin/feature-branch old-commit feature-branch
```

Hoặc đơn giản là:

```
git pull --rebase origin feature-branch
```

## Rebase so với Reset cho việc dọn dẹp

Để dọn dẹp các commit cục bộ trước khi push:

**Rebase** (khuyên dùng):
* Bảo toàn thứ tự thời gian
* Kiểm soát tương tác
* Có thể cherry-pick các commit

**Reset** (đơn giản hơn nhưng kém linh hoạt hơn):
* Loại bỏ hoàn toàn các commit
* Bắt đầu lại từ trạng thái sạch
* Ít kiểm soát hơn đối với từng commit riêng lẻ

## Các mẫu Rebase thường gặp

### Mẫu 1: Squash tất cả các Commit

```
git rebase -i --root
# Mark all but first commit as "squash"
```

### Mẫu 2: Viết lại tất cả thông điệp Commit

```
git rebase -i HEAD~10
# Mark all commits as "reword"
```

### Mẫu 3: Loại bỏ các Commit cụ thể

```
git rebase -i HEAD~10
# Mark unwanted commits as "drop"
```

## Danh sách kiểm tra an toàn khi Rebase

Trước khi rebase:

- [ ] Commit này đã được push lên branch dùng chung chưa?
- [ ] Người khác đã dựa công việc của họ trên commit này chưa?
- [ ] Tôi đã có bản sao lưu (branch hoặc tag) chưa?
- [ ] Tôi đã thông báo với nhóm chưa?
- [ ] Tôi đã sẵn sàng force-push chưa?

## Khôi phục từ thảm họa Rebase

Nếu mọi thứ gặp sự cố:

```
# Step 1: Stay calm
# Step 2: Find the old state
git reflog

# Step 3: Reset to before the rebase
git reset --hard HEAD@{5}

# Step 4: Try again more carefully
```

## Rebase và tích hợp liên tục (CI)

Khi sử dụng CI/CD với rebasing:

1. **Rebase cục bộ** trước khi push
2. **Chạy kiểm thử** sau khi rebase
3. **Force push** chỉ branch của bạn
4. **Chờ CI** trước khi merge
5. **Không bao giờ rebase** sau khi merge

## Tóm tắt các thực hành tốt nhất

1. **Chỉ cục bộ**: Chỉ rebase các commit chưa push
2. **Rebase nhỏ**: Rebase thường xuyên để tránh xung đột lớn
3. **Kiểm thử kỹ lưỡng**: Chạy kiểm thử sau khi rebase
4. **Thông báo**: Cảnh báo nhóm trước khi force-push
5. **Sao lưu**: Tạo một branch sao lưu trước các lần rebase lớn
6. **Cẩn thận với -f**: Kiểm tra kỹ hai lần trước khi force-push

## Tổng kết hôm nay

Các kỹ thuật rebase nâng cao mang đến cho bạn những công cụ mạnh mẽ để duy trì lịch sử commit sạch và dễ hiểu. Mặc dù các tính năng này có thể cải thiện đáng kể quy trình làm việc của bạn, chúng đòi hỏi sự thực hành và sử dụng cẩn thận. Điều then chốt là biết khi nào nên dùng rebase và khi nào nên gắn bó với các lựa chọn an toàn hơn như merge.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git rebase --exec
* git rebase --onto
* git rebase -X
* git rebase --preserve-merges
* git rebase --rebase-merges
* git rebase --fork-point
* git rebase --root
* git pull --rebase
* git push -f
