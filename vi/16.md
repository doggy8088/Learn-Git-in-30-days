# Ngày 16: Dùng git reflog để theo dõi lịch sử thay đổi

Học các lệnh quản lý phiên bản của Git không khó, nhưng hiểu Git thực sự làm gì với repository của bạn lại có thể khá thách thức. Khi bạn dần hiểu các khái niệm cốt lõi và nguyên lý vận hành của Git, bạn có thể kiểm soát hiệu quả các thay đổi phiên bản trong Git repository của mình. Bài viết này giải thích cách Git ghi lại lịch sử thay đổi cho mỗi phiên bản.

## Hiểu git reflog

`git reflog` (reference log — nhật ký tham chiếu) là một cơ chế ghi lại thời điểm các đầu mút của branch và các tham chiếu khác được cập nhật trong repository cục bộ. Trước khi bạn hiểu đầy đủ các nguyên lý cơ bản và cấu trúc object của Git, bạn không thể thực sự hiểu quy trình ghi lại phiên bản. Khi bạn không hiểu quy trình ghi lại phiên bản, bạn tự nhiên sẽ lo lắng "phiên bản của tôi đã đi đâu?" Bạn có thể đã nghe ai đó nói "Chúng ta dùng quản lý phiên bản, nên mọi phiên bản đều được bảo toàn, cứ thoải mái sửa mã nguồn." Biết điều này là một chuyện, biết cách làm là chuyện khác, và việc bạn có thực sự làm được hay không lại là chuyện khác nữa.

May mắn thay, Git có một cơ chế ghi nhật ký nghiêm ngặt, và cơ chế này rất cởi mở — các tệp nhật ký đều ở định dạng văn bản và khá dễ hiểu. Hãy cùng giải thích quy trình ghi lại phiên bản này.

Reflog đặc biệt hữu ích cho:

* Tìm các commit không còn có thể truy cập được từ bất kỳ branch nào
* Khôi phục sau các lần reset hoặc rebase nhầm lẫn
* Hiểu bạn đã làm gì trong repository của mình
* Hoàn tác các thay đổi vô tình

## Thư mục logs

Nếu bạn vào thư mục `.git/` của bất kỳ working directory Git nào, bạn có thể thấy một thư mục `logs`. Thư mục `logs` này chứa một tệp `HEAD` ghi lại lịch sử thay đổi phiên bản của "branch hiện tại".

Nội dung tệp trông như thế này (các object ID được viết tắt cho dễ đọc):

```
0000000 f5685e0 Will <xxxx@gmail.com> 1381718394 +0800	commit (initial): Initial commit
f5685e0 38d924f Will <xxxx@gmail.com> 1381718395 +0800	commit: a.txt: set 1 as content
38d924f efa1e0c Will <xxxx@gmail.com> 1381734238 +0800	commit: test
efa1e0c af493e5 Will <xxxx@gmail.com> 1381837967 +0800	commit: Add c.txt
```

## Cách sử dụng cơ bản

Để xem reflog:

```
git reflog
```

Lệnh này hiển thị danh sách các hành động gần đây theo thứ tự thời gian ngược. Từ tệp văn bản, bạn có thể thấy "phiên bản đầu tiên" ở trên cùng, nhưng thông qua `git reflog`, "phiên bản mới nhất" được hiển thị đầu tiên, và "phiên bản đầu tiên" ở cuối cùng.

Mỗi mục hiển thị:
* Mã băm của commit
* Tham chiếu (thường là HEAD)
* Hành động đã được thực hiện
* Thông điệp commit

## Định dạng Reflog

Đầu ra trông như thế này:

```
a1b2c3d HEAD@{0}: commit: Add new feature
e4f5g6h HEAD@{1}: checkout: moving from master to feature-branch
i7j8k9l HEAD@{2}: reset: moving to HEAD~1
```

Ký hiệu `HEAD@{n}` đề cập tới giá trị trước thứ n của HEAD. Ở đây, mỗi phiên bản trong nhật ký lịch sử có một số đại diện cho vị trí của phiên bản này trong tệp nhật ký. `HEAD@{0}` luôn đại diện cho "phiên bản mới nhất" của branch hiện tại, nói cách khác, là thao tác Git gần đây nhất bạn đã thực hiện trên "branch" này. Bất kỳ thay đổi phiên bản nào bạn thực hiện đối với Git đều sẽ được ghi lại đầy đủ.

## Khôi phục từ các thay đổi vô tình

Khi người mới bắt đầu sử dụng Git, họ có thể vô tình thực thi các lệnh không chính xác, chẳng hạn như xung đột xảy ra trong quá trình `git merge`, hoặc sai sót xảy ra khi thực thi `git pull` để lấy phiên bản mới nhất từ remote repository. Trong những tình huống như vậy, bạn có thể sử dụng "tên tham chiếu" đặc biệt `HEAD@{n}` để "định vị" phiên bản này và khôi phục phiên bản Git repository hiện tại về một phiên bản trước đó.

Ví dụ, nếu chúng ta muốn "hủy bỏ" bản ghi phiên bản gần đây nhất, chúng ta có thể dùng `git reset HEAD@{1} --hard` để khôi phục thay đổi. Điều này có nghĩa là thay đổi ban đầu ở `HEAD@{0}` sẽ bị xóa. Tuy nhiên, trong Git, mọi thay đổi đều được ghi lại, bao gồm cả hành động thực thi `git reset "HEAD@{1}" --hard` của bạn.

Điều này có nghĩa là gì? Nó có nghĩa là khi thực thi bất kỳ lệnh Git nào, bạn không còn cần lo lắng rằng bất kỳ dữ liệu nào của mình sẽ bị mất. Dù lệnh bạn nhập sai đến đâu, tất cả các tệp đã nằm trong repository đều sẽ được bảo toàn, tuyệt đối không có khả năng bị mất. Vì vậy, nếu bạn muốn hoàn tác hành động `git reset "HEAD@{1}" --hard` mà bạn vừa thực thi, chỉ cần thực thi lại `git reset "HEAD@{1}" --hard`. Thật tuyệt vời phải không!

## Xem Reflog chi tiết

Để có thông tin chi tiết hơn:

```
git reflog show --all
```

Để xem reflog của một branch cụ thể:

```
git reflog show branch-name
```

## Sử dụng Reflog để khôi phục Commit

Nếu bạn vô tình reset hoặc làm mất các commit, bạn có thể khôi phục chúng bằng reflog:

```
# Find the commit you want to recover
git reflog

# Reset to that commit
git reset --hard HEAD@{2}
```

Hoặc sử dụng trực tiếp mã băm của commit:

```
git reset --hard a1b2c3d
```

## Khôi phục các Branch đã xóa

Nếu bạn xóa nhầm một branch:

```
# Find the commit where the branch was deleted
git reflog

# Recreate the branch
git branch branch-name HEAD@{3}
# or
git branch branch-name <commit-hash>
```

## Thời hạn của Reflog

Theo mặc định, các mục reflog hết hạn sau 90 ngày đối với các commit có thể truy cập được và 30 ngày đối với các commit không thể truy cập được. Bạn có thể cấu hình điều này:

```
git config gc.reflogExpire "90 days"
git config gc.reflogExpireUnreachable "30 days"
```

## Dọn dẹp Reflog

Để dọn dẹp thủ công các mục reflog:

```
# Remove old reflog entries
git reflog expire --expire=now --all

# Run garbage collection
git gc --prune=now
```

## Hạn chế của Reflog

Những điểm quan trọng cần nhớ:

* Reflog chỉ ở cục bộ — nó không được chia sẻ với người khác
* Reflog theo dõi các thay đổi đối với repository của bạn, không phải các tệp
* Nó có thể giúp bạn khôi phục các commit, nhưng không thể khôi phục các thay đổi chưa commit

## Ví dụ thực tế

### Ví dụ 1: Hoàn tác một Hard Reset

```
# You accidentally reset
git reset --hard HEAD~3

# Find the old position
git reflog

# Restore to the old position
git reset --hard HEAD@{1}
```

### Ví dụ 2: Khôi phục sau một lần Rebase nhầm lẫn

```
# After a problematic rebase
git reflog

# Find the commit before the rebase (usually labeled "rebase finished")
git reset --hard HEAD@{5}
```

## Tóm tắt hôm nay

`git reflog` là một tính năng an toàn mạnh mẽ có thể cứu bạn khỏi nhiều sai lầm với Git. Nó đặc biệt có giá trị khi bạn cần khôi phục sau các thao tác như reset, rebase hoặc xóa branch. Mặc dù nó không thay thế được việc sao lưu thường xuyên, nhưng nó là một công cụ vô giá cho việc khôi phục cục bộ.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git reflog
* git reflog show
* git reflog show --all
* git reset --hard HEAD@{n}
* git branch branch-name HEAD@{n}
* git reflog expire
* git gc
