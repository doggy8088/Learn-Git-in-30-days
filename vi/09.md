# Ngày 09: So sánh khác biệt giữa tệp và phiên bản

Trong quá trình sử dụng bất kỳ phần mềm quản lý phiên bản nào, bạn thường cần xem các bản ghi lịch sử và so sánh sự khác biệt giữa các phiên bản. Cách so sánh trong Git sẽ là trọng tâm của bài viết này.

## Chuẩn bị Working Directory

Chúng ta nhanh chóng tạo một Git Repository và working directory với hai tệp và hai bản ghi thay đổi phiên bản thông qua các lệnh sau:

```
mkdir git-demo
cd git-demo
git init

echo 1 > a.txt
echo 2 > b.txt
git add .
git commit -m "Initial commit"

echo 3 > a.txt
echo 4 > b.txt
git add .
git commit -m "Update a.txt and b.txt to 3 and 4"
```

## Khái niệm cơ bản của git diff

Để so sánh sự khác biệt giữa hai phiên bản trong Git, bạn thường sử dụng lệnh `git diff`. Trước tiên hãy thực thi một lệnh đơn giản để so sánh sự khác biệt giữa hai phiên bản:

1. Đầu tiên thực thi `git log` để lấy thông tin phiên bản và lấy id của hai commit object cuối cùng
2. Chúng ta thực thi lệnh `git diff commit1 commit2` để so sánh sự khác biệt giữa hai phiên bản, trong đó commit1 nên sử dụng phiên bản cũ hơn và commit2 nên sử dụng phiên bản mới hơn.

Như thể hiện trong hình sau:

![hình ảnh](figures/09/01.png)

Từ kết quả đầu ra của việc thực thi `git diff`, chúng ta có thể nhận được một kết quả thực thi. Vì chúng ta có hai tệp trong hai Repository này, và cả hai đều đã thay đổi giữa hai phiên bản này, nó sẽ liệt kê hai đoạn kết quả "so sánh khác biệt".

Bạn có thể thấy từ hình trên rằng mỗi đoạn bắt đầu bằng `diff --git`, đại diện cho hai tệp nào git đang so sánh.

Dòng thứ hai `index 37bcc8b..d855592 100644` đại diện cho "Dòng tiêu đề" (Header Line) khi git thực hiện việc so sánh này. Có thể có một vài dòng ở đây, và thông tin không nhất thiết chỉ là những điều này. Nhiều thông tin bổ sung về việc so sánh khác biệt này sẽ được đánh dấu ở đây. Ví dụ, dòng index, hai hash id sau nó (`37bcc8b..d855592`) đại diện cho hai blob object id trong nơi lưu trữ object Git (object storage), được sử dụng để so sánh hai blob object này. `100644` sau nó là một thuộc tính git, hơi giống các thuộc tính tệp trong môi trường Linux, chẳng hạn như khai báo đây là một tệp, thư mục, có thể đọc, có thể ghi, có thể thực thi, v.v. Dưới đây là một số ví dụ phổ biến về thuộc tính git:

```
0100000000000000 (040000): Directory
1000000110100100 (100644): Regular non-executable file
1000000110110100 (100664): Regular non-executable group-writeable file
1000000111101101 (100755): Regular executable file
1010000000000000 (120000): Symbolic link
1110000000000000 (160000): Gitlink
```

Đối với các liên kết liên quan, vui lòng tham khảo chuỗi thảo luận sau:

* [How to read the mode field of git-ls-tree's output](https://stackoverflow.com/a/8347325/910074)

Dòng thứ ba `--- a/a.txt` đại diện cho phiên bản "cũ hơn" trong hai phiên bản được so sánh.

Dòng thứ tư `+++ b/a.txt` đại diện cho phiên bản "mới hơn" trong hai phiên bản được so sánh.

Dòng thứ năm `@@ -1 +1 @@` đại diện cho tổng số dòng trong phiên bản cũ và phiên bản mới của tệp này. -1 đại diện cho phiên bản cũ chỉ có 1 dòng, và +1 đại diện cho phiên bản mới cũng chỉ có 1 dòng.

Cuối cùng, tất cả nội dung đã thay đổi được liệt kê. Có ba cách biểu diễn có thể ở đây:

* Bắt đầu bằng dấu trừ -, nó có nghĩa là dòng này đã bị xóa trong quá trình từ phiên bản cũ sang phiên bản mới.
* Bắt đầu bằng dấu cộng +, nó có nghĩa là dòng này đã được thêm vào trong quá trình từ phiên bản cũ sang phiên bản mới.
* Bắt đầu bằng ký tự khoảng trắng, nó có nghĩa là dòng này xuất hiện trong cả hai phiên bản mà không có bất kỳ thay đổi nào.

Điều này hoàn thành việc so sánh khác biệt của blob object đầu tiên trong hai phiên bản này, và sau đó nó sẽ hiển thị việc so sánh khác biệt của blob object thứ hai trong phiên bản đó, và cứ thế tiếp tục.

Khi sử dụng `git diff` trong Git, thực ra, tree object là đơn vị so sánh. Chúng ta đã học được từ sơ đồ và video trong [Ngày 06: Phân tích cấu trúc dữ liệu Git - Cấu trúc Object] rằng mỗi commit object thực ra bao gồm một tree object của thư mục gốc. Vì vậy khi chúng ta vừa sử dụng `git diff` để so sánh hai commit object, chúng ta thực ra đang so sánh các tree object dưới các commit object đó, và quá trình so sánh sẽ tiếp tục đệ quy xuống dưới. Từ đó, bạn hẳn có thể cảm nhận được rằng cơ chế so sánh diff của Git rất mạnh mẽ. Bạn có thể nhanh chóng so sánh các thay đổi giữa bất kỳ hai phiên bản nào.

Khi sử dụng lệnh `git diff`, chủ yếu có ba nguồn tree object:

* Các tree object tồn tại trong tất cả các đồ thị commit, có nghĩa là bất kỳ tree object nào trong bất kỳ phiên bản nào.
* Index, đại diện cho thông tin sau khi bạn đã gửi trạng thái tệp đến "cơ sở dữ liệu index". Thực ra, các tree object đã được tạo khi sử dụng lệnh `git add`.
* Working directory hiện tại của bạn, mặc dù các thay đổi đối với working directory chưa trở thành tree object, chúng có thể được sử dụng thông qua `git diff`.

## Bốn phương pháp so sánh cơ bản

Để so sánh bất kỳ hai phiên bản nào thông qua lệnh `git diff`, thường có bốn cách sử dụng lệnh sau:

1. git diff

   Không có bất kỳ tham số nào, những gì được so sánh là sự khác biệt giữa "working directory" và "index". Đây là một lệnh rất thường được sử dụng vì trước khi bạn thực thi lệnh `git add .`, bạn có thể sử dụng `git diff` trước để xem bạn đã thay đổi những gì.

   **Lưu ý**: Thực ra, trong quá trình sử dụng quản lý phiên bản Git, trước khi thực thi `git commit`, việc thực thi lệnh `git add` vài lần để xác nhận những tệp nào sẽ thêm vào index, và cuối cùng commit thành phiên bản, là điều thực sự có thể.

2. git diff commit

   Nếu bạn chỉ thêm một commit id sau `git diff`, những gì được so sánh là "working directory" và "tree object trong commit object được chỉ định".

   Lệnh được sử dụng phổ biến nhất là `git diff HEAD` vì điều này đại diện cho việc so sánh "working directory" với "phiên bản mới nhất của branch hiện tại". Phương pháp so sánh này sẽ không so sánh trạng thái "index", vì vậy bạn phải phân biệt rõ ràng bạn đang so sánh nguồn tree object nào.

3. git diff --cached commit

   Trước khi thực thi `git commit`, trạng thái index nên sẵn sàng. Vì vậy nếu bạn muốn so sánh "trạng thái index hiện tại" với "tree object trong commit object được chỉ định", bạn có thể sử dụng lệnh này để hoàn thành tác vụ so sánh.

   Lệnh được sử dụng phổ biến nhất cũng là `git diff --cached HEAD`, có nghĩa là so sánh "trạng thái index hiện tại" với "phiên bản mới nhất của branch hiện tại". Phương pháp so sánh này sẽ không so sánh nội dung tệp của "working directory", mà trực tiếp so sánh sự khác biệt giữa "index" và "phiên bản mới nhất hiện tại". Điều này giúp bạn tìm ra những thay đổi nào có ở đó trước khi thực thi `git commit`, có nghĩa là những thay đổi nào bạn sẽ tạo thành một phiên bản.

   **Lưu ý 1**: `git diff --cached` và `git diff --staged` có kết quả hoàn toàn giống nhau. `--staged` chỉ là một bí danh cho `--cached` để giúp bạn dễ nhớ hơn!

   **Lưu ý 2**: `git diff --cached` và `git diff --cached HEAD` cũng có kết quả hoàn toàn giống nhau khi thực thi. HEAD ở cuối có thể được bỏ qua.

4. git diff commit1 commit2

   Cách cuối cùng là so sánh sự khác biệt giữa hai phiên bản khác nhau (commit id). Lệnh này có thể bỏ qua bất kỳ thay đổi nào trong "index" và "working directory" và trực tiếp so sánh hai phiên bản cụ thể. Thực ra, Git so sánh các tree object trong hai commit object của phiên bản cụ thể đó.

   Lệnh được sử dụng phổ biến nhất là `git diff HEAD^ HEAD`, có nghĩa là bạn muốn so sánh sự khác biệt giữa [phiên bản trước của phiên bản mới nhất] và [phiên bản mới nhất]. Ý nghĩa của HEAD và ^ ở đây sẽ được giải thích trong các bài viết sau.

## Tóm tắt hôm nay

`git diff` được giới thiệu hôm nay là một lệnh rất thường được sử dụng, và bạn nên sử dụng nó thành thạo. Cuối cùng hãy xem lại sự khác biệt giữa các lệnh thường dùng của nó:

```
git diff                 => working directory vs index
git diff HEAD            => working directory vs HEAD
git diff --cached HEAD   => index     vs HEAD
git diff --cached        => index     vs HEAD
git diff HEAD^ HEAD     => HEAD^   vs HEAD
```

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git log
* git diff
* git diff HEAD
* git diff --cached
* git diff --staged
* git diff HEAD^ HEAD
