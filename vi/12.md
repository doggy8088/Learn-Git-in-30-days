# Ngày 12: Hiểu tên tương đối của Git Object

Sau khi đã hiểu "tên tuyệt đối" và "tên tham chiếu" của Git object, giờ chúng ta sẽ giới thiệu "tên tương đối", cũng là loại tên thường được sử dụng trong quá trình quản lý phiên bản bằng Git.

Hãy cùng ôn lại. Trong quản lý phiên bản bằng Git, mỗi phiên bản đại diện cho một commit object. Mỗi commit object có một "tên tuyệt đối" — một chuỗi 40 ký tự thu được bằng phép băm SHA1 trên nội dung. Bạn có thể sử dụng từ 4 đến 40 ký tự đầu tiên làm tên định danh của commit object đó. Trong quá trình quản lý phiên bản, bạn cũng có thể sử dụng "tên tham chiếu" để đại diện cho một commit object cụ thể. Mỗi "tên tham chiếu" cuối cùng đều tương ứng với "tên tuyệt đối" của một object. "Tên tham chiếu" được chia nhỏ hơn thành "tham chiếu thông thường" và "tham chiếu tượng trưng". Trong đó, "tham chiếu thông thường" tương ứng trực tiếp với "tên tuyệt đối", trong khi "tham chiếu tượng trưng" tương ứng với một "tham chiếu thông thường" khác.

Bài viết này sẽ giới thiệu cách sử dụng ký hiệu "tên tương đối", cho phép bạn tìm các "commit object" khác dựa trên vị trí tương đối của chúng sau khi đã tìm được một commit object cụ thể.

## Ký hiệu tên tương đối

Sử dụng tên tương đối thực ra rất đơn giản. Có hai ký hiệu đặc biệt bạn phải nhớ, một là `^` và một là `~`.

Để tìm phiên bản trước của `HEAD`, chúng ta sẽ dùng `HEAD~` hoặc `HEAD~1` để biểu diễn "phiên bản trước của commit object HEAD". **Lưu ý**: Đến đây bạn hẳn đã biết rất rõ rằng `HEAD` là một "tên tham chiếu tượng trưng" có sẵn trong Git, đại diện cho phiên bản mới nhất của branch hiện tại.

Nếu bạn muốn tìm hai phiên bản trước một branch `f2e` khác (không bao gồm phiên bản `HEAD` của `f2e`), bạn có thể dùng `f2e~2` hoặc `f2e~~` để biểu diễn. Đây là cách biểu diễn cơ bản nhất.

Trong các repository không có branch và merge, ý nghĩa mà `^1` và `~1` biểu đạt là hoàn toàn giống nhau, cả hai đều đại diện cho "phiên bản trước". Nhưng trên thực tế, trong các repository có branch và merge, chúng có ý nghĩa khác nhau. Phần này sẽ được giải thích sau.

Đây là ký hiệu "tên tương đối" cơ bản nhất.

## Mối liên kết giữa các Commit Object

Trong các Git repository phổ biến hơn, theo mặc định sẽ chỉ có một "commit object gốc", đó là phiên bản đầu tiên chúng ta tạo ra, còn được gọi là "Initial Commit". Bạn cũng cần phải có ít nhất commit object đầu tiên trước khi có thể bắt đầu tạo branch. Vì vậy, chúng ta có thể nói: "Trong một Git repository, trong số tất cả các commit object, ngoại trừ commit object đầu tiên, bất kỳ commit object nào khác cũng phải có một hoặc nhiều commit object cha." Tại sao lại có thể có "nhiều hơn một" commit object cha? Bởi vì rất có khả năng bạn sẽ merge hai hoặc nhiều branch vào một branch khác. Vì vậy commit object sau khi merge sẽ có nhiều commit object cha.

Hãy dùng một ví dụ đơn giản để chứng minh điều này. Chúng ta dùng `git cat-file -p [object_id]` để lấy nội dung của hai commit object đầu tiên, qua đó hiểu rằng mỗi commit object thực sự sẽ có một thuộc tính parent trỏ tới tên tuyệt đối của commit object cha, ngoại trừ commit object đầu tiên sẽ không có thuộc tính parent. ## Hiểu sự khác biệt giữa `^` và `~` trong ký hiệu tên tương đối

Ý nghĩa của `~` đại diện cho "commit object cha đầu tiên".

Ý nghĩa mà `^` biểu đạt là "khi có nhiều commit object cha, sẽ đại diện cho commit object cha thế hệ đầu tiên nào".

Nếu bạn có một "tên tham chiếu" là `C`, để tìm commit object cha đầu tiên của nó, bạn có thể dùng các cách biểu diễn sau:

* `C^`
* `C^1`
* `C~`
* `C~1`

Nếu bạn muốn tìm commit object cha thứ hai của nó (không có merge), bạn có thể dùng các cách biểu diễn sau:

* `C^^`
* `C^1^1`
* `C~2`
* `C~~`
* `C~1~1`

Nhưng bạn không thể dùng `C^2` để biểu diễn "commit object cha thứ hai"! Lý do là khi không có merge, `C` này chỉ có một object cha duy nhất. Bạn chỉ có thể dùng `C^2` để biểu diễn "object cha thứ hai của object ở lớp trước".

Những điều trên nghe có vẻ hơi trừu tượng và rối rắm. Tôi đã đặc biệt vẽ một sơ đồ cho bạn xem. Qua sơ đồ, mọi thứ có thể sẽ rõ ràng hơn. Như thể hiện trong hình sau, chúng ta muốn tìm các commit object khác (object cha) trong đường dẫn tương đối của commit object `C`. Vì commit object `C` này có ba object cha, điều này có nghĩa là commit object này được tạo ra thông qua merge. Vậy để tìm từng đường dẫn thông qua "tên tương đối", bạn phải sử dụng kết hợp các kỹ thuật `^` và `~` để định vị từng phiên bản bạn muốn mở.

## Giới thiệu lệnh `git rev-parse`

Trong công cụ Git for Windows, có một lệnh `git rev-parse`. Thông qua lệnh này, bạn có thể phân giải bất kỳ "tên tham chiếu" hoặc "tên tương đối" nào thành "tên tuyệt đối". Mặc dù công cụ này không được dùng thường xuyên lắm, nhưng nó khá thiết thực khi giảng dạy về Git. Các ví dụ sử dụng như sau:

* git rev-parse master
* git rev-parse HEAD
* git rev-parse ORIG_HEAD
* git rev-parse HEAD^
* git rev-parse HEAD~5

## Tóm tắt hôm nay

Sau khi hiểu "tên tương đối", các cách biểu diễn commit object trong Git đã được giải thích đầy đủ. Tôi tin rằng bạn sẽ có thể kiểm soát tốt hơn các thao tác giữa các phiên bản khác nhau của Git.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git log
* git cat-file -p [object_id]
* git rev-parse
