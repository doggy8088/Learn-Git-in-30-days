# Ngày 26: Nhiều người cùng làm việc trên một Remote Repository

Khi nhiều người làm việc trong cùng một repository, việc phối hợp và hiểu các quy trình làm việc Git trở nên rất quan trọng. Bài viết này khám phá các thực hành tốt nhất và các tình huống thường gặp trong cộng tác nhóm.

## Các thách thức thường gặp trong cộng tác nhóm

1. **Xung đột merge (merge conflict)**: Nhiều người chỉnh sửa cùng các tệp
2. **Các branch bị phân kỳ**: Local và remote mất đồng bộ
3. **Mất commit**: Vô tình ghi đè công việc của người khác
4. **Khoảng cách giao tiếp**: Không biết người khác đang làm gì

## Quy trình làm việc nhóm cơ bản

### Quy trình hàng ngày

```
# Morning: Get latest changes
git pull origin main

# Create feature branch
git checkout -b feature-name

# Work and commit frequently
git add .
git commit -m "Progress on feature"

# Before finishing: update with latest main
git checkout main
git pull origin main
git checkout feature-name
git merge main

# Resolve any conflicts

# Push your branch
git push origin feature-name

# Create pull request for review
```

### Luôn cập nhật

Fetch các thay đổi thường xuyên:

```
# Check what's changed
git fetch origin

# View remote changes
git log main..origin/main

# Merge if appropriate
git merge origin/main
```

## Xử lý công việc đồng thời

### Tình huống 1: Cùng tệp, khác dòng

Thường merge tự động:

```
git pull origin main
# If auto-merge succeeds, you're done!
```

### Tình huống 2: Cùng tệp, cùng dòng

Yêu cầu giải quyết thủ công:

```
git pull origin main
# Conflict!

# Edit conflicting files
# Remove markers: <<<<<<<, =======, >>>>>>>
# Keep the correct changes

# Stage resolved files
git add resolved-file.txt

# Complete the merge
git commit
```

### Tình huống 3: Một người Rebase

Có thể gây ra vấn đề lớn nếu branch được dùng chung:

```
# If someone rebased a shared branch
git fetch origin

# You need to rebase your work
git rebase origin/feature-branch

# Or start fresh
git reset --hard origin/feature-branch
```

## Quy trình Code Review

### Tạo Pull Request tốt

1. **Tiêu đề mô tả rõ ràng**: "Add user authentication feature"
2. **Mô tả chi tiết**:
   * PR này làm gì?
   * Tại sao cần thay đổi này?
   * Nó đã được kiểm thử như thế nào?
3. **Giữ nó nhỏ gọn**: Dễ review hơn
4. **Một mối quan tâm cho mỗi PR**: Đừng trộn tính năng và bản sửa lỗi
5. **Cập nhật với main**: Đảm bảo nó merge sạch

### Review Pull Request

1. **Kiểm tra mã** logic và phong cách
2. **Kiểm thử cục bộ** nếu có thể
3. **Để lại phản hồi mang tính xây dựng**
4. **Phê duyệt hoặc yêu cầu thay đổi**
5. **Merge khi sẵn sàng**

## Giải quyết xung đột trong nhóm

### Giao tiếp trước tiên

* **Trao đổi với nhóm của bạn**: Thường ngăn chặn được vấn đề
* **Dùng bình luận PR**: Đặt câu hỏi, thảo luận cách tiếp cận
* **Ghi lại các quyết định**: Cập nhật mô tả PR hoặc bình luận

### Giải pháp kỹ thuật

#### Giải quyết xung đột

```
# Update your branch
git fetch origin
git merge origin/main

# Resolve conflicts in files
# Stage changes
git add .

# Complete merge
git commit
```

#### Hủy bỏ và bắt đầu lại

```
# If resolution is too complex
git merge --abort

# Talk to the other developer
# Coordinate who makes what changes
```

## Quy tắc bảo vệ Branch

Trên GitHub, bảo vệ các branch quan trọng:

1. **Yêu cầu review pull request**
2. **Yêu cầu kiểm tra trạng thái** (CI/CD)
3. **Buộc lịch sử tuyến tính**
4. **Bao gồm cả quản trị viên**

Cấu hình tại: Settings > Branches > Branch protection rules

## Tích hợp liên tục (CI)

Dùng CI để phát hiện vấn đề sớm:

```yaml
# Example .github/workflows/test.yml
name: Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - run: npm install
      - run: npm test
```

## Công cụ giao tiếp

### Thông điệp Commit

Tuân theo các quy ước:

```
<type>(<scope>): <subject>

<body>

<footer>
```

Ví dụ:

```
feat(auth): add user login functionality

Implement JWT-based authentication with email and password.
Includes password hashing with bcrypt and token refresh.

Closes #123
```

### Mẫu Pull Request

Tạo `.github/pull_request_template.md`:

```markdown
## Description
<!-- Describe your changes -->

## Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Breaking change

## Testing
<!-- How was this tested? -->

## Checklist
- [ ] Tests pass
- [ ] Documentation updated
- [ ] No merge conflicts
```

## Xử lý nhóm lớn

### Feature Flag

Triển khai mã chưa sẵn sàng:

```javascript
if (featureFlags.newUI) {
  return <NewUI />;
} else {
  return <OldUI />;
}
```

### Release Branch

Tách phát triển khỏi phát hành:

```
main (production)
├── release/v2.0
├── release/v1.9
└── develop (integration)
    ├── feature/login
    ├── feature/dashboard
    └── feature/reports
```

## Tóm tắt các thực hành tốt nhất

1. **Pull trước khi push**: Luôn lấy các thay đổi mới nhất trước
2. **Commit thường xuyên**: Các commit nhỏ, hợp lý
3. **Push thường xuyên**: Chia sẻ công việc của bạn, nhận phản hồi
4. **Sử dụng branch**: Giữ main ổn định
5. **Viết kiểm thử**: Phát hiện vấn đề trước người khác
6. **Review code**: Học hỏi lẫn nhau
7. **Giao tiếp**: Thà giao tiếp quá nhiều nếu cần
8. **Tài liệu hóa**: README, wiki, bình luận
9. **Kiên nhẫn**: Xung đột xảy ra, hãy cùng giải quyết
10. **Giúp đỡ người khác**: Thành công của nhóm là thành công của bạn

## Tổng kết hôm nay

Cộng tác nhóm thành công với Git đòi hỏi cả kỹ năng kỹ thuật lẫn giao tiếp tốt. Hiểu các quy trình làm việc thường gặp, xử lý xung đột một cách khéo léo, và sử dụng các công cụ như pull request và CI/CD sẽ giúp nhóm của bạn làm việc suôn sẻ cùng nhau.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git pull origin main
* git fetch origin
* git merge origin/main
* git rebase origin/branch
* git push origin branch
* git log main..origin/main
