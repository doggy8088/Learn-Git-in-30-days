# Ngày 29: Cách nhập dự án Subversion vào Git Repository

Nhiều tổ chức vẫn sử dụng Subversion (SVN) nhưng muốn chuyển sang Git. Bài viết này giải thích cách nhập các SVN repository vào Git trong khi vẫn bảo toàn lịch sử.

## Tại sao chuyển từ SVN sang Git?

**Ưu điểm của Git**:
* Quy trình làm việc phân tán
* Thao tác nhanh hơn (cục bộ)
* Rẽ nhánh và merge tốt hơn
* Làm việc ngoại tuyến
* Quy trình làm việc linh hoạt hơn
* Công cụ và hệ sinh thái tốt hơn

**Thách thức**:
* Đường cong học tập
* Các khái niệm khác biệt
* Thay đổi quy trình làm việc
* Thích ứng của nhóm

## Các chiến lược chuyển đổi

### 1. Nhập nhanh (Đơn giản)

Nhanh nhưng mất một số siêu dữ liệu SVN:

```
# Clone entire SVN repository
git svn clone http://svn.example.com/repo

# Or specify trunk/branches/tags structure
git svn clone http://svn.example.com/repo --trunk=trunk --branches=branches --tags=tags
```

### 2. Nhập đúng cách (Khuyên dùng)

Bảo toàn tác giả, branch và tag:

```
# Create authors file
# Map SVN users to Git users
echo "svnuser1 = John Doe <john@example.com>" >> authors.txt
echo "svnuser2 = Jane Smith <jane@example.com>" >> authors.txt

# Clone with authors file
git svn clone http://svn.example.com/repo \
  --authors-file=authors.txt \
  --trunk=trunk \
  --branches=branches \
  --tags=tags \
  --no-metadata
```

### 3. Sử dụng svn2git (Dễ nhất)

Cài đặt svn2git:

```
# On Mac
brew install svn2git

# On Linux
gem install svn2git
```

Tạo tệp tác giả (authors file):

```
# Generate authors list from SVN
svn log -q http://svn.example.com/repo | \
  awk -F '|' '/^r/ {print $2}' | \
  sort -u > authors.txt

# Edit authors.txt to add email addresses
# Format: svnuser = Full Name <email@example.com>
```

Thực hiện chuyển đổi:

```
# Create new directory
mkdir git-repo
cd git-repo

# Run migration
svn2git http://svn.example.com/repo \
  --authors authors.txt
```

## Quy trình chuyển đổi từng bước

### Giai đoạn 1: Chuẩn bị

```
1. Identify SVN repository structure
2. Create authors mapping file
3. Decide on Git repository structure
4. Plan branch/tag strategy
5. Communicate with team
```

### Giai đoạn 2: Chuyển đổi thử nghiệm

```
# Do test migration first
git svn clone http://svn.example.com/repo test-migration

# Verify:
- Commit history
- Branches
- Tags
- File contents
```

### Giai đoạn 3: Tạo tệp tác giả

Trích xuất các tác giả SVN:

```
svn log -q http://svn.example.com/repo | \
  grep "^r" | \
  awk '{print $3}' | \
  sort -u > svn-authors.txt
```

Chuyển đổi sang định dạng Git:

```
# authors.txt
jdoe = John Doe <john.doe@example.com>
jsmith = Jane Smith <jane.smith@example.com>
admin = Administrator <admin@example.com>
```

### Giai đoạn 4: Thực hiện chuyển đổi

```
# Clone SVN repository
git svn clone http://svn.example.com/repo \
  --authors-file=authors.txt \
  --stdlayout \
  migrated-repo

cd migrated-repo

# Convert SVN tags to Git tags
git for-each-ref refs/remotes/tags | cut -d / -f 4- | \
while read tagname; do
  git tag "$tagname" "refs/remotes/tags/$tagname"
  git branch -r -d "tags/$tagname"
done

# Convert SVN branches to Git branches
git for-each-ref refs/remotes/origin | cut -d / -f 4- | \
while read branchname; do
  git branch "$branchname" "refs/remotes/origin/$branchname"
done

# Remove SVN remote
git remote rm origin
```

### Giai đoạn 5: Push lên Git Remote

```
# Add Git remote
git remote add origin https://github.com/your-org/repo.git

# Push all branches
git push -u origin --all

# Push all tags
git push -u origin --tags
```

## Xử lý các trường hợp đặc biệt

### Repository lớn

Đối với các repository lớn, hãy nhập theo từng phần tăng dần:

```
# Start from revision 1000
git svn clone http://svn.example.com/repo \
  -r 1000:HEAD \
  --authors-file=authors.txt
```

### Bỏ qua các đường dẫn

Tạo `.gitignore` dựa trên các mục bỏ qua của SVN:

```
# Extract SVN ignores
git svn show-ignore > .gitignore

# Commit
git add .gitignore
git commit -m "Add .gitignore from SVN"
```

### Tệp nhị phân

SVN và Git xử lý tệp nhị phân khác nhau:

```
# For large binary files, consider Git LFS
git lfs install
git lfs track "*.psd"
git lfs track "*.zip"
```

## Cầu nối SVN (git-svn)

Tiếp tục sử dụng SVN trong khi chuyển đổi:

```
# Clone with git-svn
git svn clone http://svn.example.com/repo

# Work normally with Git locally

# Get SVN updates
git svn rebase

# Push to SVN
git svn dcommit
```

**Quy trình làm việc**:

```
# Pull from SVN
git svn rebase

# Make changes
git add .
git commit -m "Changes"

# Push to SVN
git svn dcommit
```

## Các công việc sau chuyển đổi

### 1. Xác minh việc chuyển đổi

```
# Check commit count
git log --oneline | wc -l

# Compare with SVN
# Should match or be close

# Check specific files
git log -- path/to/file.txt
svn log path/to/file.txt

# Verify branches
git branch -a

# Verify tags
git tag
```

## So sánh: Lệnh SVN so với Git

```
# Checkout
SVN: svn checkout
Git: git clone

# Update
SVN: svn update
Git: git pull

# Commit
SVN: svn commit
Git: git commit + git push

# Status
SVN: svn status
Git: git status

# Log
SVN: svn log
Git: git log

# Branch
SVN: svn copy .../trunk .../branches/name
Git: git checkout -b name

# Tag
SVN: svn copy .../trunk .../tags/v1.0
Git: git tag v1.0

# Merge
SVN: svn merge
Git: git merge

# Diff
SVN: svn diff
Git: git diff
```

## Khắc phục sự cố

### Vấn đề: Thiếu Commit

```
# Check SVN revision range
git svn log | head -n 20

# Re-clone from specific revision
git svn clone -r START:HEAD ...
```

### Vấn đề: Lỗi ánh xạ tác giả

```
# Add missing authors to authors.txt
# Re-run migration
```

### Vấn đề: Thư mục .git lớn

```
# Garbage collection
git gc --aggressive --prune=now

# Consider shallow clone for very old history
```

## Tổng kết hôm nay

Việc chuyển từ SVN sang Git đòi hỏi kế hoạch và thực hiện cẩn thận. Sử dụng các công cụ phù hợp như `svn2git` và duy trì ánh xạ tác giả đảm bảo quá trình chuyển đổi suôn sẻ. Hãy dành thời gian kiểm thử việc chuyển đổi, xác minh kết quả, và đào tạo nhóm của bạn về quy trình làm việc Git.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git svn clone
* git svn rebase
* git svn dcommit
* git svn show-ignore
* git for-each-ref
* git gc --aggressive
