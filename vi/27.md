# Ngày 27: Quản lý phiên bản bằng Branch trên cùng một Remote Repository

Các nhóm khác nhau sử dụng các chiến lược rẽ nhánh khác nhau. Bài viết này khám phá các mô hình rẽ nhánh phổ biến và khi nào nên sử dụng mỗi mô hình.

## Tại sao chiến lược rẽ nhánh quan trọng

Không có chiến lược rõ ràng:
* Xung đột mã tăng lên
* Việc phát hành trở nên hỗn loạn
* Lỗi lọt vào production
* Phối hợp nhóm gặp khó khăn

## GitHub Flow

**Phù hợp nhất cho**: Ứng dụng web, triển khai liên tục

### Chiến lược

* Một branch chính: `main`
* Feature branch cho mọi thay đổi
* Triển khai từ `main`

### Quy trình làm việc

```
1. Create branch from main
   git checkout -b feature-name

2. Work and commit
   git commit -am "Add feature"

3. Push and create PR
   git push origin feature-name

4. Review and discuss

5. Deploy from branch (staging)

6. Merge to main
   # On GitHub: Merge PR

7. Deploy from main (production)
```

### Ưu điểm
* Đơn giản và thẳng thắn
* Phát triển nhịp độ nhanh
* main luôn sẵn sàng triển khai
* Tuyệt vời cho triển khai liên tục

### Nhược điểm
* Không hỗ trợ phát hành dài hạn
* Yêu cầu CI/CD tốt
* Không lý tưởng cho nhiều phiên bản

## Git Flow

**Phù hợp nhất cho**: Phần mềm có phát hành, nhiều phiên bản

### Các loại Branch

* **main**: Mã sẵn sàng cho production
* **develop**: Branch tích hợp
* **feature/**: Tính năng mới
* **release/**: Chuẩn bị phát hành
* **hotfix/**: Sửa lỗi khẩn cấp

### Quy trình làm việc

```
# Start new feature
git checkout -b feature/login develop

# Work on feature
git commit -am "Implement login"

# Finish feature
git checkout develop
git merge --no-ff feature/login
git branch -d feature/login

# Start release
git checkout -b release/1.0 develop

# Prepare release (bug fixes only)
git commit -am "Bump version to 1.0"

# Finish release
git checkout main
git merge --no-ff release/1.0
git tag -a 1.0

git checkout develop
git merge --no-ff release/1.0
git branch -d release/1.0

# Hotfix
git checkout -b hotfix/1.0.1 main
git commit -am "Fix critical bug"

git checkout main
git merge --no-ff hotfix/1.0.1
git tag -a 1.0.1

git checkout develop
git merge --no-ff hotfix/1.0.1
git branch -d hotfix/1.0.1
```

### Ưu điểm
* Phân tách mối quan tâm rõ ràng
* Hỗ trợ nhiều phiên bản
* Quy trình phát hành có cấu trúc

### Nhược điểm
* Phức tạp hơn
* Chu kỳ phát triển chậm hơn
* Chi phí phụ thêm cho các dự án đơn giản

## GitLab Flow

**Phù hợp nhất cho**: Các tổ chức có môi trường staging và production

### Chiến lược

* Các branch theo môi trường: `main`, `staging`, `production`
* Feature branch merge vào `main`
* Thăng cấp qua các môi trường

### Quy trình làm việc

```
# Feature development
git checkout -b feature-name main
# Work and commit
git push origin feature-name
# Create MR to main

# After merge to main
# Deploy to staging
git checkout staging
git merge main
git push origin staging

# After testing in staging
# Deploy to production
git checkout production
git merge staging
git push origin production
```

### Ưu điểm
* Triển khai dựa trên môi trường
* Lộ trình thăng cấp rõ ràng
* Phù hợp cho các ngành bị quản lý chặt chẽ

### Nhược điểm
* Nhiều branch hơn cần quản lý
* Yêu cầu tự động hóa
* Có thể chậm hơn

## Trunk-Based Development

**Phù hợp nhất cho**: Các nhóm hiệu suất cao, triển khai liên tục

### Chiến lược

* Một trunk duy nhất: `main`
* Các feature branch có vòng đời rất ngắn (< 1 ngày)
* Feature flag cho các tính năng chưa hoàn thiện

### Quy trình làm việc

```
# Create short-lived branch
git checkout -b quick-fix main

# Make small change
git commit -am "Fix button color"

# Merge same day
git checkout main
git merge quick-fix
git push origin main

# Or commit directly to main
# (with CI and feature flags)
```

### Ưu điểm
* Tích hợp nhanh nhất
* Giảm xung đột merge
* Khuyến khích CI/CD
* Chất lượng mã cao

### Nhược điểm
* Yêu cầu kỷ luật
* Cần CI/CD tốt
* Độ phức tạp của feature flag

## Release Flow (Microsoft)

**Phù hợp nhất cho**: Phần mềm doanh nghiệp, phát hành theo kế hoạch

### Chiến lược

* `main`: Luôn sẵn sàng phát hành
* `release/*`: Các branch ổn định hóa
* Topic branch: Các tính năng vòng đời ngắn

### Quy trình làm việc

```
# Create topic branch
git checkout -b users/name/feature main

# Work and create PR
git push origin users/name/feature

# Create release branch
git checkout -b release/v2.0 main

# Cherry-pick into release
git cherry-pick <commit-hash>

# Release
git checkout main
git merge release/v2.0
git tag v2.0
```

### Ưu điểm
* Lịch phát hành linh hoạt
* Phát triển và ổn định hóa song song
* Phù hợp cho doanh nghiệp

### Nhược điểm
* Có thể phức tạp
* Yêu cầu cherry-pick
* Nhiều công việc bảo trì hơn

## Lựa chọn chiến lược

### Dùng GitHub Flow khi:
* Triển khai liên tục
* Ứng dụng web
* Nhóm nhỏ
* Lặp lại nhanh

### Dùng Git Flow khi:
* Phát hành theo lịch
* Ứng dụng desktop/mobile
* Cần hỗ trợ nhiều phiên bản
* Vòng đời phần mềm truyền thống

### Dùng GitLab Flow khi:
* Nhiều môi trường
* Triển khai theo giai đoạn
* Yêu cầu quản lý tuân thủ

### Dùng Trunk-Based khi:
* Nhóm giàu kinh nghiệm
* CI/CD xuất sắc
* Triển khai liên tục
* Tần suất phát hành cao

## Quy ước đặt tên Branch

### Feature Branch
```
feature/user-authentication
feature/dark-mode
feat/issue-123
```

### Bug Fix Branch
```
fix/login-error
bugfix/issue-456
hotfix/critical-security-patch
```

### Release Branch
```
release/1.0
release/2.0.0
release/v1.5
```

### Các Branch khác
```
docs/update-readme
test/integration-tests
refactor/database-layer
chore/update-dependencies
```

## Các lệnh quản lý Branch

### Liệt kê Branch
```
# Local branches
git branch

# All branches (including remote)
git branch -a

# With last commit
git branch -v

# Merged branches
git branch --merged

# Unmerged branches
git branch --no-merged
```

### Xóa Branch
```
# Delete local branch
git branch -d feature-name

# Force delete
git branch -D feature-name

# Delete remote branch
git push origin --delete feature-name
```

### Đổi tên Branch
```
# Rename current branch
git branch -m new-name

# Rename other branch
git branch -m old-name new-name
```

## Tổng kết hôm nay

Việc lựa chọn chiến lược rẽ nhánh phù hợp phụ thuộc vào nhóm, dự án và mô hình triển khai của bạn. Không có giải pháp nào phù hợp cho tất cả. Hãy bắt đầu với một chiến lược đơn giản như GitHub Flow và phát triển khi cần. Điều then chốt là tính nhất quán và giao tiếp.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git checkout -b branch-name
* git merge --no-ff
* git cherry-pick
* git branch -m
* git branch --merged
* git branch --no-merged
* git push origin --delete
