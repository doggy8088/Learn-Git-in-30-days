# Ngày 22: Sửa lịch sử phiên bản đã commit Phần 4 (rebase)

Chúng ta đã thảo luận ba phương pháp khác nhau để sửa phiên bản. Nói một cách nghiêm ngặt, `git revert` và `git cherry-pick` không thực sự "sửa bản ghi lịch sử phiên bản" - chúng áp dụng các phiên bản đã commit trước đó, dù là "áp dụng lại" hay "áp dụng ngược". Bài viết này sẽ giải thích cơ chế Rebase của Git, cơ chế thực sự được dùng để sửa đổi các bản ghi commit. Tính năng này rất quan trọng và mạnh mẽ.

## Hiểu git rebase

Rebase là một trong những tính năng mạnh mẽ nhất nhưng cũng tiềm ẩn nguy hiểm của Git. Nó cho phép bạn viết lại lịch sử commit, làm cho lịch sử sạch hơn và tuyến tính hơn.

Rebase là quá trình di chuyển hoặc kết hợp một dãy commit sang một commit cơ sở (base) mới. Khác với merge, vốn bảo toàn lịch sử đầy đủ, rebase viết lại lịch sử để tạo ra một tiến trình tuyến tính.

## Rebase cơ bản

Thao tác rebase cơ bản:

```
# On feature branch
git checkout feature-branch

# Rebase onto main
git rebase main
```

Thao tác này phát lại tất cả các commit từ `feature-branch` lên trên `main`.

## Cách Rebase hoạt động

Khi bạn rebase:

1. Git tìm tổ tiên chung của branch của bạn và branch đích
2. Nó lưu tất cả các commit từ branch của bạn kể từ tổ tiên đó
3. Nó reset branch của bạn về branch đích
4. Nó áp dụng lại từng commit đã lưu, lần lượt từng cái một

## Rebase so với Merge

**Merge**:
* Bảo toàn lịch sử đầy đủ
* Cho thấy khi nào các branch phân nhánh và hợp nhất
* An toàn cho các branch dùng chung
* Tạo merge commit

**Rebase**:
* Tạo lịch sử tuyến tính
* Sạch hơn, dễ hiểu hơn
* Viết lại lịch sử (nguy hiểm cho các branch dùng chung)
* Không có merge commit

So sánh trực quan:

```
# Before rebase
     C---D feature
    /
A---B---E---F main

# After git rebase main (on feature)
             C'---D' feature
            /
A---B---E---F main

# After git merge feature (on main)
     C---D 
    /     A---B---E---F---G main
```

## Xử lý xung đột trong quá trình Rebase

Nếu xung đột xảy ra:

```
# Git pauses the rebase
# Resolve conflicts in the files
# Stage the resolved files
git add <resolved-files>

# Continue the rebase
git rebase --continue
```

Để hủy bỏ rebase:

```
git rebase --abort
```

Để bỏ qua commit hiện tại:

```
git rebase --skip
```

## Interactive Rebase

Interactive rebase cho phép bạn toàn quyền kiểm soát các commit:

```
git rebase -i HEAD~3
```

Thao tác này mở một trình soạn thảo, nơi bạn có thể:

* **pick**: Giữ nguyên commit
* **reword**: Thay đổi thông điệp commit
* **edit**: Dừng lại để amend commit
* **squash**: Kết hợp với commit trước đó, giữ cả hai thông điệp
* **fixup**: Kết hợp với commit trước đó, bỏ thông điệp này
* **drop**: Xóa hoàn toàn commit

Ví dụ trình soạn thảo interactive rebase:

```
pick abc123 Add feature A
reword def456 Add feature B
squash ghi789 Fix typo in feature B
drop jkl012 Experimental change
```

## Các tác vụ Interactive Rebase thường gặp

### Gộp (Squash) các Commit

Kết hợp nhiều commit thành một:

```
git rebase -i HEAD~3

# In the editor, change:
pick abc123 First commit
pick def456 Second commit
pick ghi789 Third commit

# To:
pick abc123 First commit
squash def456 Second commit
squash ghi789 Third commit
```

### Sắp xếp lại thứ tự các Commit

Chỉ cần sắp xếp lại thứ tự các dòng trong trình soạn thảo interactive rebase.

### Chỉnh sửa một Commit

```
git rebase -i HEAD~3

# Change "pick" to "edit" for the commit you want to modify
# Git will stop at that commit
# Make your changes
git add .
git commit --amend
git rebase --continue
```

## Rebase lên một Branch khác

```
git rebase --onto new-base old-base feature-branch
```

Thao tác này di chuyển các commit từ `feature-branch` nằm sau `old-base` lên trên `new-base`.

## Autosquash

Tự động squash các fixup commit:

```
# Create a fixup commit
git commit --fixup <commit-to-fix>

# Later, rebase with autosquash
git rebase -i --autosquash main
```

## Quy tắc vàng của Rebasing

**Không bao giờ rebase các commit đã được push lên repository dùng chung!**

Rebase viết lại lịch sử, điều này có thể gây ra vấn đề lớn cho những người khác đã dựa công việc của họ trên các commit đó.

An toàn cho:
* Các commit cục bộ chưa được push
* Các feature branch do bạn sở hữu
* Dọn dẹp trước khi tạo pull request

Nguy hiểm cho:
* Branch main/master
* Các feature branch dùng chung
* Bất kỳ commit nào mà người khác có thể đã dựa vào để làm việc

## Khôi phục từ lỗi Rebase

Nếu một lần rebase gặp sự cố:

```
# Find the commit before the rebase
git reflog

# Reset to that commit
git reset --hard HEAD@{2}
```

## Các thực hành tốt nhất

1. **Rebase trước khi push**: Dọn dẹp các commit cục bộ của bạn trước khi chia sẻ
2. **Đừng rebase lịch sử công khai**: Chỉ rebase các commit cục bộ
3. **Sao lưu trước khi rebase lớn**: Tạo một branch trước
4. **Thông báo**: Cho nhóm của bạn biết nếu bạn buộc phải rebase mã dùng chung
5. **Thực hành**: Thử rebase trên các branch dùng một lần trước

## Tổng kết hôm nay

Rebase là một công cụ mạnh mẽ để tạo lịch sử commit sạch và tuyến tính. Mặc dù nó rất tuyệt cho công việc cục bộ và chuẩn bị branch để merge, nó phải được sử dụng cẩn thận để tránh viết lại lịch sử dùng chung. Hiểu khi nào và làm thế nào để sử dụng rebase là điều thiết yếu cho các quy trình làm việc Git nâng cao.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git rebase
* git rebase main
* git rebase -i
* git rebase --continue
* git rebase --abort
* git rebase --skip
* git rebase --onto
* git rebase --autosquash
* git commit --fixup
