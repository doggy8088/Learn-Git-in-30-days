# Ngày 28: Hiểu quy trình Fork và Pull Request trên GitHub

Fork và pull request là nền tảng của cộng tác mã nguồn mở trên GitHub. Bài viết này giải thích cách đóng góp cho các dự án mà bạn không có quyền ghi.

## Hiểu về Fork

Một fork là một bản sao hoàn chỉnh của một repository trong tài khoản GitHub của bạn. Nó cho phép bạn:
* Tự do thử nghiệm mà không ảnh hưởng đến dự án gốc
* Đề xuất thay đổi thông qua pull request
* Tùy biến dự án theo nhu cầu của bạn

## Fork so với Clone so với Branch

* **Fork**: Sao chép repository trên GitHub (tài khoản của bạn)
* **Clone**: Sao chép repository về máy cục bộ
* **Branch**: Tạo một đường phát triển phân nhánh

## Fork một Repository

### Trên GitHub

1. Điều hướng tới repository
2. Nhấp nút "Fork" (trên cùng bên phải)
3. Chọn nơi để fork (tài khoản của bạn hoặc tổ chức)
4. Chờ GitHub tạo fork

### Clone Fork của bạn

```
# Clone your fork
git clone https://github.com/your-username/repo-name.git

# Navigate to directory
cd repo-name

# Add upstream remote
git remote add upstream https://github.com/original-owner/repo-name.git

# Verify remotes
git remote -v
# origin    https://github.com/your-username/repo-name.git (fetch)
# origin    https://github.com/your-username/repo-name.git (push)
# upstream  https://github.com/original-owner/repo-name.git (fetch)
# upstream  https://github.com/original-owner/repo-name.git (push)
```

## Quy trình Pull Request hoàn chỉnh

### Bước 1: Đồng bộ Fork của bạn

```
# Fetch upstream changes
git fetch upstream

# Checkout your main branch
git checkout main

# Merge upstream changes
git merge upstream/main

# Push to your fork
git push origin main
```

### Bước 2: Tạo Feature Branch

```
# Create and checkout feature branch
git checkout -b fix-typo-in-readme

# Make your changes
# Edit files...

# Stage changes
git add README.md

# Commit changes
git commit -m "Fix typo in installation instructions"
```

### Bước 3: Push lên Fork của bạn

```
# Push branch to your fork
git push origin fix-typo-in-readme
```

### Bước 4: Tạo Pull Request

1. Vào fork của bạn trên GitHub
2. Nhấp nút "Compare & pull request"
3. Điền chi tiết PR:
   * **Title**: Mô tả rõ ràng, súc tích
   * **Description**: Cái gì, tại sao, và như thế nào
   * Tham chiếu các issue nếu có
4. Nhấp "Create pull request"

### Bước 5: Phản hồi ý kiến

```
# Make requested changes
# Edit files...

# Commit changes
git add .
git commit -m "Address review feedback"

# Push updates
git push origin fix-typo-in-readme
# PR automatically updates!
```

### Bước 6: Sau khi Merge

```
# Switch to main
git checkout main

# Pull merged changes
git pull upstream main

# Push to your fork
git push origin main

# Delete feature branch
git branch -d fix-typo-in-readme
git push origin --delete fix-typo-in-readme
```

## Giữ Fork luôn cập nhật

### Đồng bộ thường xuyên

```
# Fetch and merge in one command
git checkout main
git pull upstream main
git push origin main
```

### Đồng bộ tự động

Sử dụng nút "Fetch upstream" của GitHub trên trang fork của bạn, hoặc thiết lập GitHub Actions:

```yaml
# .github/workflows/sync-upstream.yml
name: Sync Fork
on:
  schedule:
    - cron: '0 0 * * *'  # Daily
  workflow_dispatch:
jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: TobKed/github-forks-sync-action@v1
        with:
          upstream: original-owner/repo-name
          target: your-username/repo-name
```

## Nhiều Commit trong một PR

### Cách 1: Interactive Rebase

```
# Squash commits
git rebase -i HEAD~3

# In editor, change 'pick' to 'squash' for commits to combine
# Save and edit commit message

# Force push (since you're rewriting history)
git push -f origin feature-branch
```

### Cách 2: Soft Reset

```
# Reset to before your commits
git reset --soft HEAD~3

# Create single commit
git commit -m "Complete feature implementation"

# Force push
git push -f origin feature-branch
```

## Xử lý xung đột Merge trong PR

```
# Sync with upstream
git fetch upstream

# Rebase on upstream/main
git rebase upstream/main

# Resolve conflicts
# Edit conflicting files
git add resolved-files
git rebase --continue

# Force push
git push -f origin feature-branch
```

## Draft Pull Request

Tạo draft PR để nhận phản hồi sớm:

1. Khi tạo PR, nhấp mũi tên thả xuống trên "Create pull request"
2. Chọn "Create draft pull request"
3. Đánh dấu sẵn sàng khi hoàn tất

Lợi ích:
* Nhận phản hồi sớm
* Cho thấy công việc đang tiến hành
* Ngăn việc merge vô tình

## Các thực hành tốt nhất cho Pull Request

### Trước khi tạo PR

- [ ] Mã hoạt động và đã được kiểm thử
- [ ] Tuân theo hướng dẫn phong cách của dự án
- [ ] Tài liệu đã được cập nhật
- [ ] Các commit sạch và hợp lý
- [ ] Branch đã cập nhật với main

### Viết PR tốt

**Title**:
```
❌ Fix stuff
✅ Fix null pointer exception in user login
```

**Description**:
```
## What
Fixes a null pointer exception that occurs when users login with empty passwords.

## Why
Bug #123 reported crashes on invalid login attempts.

## How
Added null check before password validation.

## Testing
- Tested with empty password
- Tested with valid password
- Tested with invalid password

Closes #123
```

### Trong quá trình Review

* Phản hồi tất cả các bình luận
* Đặt câu hỏi nếu chưa rõ
* Thực hiện các thay đổi được yêu cầu một cách kịp thời
* Cởi mở với các đề xuất
* Cảm ơn người review

## Đóng góp cho mã nguồn mở

### Tìm dự án

1. **GitHub Explore**: https://github.com/explore
2. **First Timers Only**: https://www.firsttimersonly.com/
3. **Good First Issue**: Tìm kiếm trên GitHub
4. **Up For Grabs**: https://up-for-grabs.net/

### Trước khi đóng góp

1. Đọc `CONTRIBUTING.md`
2. Kiểm tra các issue đang mở
3. Xem các PR hiện có
4. Hiểu quy tắc ứng xử (code of conduct)
5. Thiết lập môi trường phát triển

### PR đầu tiên của bạn

Bắt đầu từ việc nhỏ:
* Sửa lỗi chính tả
* Cải thiện tài liệu
* Thêm kiểm thử
* Sửa các lỗi hiển nhiên

### Xây dựng uy tín

1. Bắt đầu với tài liệu
2. Báo cáo các lỗi tốt
3. Giúp đỡ người khác trong các issue
4. Gửi các PR chất lượng
5. Kiên nhẫn và tôn trọng

## Các lỗi thường gặp cần tránh

1. **Không đồng bộ fork**: Luôn cập nhật trước khi tạo PR
2. **Quá nhiều thay đổi**: Giữ PR tập trung
3. **Không có mô tả**: Giải thích cái gì và tại sao
4. **Force push lên main**: Không bao giờ làm điều này
5. **Tranh cãi với maintainer**: Hãy tôn trọng
6. **Không kiểm thử**: Luôn kiểm thử các thay đổi của bạn

## Tổng kết hôm nay

Fork và pull request cho phép cộng tác mã nguồn mở trên quy mô lớn. Hiểu quy trình làm việc này mở ra hàng nghìn dự án mà bạn có thể đóng góp. Hãy bắt đầu từ việc nhỏ, kiên nhẫn, và nhớ rằng mọi người đóng góp giàu kinh nghiệm cũng từng là người mới bắt đầu.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git clone <fork-url>
* git remote add upstream <original-url>
* git fetch upstream
* git merge upstream/main
* git push origin branch-name
* git push -f origin branch-name
* git rebase -i HEAD~n
* git reset --soft HEAD~n
