# Ngày 17: Khái niệm cơ bản và cách sử dụng Merge

Như đã đề cập trong Ngày 08 (Khái niệm cơ bản và cách sử dụng Branch), chúng ta đã học về "branch". Giờ chúng ta sẽ thảo luận về cách thực hiện "merge". Vì Git là một hệ thống quản lý phiên bản phân tán (DVCS), bạn sẽ liên tục thực hiện các thao tác tạo branch và merge, dù là merge có chủ ý (`git merge`) hay merge vô ý (`git pull`). Nói tóm lại, các thao tác "tạo branch" và "merge" thực sự xảy ra thường xuyên khi sử dụng Git để quản lý phiên bản. Bài viết này sẽ giải thích các khái niệm cơ bản và cách sử dụng các thao tác "merge".

## Hiểu các khái niệm về Merge

Khi bạn tạo các branch trong một working directory của Git, bạn có thể phát triển hệ thống của mình theo các nhu cầu khác nhau một cách riêng biệt mà không ảnh hưởng lẫn nhau. Ví dụ, bạn có thể giữ hệ thống vốn ổn định của mình trong branch `master` để phát triển, và khi bạn cần sửa lỗi, hãy tạo thêm một branch `bugfix` để sửa các lỗi phần mềm. Sau khi các lỗi đã được sửa, bạn có thể áp dụng lại các thay đổi từ branch `bugfix` vào `master` thông qua "merge". Đây là một trong những tình huống sử dụng chính.

Nhìn chung, mọi người phát triển trên một branch chính hoặc branch mặc định (`master`), sau đó tạo các branch theo nhu cầu (`bugfix`), và cuối cùng merge hai branch thành một. Trên thực tế, khi thực hiện thao tác "merge", bạn merge một branch khác vào branch hiện tại, rồi loại bỏ branch còn lại theo cách thủ công. Điều này phù hợp với khái niệm "merge hai branch thành một".

Trong thực tế, thường có những cơ hội merge ba, bốn hoặc nhiều branch hơn vào một trong số chúng. Ví dụ, ngoài branch chính (`master`), bạn còn tạo một branch để gỡ lỗi (`bugfix`) và một branch để thêm tính năng (`feature`). Sau khi phát triển đến một mức độ nhất định, bạn có thể quyết định có merge cả hai branch này trở lại branch chính (`master`) cùng nhau hay không.

Khi sử dụng merge trong Git, có một khái niệm quan trọng: **hành động merge phải xảy ra trong cùng một repository**. Hãy nhớ lại rằng trong bất kỳ Git repository nào, phải có một Initial Commit object (phiên bản ban đầu), và tất cả các phiên bản khác sẽ liên quan tới phiên bản này. Chúng ta gọi mối quan hệ này là "object được theo dõi trên các đầu mút của branch", vì vậy bạn không thể merge một branch cụ thể từ một repository vào một branch của một repository khác hoàn toàn không liên quan.

Khi merge, nếu hai branch đã sửa đổi cùng một tệp, nhưng miễn là các dòng được sửa đổi khác nhau, Git sẽ tự động áp dụng/merge hai thay đổi này cho bạn. Nhưng nếu tình cờ bạn sửa đổi "cùng một tệp" tại "cùng một dòng" trong cả hai branch, một sự kiện xung đột sẽ xảy ra trong quá trình merge. Khi xung đột merge xảy ra, Git sẽ không quyết định bất cứ điều gì thay bạn, mà sẽ giao công việc "giải quyết xung đột" cho "bạn", và các tệp xung đột này đều sẽ được đánh dấu với trạng thái `unmerged`. Sau một xung đột merge, bạn có thể dùng lệnh `git status` để xem các trạng thái này.

## Các loại Merge

Có hai loại merge chính trong Git:

1. **Fast-forward merge**: Được sử dụng khi branch đích chưa phân kỳ khỏi branch nguồn
2. **Three-way merge (merge ba chiều)**: Được sử dụng khi cả hai branch đều có commit mới

## Fast-Forward Merge

Fast-forward merge xảy ra khi branch hiện tại chưa phân kỳ khỏi branch đang được merge. Git đơn giản chỉ di chuyển con trỏ branch về phía trước.

```
# On master branch
git merge feature-branch
```

Nếu `master` chưa có bất kỳ commit mới nào kể từ khi `feature-branch` được tạo, Git sẽ thực hiện fast-forward merge.

## Three-Way Merge

Khi cả hai branch đều có commit mới, Git thực hiện three-way merge, tạo một merge commit mới kết hợp các thay đổi từ cả hai branch.

```
# On master branch
git merge feature-branch
```

Điều này tạo một commit mới với hai commit cha.

## Ngăn chặn Fast-Forward

Đôi khi bạn muốn bảo toàn lịch sử branch ngay cả khi fast-forward là khả thi:

```
git merge --no-ff feature-branch
```

Lệnh này luôn tạo một merge commit, ngay cả đối với các fast-forward merge.

## Xung đột Merge

Xung đột xảy ra khi cùng một dòng trong cùng một tệp đã bị thay đổi khác nhau trong hai branch đang được merge. Khi điều này xảy ra:

1. Git tạm dừng quá trình merge
2. Đánh dấu các tệp xung đột
3. Thêm các dấu hiệu xung đột vào tệp
4. Chờ bạn giải quyết các xung đột

## Xem các tệp xung đột

Để xem những tệp nào có xung đột:

```
git status
```

Các tệp có xung đột được liệt kê là "both modified".

## Dấu hiệu xung đột

Git thêm các dấu hiệu vào các tệp xung đột:

```
<<<<<<< HEAD
Your changes
=======
Their changes
>>>>>>> branch-name
```

* `<<<<<<< HEAD`: Đánh dấu điểm bắt đầu của các thay đổi của bạn
* `=======`: Phân tách hai phiên bản
* `>>>>>>> branch-name`: Đánh dấu điểm kết thúc của các thay đổi đến

## Giải quyết xung đột

Để giải quyết xung đột:

1. Mở các tệp xung đột
2. Tìm các dấu hiệu xung đột
3. Chỉnh sửa tệp để giải quyết xung đột
4. Loại bỏ các dấu hiệu xung đột
5. Stage các tệp đã giải quyết: `git add <file>`
6. Hoàn thành merge: `git commit`

## Hủy bỏ một Merge

Nếu bạn muốn hủy một merge đang diễn ra:

```
git merge --abort
```

Lệnh này đưa repository của bạn trở lại trạng thái trước khi merge bắt đầu.

## Xem lịch sử Merge

Để xem các merge commit trong lịch sử của bạn:

```
git log --oneline --graph --all
```

Lệnh này hiển thị biểu diễn trực quan về lịch sử branch và merge của bạn.

## Chiến lược Merge

Git hỗ trợ các chiến lược merge khác nhau:

* **recursive** (mặc định): Chiến lược three-way merge mặc định
* **ours**: Luôn ưu tiên phiên bản của chúng ta trong các xung đột
* **theirs**: Luôn ưu tiên phiên bản của họ trong các xung đột

```
git merge -X ours branch-name
git merge -X theirs branch-name
```

## Thực hành tốt nhất

1. **Commit công việc của bạn** trước khi merge
2. **Pull các thay đổi mới nhất** từ remote trước khi merge
3. **Kiểm tra merge** trước khi push lên các branch dùng chung
4. **Trao đổi** với nhóm của bạn về các lần merge
5. **Giữ các lần merge nhỏ** khi có thể

## Tóm tắt hôm nay

Merge là một thao tác cơ bản của Git, cho phép bạn kết hợp công việc từ các branch khác nhau. Hiểu cách merge hoạt động, đặc biệt là cách xử lý xung đột, là điều thiết yếu cho việc cộng tác hiệu quả. Hãy thực hành merge thường xuyên để trở nên thoải mái với quy trình này.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git merge
* git merge --no-ff
* git merge --abort
* git merge -X ours
* git merge -X theirs
* git log --graph
* git status
