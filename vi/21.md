# Ngày 21: Sửa lịch sử phiên bản đã commit Phần 3 (cherry-pick)

Trong quá trình quản lý phiên bản, có một tình huống phổ biến khác: bạn đã phát triển trong một branch được một thời gian, nhưng sau đó quyết định không muốn toàn bộ branch đó nữa. Tuy nhiên, trong đó có một vài commit mà bạn vẫn muốn giữ lại. Trong trường hợp này, bạn không thể xóa branch, nhưng việc merge toàn bộ branch trở lại cũng không phù hợp. Bạn nên làm gì? Bài viết này sẽ giải thích cách sử dụng lệnh `git cherry-pick` để "chọn thủ công" các thay đổi mà bạn muốn áp dụng.

## Hiểu git cherry-pick

Đôi khi bạn muốn áp dụng các commit cụ thể từ một branch sang branch khác mà không cần merge toàn bộ branch. Lệnh `cherry-pick` của Git cho phép bạn làm chính xác điều đó - chọn lọc các commit và áp dụng chúng vào branch hiện tại của bạn.

`git cherry-pick` áp dụng các thay đổi được đưa vào bởi các commit hiện có vào branch hiện tại của bạn. Nó tạo ra các commit mới với cùng thay đổi nhưng mã băm commit khác nhau.

## Cherry-Pick cơ bản

Để cherry-pick một commit đơn lẻ:

```
# Switch to the target branch
git checkout main

# Cherry-pick the commit
git cherry-pick <commit-hash>
```

Thao tác này tạo một commit mới trên branch hiện tại với cùng thay đổi như commit đã chỉ định.

## Cherry-Pick nhiều Commit

Để cherry-pick nhiều commit:

```
# Cherry-pick several commits
git cherry-pick <hash1> <hash2> <hash3>
```

Để cherry-pick một dải commit:

```
# Cherry-pick commits from commit1 to commit2 (exclusive of commit1)
git cherry-pick commit1..commit2

# Cherry-pick commits from commit1 to commit2 (inclusive of commit1)
git cherry-pick commit1^..commit2
```

## Cherry-Pick mà không Commit

Để áp dụng các thay đổi mà không tự động tạo commit:

```
git cherry-pick --no-commit <commit-hash>
# or
git cherry-pick -n <commit-hash>
```

Điều này hữu ích khi bạn muốn cherry-pick nhiều commit và tạo một commit duy nhất.

## Xử lý xung đột

Nếu xung đột xảy ra trong quá trình cherry-pick:

```
# Resolve conflicts in the files
# Stage the resolved files
git add <resolved-files>

# Continue the cherry-pick
git cherry-pick --continue
```

Để hủy bỏ một cherry-pick đang thực hiện:

```
git cherry-pick --abort
```

Để bỏ qua commit hiện tại và tiếp tục với commit tiếp theo:

```
git cherry-pick --skip
```

## Cherry-Pick kèm chỉnh sửa

Để chỉnh sửa thông điệp commit trong khi cherry-pick:

```
git cherry-pick -e <commit-hash>
# or
git cherry-pick --edit <commit-hash>
```

## Cherry-Pick và Sign-off

Để thêm một dòng sign-off vào thông điệp commit:

```
git cherry-pick -s <commit-hash>
# or
git cherry-pick --signoff <commit-hash>
```

## Các trường hợp sử dụng thực tế

### Trường hợp 1: Áp dụng Hotfix cho nhiều Branch

```
# Fix created on main branch (commit abc123)
git checkout release-1.0
git cherry-pick abc123

git checkout release-2.0
git cherry-pick abc123
```

### Trường hợp 2: Tích hợp tính năng có chọn lọc

```
# Feature branch has commits A, B, C, D
# You only want B and C on main

git checkout main
git cherry-pick <hash-B> <hash-C>
```

### Trường hợp 3: Khôi phục các Commit bị mất

```
# Find the lost commit using reflog
git reflog

# Cherry-pick it to current branch
git cherry-pick <lost-commit-hash>
```

## Cherry-Pick so với Merge so với Rebase

**Cherry-pick**:
* Áp dụng có chọn lọc các commit cụ thể
* Tạo mã băm commit mới
* Phù hợp cho việc tích hợp có chọn lọc

**Merge**:
* Kết hợp toàn bộ các branch
* Bảo toàn lịch sử đầy đủ
* Tốt nhất cho việc tích hợp các feature branch

**Rebase**:
* Phát lại các commit trên base mới
* Lịch sử tuyến tính
* Phù hợp cho việc dọn dẹp lịch sử

## Các thực hành tốt nhất

1. **Sử dụng tiết kiệm**: Cherry-pick có thể làm lịch sử trở nên rối rắm nếu lạm dụng
2. **Ghi lại lý do**: Giải thích lý do bạn cherry-pick trong thông điệp commit
3. **Tránh trùng lặp**: Đừng cherry-pick các commit mà sau này sẽ được merge
4. **Kiểm tra các phụ thuộc**: Đảm bảo commit không phụ thuộc vào các commit khác
5. **Kiểm thử sau khi cherry-pick**: Xác minh các thay đổi hoạt động trong ngữ cảnh mới

## Theo dõi các Commit đã Cherry-Pick

Git có thể theo dõi các commit đã cherry-pick:

```
# Cherry-pick with -x flag
git cherry-pick -x <commit-hash>
```

Thao tác này thêm một dòng vào thông điệp commit: "(cherry picked from commit ...)"

## Các lỗi thường gặp cần tránh

1. **Cherry-pick merge commit**: Thường gây ra vấn đề
2. **Cherry-pick từ feature sang main**: Có thể tạo commit trùng lặp khi merge
3. **Không kiểm thử**: Các thay đổi có thể hoạt động khác nhau trong các branch khác nhau
4. **Bỏ qua các phụ thuộc**: Commit đã cherry-pick có thể cần các commit khác để hoạt động

## Tổng kết hôm nay

`git cherry-pick` là một công cụ mạnh mẽ để áp dụng có chọn lọc các commit từ một branch sang branch khác. Nó đặc biệt hữu ích cho việc áp dụng hotfix cho nhiều release branch hoặc chọn các tính năng cụ thể từ một development branch. Tuy nhiên, nên sử dụng nó một cách thận trọng vì nó có thể làm phức tạp lịch sử nếu lạm dụng.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git cherry-pick <commit>
* git cherry-pick <commit1> <commit2>
* git cherry-pick commit1..commit2
* git cherry-pick --no-commit
* git cherry-pick -n
* git cherry-pick --continue
* git cherry-pick --abort
* git cherry-pick --skip
* git cherry-pick -e
* git cherry-pick -x
* git cherry-pick --signoff
