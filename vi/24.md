# Ngày 24: Sử dụng GitHub Remote Repository - Bắt đầu

GitHub hiện là nền tảng quản lý Git trực tuyến được sử dụng rộng rãi nhất trên thế giới. Nó bao gồm triển khai remote repository Git hoàn chỉnh, cơ chế theo dõi issue và báo cáo toàn diện, cùng hàng nghìn dự án mã nguồn mở sử dụng GitHub cho quản lý phiên bản Git. Ngay cả trong nhiều công ty, GitHub cũng được chọn làm nền tảng Git chính. Bài viết này sẽ hướng dẫn bạn cách sử dụng GitHub cơ bản nhất.

## GitHub là gì?

GitHub là một nền tảng dựa trên web:
* Lưu trữ các Git repository trên đám mây
* Cung cấp các công cụ cộng tác (issue, pull request, bảng dự án)
* Cung cấp CI/CD thông qua GitHub Actions
* Cho phép code review và thảo luận
* Cung cấp lưu trữ miễn phí cho các dự án mã nguồn mở
* Đóng vai trò là nền tảng xã hội cho các nhà phát triển và dự án mã nguồn mở

## Tạo tài khoản GitHub

1. Truy cập https://github.com
2. Nhấp "Sign up"
3. Làm theo quy trình đăng ký
4. Xác minh địa chỉ email của bạn

## Tạo một Repository mới trên GitHub

Có hai cách tiếp cận chính khi tạo một GitHub repository:

1. **Repository trống (không có commit ban đầu)**: Tốt nhất khi bạn đã có một local repository để push
2. **Repository đã khởi tạo (có commit ban đầu)**: GitHub tạo các tệp README, .gitignore và/hoặc giấy phép cho bạn

### Tạo một Repository trống

1. Nhấp biểu tượng "+" ở góc trên bên phải
2. Chọn "New repository"
3. Điền vào:
   * **Repository name**
   * **Description** (tùy chọn)
   * **Public or Private**
   * **Không đánh dấu** "Initialize this repository with a README"
   * Để .gitignore và license là "None"
4. Nhấp "Create repository"

Sau khi tạo, GitHub hiển thị hướng dẫn để push một repository hiện có.

### Tạo một Repository đã khởi tạo

1. Làm theo các bước 1-3 ở trên
2. **Đánh dấu** "Initialize this repository with a README"
3. Tùy chọn chọn:
   * **Mẫu .gitignore** cho ngôn ngữ của bạn
   * **License** cho dự án của bạn
4. Nhấp "Create repository"

GitHub sẽ tạo một commit ban đầu với các tệp đã chọn.

## Kết nối Local Repository với GitHub

### Cách 1: Push một Repository hiện có

```
# Add remote
git remote add origin https://github.com/username/repo-name.git

# Push to GitHub
git push -u origin main
```

### Cách 2: Clone từ GitHub

```
# Clone the repository
git clone https://github.com/username/repo-name.git

# Navigate to the directory
cd repo-name
```

## Hiểu về Remote

Một remote là một tham chiếu tới một repository được lưu trữ ở nơi khác. Các lệnh thường dùng:

```
# List remotes
git remote -v

# Add a remote
git remote add <name> <url>

# Remove a remote
git remote remove <name>

# Rename a remote
git remote rename <old> <new>

# Change remote URL
git remote set-url origin <new-url>
```

## Push lên GitHub

Push các commit của bạn lên GitHub:

```
# Push to the default branch
git push origin main

# Push all branches
git push --all

# Push tags
git push --tags
```

Cờ `-u` thiết lập theo dõi upstream:

```
git push -u origin main
# After this, you can just use:
git push
```

## Pull từ GitHub

Lấy các cập nhật từ GitHub:

```
# Fetch changes
git fetch origin

# Fetch and merge
git pull origin main

# If upstream is set
git pull
```

## Các phương thức xác thực

### HTTPS

Yêu cầu tên người dùng và mật khẩu/token:

```
https://github.com/username/repo-name.git
```

### SSH

Yêu cầu thiết lập khóa SSH:

```
git@github.com:username/repo-name.git
```

Thiết lập khóa SSH:

```
# Generate SSH key
ssh-keygen -t ed25519 -C "your.email@example.com"

# Add to ssh-agent
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# Copy public key
cat ~/.ssh/id_ed25519.pub
# Add this key to GitHub settings
```

### Personal Access Token

Cho xác thực HTTPS:

1. Vào GitHub Settings > Developer settings > Personal access tokens
2. Tạo token mới
3. Dùng token làm mật khẩu khi push

## Các tính năng của GitHub

### Issues

Theo dõi lỗi, cải tiến và các tác vụ:

* Tạo tiêu đề mô tả rõ ràng
* Cung cấp các bước tái hiện cho lỗi
* Dùng nhãn (label) để tổ chức
* Tham chiếu các commit và pull request

### Wiki

Tài liệu cho dự án của bạn:

* Hướng dẫn bắt đầu
* Tài liệu API
* Các câu hỏi thường gặp (FAQ)
* Sơ đồ kiến trúc

### Projects

Tổ chức công việc với bảng Kanban:

* To Do
* In Progress
* Done

### Releases

Đánh dấu các cột mốc quan trọng:

1. Vào "Releases"
2. Nhấp "Draft a new release"
3. Chọn một tag
4. Thêm ghi chú phát hành
5. Đính kèm tệp nhị phân nếu cần

## Các thực hành tốt nhất cho quy trình làm việc trên GitHub

1. **Commit thường xuyên**: Tạo các commit nhỏ, hợp lý
2. **Viết thông điệp tốt**: Giải thích lý do, không chỉ là làm gì
3. **Pull trước khi push**: Luôn lấy các thay đổi mới nhất trước
4. **Sử dụng branch**: Đừng commit trực tiếp vào main
5. **Review code**: Dùng pull request cho các thay đổi

## Các tác vụ thường gặp

### Fork một Repository

1. Nhấp "Fork" trên trang repository
2. Clone fork của bạn:
   ```
   git clone https://github.com/your-username/repo-name.git
   ```
3. Thêm upstream remote:
   ```
   git remote add upstream https://github.com/original-owner/repo-name.git
   ```

### Đồng bộ một Fork

```
git fetch upstream
git checkout main
git merge upstream/main
git push origin main
```

## Tổng kết hôm nay

GitHub cung cấp một nền tảng mạnh mẽ để lưu trữ các Git repository và cộng tác với người khác. Hiểu cách kết nối local repository của bạn với GitHub, push và pull các thay đổi, và sử dụng các tính năng của GitHub là điều thiết yếu cho phát triển phần mềm hiện đại.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git remote add
* git remote -v
* git remote remove
* git remote rename
* git push -u origin main
* git push --all
* git push --tags
* git pull origin main
* git fetch origin
* git clone
