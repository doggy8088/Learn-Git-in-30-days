# Ngày 05: Hiểu mối quan hệ giữa Repository, Working Directory, Objects và Index

Trong quá trình sử dụng quản lý phiên bản Git, một số khái niệm rất cơ bản phải được thiết lập để bạn có thể học hiệu quả và có ý nghĩa hơn. Với sự hỗ trợ của các khái niệm rõ ràng và chính xác, nó không chỉ giúp bạn học các thao tác lệnh Git, mà quan trọng hơn, việc học kiến thức liên quan đến Git sẽ trở nên dễ dàng hơn.

## Hiểu về Repository

Khi chúng ta sử dụng Git để quản lý phiên bản, một cách tự nhiên, chúng ta cần một "repository" để lưu trữ thông tin phiên bản này. Từ tiếng Anh Repository có nghĩa là như vậy. Tôi quen dịch từ tiếng Anh này là "儲存庫" (kho lưu trữ), đại diện cho một không gian hoặc một thư mục và một loạt các tệp được sử dụng để lưu trữ tất cả các phiên bản.

Nếu bạn có kinh nghiệm sử dụng Git, bạn hẳn biết rất rõ rằng có nhiều cách để tạo một Repository. Nếu bạn muốn tạo một Git Repository trong bất kỳ thư mục nào, chỉ cần nhập lệnh sau để hoàn thành việc tạo:

    git init

Thông qua sơ đồ sau đây về quá trình tạo một Git Repository, chúng ta có thể biết rõ rằng khi chúng ta thực thi git init trong thư mục G:\git-demo, Git sẽ tự động giúp chúng ta tạo một cái gọi là Git Repository trong thư mục .git của thư mục đó. Đừng nghi ngờ, thư mục .git này là một Git Repository hoàn chỉnh. Trong tương lai, tất cả các thay đổi phiên bản sẽ được tự động lưu trữ trong thư mục này.

## Hiểu về Working Directory

Trong ví dụ trên, thư mục G:\git-demo sẽ tự động trở thành "working directory" của chúng ta. Ý nghĩa của "working directory" là chúng ta đang chuẩn bị phát triển các tệp dự án, và tất cả công việc trong tương lai sẽ được chỉnh sửa trong thư mục này, cho dù đó là thêm tệp, sửa đổi tệp, xóa tệp, đổi tên tệp, ... và tất cả các thao tác liên quan đến Git khác sẽ được hoàn thành trong thư mục này, vì vậy nó được gọi là "working directory".

Khi chúng ta vận hành các tham số lệnh liên quan đến Git, chúng ta thường thực thi chúng trong "working directory".

Vì sẽ có nhiều tình huống phân nhánh khi sử dụng quản lý phiên bản Git, working directory có thể chuyển đổi giữa các branch khác nhau. Một số lệnh git sẽ cập nhật các tệp trong working directory khi chúng được thực thi. Ví dụ, khi bạn sử dụng git checkout để chuyển sang một branch khác, vì cấu trúc thư mục của branch hiện tại không hoàn toàn giống với branch bạn muốn chuyển sang, rất có khả năng nó sẽ cập nhật các tệp trong working directory hiện tại của bạn để các thư mục và tệp này dưới working directory hiện tại giống với các thư mục và tệp dưới một branch khác cần chuyển sang.

Vì vậy, giữ cho working directory sạch sẽ vào đúng thời điểm là một nguyên tắc cơ bản trong quá trình quản lý phiên bản, đặc biệt là khi hợp nhất trong tương lai. Điều này đặc biệt quan trọng. Tôi sẽ giải thích thêm kiến thức liên quan trong các bài viết sau.

## Hiểu về cấu trúc dữ liệu của Git

Có hai cấu trúc dữ liệu quan trọng trong Git, đó là "object" và "index".

"Object" được sử dụng để lưu tất cả các tệp và bản ghi phiên bản trong Repository, trong khi "index" được sử dụng để lưu trạng thái của thư mục trước khi vào Repository.

## Về Object

Cái gọi là "object" là một "tệp đặc biệt". Quá trình tạo ra tệp này rất thú vị. Nó lấy nội dung của một tệp, tạo ra một giá trị băm SHA1 thông qua nội dung, và sau đó đặt tên cho một tệp theo giá trị băm SHA1 này.

Trong quá trình sử dụng Git để quản lý phiên bản, tất cả các thư mục và tệp cần được kiểm soát trước tiên sẽ phân biệt giữa "thông tin thư mục" và "nội dung tệp", mà chúng ta gọi là tree object và blob object.

Trong số đó, blob object sử dụng "nội dung tệp" gốc làm nội dung của tệp blob (lưu ý: blob object thực ra là một tệp vật lý), và sau đó thực hiện một phép toán băm SHA1 trên nội dung của nó để tạo ra một hash id, và sau đó sử dụng hash id này làm tên tệp của tệp blob. Từ đó, chúng ta có thể biết rằng một blob object là một tệp "chỉ có nội dung". Tên tệp của nó được tạo ra từ nội dung, vì vậy bất kỳ tệp blob đơn lẻ nào thường không giúp ích cho việc quản lý phiên bản.

Một tree object khác được sử dụng để lưu trữ những tệp nào được bao gồm trong một thư mục cụ thể và tên tệp của blob object tương ứng với tệp này là gì. Trong một tree object, ngoài việc chứa tên tệp và thông tin liên quan của blob object, nó cũng có thể chứa các tree object khác. Vì vậy tree object thực ra đồng nghĩa với "thư mục".

Bất kể blob object và tree object, đây đều là các object, và các object này sẽ được lưu trữ trong một cái gọi là "nơi lưu trữ object" (object storage), và "nơi lưu trữ object" này theo mặc định nằm trong thư mục objects của "Repository", như thể hiện trong hình sau:

## Về Index

Cái gọi là "index" là một tệp tạm thời thay đổi thường xuyên, thường nằm trong một tệp có tên index trong thư mục .git. Nói một cách đơn giản, mục đích của "index" chủ yếu là ghi lại "những tệp nào sắp được gửi đến phiên bản commit tiếp theo". Nói cách khác, nếu bạn muốn gửi một phiên bản đến Git Repository, thì trước tiên bạn phải cập nhật trạng thái index, và các thay đổi sẽ được gửi đi.

Tệp index này thường lưu trạng thái của một phiên bản cụ thể trong Git Repository. Trạng thái này có thể được đại diện bởi bất kỳ commit object và tree object nào.

Chúng ta thường không trực tiếp chỉnh sửa tệp nhị phân .git\index, mà thao tác tệp index này thông qua các lệnh git tiêu chuẩn. Các lệnh để thao tác tệp index đại khái như sau:

* git add
* git mv
* git rm
* git status
* git commit
* git ls-files

"Index" của Git là một trung gian giữa "nơi lưu trữ object" (object storage) và "working directory" (working directory).

Bạn có thể đã đoán được rằng mối quan hệ giữa các khái niệm này mà bài viết muốn trình bày chi tiết có thể được giải thích bằng 5 bước sau:

* Để sử dụng quản lý phiên bản Git, trước tiên bạn phải tạo một "working directory" và "Repository". (mkdir, git init)
* Trước tiên bạn phải phát triển trong "working directory", bạn có thể tạo thư mục, tạo tệp, sửa đổi tệp, xóa tệp, ... và các thao tác khác.
* Sau đó khi bạn muốn gửi một phiên bản mới đến "Repository" của Git, trước tiên bạn phải cập nhật trạng thái "index". (git add, git mv, ...)
* Sau đó Git sẽ quyết định những tệp nào sẽ gửi đến "Repository" của Git dựa trên trạng thái hiện tại của "index". (git status)
* Cuối cùng, khi gửi các thay đổi (git commit), thông tin phiên bản sẽ được ghi vào "nơi lưu trữ object" (lúc này, một commit object sẽ được ghi).

Chúng ta sẽ nói về cấu trúc index chi tiết và các thao tác lệnh trong các bài viết sắp tới.

    Lưu ý: Vì khái niệm tree rất giống với thư mục, khi đọc các văn bản gốc nước ngoài, working directory thường được viết là working tree!

## Tóm tắt hôm nay

Điều quan trọng nhất về kiến trúc Git được thảo luận hôm nay là mối quan hệ giữa "object" và "index", bởi vì nếu không có thông tin "index", Git không thể tạo các phiên bản.

Dựa trên sự khác biệt giữa "object" và "index", bạn hẳn có thể nhận thấy rằng "object" là một loại tệp "bất biến". Về nguyên tắc, bất kỳ object nào được ghi vào "nơi lưu trữ object" sẽ không thay đổi nữa, bởi vì tất cả các object đều được tạo ra từ nội dung tệp gốc. Chúng ta cũng có thể nói đây là một "cơ sở dữ liệu object" (object database), và cơ sở dữ liệu này thường chỉ tăng thêm nội dung, và có ít trường hợp "xóa nội dung" hoặc "thay đổi nội dung" hơn. Dữ liệu chỉ bị xóa khi thực thi git gc để dọn dẹp dữ liệu rác. "Index" là một tệp index "có thể thay đổi" được sử dụng để ghi lại nội dung mà working directory hiện tại đã sẵn sàng để commit.

Khi bạn từng bước tiếp cận cốt lõi của Git, từ từ biến các khái niệm trừu tượng mơ hồ và không rõ ràng thành kiến thức khái niệm cụ thể, bạn sẽ không còn cảm thấy bất an về Git nữa. Hãy tiếp tục nỗ lực học tập, thành công đang ở phía trước.
