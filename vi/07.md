# Ngày 07: Phân tích cấu trúc dữ liệu Git - Cấu trúc Index

Chúng ta biết có hai cấu trúc dữ liệu quan trọng trong Git, đó là "object" và "index". Bài viết này chủ yếu được sử dụng để giải thích các chi tiết của "index". Trong quá trình sử dụng quản lý phiên bản Git, bạn có thể dễ dàng hiểu cách sử dụng các lệnh git, nhưng dễ rơi vào việc học thuộc lòng và không thể sử dụng chúng một cách linh hoạt. Ngay cả Linus Torvalds cũng đã đề cập trong Mailing List: "Trước khi người dùng hiểu ý nghĩa của index, họ không thể hiểu đầy đủ khả năng của Git." Vì vậy, việc hiểu mục đích của "index" là rất quan trọng.

## Về Index

Nói một cách đơn giản, mục đích của "index" chủ yếu là ghi lại "những tệp nào sắp được gửi đến phiên bản commit tiếp theo".

Nói cách khác, "nếu bạn muốn gửi một phiên bản đến Git Repository, thì trước tiên bạn phải cập nhật trạng thái index, và các thay đổi sẽ được gửi đi."

"Index" này thực ra có nhiều tên gọi khác trong nhiều bài viết nước ngoài, nhưng chúng đều có cùng một ý nghĩa. Đừng bối rối khi bạn thấy các từ liên quan trong tương lai.

* Index
* Cache
* Directory cache
* Current directory cache
* Staging area
* Staged files

Ví dụ, lệnh `git diff --cached` hoàn toàn đồng nghĩa với `git diff --staged`.

## Các lệnh để thao tác Index

Vì "index" rất quan trọng đối với Git, hầu hết các lệnh đều có các tham số liên quan đến Git index. Tuy nhiên, chúng ta đại khái liệt kê một vài lệnh liên quan trực tiếp đến "index" để giải thích.

Trước khi giải thích các lệnh, bạn có thể xem trước sơ đồ sau, minh họa vòng đời của việc thay đổi trạng thái thông qua các lệnh. Thực ra, các quá trình thay đổi này đều là các quá trình cập nhật "tệp index":

![hình ảnh](figures/07/01.png)

Đầu tiên, hãy để tôi giới thiệu bốn trạng thái tệp:

* untracked (không được theo dõi, đại diện cho trạng thái của các tệp chưa được thêm vào Git Repository)
* unmodified (không bị sửa đổi, đại diện cho trạng thái khi một tệp được thêm vào lần đầu tiên, hoặc nội dung tệp nhất quán với nội dung HEAD)
* modified (đã sửa đổi, đại diện cho việc tệp đã được chỉnh sửa, hoặc nội dung tệp không nhất quán với nội dung HEAD)
* staged (chờ để commit, đại diện cho việc các tệp này sẽ đều được gửi đến Repository vào lần thực thi git commit tiếp theo)

### git status

Lấy trạng thái của **working tree** (cây làm việc).

Vì chúng ta đã nói về mối quan hệ giữa Repository, working directory, object, và index, chúng ta có thể giải thích mối quan hệ này trong một câu:

```txt
Git repository operation is to write data into Git objects by updating the index with changes in the working directory.
```

Mục đích của lệnh `git status` ở đây là hiển thị sự khác biệt giữa **phiên bản mới nhất** và **tệp index**. Các khác biệt ở đây bao gồm một số mối quan hệ tinh tế. Hãy sử dụng một ví dụ để giải thích mối quan hệ này.

Sau đây là kết quả của việc thực thi git status:

```sh
G:\git-demo>git status
# On branch master
# Changes to be committed:
#   (use "git reset HEAD <file>..." to unstage)
#
#       new file:   c.txt
#
# Changes not staged for commit:
#   (use "git add <file>..." to update what will be committed)
#   (use "git checkout -- <file>..." to discard changes in working directory)
#
#       modified:   a.txt
#
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#
#       b.txt
```

Ở đây bạn sẽ thấy ba nhóm khác nhau, đó là:

* Changes to be committed (các thay đổi sẵn sàng để gửi đi)
  * Có một tệp `new file: c.txt` trong khu vực này, có nghĩa là c.txt là một tệp mới và đã được đánh dấu là sẵn sàng để commit.
  * Điều này đại diện cho một số điều:
    1. Tệp c.txt hiện đang tồn tại trong **working directory**
    2. Tệp c.txt đã được thêm vào **index**
    3. Nội dung của c.txt trong **index** nhất quán với nội dung trong **working directory**
    4. Khi thực thi git commit, nội dung trong **index** sẽ được commit (không phải nội dung trong working directory)

* Changes not staged for commit (các thay đổi đã được sửa đổi nhưng chưa được staged để commit)
  * Có một tệp `modified: a.txt` trong khu vực này, có nghĩa là a.txt là một tệp đã sửa đổi nhưng chưa được đánh dấu là sẵn sàng để commit.
  * Điều này đại diện cho một số điều:
    1. Tệp a.txt hiện đang tồn tại trong **working directory**
    2. Tệp a.txt đã được thêm vào **index**
    3. Nội dung của a.txt trong **index** không nhất quán với nội dung trong **working directory**
    4. Khi thực thi git commit, chỉ nội dung trong **index** sẽ được commit (không phải nội dung trong working directory)

* Untracked files (các tệp không được theo dõi)
  * Có một tệp `b.txt` trong khu vực này, có nghĩa là b.txt là một tệp mới và chưa được thêm vào index.
  * Điều này đại diện cho một số điều:
    1. Tệp b.txt hiện đang tồn tại trong **working directory**
    2. Tệp b.txt chưa được thêm vào **index**
    3. Khi thực thi git commit, tệp này sẽ không được commit

### git add

Thêm nội dung tệp vào index (stage các tệp cho lần commit tiếp theo).

Lệnh `git add` có nhiều cách sử dụng. Nói một cách đơn giản, việc thực thi lệnh này sẽ "cập nhật index", nhưng cách index được cập nhật có thể khác nhau tùy thuộc vào trạng thái tệp hiện tại:

* Nếu tệp ở trạng thái **untracked**, việc thực thi `git add` sẽ thêm nội dung tệp vào index
* Nếu tệp ở trạng thái **modified**, việc thực thi `git add` sẽ cập nhật nội dung tệp vào index
* Nếu tệp ở trạng thái **staged**, việc thực thi `git add` sẽ cập nhật lại nội dung tệp vào index

### git rm

Xóa tệp khỏi working tree và khỏi index.

Lệnh này sẽ xóa tệp khỏi cả **working directory** và **index**. Sau khi xóa, bạn cần thực thi git commit để hoàn thành hành động xóa này.

### git mv

Di chuyển hoặc đổi tên một tệp, một thư mục, hoặc một symlink.

Lệnh này sẽ di chuyển hoặc đổi tên tệp trong cả **working directory** và **index**. Sau khi di chuyển hoặc đổi tên, bạn cần thực thi git commit để hoàn thành hành động này.

### git commit

Ghi lại các thay đổi vào Repository.

Lệnh này sẽ ghi nội dung **index** hiện tại vào **cơ sở dữ liệu object** và tạo ra một commit object.

### git ls-files

Hiển thị thông tin về các tệp trong index và working tree.

Lệnh này có thể hiển thị danh sách tệp và trạng thái trong index. Đây là một lệnh rất hữu ích có thể giúp bạn hiểu trạng thái hiện tại của index.

Một số tham số phổ biến:

* `git ls-files -s` hoặc `git ls-files --stage` : Hiển thị danh sách tệp và thông tin chi tiết trong index
* `git ls-files -c` hoặc `git ls-files --cached` : Hiển thị danh sách tệp đã lưu trong bộ nhớ đệm (cached)
* `git ls-files -d` hoặc `git ls-files --deleted` : Hiển thị danh sách tệp đã xóa
* `git ls-files -m` hoặc `git ls-files --modified` : Hiển thị danh sách tệp đã sửa đổi
* `git ls-files -o` hoặc `git ls-files --others` : Hiển thị danh sách tệp không được theo dõi

## Tóm tắt hôm nay

"Index" trong Git là một khái niệm rất quan trọng. Thông qua index, Git có thể biết những tệp nào sắp được gửi đến phiên bản commit tiếp theo. Thông qua các lệnh khác nhau, chúng ta có thể cập nhật trạng thái index và kiểm soát những tệp nào sẽ được gửi đi. Việc hiểu index có thể giúp bạn làm chủ quản lý phiên bản Git tốt hơn.
