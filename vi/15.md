# Ngày 15: Tag - Đánh dấu các sự kiện quan trọng trong quản lý phiên bản

Khi sử dụng Git để quản lý phiên bản, một số lượng lớn các phiên bản sẽ được tạo ra. Theo thời gian, trong số rất nhiều phiên bản này, chắc chắn sẽ có một số phiên bản quan trọng đáng được ghi lại. Đây chính là điều mà "tag" có thể giúp chúng ta thực hiện.

## Hiểu về Tag - Các khái niệm cơ bản

Về cơ bản, mục đích của một tag là đánh dấu một "phiên bản" hoặc "commit object" cụ thể bằng một "cái tên dễ nhớ" để giúp chúng ta ghi nhớ một phiên bản đặc biệt nào đó.

Tag là một tham chiếu trỏ tới một commit cụ thể trong lịch sử Git của bạn. Khác với branch, tag không di chuyển khi bạn tạo các commit mới — chúng luôn trỏ tới cùng một commit. Điều này khiến tag trở nên lý tưởng để đánh dấu các điểm phát hành hoặc các cột mốc quan trọng khác.

Git hỗ trợ hai loại tag:

1. **Lightweight tag (tag nhẹ)**: Đơn giản là một cái tên (bí danh) cho một commit cụ thể — nó là một loại "tên tham chiếu"
2. **Annotated tag (tag có chú thích)**: Được lưu trữ dưới dạng Git object đầy đủ với siêu dữ liệu bổ sung

Như đã đề cập trong Ngày 11 (Hiểu tham chiếu Git Object), "tham chiếu thông thường" bao gồm "tên tag", và "tên tag" ở đây đề cập tới "lightweight tag". Vì vậy, "lightweight tag" có thể được coi chỉ là một "bí danh" cho một phiên bản commit nào đó, là một loại "tên tương đối".

"Annotated tag" là một loại Git object. Như đã đề cập trong Ngày 06 (Phân tích cấu trúc dữ liệu Git - Cấu trúc Object), Git object bao gồm 4 loại object: Blob, Tree, Commit và Tag object. "Annotated tag" được đề cập ở đây là một Tag object. Tag object được lưu trữ trong kho lưu trữ object của Git (lưu trong thư mục `.git\objects\`) và được liên kết với một commit object khác. Khi tạo "annotated tag", bạn có thể bao gồm "thông điệp phiên bản" giống như khi tạo commit object. Trong cơ chế tag có sẵn của Git, bạn thậm chí có thể sử dụng khóa GnuPG để ký Tag object nhằm đảm bảo tính "không thể chối bỏ" của thông điệp.

Mặc dù chúng ta có hai loại tag này, và cả hai đều trông giống như "bí danh" cho commit object, cách sử dụng của hai loại tag này chỉ có những khác biệt nhỏ. Trong hầu hết các trường hợp sử dụng, chúng ta dùng "annotated tag" để tạo "tag object" và cung cấp "thông điệp phiên bản", bởi vì loại "tag" này là một "object vĩnh viễn" trong Git repository. (Các Git object được lưu trong kho lưu trữ object là bất biến; chỉ có index mới thay đổi.)

## Tạo Lightweight Tag

Cách đơn giản nhất để tạo một tag:

```
git tag v1.0
```

Lệnh này tạo một lightweight tag có tên `v1.0` trỏ tới commit hiện tại (HEAD).

Để gắn tag cho một commit cụ thể:

```
git tag v0.9 <commit-hash>
```

**Lưu ý**: Tất cả các tệp trong `.git\refs\` đều là "tên tham chiếu".

Cách sử dụng cơ bản:
* Liệt kê tất cả các tag: `git tag`
* Tạo lightweight tag: `git tag [tagname]`
* Xóa lightweight tag: `git tag [tagname] -d`

Nếu bạn muốn xem nội dung của một "lightweight tag", bạn có thể dùng `git cat-file -p [tagname]`. Nếu bạn muốn xem loại object của "lightweight tag", bạn có thể dùng `git cat-file -t [tagname]`.

**Lưu ý quan trọng**: Một lightweight tag không phải là một Git object. Từ những điều trên, bạn có thể thấy tên tag truy xuất nội dung của commit object, và loại object tìm được bằng cái tên đó là một commit object.

## Tạo Annotated Tag

Annotated tag được khuyến nghị cho hầu hết các trường hợp sử dụng vì chúng lưu trữ thêm thông tin:

```
git tag -a v1.0 -m "Release version 1.0"
```

Cờ `-a` tạo một annotated tag, và `-m` chỉ định thông điệp của tag.

Những khác biệt so với lightweight tag:
1. Khi thực thi `git tag` để liệt kê tất cả các tag, tất cả các tag bị trộn lẫn với nhau và bạn không thể thấy loại tag
2. Việc tạo "annotated tag" yêu cầu tham số `-a`
3. Việc tạo "annotated tag" phải bao gồm một "thông điệp phiên bản", giống như khi thực thi `git commit`, cả hai đều có tham số `-m` khả dụng

## Liệt kê Tag

Để xem tất cả các tag trong repository của bạn:

```
git tag
```

Để xem các tag khớp với một mẫu:

```
git tag -l "v1.*"
```

## Xem thông tin Tag

Đối với một lightweight tag:

```
git show v1.0
```

Lệnh này hiển thị commit mà tag trỏ tới.

Đối với một annotated tag:

```
git show v1.0
```

Lệnh này hiển thị thông tin của tag cộng với chi tiết của commit.

## Gắn Tag cho các Commit cũ

Bạn có thể gắn tag cho các commit không ở HEAD:

```
git log --oneline  # Find the commit hash
git tag -a v0.5 -m "Beta release" <commit-hash>
```

## Đẩy Tag lên Remote

Theo mặc định, `git push` không truyền các tag. Bạn cần đẩy chúng một cách rõ ràng:

```
# Push a specific tag
git push origin v1.0

# Push all tags
git push origin --tags
```

## Xóa Tag

Để xóa một tag cục bộ:

```
git tag -d v1.0
```

Để xóa một tag từ xa:

```
git push origin :refs/tags/v1.0
# or
git push origin --delete v1.0
```

## Checkout Tag

Bạn có thể checkout mã nguồn tại một tag cụ thể:

```
git checkout v1.0
```

Điều này đặt bạn vào trạng thái "detached HEAD". Nếu bạn muốn thực hiện thay đổi, hãy tạo một branch mới:

```
git checkout -b version-1-fixes v1.0
```

## Tóm tắt hôm nay

Tag là một phần thiết yếu của quản lý phiên bản, cho phép bạn đánh dấu các điểm quan trọng trong lịch sử dự án của mình. Annotated tag đặc biệt hữu ích cho các bản phát hành vì chúng có thể lưu trữ thêm thông tin như ghi chú phát hành, thông tin người gắn tag và chữ ký.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git tag
* git tag -a
* git tag -l
* git show
* git push origin --tags
* git tag -d
* git checkout
