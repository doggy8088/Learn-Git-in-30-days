# Ngày 13: Tạm cất thay đổi trong Working Directory và Index (Stash)

Bạn đã bao giờ gặp tình huống này chưa: bạn đang phát triển một hệ thống được nửa chừng, bỗng nhiên sếp hoặc khách hàng đưa ra một "mệnh lệnh khẩn cấp", yêu cầu bạn khẩn trương sửa một lỗi trong hệ thống hiện có hoặc thêm một tính năng? Chương trình trước mắt bạn sắp hoàn thành, và "việc khẩn cấp" của sếp thì không thể trì hoãn. Trạng thái phát triển phần mềm dở dang cộng với yêu cầu điều chỉnh khẩn cấp thực sự là một thử thách lớn đối với chất lượng phần mềm. Nếu bạn gặp rắc rối này, Git có thể giúp bạn hoàn thành nhiệm vụ một cách xuất sắc.

## Hiểu lệnh git stash

Chúng ta biết rằng khi sử dụng quản lý phiên bản bằng Git, có sự phân biệt giữa "working directory" và "index". Trong working directory, sẽ có những tệp bạn đã thay đổi dở dang và chưa hoàn thành (chưa được thêm vào index), và cũng sẽ có những tệp mới chưa được thêm vào (chưa được thêm vào index). Dữ liệu được đặt trong index là nội dung bạn dự định tạo thành một phiên bản (tạo một commit object) thông qua `git commit`.

Khi bạn đang phát triển tính năng được nửa chừng và bị gián đoạn khẩn cấp, bạn chắc chắn sẽ rất vội, đặc biệt là không biết phải xử lý những chương trình viết dở dang trong tay như thế nào. Trong Git, có một lệnh `git stash` có thể tự động giúp bạn tạo một "phiên bản đặc biệt" (cũng là một commit object) cho những tệp viết dở dang đó. Chúng ta gọi các phiên bản này là phiên bản stash, hoặc bạn có thể gọi trực tiếp là "phiên bản tạm cất".

## Tạo phiên bản Stash

Các tệp chúng ta đã thay đổi dở dang có thể có các trạng thái sau:

* Tệp mới (tệp chưa được theo dõi — untracked files)
* Tệp mới (tệp đã được thêm vào index) (tracked/staged files)
* Tệp đã sửa đổi (tệp chưa được thêm vào index) (tracked/unstaged files)
* Tệp đã sửa đổi (tệp đã được thêm vào index) (tracked/staged files)
* Tệp đã xóa (tệp chưa được thêm vào index) (tracked/unstaged files)
* Tệp đã xóa (tệp đã được thêm vào index) (tracked/staged files)

Nếu bạn muốn tạo một "phiên bản tạm cất" cho các tệp đang phát triển dở dang này, bạn có hai lựa chọn:

* `git stash` sẽ tạo một phiên bản tạm cất cho tất cả các tệp đã được theo dõi (tracked)
* `git stash -u` sẽ bao gồm tất cả các tệp tracked hoặc untracked, tất cả đều sẽ được tạo thành phiên bản tạm cất

**Lưu ý**: `git stash` cũng có thể được viết là `git stash save`. Kết quả của hai lệnh là giống nhau, chỉ là tham số `save` có thể được lược bỏ.

### Quy trình làm việc mẫu

Dưới đây là một ví dụ thực tế đơn giản:

```bash
# You're working on features
echo "new feature" > feature.txt
git add feature.txt

# Suddenly need to fix a bug
# Stash your work-in-progress
git stash

# Now working directory is clean
# Fix the bug on another branch
git checkout main
# ... make fixes ...
git commit -m "Fix urgent bug"

# Return to your feature work
git checkout feature-branch
git stash pop  # Restore your work
```

## Khôi phục các thay đổi đã Stash

Sau khi stash các thay đổi của mình, bạn có thể chuyển sang một branch khác hoặc làm công việc khẩn cấp. Khi bạn sẵn sàng tiếp tục công việc ban đầu, bạn có thể khôi phục các thay đổi đã stash bằng cách sử dụng:

* `git stash pop` - Áp dụng stash gần nhất và loại bỏ nó khỏi danh sách stash
* `git stash apply` - Áp dụng stash gần nhất nhưng vẫn giữ nó trong danh sách stash

## Liệt kê các thay đổi đã Stash

Để xem bạn đã stash những gì, hãy sử dụng:

```
git stash list
```

Lệnh này sẽ hiển thị tất cả các thay đổi đã stash cùng với tham chiếu stash của chúng (stash@{0}, stash@{1}, v.v.).

## Áp dụng một Stash cụ thể

Nếu bạn có nhiều stash, bạn có thể áp dụng một stash cụ thể bằng cách tham chiếu số của nó:

```
git stash apply stash@{2}
```

## Xóa Stash

Để loại bỏ một stash cụ thể khỏi danh sách:

```
git stash drop stash@{0}
```

Để loại bỏ tất cả các stash:

```
git stash clear
```

## Stash các tệp chưa được theo dõi (Untracked)

Theo mặc định, `git stash` chỉ stash các tệp đã được theo dõi (tracked). Để stash cả các tệp untracked:

```
git stash -u
```

Hoặc để stash mọi thứ bao gồm cả các tệp bị bỏ qua (ignored):

```
git stash -a
```

## Tạo Stash có tên

Bạn có thể đặt cho stash của mình một thông điệp mô tả:

```
git stash save "Work in progress on feature X"
```

Điều này giúp việc nhận diện các stash sau này dễ dàng hơn.

## Xem nội dung Stash

Để xem những gì có trong một stash cụ thể mà không áp dụng nó:

```
git stash show stash@{0}
```

Để xem diff chi tiết:

```
git stash show -p stash@{0}
```

## Tóm tắt hôm nay

Lệnh `git stash` là một công cụ rất thiết thực, cho phép bạn tạm thời gác công việc hiện tại sang một bên mà không cần commit nó. Điều này đặc biệt hữu ích khi bạn cần nhanh chóng chuyển ngữ cảnh để làm việc khác. Cơ chế stash đảm bảo các thay đổi đang thực hiện dở dang của bạn được lưu trữ an toàn và có thể được khôi phục sau này.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git stash
* git stash save
* git stash -u
* git stash list
* git stash pop
* git stash apply
* git stash drop
* git stash clear
* git stash show
