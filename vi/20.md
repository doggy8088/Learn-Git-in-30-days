# Ngày 20: Sửa lịch sử phiên bản đã commit Phần 2 (revert)

Trong quá trình quản lý phiên bản, có một tình huống phổ biến khác: sau khi thực thi nhiều commit, bạn phát hiện rằng một số commit trước đó đã sai. Ví dụ, bạn vô tình commit mã kiểm thử, gây ra sự cố trong phiên bản hiện tại. Trong trường hợp này, bạn cần hiểu nội dung được giải thích trong bài viết này.

Trong Ngày 18, chúng ta đã học về `git reset` và `git commit --amend` để sửa lịch sử commit cục bộ. Tuy nhiên, các lệnh này viết lại lịch sử và không nên được sử dụng cho các commit đã được push lên các repository dùng chung. Đối với lịch sử đã chia sẻ, `git revert` là phương án thay thế an toàn.

## Hiểu git revert

`git revert` tạo một commit mới hoàn tác các thay đổi từ một commit trước đó. Khác với `reset`, nó không viết lại lịch sử — nó bổ sung vào lịch sử. Điều này khiến nó an toàn cho các branch dùng chung.

Giả sử tại thời điểm này bạn phát hiện rằng một commit trước đó (chẳng hạn như `HEAD~` hoặc `HEAD^` hoặc một mã băm commit cụ thể) đã được thực hiện không chính xác. Bạn muốn hoàn tác **riêng phiên bản cụ thể đó**, thay vì reset về phiên bản đầu tiên và làm lại mọi thứ. Trong trường hợp này, bạn có thể thử lệnh `git revert`, lệnh này có thể hoàn tác các thay đổi của một phiên bản nào đó thông qua các bước "đảo ngược".

"Đảo ngược" có nghĩa là gì? Hãy thử ngay lệnh này.

**Lưu ý quan trọng**: Trước khi thực thi lệnh `git revert`, hãy đảm bảo working directory của bạn sạch! Nếu bạn có các tệp đã được sửa đổi một phần, bạn nên sử dụng `git stash` để tạo một stash tạm thời.

## Revert cơ bản

Để hoàn tác commit gần đây nhất:

```
git revert HEAD
```

Lệnh này tạo một commit mới hoàn tác các thay đổi trong commit cuối cùng.

## Hoàn tác một Commit cụ thể

Giả sử từ lịch sử `git log`, bạn đã tìm thấy một phiên bản có vấn đề. Trước tiên bạn có thể kiểm tra bản ghi thay đổi của phiên bản này. Bạn có thể dùng `git log` để tìm ID của commit, sau đó dùng `git show [commit_id]` để xem thông tin liên quan của phiên bản đó.

Để hoàn tác một commit cụ thể:

```
git revert <commit-hash>
```

Ví dụ:

```
git revert a1b2c3d
```

Trong quá trình thực thi, bạn sẽ được yêu cầu chỉnh sửa thông điệp commit cuối cùng. Theo mặc định, nó thêm từ `Revert` và cũng thêm `This reverts commit xxxx` ở dòng thứ ba để cho bạn biết rằng mục đích chính của phiên bản này là hoàn tác từ phiên bản `xxxx`.

## Hoàn tác nhiều Commit

Để hoàn tác một loạt các commit:

```
# Revert commits from HEAD~3 to HEAD~1 (3 commits)
git revert HEAD~3..HEAD
```

Hoặc hoàn tác nhiều commit cụ thể:

```
git revert <hash1> <hash2> <hash3>
```

## Revert mà không Commit

Để stage các thay đổi revert mà không tự động commit:

```
git revert --no-commit HEAD
# or
git revert -n HEAD
```

Điều này hữu ích khi bạn muốn hoàn tác nhiều commit và tạo một revert commit duy nhất:

```
git revert --no-commit HEAD~3..HEAD
git commit -m "Revert last 3 commits"
```

## Xử lý xung đột

Đôi khi việc hoàn tác một commit có thể gây ra xung đột:

```
git revert <commit-hash>
# If conflicts occur...
# 1. Resolve conflicts in the files
# 2. Stage the resolved files
git add <resolved-files>
# 3. Continue the revert
git revert --continue
```

Để hủy bỏ một revert đang diễn ra:

```
git revert --abort
```

## Hoàn tác một Merge Commit

Hoàn tác một merge phức tạp hơn vì một merge commit có hai commit cha. Bạn phải chỉ định sẽ hoàn tác về commit cha nào:

```
# -m 1 means keep changes from the first parent (usually mainline)
git revert -m 1 <merge-commit-hash>
```

## Khi nào dùng Revert và khi nào dùng Reset

**Sử dụng `git revert` khi:**
* Commit đã được push lên một repository dùng chung
* Bạn muốn bảo toàn lịch sử
* Làm việc trên một branch công khai (main, develop, v.v.)
* Bạn cần một bản ghi về thao tác hoàn tác

**Sử dụng `git reset` khi:**
* Commit chỉ ở trong repository cục bộ của bạn
* Bạn muốn loại bỏ hoàn toàn các commit khỏi lịch sử
* Làm việc trên một branch tính năng riêng tư
* Commit là một sai lầm không nên có trong lịch sử

## Hoàn tác và áp dụng lại các thay đổi

Đôi khi bạn hoàn tác một commit nhưng sau đó lại muốn áp dụng lại nó:

```
# First, revert a commit
git revert <commit-hash>

# Later, revert the revert
git revert <revert-commit-hash>
```

## Ví dụ thực tế

### Ví dụ 1: Hoàn tác một Commit lỗi trên Branch chính

```
# Commit a1b2c3d introduced a bug
git revert a1b2c3d
git push origin main
```

### Ví dụ 2: Hoàn tác nhiều Commit

```
# Revert the last 5 commits as a single revert commit
git revert --no-commit HEAD~5..HEAD
git commit -m "Revert last 5 commits due to critical bug"
git push origin main
```

### Ví dụ 3: Hoàn tác rồi thực hiện sửa chữa

```
# Revert a problematic commit
git revert a1b2c3d

# Make necessary corrections
# ... edit files ...

# Commit the corrections
git add .
git commit -m "Fix issues from reverted commit"
git push origin main
```

## Thực hành tốt nhất

1. **Viết thông điệp rõ ràng**: Giải thích lý do bạn hoàn tác
   ```
   git revert a1b2c3d -m "Revert feature X due to performance issues"
   ```

2. **Kiểm tra trước khi push**: Đảm bảo việc hoàn tác không làm hỏng bất cứ thứ gì

3. **Trao đổi**: Cho nhóm của bạn biết khi bạn hoàn tác các commit

4. **Cân nhắc các phương án thay thế**: Đôi khi một bản sửa hướng về phía trước tốt hơn một lần revert

5. **Ghi lại lý do**: Tham chiếu số issue hoặc cung cấp ngữ cảnh

## Xem lịch sử Revert

Để xem các revert commit trong lịch sử của bạn:

```
git log --oneline --grep="Revert"
```

## Tóm tắt hôm nay

`git revert` là cách an toàn để hoàn tác các thay đổi trong các repository dùng chung. Nó duy trì tính toàn vẹn của lịch sử trong khi hoàn tác các thay đổi không mong muốn. Hiểu khi nào dùng `revert` so với `reset` là điều then chốt cho việc cộng tác hiệu quả và duy trì lịch sử dự án sạch sẽ, dễ hiểu.

Hãy để tôi sắp xếp lại các lệnh và tham số Git đã học hôm nay:

* git revert
* git revert HEAD
* git revert <commit-hash>
* git revert --no-commit
* git revert -n
* git revert -m
* git revert --continue
* git revert --abort
