# Hari 21: Membetulkan Sejarah Versi yang Telah Di-commit Bahagian 3 (cherry-pick)

Dalam proses kawalan versi, terdapat satu lagi situasi lazim: anda telah membangunkan dalam sesebuah cabang untuk seketika, tetapi kemudian memutuskan bahawa anda tidak lagi mahukan keseluruhan cabang tersebut. Walau bagaimanapun, terdapat beberapa commit di dalamnya yang masih ingin anda kekalkan. Dalam kes ini, anda tidak boleh memadamkan cabang tersebut, tetapi mencantumkan keseluruhan cabang kembali juga tidak sesuai. Apakah yang patut anda lakukan? Artikel ini akan menerangkan cara menggunakan perintah `git cherry-pick` untuk "memilih secara manual" perubahan yang ingin anda gunakan.

## Memahami git cherry-pick

Kadangkala anda ingin menggunakan commit tertentu daripada satu cabang ke cabang lain tanpa mencantumkan keseluruhan cabang. Perintah `cherry-pick` Git membolehkan anda berbuat demikian - memilih commit secara terpilih dan menggunakannya pada cabang semasa anda.

`git cherry-pick` menggunakan perubahan yang diperkenalkan oleh commit sedia ada pada cabang semasa anda. Ia mencipta commit baharu dengan perubahan yang sama tetapi hash commit yang berbeza.

## Cherry-Pick Asas

Untuk cherry-pick satu commit:

```
# Switch to the target branch
git checkout main

# Cherry-pick the commit
git cherry-pick <commit-hash>
```

Ini mencipta commit baharu pada cabang semasa dengan perubahan yang sama seperti commit yang dinyatakan.

## Cherry-Pick Berbilang Commit

Untuk cherry-pick berbilang commit:

```
# Cherry-pick several commits
git cherry-pick <hash1> <hash2> <hash3>
```

Untuk cherry-pick julat commit:

```
# Cherry-pick commits from commit1 to commit2 (exclusive of commit1)
git cherry-pick commit1..commit2

# Cherry-pick commits from commit1 to commit2 (inclusive of commit1)
git cherry-pick commit1^..commit2
```

## Cherry-Pick Tanpa Membuat Commit

Untuk menggunakan perubahan tanpa mencipta commit secara automatik:

```
git cherry-pick --no-commit <commit-hash>
# or
git cherry-pick -n <commit-hash>
```

Ini berguna apabila anda ingin cherry-pick berbilang commit dan mencipta satu commit sahaja.

## Mengendalikan Konflik

Jika konflik berlaku semasa cherry-pick:

```
# Resolve conflicts in the files
# Stage the resolved files
git add <resolved-files>

# Continue the cherry-pick
git cherry-pick --continue
```

Untuk membatalkan cherry-pick yang sedang berjalan:

```
git cherry-pick --abort
```

Untuk melangkau commit semasa dan meneruskan dengan commit berikutnya:

```
git cherry-pick --skip
```

## Cherry-Pick dengan Suntingan

Untuk menyunting mesej commit semasa cherry-pick:

```
git cherry-pick -e <commit-hash>
# or
git cherry-pick --edit <commit-hash>
```

## Cherry-Pick dan Tandatangan (Sign-off)

Untuk menambah baris tandatangan pada mesej commit:

```
git cherry-pick -s <commit-hash>
# or
git cherry-pick --signoff <commit-hash>
```

## Kes Penggunaan Praktikal

### Kes Penggunaan 1: Menggunakan Hotfix pada Berbilang Cabang

```
# Fix created on main branch (commit abc123)
git checkout release-1.0
git cherry-pick abc123

git checkout release-2.0
git cherry-pick abc123
```

### Kes Penggunaan 2: Integrasi Ciri Secara Terpilih

```
# Feature branch has commits A, B, C, D
# You only want B and C on main

git checkout main
git cherry-pick <hash-B> <hash-C>
```

### Kes Penggunaan 3: Memulihkan Commit yang Hilang

```
# Find the lost commit using reflog
git reflog

# Cherry-pick it to current branch
git cherry-pick <lost-commit-hash>
```

## Cherry-Pick vs Cantuman vs Rebase

**Cherry-pick**:
* Menggunakan commit tertentu secara terpilih
* Mencipta hash commit baharu
* Sesuai untuk integrasi terpilih

**Cantuman (Merge)**:
* Menggabungkan keseluruhan cabang
* Mengekalkan sejarah yang lengkap
* Terbaik untuk mengintegrasikan cabang ciri

**Rebase**:
* Memainkan semula commit pada asas baharu
* Sejarah linear
* Sesuai untuk membersihkan sejarah

## Amalan Terbaik

1. **Gunakan dengan berhemat**: Cherry-pick boleh mengelirukan sejarah jika digunakan secara berlebihan
2. **Dokumenkan sebabnya**: Terangkan mengapa anda cherry-pick dalam mesej commit
3. **Elakkan pertindihan**: Jangan cherry-pick commit yang akan dicantumkan kemudian
4. **Semak kebergantungan**: Pastikan commit tersebut tidak bergantung pada commit lain
5. **Uji selepas cherry-pick**: Sahkan perubahan berfungsi dalam konteks baharu

## Menjejak Commit yang Telah Di-cherry-pick

Git boleh menjejak commit yang telah di-cherry-pick:

```
# Cherry-pick with -x flag
git cherry-pick -x <commit-hash>
```

Ini menambah satu baris pada mesej commit: "(cherry picked from commit ...)"

## Kesilapan Lazim yang Perlu Dielakkan

1. **Cherry-pick commit cantuman**: Biasanya menyebabkan masalah
2. **Cherry-pick dari cabang ciri ke main**: Boleh mencipta commit pendua apabila mencantumkan
3. **Tidak menguji**: Perubahan mungkin berkelakuan berbeza dalam cabang yang berbeza
4. **Mengabaikan kebergantungan**: Commit yang di-cherry-pick mungkin memerlukan commit lain untuk berfungsi

## Ringkasan Hari Ini

`git cherry-pick` ialah alat yang berkuasa untuk menggunakan commit daripada satu cabang ke cabang lain secara terpilih. Ia amat berguna untuk menggunakan hotfix pada berbilang cabang keluaran atau memilih ciri tertentu daripada cabang pembangunan. Walau bagaimanapun, ia harus digunakan dengan bijaksana kerana boleh merumitkan sejarah jika digunakan secara berlebihan.

Izinkan saya menyusun semula perintah dan parameter Git yang dipelajari hari ini:

* git cherry-pick <commit>
* git cherry-pick <commit1> <commit2>
* git cherry-pick commit1..commit2
* git cherry-pick --no-commit
* git cherry-pick -n
* git cherry-pick --continue
* git cherry-pick --abort
* git cherry-pick --skip
* git cherry-pick -e
* git cherry-pick -x
* git cherry-pick --signoff
