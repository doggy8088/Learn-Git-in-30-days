# Hari 20: Membetulkan Sejarah Versi yang Telah Di-commit Bahagian 2 (revert)

Dalam proses kawalan versi, terdapat satu lagi situasi lazim: selepas melaksanakan berbilang commit, anda mendapati bahawa beberapa commit sebelumnya adalah salah. Contohnya, anda secara tidak sengaja membuat commit kod ujian, menyebabkan masalah dalam versi semasa. Dalam kes ini, anda perlu memahami kandungan yang diterangkan dalam artikel ini.

Dalam Hari 18, kami mempelajari tentang `git reset` dan `git commit --amend` untuk membetulkan sejarah commit setempat. Walau bagaimanapun, perintah ini menulis semula sejarah dan tidak sepatutnya digunakan untuk commit yang telah di-push ke repositori yang dikongsi. Untuk sejarah yang dikongsi, `git revert` ialah alternatif yang selamat.

## Memahami git revert

`git revert` mencipta commit baharu yang membuat asal perubahan daripada commit sebelumnya. Tidak seperti `reset`, ia tidak menulis semula sejarah - ia menambah kepadanya. Ini menjadikannya selamat untuk cabang yang dikongsi.

Andaikan pada ketika ini anda mendapati bahawa commit sebelumnya (seperti `HEAD~` atau `HEAD^` atau hash commit tertentu) telah dilakukan secara salah. Anda ingin me-revert **versi tertentu itu** sahaja, dan bukannya me-reset ke versi pertama dan membuat semula semuanya. Dalam kes ini, anda boleh mencuba perintah `git revert`, yang boleh membuat asal perubahan versi tertentu melalui langkah "songsang."

Apakah maksud "songsang"? Mari kita cuba perintah ini dengan segera.

**Nota Penting**: Sebelum melaksanakan perintah `git revert`, pastikan direktori kerja anda bersih! Jika anda mempunyai fail yang diubah suai sebahagiannya, adalah disyorkan untuk menggunakan `git stash` untuk mencipta simpanan sementara.

## Revert Asas

Untuk me-revert commit paling terkini:

```
git revert HEAD
```

Ini mencipta commit baharu yang membuat asal perubahan dalam commit terakhir.

## Me-revert Commit Tertentu

Andaikan daripada sejarah `git log`, anda menjumpai versi yang bermasalah. Anda boleh terlebih dahulu menyemak rekod perubahan versi ini. Anda boleh menggunakan `git log` untuk mencari ID commit, kemudian gunakan `git show [commit_id]` untuk melihat maklumat berkaitan versi itu.

Untuk me-revert commit tertentu:

```
git revert <commit-hash>
```

Contohnya:

```
git revert a1b2c3d
```

Semasa pelaksanaan, anda akan diminta untuk menyunting mesej commit akhir. Secara lalai, ia menambah perkataan `Revert` dan juga menambah `This reverts commit xxxx` pada baris ketiga untuk memberitahu anda bahawa tujuan utama versi ini ialah untuk me-revert daripada versi `xxxx`.

## Me-revert Berbilang Commit

Untuk me-revert julat commit:

```
# Revert commits from HEAD~3 to HEAD~1 (3 commits)
git revert HEAD~3..HEAD
```

Atau revert berbilang commit tertentu:

```
git revert <hash1> <hash2> <hash3>
```

## Revert Tanpa Membuat Commit

Untuk mempentaskan perubahan revert tanpa membuat commit secara automatik:

```
git revert --no-commit HEAD
# or
git revert -n HEAD
```

Ini berguna apabila anda ingin me-revert berbilang commit dan mencipta satu commit revert:

```
git revert --no-commit HEAD~3..HEAD
git commit -m "Revert last 3 commits"
```

## Mengendalikan Konflik

Kadangkala me-revert commit boleh menyebabkan konflik:

```
git revert <commit-hash>
# If conflicts occur...
# 1. Resolve conflicts in the files
# 2. Stage the resolved files
git add <resolved-files>
# 3. Continue the revert
git revert --continue
```

Untuk membatalkan revert yang sedang berjalan:

```
git revert --abort
```

## Me-revert Commit Cantuman

Me-revert cantuman adalah lebih kompleks kerana commit cantuman mempunyai dua induk. Anda mesti menentukan induk mana untuk di-revert:

```
# -m 1 means keep changes from the first parent (usually mainline)
git revert -m 1 <merge-commit-hash>
```

## Bila Menggunakan Revert vs Reset

**Gunakan `git revert` apabila:**
* Commit telah di-push ke repositori yang dikongsi
* Anda ingin mengekalkan sejarah
* Bekerja pada cabang awam (main, develop, dan sebagainya)
* Anda memerlukan rekod operasi membuat asal

**Gunakan `git reset` apabila:**
* Commit hanya berada dalam repositori setempat anda
* Anda ingin mengeluarkan commit daripada sejarah sepenuhnya
* Bekerja pada cabang ciri peribadi
* Commit ialah kesilapan yang tidak sepatutnya berada dalam sejarah

## Me-revert dan Menggunakan Semula Perubahan

Kadangkala anda me-revert commit tetapi kemudian ingin menggunakannya semula:

```
# First, revert a commit
git revert <commit-hash>

# Later, revert the revert
git revert <revert-commit-hash>
```

## Contoh Praktikal

### Contoh 1: Revert Commit Buruk pada Cabang Utama

```
# Commit a1b2c3d introduced a bug
git revert a1b2c3d
git push origin main
```

### Contoh 2: Revert Berbilang Commit

```
# Revert the last 5 commits as a single revert commit
git revert --no-commit HEAD~5..HEAD
git commit -m "Revert last 5 commits due to critical bug"
git push origin main
```

### Contoh 3: Revert Kemudian Buat Pembetulan

```
# Revert a problematic commit
git revert a1b2c3d

# Make necessary corrections
# ... edit files ...

# Commit the corrections
git add .
git commit -m "Fix issues from reverted commit"
git push origin main
```

## Amalan Terbaik

1. **Tulis mesej yang jelas**: Terangkan mengapa anda me-revert
   ```
   git revert a1b2c3d -m "Revert feature X due to performance issues"
   ```

2. **Uji sebelum push**: Pastikan revert tidak merosakkan apa-apa

3. **Berkomunikasi**: Beritahu pasukan anda apabila anda me-revert commit

4. **Pertimbangkan alternatif**: Kadangkala pembetulan ke hadapan adalah lebih baik daripada revert

5. **Dokumenkan sebabnya**: Rujuk nombor isu atau sediakan konteks

## Melihat Sejarah Revert

Untuk melihat commit revert dalam sejarah anda:

```
git log --oneline --grep="Revert"
```

## Ringkasan Hari Ini

`git revert` ialah cara selamat untuk membuat asal perubahan dalam repositori yang dikongsi. Ia mengekalkan integriti sejarah sambil membuat asal perubahan yang tidak diingini. Memahami bila menggunakan `revert` berbanding `reset` adalah penting untuk kerjasama yang berkesan dan mengekalkan sejarah projek yang bersih dan mudah difahami.

Izinkan saya menyusun semula perintah dan parameter Git yang dipelajari hari ini:

* git revert
* git revert HEAD
* git revert <commit-hash>
* git revert --no-commit
* git revert -n
* git revert -m
* git revert --continue
* git revert --abort
