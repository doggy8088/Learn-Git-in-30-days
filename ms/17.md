# Hari 17: Konsep Asas dan Penggunaan Cantuman (Merge)

Seperti yang disebutkan dalam Hari 08 (Konsep Asas dan Penggunaan Cabang), kami telah mempelajari tentang "cabang." Sekarang kami akan membincangkan cara melakukan "cantuman." Oleh kerana Git ialah sistem kawalan versi teragih (DVCS), anda akan sentiasa melakukan operasi pencabangan dan cantuman, sama ada cantuman yang disengajakan (`git merge`) atau cantuman yang tidak disengajakan (`git pull`). Ringkasnya, operasi "pencabangan" dan "cantuman" sememangnya kerap berlaku apabila menggunakan Git untuk kawalan versi. Artikel ini akan menerangkan konsep asas dan penggunaan operasi "cantuman."

## Memahami Konsep Cantuman

Apabila anda mencipta cabang dalam direktori kerja Git, anda boleh membangunkan sistem anda mengikut keperluan berbeza secara berasingan tanpa menjejaskan satu sama lain. Contohnya, anda boleh mengekalkan sistem anda yang asalnya stabil dalam cabang `master` untuk pembangunan, dan apabila anda perlu membetulkan ralat, cipta cabang `bugfix` tambahan untuk membetulkan ralat perisian. Selepas pepijat dibetulkan, anda boleh menggunakan semula perubahan daripada cabang `bugfix` ke `master` melalui "cantuman." Ini ialah salah satu senario penggunaan utama.

Secara amnya, semua orang membangun pada cabang utama atau lalai (`master`), kemudian mencipta cabang mengikut keperluan (`bugfix`), dan akhirnya mencantumkan kedua-dua cabang menjadi satu. Sebenarnya, apabila melakukan operasi "cantuman," anda mencantumkan cabang lain ke dalam cabang semasa, dan kemudian mengeluarkan cabang lain itu secara manual. Ini sepadan dengan konsep "mencantumkan dua cabang menjadi satu."

Dalam praktiknya, sering terdapat peluang untuk mencantumkan tiga, empat, atau lebih cabang menjadi salah satu daripadanya. Contohnya, selain cabang utama (`master`), anda juga mencipta cabang untuk penyahpepijatan (`bugfix`) dan cabang untuk menambah ciri (`feature`). Selepas membangun hingga tahap tertentu, anda boleh memutuskan sama ada untuk mencantumkan kedua-dua cabang ini kembali ke cabang utama (`master`) bersama-sama.

Apabila menggunakan cantuman dalam Git, terdapat konsep penting: **tindakan cantuman mesti berlaku dalam repositori yang sama**. Ingat kembali bahawa dalam mana-mana repositori Git, mesti ada objek Initial Commit (versi awal), dan semua versi lain akan berkaitan dengan versi ini. Kami memanggil hubungan ini "objek yang dijejak pada kepala cabang," jadi anda tidak boleh mencantumkan cabang tertentu daripada satu repositori ke dalam cabang repositori lain yang sama sekali tidak berkaitan.

Semasa mencantum, jika kedua-dua cabang telah mengubah suai fail yang sama, tetapi selagi baris yang diubah suai berbeza, Git akan menggunakan/mencantumkan kedua-dua perubahan ini untuk anda secara automatik. Tetapi jika kebetulan anda mengubah suai "fail yang sama" pada "baris yang sama" dalam kedua-dua cabang, peristiwa konflik akan berlaku semasa cantuman. Apabila konflik cantuman berlaku, Git tidak akan memutuskan apa-apa untuk anda, tetapi akan menyerahkan kerja "menyelesaikan konflik" kepada "anda," dan fail yang berkonflik ini semuanya akan ditandakan dengan status `unmerged`. Selepas konflik cantuman, anda boleh menggunakan perintah `git status` untuk melihat status ini.

## Jenis Cantuman

Terdapat dua jenis cantuman utama dalam Git:

1. **Cantuman fast-forward**: Digunakan apabila cabang sasaran belum menyimpang daripada cabang sumber
2. **Cantuman tiga hala**: Digunakan apabila kedua-dua cabang mempunyai commit baharu

## Cantuman Fast-Forward

Cantuman fast-forward berlaku apabila cabang semasa belum menyimpang daripada cabang yang dicantumkan. Git hanya menggerakkan penunjuk cabang ke hadapan.

```
# On master branch
git merge feature-branch
```

Jika `master` belum mempunyai sebarang commit baharu sejak `feature-branch` dicipta, Git melakukan cantuman fast-forward.

## Cantuman Tiga Hala

Apabila kedua-dua cabang mempunyai commit baharu, Git melakukan cantuman tiga hala, mencipta commit cantuman baharu yang menggabungkan perubahan daripada kedua-dua cabang.

```
# On master branch
git merge feature-branch
```

Ini mencipta commit baharu dengan dua commit induk.

## Menghalang Fast-Forward

Kadangkala anda ingin mengekalkan sejarah cabang walaupun fast-forward boleh dilakukan:

```
git merge --no-ff feature-branch
```

Ini sentiasa mencipta commit cantuman, walaupun untuk cantuman fast-forward.

## Konflik Cantuman

Konflik berlaku apabila baris yang sama dalam fail yang sama telah diubah secara berbeza dalam kedua-dua cabang yang dicantumkan. Apabila ini berlaku:

1. Git menghentikan sementara cantuman
2. Menandakan fail yang berkonflik
3. Menambah penanda konflik pada fail
4. Menunggu anda menyelesaikan konflik

## Melihat Fail yang Berkonflik

Untuk melihat fail mana yang mempunyai konflik:

```
git status
```

Fail yang mempunyai konflik disenaraikan sebagai "both modified".

## Penanda Konflik

Git menambah penanda pada fail yang berkonflik:

```
<<<<<<< HEAD
Your changes
=======
Their changes
>>>>>>> branch-name
```

* `<<<<<<< HEAD`: Menandakan permulaan perubahan anda
* `=======`: Memisahkan kedua-dua versi
* `>>>>>>> branch-name`: Menandakan akhir perubahan yang masuk

## Menyelesaikan Konflik

Untuk menyelesaikan konflik:

1. Buka fail yang berkonflik
2. Cari penanda konflik
3. Sunting fail untuk menyelesaikan konflik
4. Keluarkan penanda konflik
5. Pentaskan fail yang diselesaikan: `git add <file>`
6. Selesaikan cantuman: `git commit`

## Membatalkan Cantuman

Jika anda ingin membatalkan cantuman yang sedang berjalan:

```
git merge --abort
```

Ini memulangkan repositori anda ke keadaan sebelum cantuman bermula.

## Melihat Sejarah Cantuman

Untuk melihat commit cantuman dalam sejarah anda:

```
git log --oneline --graph --all
```

Ini menunjukkan perwakilan visual sejarah cabang dan cantuman anda.

## Strategi Cantuman

Git menyokong strategi cantuman yang berbeza:

* **recursive** (lalai): Strategi cantuman tiga hala lalai
* **ours**: Sentiasa mengutamakan versi kami dalam konflik
* **theirs**: Sentiasa mengutamakan versi mereka dalam konflik

```
git merge -X ours branch-name
git merge -X theirs branch-name
```

## Amalan Terbaik

1. **Commit kerja anda** sebelum mencantum
2. **Pull perubahan terkini** daripada jauh sebelum mencantum
3. **Uji cantuman** sebelum push ke cabang yang dikongsi
4. **Berkomunikasi** dengan pasukan anda tentang cantuman
5. **Kekalkan cantuman kecil** apabila boleh

## Ringkasan Hari Ini

Cantuman ialah operasi Git asas yang membolehkan anda menggabungkan kerja daripada cabang yang berbeza. Memahami cara cantuman berfungsi, terutamanya cara mengendalikan konflik, adalah penting untuk kerjasama yang berkesan. Amalkan cantuman secara berkala untuk menjadi selesa dengan proses tersebut.

Izinkan saya menyusun semula perintah dan parameter Git yang dipelajari hari ini:

* git merge
* git merge --no-ff
* git merge --abort
* git merge -X ours
* git merge -X theirs
* git log --graph
* git status
