# Hari 23: Membetulkan Sejarah Versi yang Telah Di-commit Bahagian 5 (rebase 2)

Dalam artikel sebelumnya, kami membincangkan bahawa Rebase digunakan untuk "menentukan semula versi asas" bagi dua cabang sedia ada. Selepas melaksanakan Rebase, ia juga mengubah titik permulaan cabang asal (titik cabang dipindahkan), menyebabkan perubahan dalam graf versi. Walau bagaimanapun, Rebase boleh melakukan lebih daripada sekadar ini - ia juga boleh digunakan untuk mengubah suai maklumat versi bagi mana-mana versi pada garis cabang tertentu.

Artikel ini meneruskan penerokaan kami tentang `git rebase`, mendalami teknik lanjutan dan aliran kerja praktikal untuk menggunakan rebase secara berkesan, termasuk mengubah suai maklumat commit pada sesebuah cabang.

## Teknik Rebase Interaktif Lanjutan

### Membahagikan Commit

Untuk membahagikan satu commit kepada berbilang commit:

```
git rebase -i HEAD~3

# Mark the commit to split with "edit"
# When Git stops at that commit:
git reset HEAD^
git add file1
git commit -m "First part"
git add file2
git commit -m "Second part"
git rebase --continue
```

### Menggabungkan dan Menyusun Semula

Anda boleh menyusun semula dan menggabungkan commit dalam satu operasi:

```
git rebase -i HEAD~5

# In the editor:
pick abc123 Feature A
squash def456 Fix for A
pick jkl012 Feature C  # Moved before B
pick ghi789 Feature B  # Moved after C
fixup mno345 Typo fix for B
```

## Rebase dengan Exec

Jalankan perintah selepas setiap commit semasa rebase:

```
git rebase -i --exec "npm test" HEAD~5
```

Ini menjalankan `npm test` selepas menggunakan setiap commit, membantu anda mencari commit yang mana memecahkan ujian.

## Rebase ke Commit Tertentu

Daripada nama cabang, anda boleh rebase ke commit tertentu:

```
git rebase --onto <new-base-commit> <old-base-commit> <branch>
```

Contoh kes penggunaan - mengeluarkan commit dari tengah sejarah:

```
# Remove commits between B and D
#     A---B---C---D---E feature
# Becomes:
#     A---B---D'---E' feature

git rebase --onto B D feature
```

## Rebase dengan Pilihan Strategi

Gunakan strategi cantuman semasa rebase:

```
# Always prefer our version in conflicts
git rebase -X ours main

# Always prefer their version
git rebase -X theirs main
```

## Mengekalkan Commit Cantuman

Secara lalai, rebase meratakan commit cantuman. Untuk mengekalkannya:

```
git rebase -p main
# or
git rebase --preserve-merges main
```

Nota: `-p` telah ditamatkan penggunaannya (deprecated); gunakan `--rebase-merges` sebaliknya:

```
git rebase --rebase-merges main
```

## Rebase dengan Fork-Point

Cari titik fork secara automatik:

```
git rebase --fork-point main
```

Ini berguna apabila cabang jauh telah di-force-push.

## Aliran Kerja: Memastikan Cabang Ciri Sentiasa Dikemas Kini

Aliran kerja lazim untuk memastikan cabang ciri anda sentiasa dikemas kini dengan main:

```
# On feature branch
git fetch origin
git rebase origin/main

# Or in one command
git pull --rebase origin main
```

## Aliran Kerja: Menyediakan untuk Pull Request

Bersihkan commit anda sebelum mencipta pull request:

```
# 1. Interactive rebase to clean history
git rebase -i main

# 2. Squash fixup commits, reword messages
# 3. Force push to update your branch
git push -f origin feature-branch
```

## Aliran Kerja: Mengemas Kini Selepas Semakan Kod

Selepas maklum balas semakan kod:

```
# Make changes
git add .
git commit --fixup <original-commit>

# Rebase with autosquash
git rebase -i --autosquash main

# Force push the updated branch
git push -f origin feature-branch
```

## Menangani Force Push

Apabila seseorang force-push cabang yang sedang anda usahakan:

```
# Fetch the updated branch
git fetch origin

# Rebase your work onto the new history
git rebase --onto origin/feature-branch old-commit feature-branch
```

Atau hanya:

```
git pull --rebase origin feature-branch
```

## Rebase vs Reset untuk Pembersihan

Untuk membersihkan commit setempat sebelum push:

**Rebase** (disyorkan):
* Mengekalkan susunan kronologi
* Kawalan interaktif
* Boleh cherry-pick commit

**Reset** (lebih mudah tetapi kurang fleksibel):
* Mengeluarkan commit sepenuhnya
* Memulakan semula dari keadaan bersih
* Kurang kawalan ke atas commit individu

## Corak Rebase yang Lazim

### Corak 1: Gabungkan Semua Commit (Squash)

```
git rebase -i --root
# Mark all but first commit as "squash"
```

### Corak 2: Tulis Semula Semua Mesej Commit

```
git rebase -i HEAD~10
# Mark all commits as "reword"
```

### Corak 3: Keluarkan Commit Tertentu

```
git rebase -i HEAD~10
# Mark unwanted commits as "drop"
```

## Senarai Semak Keselamatan Rebase

Sebelum membuat rebase:

- [ ] Adakah commit ini telah di-push ke cabang yang dikongsi?
- [ ] Adakah orang lain telah mendasarkan kerja pada commit ini?
- [ ] Adakah saya mempunyai sandaran (cabang atau tag)?
- [ ] Adakah saya telah berkomunikasi dengan pasukan?
- [ ] Adakah saya bersedia untuk force-push?

## Memulihkan daripada Bencana Rebase

Jika keadaan menjadi salah:

```
# Step 1: Stay calm
# Step 2: Find the old state
git reflog

# Step 3: Reset to before the rebase
git reset --hard HEAD@{5}

# Step 4: Try again more carefully
```

## Rebase dan Integrasi Berterusan (CI)

Apabila menggunakan CI/CD dengan rebase:

1. **Rebase secara setempat** sebelum push
2. **Jalankan ujian** selepas rebase
3. **Force push** hanya cabang anda
4. **Tunggu CI** sebelum mencantumkan
5. **Jangan sekali-kali rebase** selepas cantuman

## Ringkasan Amalan Terbaik

1. **Setempat sahaja**: Hanya rebase commit yang belum di-push
2. **Rebase kecil**: Rebase dengan kerap untuk mengelakkan konflik besar
3. **Uji dengan teliti**: Jalankan ujian selepas rebase
4. **Berkomunikasi**: Beri amaran kepada pasukan sebelum force-push
5. **Sandaran**: Cipta cabang sandaran sebelum rebase besar
6. **Berhati-hati dengan -f**: Semak dua kali sebelum force-push

## Ringkasan Hari Ini

Teknik rebase lanjutan memberikan anda alat yang berkuasa untuk mengekalkan sejarah commit yang bersih dan mudah difahami. Walaupun ciri-ciri ini boleh meningkatkan aliran kerja anda dengan ketara, ia memerlukan latihan dan penggunaan yang berhati-hati. Kuncinya ialah mengetahui bila untuk menggunakan rebase dan bila untuk kekal dengan alternatif yang lebih selamat seperti cantuman.

* git rebase -X
* git rebase --preserve-merges
* git rebase --rebase-merges
* git rebase --fork-point
* git rebase --root
* git pull --rebase
* git push -f
