# Hari 12: Memahami Nama Relatif Objek Git

Selepas memahami "nama mutlak" dan "nama rujukan" objek Git, kami kini akan memperkenalkan "nama relatif," yang juga lazim digunakan dalam proses kawalan versi Git.

Mari kita mengulang kaji semula. Dalam kawalan versi Git, setiap versi mewakili objek commit. Setiap objek commit mempunyai "nama mutlak" - rentetan 40 aksara yang diperoleh dengan hashing SHA1 kandungan. Anda boleh menggunakan 4 hingga 40 aksara pertama sebagai nama pengenalan objek commit itu. Semasa kawalan versi, anda juga boleh menggunakan "nama rujukan" untuk mewakili objek commit tertentu. Setiap "nama rujukan" akhirnya sepadan dengan "nama mutlak" sesuatu objek. "Nama rujukan" dibahagikan lagi kepada "rujukan umum" dan "rujukan simbolik." Antaranya, "rujukan umum" sepadan secara langsung dengan "nama mutlak," manakala "rujukan simbolik" sepadan dengan "rujukan umum" lain.

Apa yang akan diperkenalkan oleh artikel ini ialah penggunaan tatatanda "nama relatif," yang membolehkan anda mencari "objek commit" lain berdasarkan kedudukan relatifnya selepas mencari objek commit tertentu.

## Tatatanda Nama Relatif

Menggunakan nama relatif sebenarnya sangat mudah. Terdapat dua simbol khas yang mesti anda ingat, satu ialah `^` dan satu lagi ialah `~`.

Untuk mencari versi sebelumnya bagi `HEAD`, kami akan menggunakan `HEAD~` atau `HEAD~1` untuk mewakili "versi sebelumnya bagi objek commit HEAD." **Nota**: Di sini anda sepatutnya sudah tahu dengan sangat baik bahawa `HEAD` ialah "nama rujukan simbolik" terbina dalam Git, yang mewakili versi terkini cabang semasa.

Jika anda ingin mencari dua versi sebelum cabang `f2e` lain (tidak termasuk versi `HEAD` bagi `f2e`), anda boleh menggunakan `f2e~2` atau `f2e~~` untuk mewakilinya. Ini ialah kaedah perwakilan yang paling asas.

Dalam repositori tanpa cabang dan cantuman, maksud yang dinyatakan oleh `^1` dan `~1` adalah sama persis, kedua-duanya mewakili "versi sebelumnya." Tetapi sebenarnya, dalam repositori dengan cabang dan cantuman, ia mempunyai maksud yang berbeza. Bahagian ini akan diterangkan kemudian.

Ini ialah tatatanda "nama relatif" yang paling asas.

## Pautan antara Objek Commit

Dalam repositori Git yang lebih lazim, hanya akan ada satu "objek commit akar" secara lalai, iaitu versi pertama yang kami cipta, juga dikenali sebagai "Initial Commit." Anda juga perlu mempunyai sekurang-kurangnya objek commit pertama sebelum anda boleh mula bercabang. Jadi kami boleh katakan: "Dalam repositori Git, antara semua objek commit, kecuali objek commit pertama, mana-mana objek commit lain mesti mempunyai satu atau lebih objek commit induk." Mengapa mungkin terdapat "lebih daripada satu" objek commit induk? Kerana anda sangat berkemungkinan mencantumkan dua atau lebih cabang ke dalam cabang lain. Jadi objek commit selepas cantuman akan mempunyai berbilang objek commit induk.

Mari kita gunakan contoh mudah untuk membuktikan ini. Kami menggunakan `git cat-file -p [object_id]` untuk mendapatkan kandungan dua objek commit pertama, sekali gus memahami bahawa setiap objek commit sememangnya akan mempunyai atribut induk yang menghala ke nama mutlak objek commit induk, kecuali objek commit pertama tidak akan mempunyai atribut induk. ## Memahami Perbezaan antara `^` dan `~` dalam Tatatanda Nama Relatif

Maksud `~` mewakili "objek commit induk pertama."

Maksud yang diwakili oleh `^` ialah "apabila terdapat berbilang objek commit induk, objek induk generasi pertama yang mana untuk diwakili."

Jika anda mempunyai "nama rujukan" `C`, untuk mencari objek commit induk pertamanya, anda boleh mempunyai ungkapan berikut:

* `C^`
* `C^1`
* `C~`
* `C~1`

Jika anda ingin mencari objek commit induk keduanya (tanpa cantuman), anda boleh mempunyai ungkapan berikut:

* `C^^`
* `C^1^1`
* `C~2`
* `C~~`
* `C~1~1`

Tetapi anda tidak boleh menggunakan `C^2` untuk menyatakan "objek commit induk kedua"! Sebabnya ialah tanpa cantuman, `C` ini hanya mempunyai satu objek induk. Anda hanya boleh menggunakan `C^2` untuk mewakili "objek induk kedua bagi objek lapisan sebelumnya."

Perkara di atas mungkin kedengaran agak abstrak dan memutarbelitkan lidah. Saya telah melukis gambar rajah khas untuk anda lihat. Melalui gambar rajah itu, ia mungkin lebih jelas. Seperti yang ditunjukkan dalam rajah berikut, kami ingin mencari objek commit lain (objek induk) dalam laluan relatif objek commit `C`. Oleh kerana objek commit `C` ini mempunyai tiga objek induk, ini bermakna objek commit ini dicipta melalui cantuman. Kemudian untuk mencari setiap laluan melalui "nama relatif," anda mesti menggunakan gabungan kemahiran `^` dan `~` untuk mencari setiap versi yang anda ingin buka.

## Memperkenalkan Perintah `git rev-parse`

Dalam alat Git for Windows, terdapat perintah `git rev-parse`. Melalui perintah ini, anda boleh menghuraikan sebarang "nama rujukan" atau "nama relatif" menjadi "nama mutlak." Walaupun alat ini tidak kerap digunakan, ia agak praktikal apabila mengajar Git. Contoh penggunaan adalah seperti berikut:

* git rev-parse master
* git rev-parse HEAD
* git rev-parse ORIG_HEAD
* git rev-parse HEAD^
* git rev-parse HEAD~5
