# Hari 13: Menyimpan Sementara Perubahan dalam Direktori Kerja dan Indeks (Stash)

Pernahkah anda menghadapi situasi ini: anda sedang separuh jalan membangunkan sistem, dan tiba-tiba bos atau pelanggan anda memberi anda "arahan segera," meminta anda membetulkan pepijat dalam sistem sedia ada dengan segera atau menambah ciri? Program di hadapan anda hampir siap, dan "urusan segera" bos tidak boleh ditangguhkan. Keadaan pembangunan perisian yang tidak lengkap ditambah dengan keperluan pelarasan kecemasan sememangnya ujian besar terhadap kualiti perisian. Jika anda mempunyai masalah ini, Git boleh membantu anda menyelesaikan tugas itu dengan sempurna.

## Memahami Perintah git stash

Kami tahu bahawa apabila menggunakan kawalan versi Git, terdapat perbezaan antara "direktori kerja" dan "indeks." Dalam direktori kerja, akan terdapat fail yang telah anda ubah separuh jalan dan belum selesai (belum ditambah ke indeks), dan juga akan terdapat fail baharu yang belum ditambah (belum ditambah ke indeks). Data yang ditempatkan dalam indeks ialah kandungan yang anda rancang untuk mencipta versi (mencipta objek commit) melalui `git commit`.

Apabila anda sedang separuh jalan dalam pembangunan ciri dan diganggu dengan segera, anda pasti akan tergesa-gesa, terutamanya tidak tahu apa yang perlu dilakukan dengan program yang separuh ditulis semula itu. Dalam Git, terdapat perintah `git stash` yang boleh membantu anda secara automatik mencipta "versi khas" (juga objek commit) untuk fail yang separuh ditulis itu. Kami memanggil versi ini versi stash, atau anda boleh memanggilnya secara langsung "versi simpanan sementara."

## Mencipta Versi Stash

Fail yang telah kami ubah separuh jalan mungkin mempunyai keadaan berikut:

* Fail baharu (fail yang tidak dijejak)
* Fail baharu (fail yang telah ditambah ke indeks) (fail dijejak/staged)
* Fail yang diubah suai (fail yang belum ditambah ke indeks) (fail dijejak/unstaged)
* Fail yang diubah suai (fail yang telah ditambah ke indeks) (fail dijejak/staged)
* Fail yang dipadam (fail yang belum ditambah ke indeks) (fail dijejak/unstaged)
* Fail yang dipadam (fail yang telah ditambah ke indeks) (fail dijejak/staged)

Jika anda ingin mencipta "versi simpanan sementara" untuk fail yang separuh dibangunkan ini, anda mempunyai dua pilihan:

* `git stash` akan mencipta versi simpanan sementara untuk semua fail yang dijejak
* `git stash -u` akan merangkumi semua fail yang dijejak atau tidak dijejak, semuanya akan dicipta sebagai versi simpanan sementara

**Nota**: `git stash` juga boleh ditulis sebagai `git stash save`. Hasil kedua-dua perintah adalah sama, cuma parameter `save` boleh ditinggalkan.

### Contoh Aliran Kerja

Berikut ialah contoh praktikal yang mudah:

```bash
# You're working on features
echo "new feature" > feature.txt
git add feature.txt

# Suddenly need to fix a bug
# Stash your work-in-progress
git stash

# Now working directory is clean
# Fix the bug on another branch
git checkout main
# ... make fixes ...
git commit -m "Fix urgent bug"

# Return to your feature work
git checkout feature-branch
git stash pop  # Restore your work
```

## Memulihkan Perubahan yang Di-stash

Selepas menyimpan sementara perubahan anda, anda boleh beralih ke cabang lain atau mengerjakan tugas segera itu. Apabila anda bersedia untuk meneruskan kerja asal anda, anda boleh memulihkan perubahan yang disimpan sementara menggunakan:

* `git stash pop` - Menggunakan stash terkini dan mengeluarkannya daripada senarai stash
* `git stash apply` - Menggunakan stash terkini tetapi mengekalkannya dalam senarai stash

## Menyenaraikan Perubahan yang Di-stash

Untuk melihat apa yang telah anda stash, gunakan:

```
git stash list
```

Ini akan menunjukkan kepada anda semua perubahan yang di-stash dengan rujukan stash mereka (stash@{0}, stash@{1}, dan sebagainya).

## Menggunakan Stash Tertentu

Jika anda mempunyai berbilang stash, anda boleh menggunakan stash tertentu dengan merujuk nombornya:

```
git stash apply stash@{2}
```

## Menggugurkan Stash

Untuk mengeluarkan stash tertentu daripada senarai:

```
git stash drop stash@{0}
```

Untuk mengeluarkan semua stash:

```
git stash clear
```

## Menyimpan Sementara Fail yang Tidak Dijejak

Secara lalai, `git stash` hanya menyimpan sementara fail yang dijejak. Untuk turut menyimpan sementara fail yang tidak dijejak:

```
git stash -u
```

Atau untuk menyimpan sementara semuanya termasuk fail yang diabaikan:

```
git stash -a
```

## Mencipta Stash Bernama

Anda boleh memberi stash anda mesej yang deskriptif:

```
git stash save "Work in progress on feature X"
```

Ini memudahkan pengecaman stash kemudian.

## Melihat Kandungan Stash

Untuk melihat apa yang ada dalam stash tertentu tanpa menggunakannya:

```
git stash show stash@{0}
```

Untuk diff yang terperinci:

```
git stash show -p stash@{0}
```

## Ringkasan Hari Ini

Perintah `git stash` ialah alat yang sangat praktikal yang membolehkan anda mengetepikan kerja semasa anda buat sementara waktu tanpa membuat commit. Ini amat berguna apabila anda perlu menukar konteks dengan pantas untuk mengerjakan sesuatu yang lain. Mekanisme stash memastikan bahawa perubahan kerja dalam proses anda disimpan dengan selamat dan boleh dipulihkan kemudian.

Izinkan saya menyusun semula perintah dan parameter Git yang dipelajari hari ini:

* git stash
* git stash save
* git stash -u
* git stash list
* git stash pop
* git stash apply
* git stash drop
* git stash clear
* git stash show
