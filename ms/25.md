# Hari 25: Menggunakan Repositori Jauh GitHub - Konsep

Berdasarkan asas daripada Hari 24, artikel ini menerokai konsep dan aliran kerja penting apabila bekerja dengan repositori jauh GitHub.

## Memahami Cabang Penjejakan Jauh (Remote Tracking Branches)

Cabang penjejakan jauh ialah rujukan kepada keadaan cabang jauh. Ia mengikuti corak penamaan `<remote>/<branch>`:

```
# List all branches including remote tracking branches
git branch -a

# Example output:
# * main
#   feature
#   remotes/origin/main
#   remotes/origin/feature
```

## Fetch vs Pull

### Fetch

Memuat turun objek dan rujukan daripada repositori lain tetapi tidak mencantumkan:

```
git fetch origin
```

Ini mengemas kini cabang penjejakan jauh anda tetapi tidak mengubah direktori kerja anda.

### Pull

Fetch + Cantuman dalam satu perintah:

```
git pull origin main
# Equivalent to:
git fetch origin
git merge origin/main
```

Atau dengan rebase:

```
git pull --rebase origin main
```

## Cabang Upstream

Sediakan penjejakan upstream untuk memudahkan push/pull:

```
# Set upstream when pushing
git push -u origin feature-branch

# Now you can just use:
git push
git pull
```

Semak konfigurasi upstream:

```
git branch -vv
```

## Menjejak Cabang Jauh

### Cipta Cabang Setempat daripada Remote

```
# Option 1: Automatic tracking
git checkout feature-branch
# If feature-branch exists on remote, Git auto-creates and tracks it

# Option 2: Explicit tracking
git checkout -b feature-branch origin/feature-branch

# Option 3: Using track flag
git checkout --track origin/feature-branch
```

### Nyahjejak Cabang Jauh

```
git branch --unset-upstream
```

## Push dengan Nama Cabang yang Berbeza

Push cabang setempat ke remote dengan nama yang berbeza:

```
git push origin local-branch:remote-branch
```

## Memadamkan Cabang Jauh

Padamkan cabang jauh:

```
# Method 1
git push origin --delete branch-name

# Method 2
git push origin :branch-name
```

## Bekerja dengan Berbilang Remote

Anda boleh mempunyai berbilang remote (contohnya, origin dan upstream):

```
# Add upstream remote
git remote add upstream https://github.com/original/repo.git

# Fetch from upstream
git fetch upstream

# Merge upstream changes
git merge upstream/main

# Push to your origin
git push origin main
```

## Memahami Tingkah Laku git push

Mod push yang berbeza:

```
# Push current branch to matching branch on remote
git config push.default simple  # Default in Git 2.0+

# Push all matching branches
git config push.default matching

# Push current branch to branch with same name
git config push.default current

# No push without explicit ref spec
git config push.default nothing
```

## Force Push dan Bahayanya

### Bila untuk Force Push

* Anda telah rebase cabang ciri anda
* Anda satu-satunya yang bekerja pada cabang tersebut
* Anda perlu membetulkan kesilapan dalam commit yang telah di-push

### Cara Force Push

```
# Standard force push (dangerous!)
git push -f origin feature-branch

# Safer: force push with lease
git push --force-with-lease origin feature-branch
```

`--force-with-lease` hanya berjaya jika remote tidak berubah sejak kali terakhir anda fetch.

### Amalan Terbaik Force Push

1. **Jangan sekali-kali force push ke main/master**
2. **Berkomunikasi** sebelum force push cabang yang dikongsi
3. **Gunakan --force-with-lease** berbanding -f
4. **Cipta cabang sandaran** sebelum force push
5. **Hanya force push cabang ciri anda sendiri**

## Mengendalikan Cabang yang Mencapah

Apabila setempat dan jauh telah mencapah:

```
# Check the situation
git status

# Option 1: Merge remote changes
git pull origin main

# Option 2: Rebase on remote changes
git pull --rebase origin main

# Option 3: Force push (if appropriate)
git push --force-with-lease origin feature-branch
```

## Membersihkan Rujukan Penjejakan Jauh

Keluarkan cabang penjejakan jauh yang basi:

```
# See stale branches
git remote prune origin --dry-run

# Remove stale branches
git remote prune origin

# Or during fetch
git fetch --prune
```

## Repositori Bare vs Bukan Bare

### Bukan Bare (Repositori Kerja)

* Mempunyai direktori kerja
* Digunakan untuk pembangunan
* Apa yang anda klon biasanya

### Repositori Bare

* Tiada direktori kerja
* Hanya data Git
* Digunakan pada pelayan

```
# Create bare repository
git clone --bare project project.git

# Or init as bare
git init --bare project.git
```

## Corak Aliran Kerja Git

### Aliran Kerja Berpusat (Centralized Workflow)

Semua orang bekerja pada cabang main:

```
git pull origin main
# Make changes
git add .
git commit -m "Changes"
git push origin main
```

### Aliran Kerja Cabang Ciri (Feature Branch Workflow)

Setiap ciri mendapat cabangnya sendiri:

```
git checkout -b feature-x
# Work on feature
git push origin feature-x
# Create pull request
# After merge, delete branch
git branch -d feature-x
git push origin --delete feature-x
```

### Aliran Kerja Gitflow

Menggunakan berbilang cabang jangka panjang:

* **main**: Kod sedia untuk pengeluaran
* **develop**: Cabang integrasi
* **feature/**: Pembangunan ciri
* **release/**: Penyediaan keluaran
* **hotfix/**: Pembetulan kecemasan

## Aliran Kerja Pull Request

1. **Fork** repositori (untuk sumber terbuka)
2. **Klon** fork anda
3. **Cipta cabang ciri**
   ```
   git checkout -b feature-name
   ```
4. **Buat perubahan dan commit**
5. **Push ke fork anda**
   ```
   git push origin feature-name
   ```
6. **Cipta pull request** di GitHub
7. **Bincang dan semak** kod
8. **Buat perubahan yang diminta**
9. **Cantumkan apabila diluluskan**

## Memastikan Fork Sentiasa Dikemas Kini

```
# Add upstream remote (once)
git remote add upstream https://github.com/original/repo.git

# Fetch upstream changes
git fetch upstream

# Merge upstream/main into your main
git checkout main
git merge upstream/main

# Push to your fork
git push origin main
```

## Menyelesaikan Konflik dalam Pull Request

```
# Update your branch with target branch
git fetch origin
git checkout feature-branch
git merge origin/main

# Resolve conflicts
# ... edit files ...
git add .
git commit -m "Resolve conflicts"

# Push updated branch
git push origin feature-branch
```
