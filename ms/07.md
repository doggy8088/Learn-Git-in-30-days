# Hari 07: Menghurai Struktur Data Git - Struktur Indeks

Kita tahu terdapat dua struktur data penting dalam Git, iaitu "objek" dan "indeks". Artikel ini terutamanya digunakan untuk menerangkan butiran "indeks". Semasa proses menggunakan kawalan versi Git, anda mungkin mudah memahami penggunaan perintah git, tetapi mudah terjerumus ke dalam hafalan semata-mata dan tidak boleh menggunakannya dengan fleksibel. Malah Linus Torvalds menyebutkan dalam Mailing List: "Before users understand the meaning of the index, they cannot fully understand Git's capabilities." Oleh itu, memahami tujuan "indeks" adalah sangat penting.

## Tentang Indeks

Secara ringkasnya, tujuan "indeks" terutamanya adalah untuk merekodkan "fail mana yang akan diserahkan kepada versi commit seterusnya".

Dengan kata lain, "jika anda ingin menyerahkan versi ke repositori Git, maka anda mesti terlebih dahulu mengemas kini status indeks, dan perubahan akan diserahkan."

"Indeks" ini sebenarnya mempunyai banyak nama lain dalam banyak artikel asing, tetapi semuanya bermaksud perkara yang sama. Jangan keliru apabila anda melihat perkataan berkaitan pada masa hadapan.

* Index
* Cache
* Directory cache
* Current directory cache
* Staging area
* Staged files

Contohnya, perintah `git diff --cached` adalah sinonim sepenuhnya dengan `git diff --staged`.

## Perintah untuk Mengendalikan Indeks

Oleh kerana "indeks" sangat penting kepada Git, kebanyakan perintah mempunyai parameter yang berkaitan dengan indeks Git. Walau bagaimanapun, kami menyenaraikan secara kasar beberapa perintah yang berkaitan secara langsung dengan "indeks" untuk penerangan.

Sebelum menerangkan perintah, anda boleh melihat rajah berikut terlebih dahulu, yang menggambarkan kitaran hayat perubahan keadaan melalui perintah. Sebenarnya, proses perubahan ini semuanya ialah proses mengemas kini "fail indeks":

![imej](figures/07/01.png)

Pertama, izinkan saya memperkenalkan empat keadaan fail:

* untracked (tidak dijejak, mewakili keadaan fail yang belum ditambah ke repositori Git)
* unmodified (tidak diubah suai, mewakili keadaan apabila fail ditambah buat kali pertama, atau kandungan fail konsisten dengan kandungan HEAD)
* modified (telah diubah suai, mewakili bahawa fail telah diedit, atau kandungan fail tidak konsisten dengan kandungan HEAD)
* staged (menunggu untuk di-commit, mewakili bahawa fail ini semuanya akan dihantar ke repositori pada kali seterusnya git commit dilaksanakan)

### git status

Dapatkan status **working tree** (pokok kerja).

Oleh kerana kita telah bercakap tentang hubungan antara repositori, direktori kerja, objek, dan indeks, kita boleh menerangkan hubungan ini dalam satu ayat:

```txt
Git repository operation is to write data into Git objects by updating the index with changes in the working directory.
```

Tujuan perintah `git status` di sini ialah untuk memaparkan perbezaan antara **versi terkini** dan **fail indeks**. Perbezaan di sini merangkumi beberapa hubungan yang halus. Mari kita gunakan contoh untuk menerangkan hubungan ini.

Berikut ialah hasil pelaksanaan git status:

```sh
G:\git-demo>git status
# On branch master
# Changes to be committed:
#   (use "git reset HEAD <file>..." to unstage)
#
#       new file:   c.txt
#
# Changes not staged for commit:
#   (use "git add <file>..." to update what will be committed)
#   (use "git checkout -- <file>..." to discard changes in working directory)
#
#       modified:   a.txt
#
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#
#       b.txt
```

Di sini anda akan melihat tiga kumpulan yang berbeza, iaitu:

* Changes to be committed (perubahan sedia untuk diserahkan)
  * Terdapat fail `new file: c.txt` dalam kawasan ini, yang bermakna c.txt ialah fail baharu dan telah ditandakan sebagai sedia untuk commit.
  * Ini mewakili beberapa perkara:
    1. Fail c.txt kini wujud dalam **direktori kerja**
    2. Fail c.txt telah ditambah ke **indeks**
    3. Kandungan c.txt dalam **indeks** adalah konsisten dengan kandungan dalam **direktori kerja**
    4. Apabila melaksanakan git commit, kandungan dalam **indeks** akan di-commit (bukan kandungan dalam direktori kerja)

* Changes not staged for commit (perubahan yang telah diubah suai tetapi belum di-stage untuk commit)
  * Terdapat fail `modified: a.txt` dalam kawasan ini, yang bermakna a.txt ialah fail yang diubah suai tetapi belum ditandakan sebagai sedia untuk commit.
  * Ini mewakili beberapa perkara:
    1. Fail a.txt kini wujud dalam **direktori kerja**
    2. Fail a.txt telah ditambah ke **indeks**
    3. Kandungan a.txt dalam **indeks** adalah tidak konsisten dengan kandungan dalam **direktori kerja**
    4. Apabila melaksanakan git commit, hanya kandungan dalam **indeks** akan di-commit (bukan kandungan dalam direktori kerja)

* Untracked files (fail yang tidak dijejak)
  * Terdapat fail `b.txt` dalam kawasan ini, yang bermakna b.txt ialah fail baharu dan belum ditambah ke indeks.
  * Ini mewakili beberapa perkara:
    1. Fail b.txt kini wujud dalam **direktori kerja**
    2. Fail b.txt belum ditambah ke **indeks**
    3. Apabila melaksanakan git commit, fail ini tidak akan di-commit

### git add

Tambah kandungan fail ke indeks (stage fail untuk commit seterusnya).

Perintah `git add` mempunyai banyak kegunaan. Secara ringkasnya, melaksanakan perintah ini akan "mengemas kini indeks", tetapi cara indeks dikemas kini mungkin berbeza bergantung pada keadaan fail semasa:

* Jika fail berada dalam keadaan **untracked**, melaksanakan `git add` akan menambah kandungan fail ke indeks
* Jika fail berada dalam keadaan **modified**, melaksanakan `git add` akan mengemas kini kandungan fail ke indeks
* Jika fail berada dalam keadaan **staged**, melaksanakan `git add` akan mengemas kini kandungan fail ke indeks sekali lagi

### git rm

Buang fail daripada working tree dan daripada indeks.

Perintah ini akan memadam fail daripada kedua-dua **direktori kerja** dan **indeks**. Selepas pemadaman, anda perlu melaksanakan git commit untuk melengkapkan tindakan padam ini.

### git mv

Pindahkan atau namakan semula fail, direktori, atau symlink.

Perintah ini akan memindahkan atau menamakan semula fail dalam kedua-dua **direktori kerja** dan **indeks**. Selepas memindahkan atau menamakan semula, anda perlu melaksanakan git commit untuk melengkapkan tindakan ini.

### git commit

Rekod perubahan ke repositori.

Perintah ini akan menulis kandungan **indeks** semasa ke dalam **pangkalan data objek** dan menjana objek commit.

### git ls-files

Tunjukkan maklumat tentang fail dalam indeks dan working tree.

Perintah ini boleh memaparkan senarai fail dan status dalam indeks. Ini ialah perintah yang sangat berguna yang boleh membantu anda memahami keadaan semasa indeks.

Beberapa parameter lazim:

* `git ls-files -s` atau `git ls-files --stage` : Paparkan senarai fail dan maklumat terperinci dalam indeks
* `git ls-files -c` atau `git ls-files --cached` : Paparkan senarai fail cache
* `git ls-files -d` atau `git ls-files --deleted` : Paparkan senarai fail yang dipadam
* `git ls-files -m` atau `git ls-files --modified` : Paparkan senarai fail yang diubah suai
* `git ls-files -o` atau `git ls-files --others` : Paparkan senarai fail yang tidak dijejak

## Ringkasan Hari Ini

"Indeks" dalam Git ialah konsep yang sangat penting. Melalui indeks, Git boleh tahu fail mana yang akan diserahkan kepada versi commit seterusnya. Melalui pelbagai perintah, kita boleh mengemas kini status indeks dan mengawal fail mana yang akan diserahkan. Memahami indeks boleh membantu anda menguasai kawalan versi Git dengan lebih baik.
