# Hari 26: Ramai Orang Bekerja dalam Repositori Jauh yang Sama

Apabila ramai orang bekerja dalam repositori yang sama, penyelarasan dan pemahaman aliran kerja Git menjadi sangat penting. Artikel ini menerokai amalan terbaik dan senario lazim untuk kerjasama pasukan.

## Cabaran Lazim dalam Kerjasama Pasukan

1. **Konflik cantuman**: Ramai orang menyunting fail yang sama
2. **Cabang yang mencapah**: Setempat dan jauh menjadi tidak segerak
3. **Commit yang hilang**: Menulis ganti kerja orang lain secara tidak sengaja
4. **Jurang komunikasi**: Tidak mengetahui apa yang sedang diusahakan oleh orang lain

## Aliran Kerja Pasukan Asas

### Aliran Kerja Harian

```
# Morning: Get latest changes
git pull origin main

# Create feature branch
git checkout -b feature-name

# Work and commit frequently
git add .
git commit -m "Progress on feature"

# Before finishing: update with latest main
git checkout main
git pull origin main
git checkout feature-name
git merge main

# Resolve any conflicts

# Push your branch
git push origin feature-name

# Create pull request for review
```

### Sentiasa Dikemas Kini

Fetch perubahan dengan kerap:

```
# Check what's changed
git fetch origin

# View remote changes
git log main..origin/main

# Merge if appropriate
git merge origin/main
```

## Mengendalikan Kerja Serentak

### Senario 1: Fail yang Sama, Baris yang Berbeza

Biasanya dicantumkan secara automatik:

```
git pull origin main
# If auto-merge succeeds, you're done!
```

### Senario 2: Fail yang Sama, Baris yang Sama

Memerlukan penyelesaian manual:

```
git pull origin main
# Conflict!

# Edit conflicting files
# Remove markers: <<<<<<<, =======, >>>>>>>
# Keep the correct changes

# Stage resolved files
git add resolved-file.txt

# Complete the merge
git commit
```

### Senario 3: Seseorang Membuat Rebase

Boleh menyebabkan isu besar jika cabang dikongsi:

```
# If someone rebased a shared branch
git fetch origin

# You need to rebase your work
git rebase origin/feature-branch

# Or start fresh
git reset --hard origin/feature-branch
```

## Proses Semakan Kod

### Mencipta Pull Request yang Baik

1. **Tajuk deskriptif**: "Add user authentication feature"
2. **Penerangan terperinci**:
   * Apakah yang dilakukan oleh PR ini?
   * Mengapa perubahan ini diperlukan?
   * Bagaimanakah ia diuji?
3. **Kekalkan ia kecil**: Lebih mudah untuk disemak
4. **Satu perkara bagi setiap PR**: Jangan campurkan ciri dan pembetulan
5. **Kemas kini dengan main**: Pastikan ia bercantum dengan bersih

### Menyemak Pull Request

1. **Semak kod** dari segi logik dan gaya
2. **Uji secara setempat** jika boleh
3. **Tinggalkan maklum balas yang membina**
4. **Luluskan atau minta perubahan**
5. **Cantumkan apabila sudah bersedia**

## Menyelesaikan Konflik Pasukan

### Komunikasi Dahulu

* **Berbincang dengan pasukan anda**: Selalunya menghalang isu
* **Gunakan komen PR**: Tanya soalan, bincangkan pendekatan
* **Dokumenkan keputusan**: Kemas kini penerangan PR atau komen

### Penyelesaian Teknikal

#### Selesaikan Konflik

```
# Update your branch
git fetch origin
git merge origin/main

# Resolve conflicts in files
# Stage changes
git add .

# Complete merge
git commit
```

#### Batalkan dan Mulakan Semula

```
# If resolution is too complex
git merge --abort

# Talk to the other developer
# Coordinate who makes what changes
```

## Peraturan Perlindungan Cabang

Di GitHub, lindungi cabang penting:

1. **Wajibkan semakan pull request**
2. **Wajibkan semakan status** (CI/CD)
3. **Kuatkuasakan sejarah linear**
4. **Sertakan pentadbir**

Konfigurasikan dalam: Settings > Branches > Branch protection rules

## Integrasi Berterusan (CI)

Gunakan CI untuk mengesan isu lebih awal:

```yaml
# Example .github/workflows/test.yml
name: Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - run: npm install
      - run: npm test
```

## Alat Komunikasi

### Mesej Commit

Ikuti konvensyen:

```
<type>(<scope>): <subject>

<body>

<footer>
```

Contoh:

```
feat(auth): add user login functionality

Implement JWT-based authentication with email and password.
Includes password hashing with bcrypt and token refresh.

Closes #123
```

### Templat Pull Request

Cipta `.github/pull_request_template.md`:

```markdown
## Description
<!-- Describe your changes -->

## Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Breaking change

## Testing
<!-- How was this tested? -->

## Checklist
- [ ] Tests pass
- [ ] Documentation updated
- [ ] No merge conflicts
```

## Mengendalikan Pasukan Besar

### Bendera Ciri (Feature Flags)

Deploy kod yang belum sedia lagi:

```javascript
if (featureFlags.newUI) {
  return <NewUI />;
} else {
  return <OldUI />;
}
```

### Cabang Keluaran (Release Branches)

Asingkan pembangunan daripada keluaran:

```
main (production)
├── release/v2.0
├── release/v1.9
└── develop (integration)
    ├── feature/login
    ├── feature/dashboard
    └── feature/reports
```

## Ringkasan Amalan Terbaik

1. **Pull sebelum push**: Sentiasa dapatkan perubahan terkini terlebih dahulu
2. **Commit dengan kerap**: Commit yang kecil dan logik
3. **Push dengan kerap**: Kongsi kerja anda, dapatkan maklum balas
4. **Gunakan cabang**: Kekalkan main stabil
5. **Tulis ujian**: Kesan isu sebelum orang lain mengesannya
6. **Semak kod**: Belajar antara satu sama lain
7. **Berkomunikasi**: Berkomunikasi secara berlebihan jika perlu
8. **Dokumenkan**: README, wiki, komen
9. **Bersabar**: Konflik berlaku, selesaikannya bersama-sama
10. **Bantu orang lain**: Kejayaan pasukan adalah kejayaan anda

## Ringkasan Hari Ini

Kerjasama pasukan yang berjaya dengan Git memerlukan kedua-dua kemahiran teknikal dan komunikasi yang baik. Memahami aliran kerja lazim, mengendalikan konflik dengan anggun, dan menggunakan alat seperti pull request dan CI/CD akan membantu pasukan anda bekerja dengan lancar bersama-sama.

Izinkan saya menyusun semula perintah dan parameter Git yang dipelajari hari ini:

* git pull origin main
* git fetch origin
* git merge origin/main
* git rebase origin/branch
* git push origin branch
* git log main..origin/main
