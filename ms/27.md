# Hari 27: Kawalan Versi melalui Cabang dalam Repositori Jauh yang Sama

Pasukan yang berbeza menggunakan strategi pencabangan yang berbeza. Artikel ini menerokai model pencabangan lazim dan bila untuk menggunakan setiap satunya.

## Mengapa Strategi Pencabangan Penting

Tanpa strategi yang jelas:
* Konflik kod meningkat
* Keluaran menjadi kelam-kabut
* Pepijat terlepas ke dalam pengeluaran
* Penyelarasan pasukan terjejas

## GitHub Flow

**Terbaik untuk**: Aplikasi web, pengerahan berterusan (continuous deployment)

### Strategi

* Satu cabang utama: `main`
* Cabang ciri untuk semua perubahan
* Deploy daripada `main`

### Aliran Kerja

```
1. Create branch from main
   git checkout -b feature-name

2. Work and commit
   git commit -am "Add feature"

3. Push and create PR
   git push origin feature-name

4. Review and discuss

5. Deploy from branch (staging)

6. Merge to main
   # On GitHub: Merge PR

7. Deploy from main (production)
```

### Kelebihan
* Mudah dan terus terang
* Pembangunan yang pantas
* Main sentiasa boleh di-deploy
* Hebat untuk pengerahan berterusan

### Kekurangan
* Tiada sokongan keluaran jangka panjang
* Memerlukan CI/CD yang baik
* Tidak sesuai untuk berbilang versi

## Git Flow

**Terbaik untuk**: Perisian dengan keluaran, berbilang versi

### Jenis Cabang

* **main**: Kod sedia untuk pengeluaran
* **develop**: Cabang integrasi
* **feature/**: Ciri baharu
* **release/**: Penyediaan keluaran
* **hotfix/**: Pembetulan kecemasan

### Aliran Kerja

```
# Start new feature
git checkout -b feature/login develop

# Work on feature
git commit -am "Implement login"

# Finish feature
git checkout develop
git merge --no-ff feature/login
git branch -d feature/login

# Start release
git checkout -b release/1.0 develop

# Prepare release (bug fixes only)
git commit -am "Bump version to 1.0"

# Finish release
git checkout main
git merge --no-ff release/1.0
git tag -a 1.0

git checkout develop
git merge --no-ff release/1.0
git branch -d release/1.0

# Hotfix
git checkout -b hotfix/1.0.1 main
git commit -am "Fix critical bug"

git checkout main
git merge --no-ff hotfix/1.0.1
git tag -a 1.0.1

git checkout develop
git merge --no-ff hotfix/1.0.1
git branch -d hotfix/1.0.1
```

### Kelebihan
* Pemisahan tanggungjawab yang jelas
* Menyokong berbilang versi
* Proses keluaran yang berstruktur

### Kekurangan
* Lebih kompleks
* Kitaran pembangunan yang lebih perlahan
* Overhed untuk projek mudah

## GitLab Flow

**Terbaik untuk**: Organisasi dengan persekitaran staging dan production

### Strategi

* Cabang persekitaran: `main`, `staging`, `production`
* Cabang ciri bercantum ke `main`
* Promosi melalui persekitaran

### Aliran Kerja

```
# Feature development
git checkout -b feature-name main
# Work and commit
git push origin feature-name
# Create MR to main

# After merge to main
# Deploy to staging
git checkout staging
git merge main
git push origin staging

# After testing in staging
# Deploy to production
git checkout production
git merge staging
git push origin production
```

### Kelebihan
* Pengerahan berasaskan persekitaran
* Laluan promosi yang jelas
* Sesuai untuk industri yang dikawal selia

### Kekurangan
* Lebih banyak cabang untuk diurus
* Memerlukan automasi
* Boleh menjadi lebih perlahan

## Pembangunan Berasaskan Trunk (Trunk-Based Development)

**Terbaik untuk**: Pasukan berprestasi tinggi, pengerahan berterusan

### Strategi

* Trunk tunggal: `main`
* Cabang ciri yang sangat singkat hayatnya (< 1 hari)
* Bendera ciri untuk ciri yang belum lengkap

### Aliran Kerja

```
# Create short-lived branch
git checkout -b quick-fix main

# Make small change
git commit -am "Fix button color"

# Merge same day
git checkout main
git merge quick-fix
git push origin main

# Or commit directly to main
# (with CI and feature flags)
```

### Kelebihan
* Integrasi terpantas
* Mengurangkan konflik cantuman
* Menggalakkan CI/CD
* Kualiti kod yang tinggi

### Kekurangan
* Memerlukan disiplin
* Memerlukan CI/CD yang baik
* Kerumitan bendera ciri

## Release Flow (Microsoft)

**Terbaik untuk**: Perisian perusahaan, keluaran terancang

### Strategi

* `main`: Sentiasa sedia untuk keluaran
* `release/*`: Cabang penstabilan
* Cabang topik: Ciri yang singkat hayatnya

### Aliran Kerja

```
# Create topic branch
git checkout -b users/name/feature main

# Work and create PR
git push origin users/name/feature

# Create release branch
git checkout -b release/v2.0 main

# Cherry-pick into release
git cherry-pick <commit-hash>

# Release
git checkout main
git merge release/v2.0
git tag v2.0
```

### Kelebihan
* Jadual keluaran yang fleksibel
* Pembangunan dan penstabilan selari
* Sesuai untuk perusahaan

### Kekurangan
* Boleh menjadi kompleks
* Memerlukan cherry-pick
* Lebih banyak penyelenggaraan

## Memilih Strategi

### GitHub Flow Apabila:
* Pengerahan berterusan
* Aplikasi web
* Pasukan kecil
* Iterasi pantas

### Git Flow Apabila:
* Keluaran berjadual
* Aplikasi desktop/mudah alih
* Perlu menyokong berbilang versi
* Kitaran hayat perisian tradisional

### GitLab Flow Apabila:
* Berbilang persekitaran
* Pengerahan berperingkat
* Keperluan kawal selia

### Trunk-Based Apabila:
* Pasukan berpengalaman
* CI/CD yang cemerlang
* Pengerahan berterusan
* Kekerapan keluaran yang tinggi

## Konvensyen Penamaan Cabang

### Cabang Ciri
```
feature/user-authentication
feature/dark-mode
feat/issue-123
```

### Cabang Pembetulan Pepijat
```
fix/login-error
bugfix/issue-456
hotfix/critical-security-patch
```

### Cabang Keluaran
```
release/1.0
release/2.0.0
release/v1.5
```

### Cabang Lain
```
docs/update-readme
test/integration-tests
refactor/database-layer
chore/update-dependencies
```

## Perintah Pengurusan Cabang

### Senaraikan Cabang
```
# Local branches
git branch

# All branches (including remote)
git branch -a

# With last commit
git branch -v

# Merged branches
git branch --merged

# Unmerged branches
git branch --no-merged
```

### Padamkan Cabang
```
# Delete local branch
git branch -d feature-name

# Force delete
git branch -D feature-name

# Delete remote branch
git push origin --delete feature-name
```

### Namakan Semula Cabang
```
# Rename current branch
git branch -m new-name

# Rename other branch
git branch -m old-name new-name
```
