# Hari 28: Memahami Aliran Kerja Fork dan Pull Request di GitHub

Fork dan pull request adalah asas kepada kerjasama sumber terbuka di GitHub. Artikel ini menerangkan cara menyumbang kepada projek yang anda tidak mempunyai akses tulis.

## Memahami Fork

Fork ialah salinan lengkap sesebuah repositori di bawah akaun GitHub anda. Ia membolehkan anda:
* Bereksperimen dengan bebas tanpa menjejaskan projek asal
* Mencadangkan perubahan melalui pull request
* Menyesuaikan projek mengikut keperluan anda

## Fork vs Klon vs Cabang

* **Fork**: Salin repositori di GitHub (akaun anda)
* **Klon (Clone)**: Salin repositori ke mesin setempat
* **Cabang (Branch)**: Cipta garis pembangunan yang mencapah

## Fork Sesebuah Repositori

### Di GitHub

1. Navigasi ke repositori tersebut
2. Klik butang "Fork" (kanan atas)
3. Pilih tempat untuk fork (akaun anda atau organisasi)
4. Tunggu GitHub mencipta fork tersebut

### Mengklon Fork Anda

```
# Clone your fork
git clone https://github.com/your-username/repo-name.git

# Navigate to directory
cd repo-name

# Add upstream remote
git remote add upstream https://github.com/original-owner/repo-name.git

# Verify remotes
git remote -v
# origin    https://github.com/your-username/repo-name.git (fetch)
# origin    https://github.com/your-username/repo-name.git (push)
# upstream  https://github.com/original-owner/repo-name.git (fetch)
# upstream  https://github.com/original-owner/repo-name.git (push)
```

## Aliran Kerja Pull Request yang Lengkap

### Langkah 1: Segerakkan Fork Anda

```
# Fetch upstream changes
git fetch upstream

# Checkout your main branch
git checkout main

# Merge upstream changes
git merge upstream/main

# Push to your fork
git push origin main
```

### Langkah 2: Cipta Cabang Ciri

```
# Create and checkout feature branch
git checkout -b fix-typo-in-readme

# Make your changes
# Edit files...

# Stage changes
git add README.md

# Commit changes
git commit -m "Fix typo in installation instructions"
```

### Langkah 3: Push ke Fork Anda

```
# Push branch to your fork
git push origin fix-typo-in-readme
```

### Langkah 4: Cipta Pull Request

1. Pergi ke fork anda di GitHub
2. Klik butang "Compare & pull request"
3. Isikan butiran PR:
   * **Tajuk (Title)**: Penerangan yang jelas dan ringkas
   * **Penerangan (Description)**: Apa, mengapa, dan bagaimana
   * Rujuk isu jika berkenaan
4. Klik "Create pull request"

### Langkah 5: Balas Maklum Balas

```
# Make requested changes
# Edit files...

# Commit changes
git add .
git commit -m "Address review feedback"

# Push updates
git push origin fix-typo-in-readme
# PR automatically updates!
```

### Langkah 6: Selepas Cantuman

```
# Switch to main
git checkout main

# Pull merged changes
git pull upstream main

# Push to your fork
git push origin main

# Delete feature branch
git branch -d fix-typo-in-readme
git push origin --delete fix-typo-in-readme
```

## Memastikan Fork Sentiasa Dikemas Kini

### Penyegerakan Berkala

```
# Fetch and merge in one command
git checkout main
git pull upstream main
git push origin main
```

### Penyegerakan Automatik

Gunakan butang "Fetch upstream" GitHub pada halaman fork anda, atau sediakan GitHub Actions:

```yaml
# .github/workflows/sync-upstream.yml
name: Sync Fork
on:
  schedule:
    - cron: '0 0 * * *'  # Daily
  workflow_dispatch:
jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: TobKed/github-forks-sync-action@v1
        with:
          upstream: original-owner/repo-name
          target: your-username/repo-name
```

## Berbilang Commit dalam Satu PR

### Kaedah 1: Rebase Interaktif

```
# Squash commits
git rebase -i HEAD~3

# In editor, change 'pick' to 'squash' for commits to combine
# Save and edit commit message

# Force push (since you're rewriting history)
git push -f origin feature-branch
```

### Kaedah 2: Soft Reset

```
# Reset to before your commits
git reset --soft HEAD~3

# Create single commit
git commit -m "Complete feature implementation"

# Force push
git push -f origin feature-branch
```

## Menangani Konflik Cantuman dalam PR

```
# Sync with upstream
git fetch upstream

# Rebase on upstream/main
git rebase upstream/main

# Resolve conflicts
# Edit conflicting files
git add resolved-files
git rebase --continue

# Force push
git push -f origin feature-branch
```

## Pull Request Draf (Draft Pull Requests)

Cipta PR draf untuk maklum balas awal:

1. Semasa mencipta PR, klik lungsur turun pada "Create pull request"
2. Pilih "Create draft pull request"
3. Tandakan sebagai sedia apabila selesai

Manfaat:
* Dapatkan maklum balas awal
* Tunjukkan kerja yang sedang berjalan
* Menghalang cantuman secara tidak sengaja

## Amalan Terbaik Pull Request

### Sebelum Mencipta PR

- [ ] Kod berfungsi dan telah diuji
- [ ] Mengikuti garis panduan gaya projek
- [ ] Dokumentasi dikemas kini
- [ ] Commit adalah bersih dan logik
- [ ] Cabang dikemas kini dengan main

### Menulis PR yang Baik

**Tajuk (Title)**:
```
❌ Fix stuff
✅ Fix null pointer exception in user login
```

**Penerangan (Description)**:
```
## What
Fixes a null pointer exception that occurs when users login with empty passwords.

## Why
Bug #123 reported crashes on invalid login attempts.

## How
Added null check before password validation.

## Testing
- Tested with empty password
- Tested with valid password
- Tested with invalid password

Closes #123
```

### Semasa Semakan

* Balas semua komen
* Tanya soalan jika tidak jelas
* Buat perubahan yang diminta dengan segera
* Bersikap terbuka kepada cadangan
* Ucapkan terima kasih kepada penyemak

## Menyumbang kepada Sumber Terbuka

### Cari Projek

1. **GitHub Explore**: https://github.com/explore
2. **First Timers Only**: https://www.firsttimersonly.com/
3. **Good First Issue**: Cari di GitHub
4. **Up For Grabs**: https://up-for-grabs.net/

### Sebelum Menyumbang

1. Baca `CONTRIBUTING.md`
2. Semak isu terbuka
3. Lihat PR sedia ada
4. Fahami tatakelakuan (code of conduct)
5. Sediakan persekitaran pembangunan

### PR Pertama Anda

Mulakan dengan kecil:
* Betulkan kesilapan taip
* Tambah baik dokumentasi
* Tambah ujian
* Betulkan pepijat yang jelas

### Membina Reputasi

1. Mulakan dengan dokumentasi
2. Laporkan pepijat yang baik
3. Bantu orang lain dalam isu
4. Hantar PR yang berkualiti
5. Bersabar dan hormat-menghormati

## Kesilapan Lazim yang Perlu Dielakkan

1. **Tidak menyegerakkan fork**: Sentiasa kemas kini sebelum mencipta PR
2. **Terlalu banyak perubahan**: Kekalkan PR fokus
3. **Tiada penerangan**: Terangkan apa dan mengapa
4. **Force push ke main**: Jangan sekali-kali lakukan ini
5. **Bertengkar dengan penyelenggara**: Bersikap hormat
6. **Tidak menguji**: Sentiasa uji perubahan anda

## Ringkasan Hari Ini

Fork dan pull request membolehkan kerjasama sumber terbuka secara besar-besaran. Memahami aliran kerja ini membuka beribu-ribu projek yang boleh anda sumbangkan. Mulakan dengan kecil, bersabar, dan ingat bahawa setiap penyumbang berpengalaman juga pernah menjadi pemula.

Izinkan saya menyusun semula perintah dan parameter Git yang dipelajari hari ini:

* git clone <fork-url>
* git remote add upstream <original-url>
* git fetch upstream
* git merge upstream/main
* git push origin branch-name
* git push -f origin branch-name
* git rebase -i HEAD~n
* git reset --soft HEAD~n
