# Hari 14: Pilihan Konfigurasi Git for Windows

Menggunakan alat baris perintah Git for Windows sememangnya lebih cekap daripada beroperasi melalui alat GUI. Sebabnya ialah anda boleh mengautomasikan banyak tugas kawalan versi yang berulang melalui perintah, atau menukar prosedur operasi standard (SOP) yang kompleks menjadi operasi perintah yang mudah. Artikel ini akan berkongsi beberapa petua untuk menggunakan alat baris perintah Git for Windows.

## Tentang Pilihan Konfigurasi Alat Baris Perintah Git

Dalam alat baris perintah Git, terdapat banyak "pilihan" yang boleh ditetapkan, sama seperti kita biasanya mempunyai [Tools] -> [Preferences] apabila menggunakan alat GUI, untuk memperhalus sesetengah tingkah laku apabila perintah dilaksanakan. Yang paling lazim, sudah tentu, ialah apabila anda mula-mula menggunakan Git for Windows, anda mesti menetapkan pilihan `user.name` dan `user.email`. Tanpa kedua-dua pilihan ini ditetapkan, anda tidak mempunyai hak untuk melaksanakan `git commit`.

Untuk menyenaraikan semua pilihan yang sedang ditetapkan dalam alat Git for Windows, anda boleh menggunakan perintah `git config --list`.

**Nota**: Oleh kerana kebanyakan artikel Git di internet memperkenalkan cara menyediakan persekitaran Linux atau Mac, artikel saya akan menumpukan pada konfigurasi platform Windows. Walau bagaimanapun, kecuali laluan storan yang berbeza, penggunaan perintah sebenarnya adalah sama.

Jika anda ingin menyemak "pilihan" apa yang tersedia, anda boleh melaksanakan `git help config` pada gesaan perintah untuk memaparkan dokumentasi lengkap atau melawat [Halaman Manual git-config(1)](https://www.kernel.org/pub/software/scm/git/docs/git-config.html).

## Memahami Peringkat Konfigurasi Git

Git mempunyai tiga peringkat konfigurasi:

1. **Peringkat sistem** (`--system`): Terpakai kepada semua pengguna pada sistem
   * Lokasi: `C:\Program Files\Git\etc\gitconfig`
   * **Penting untuk Windows**: Dengan UAC didayakan, tetapan mungkin dialihkan ke `%LOCALAPPDATA%\VirtualStore\Program Files\Git\etc\gitconfig`
   * **Cadangan**: Sentiasa jalankan Command Prompt sebagai Administrator apabila menetapkan pilihan peringkat sistem
   
2. **Peringkat global** (`--global`): Terpakai kepada pengguna semasa
   * Lokasi: `C:\Users\[username]\.gitconfig` atau `%USERPROFILE%\.gitconfig`
   * Lazim digunakan untuk `user.name`, `user.email`, dan keutamaan peribadi
   
3. **Peringkat setempat** (`--local`): Terpakai hanya kepada repositori semasa
   * Lokasi: `.git\config` dalam repositori
   * Dicipta secara automatik apabila anda memulakan atau mengklon repositori

Konfigurasi pada peringkat yang lebih rendah mengatasi peringkat yang lebih tinggi (setempat > global > sistem).

## Melihat Konfigurasi

Untuk melihat semua konfigurasi semasa:

```
git config --list
```

Untuk melihat konfigurasi daripada peringkat tertentu:

```
git config --global --list
git config --local --list
git config --system --list
```

## Menetapkan Identiti Pengguna

Konfigurasi yang paling asas ialah menetapkan nama pengguna dan e-mel anda:

```
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
```

Tetapan ini digunakan dalam setiap commit yang anda buat.

## Mengkonfigurasi Editor Lalai

Tetapkan editor teks pilihan anda untuk mesej commit:

```
git config --global core.editor "code --wait"  # VS Code
git config --global core.editor "notepad"      # Notepad
git config --global core.editor "vim"          # Vim
```

## Konfigurasi Penamat Baris

Ini penting untuk pembangunan merentas platform:

```
# Windows (convert LF to CRLF on checkout, CRLF to LF on commit)
git config --global core.autocrlf true

# Linux/Mac (convert CRLF to LF on commit, no conversion on checkout)
git config --global core.autocrlf input

# No conversion
git config --global core.autocrlf false
```

### Penting: Windows UAC dan VirtualStore

Pada Windows Vista dan yang lebih baharu dengan User Account Control (UAC) didayakan, terdapat pertimbangan penting apabila menetapkan konfigurasi peringkat sistem:

**Masalahnya**: Teknologi Windows VirtualStore mengalihkan penulisan fail apabila proses bukan pentadbir cuba menulis ke direktori sistem. Ini bermakna:
- Tetapan yang dibuat dengan Command Prompt biasa pergi ke `%LOCALAPPDATA%\VirtualStore\Program Files\Git\etc\gitconfig`
- Tetapan yang dibuat dengan Command Prompt Administrator pergi ke `C:\Program Files\Git\etc\gitconfig`
- Kedua-dua lokasi ini tidak menyegerak, menyebabkan tingkah laku yang tidak dijangka

**Penyelesaiannya**: Apabila menetapkan pilihan peringkat sistem (`--system`), sentiasa jalankan Command Prompt sebagai Administrator untuk memastikan tetapan terpakai ke seluruh sistem.

Untuk maklumat lanjut: [VirtualStore - Inside Windows Vista User Account Control](https://learn.microsoft.com/en-us/previous-versions/technet-magazine/cc138019(v=msdn.10))

## Mengkonfigurasi Alias

Cipta pintasan untuk perintah yang lazim digunakan:

```
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.st status
git config --global alias.lg "log --oneline --graph --all"
```

Kemudian anda boleh menggunakan `git co` dan bukannya `git checkout`, dan sebagainya.

## Output Berwarna

Dayakan output berwarna untuk kebolehbacaan yang lebih baik:

```
git config --global color.ui auto
```

## Nama Cabang Lalai

Tetapkan nama cabang lalai untuk repositori baharu:

```
git config --global init.defaultBranch main
```

## Alat Cantuman dan Diff

Konfigurasikan alat cantuman dan diff pilihan anda:

```
git config --global merge.tool vimdiff
git config --global diff.tool vimdiff
```

## Pembantu Kelayakan

Simpan kelayakan untuk mengelakkan kemasukan kata laluan berulang:

```
# Windows
git config --global credential.helper wincred

# Cache credentials for 1 hour
git config --global credential.helper 'cache --timeout=3600'
```

## Tingkah Laku Push

Konfigurasikan tingkah laku push lalai:

```
# Push only the current branch
git config --global push.default simple

# Push all matching branches
git config --global push.default matching
```

## Nyahset Konfigurasi

Untuk mengeluarkan konfigurasi:

```
git config --global --unset user.name
git config --global --unset-all user.email
```

## Menyunting Fail Konfigurasi Secara Langsung

Anda juga boleh menyunting fail konfigurasi secara langsung:

```
git config --global --edit
git config --local --edit
```

## Ringkasan Hari Ini

Memahami dan mengkonfigurasi Git dengan betul adalah penting untuk aliran kerja yang lancar. Sistem konfigurasi adalah fleksibel dan berkuasa, membolehkan anda menyesuaikan Git agar sepadan dengan keutamaan dan persekitaran kerja anda.

Izinkan saya menyusun semula perintah dan parameter Git yang dipelajari hari ini:

* git config --list
* git config --global user.name
* git config --global user.email
* git config --global core.editor
* git config --global core.autocrlf
* git config --global alias.*
* git config --global --edit
* git config --global --unset
