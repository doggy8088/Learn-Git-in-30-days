# Hari 15: Tag - Menandakan Peristiwa Penting dalam Kawalan Versi

Apabila menggunakan Git untuk kawalan versi, sebilangan besar versi akan dijana. Lama-kelamaan, antara banyak versi ini, pasti akan ada beberapa versi penting yang berbaloi untuk direkodkan. Inilah yang boleh dibantu oleh "tag" untuk kita lakukan.

## Memahami Tag - Konsep Asas

Pada asasnya, tujuan tag ialah untuk menandakan "versi" atau "objek commit" tertentu dengan "nama yang mudah diingati" untuk membantu kita mengingati versi tertentu.

Tag ialah rujukan yang menghala ke commit tertentu dalam sejarah Git anda. Tidak seperti cabang, tag tidak bergerak apabila anda membuat commit baharu - ia sentiasa menghala ke commit yang sama. Ini menjadikan tag sesuai untuk menandakan titik keluaran atau peristiwa penting lain yang signifikan.

Git menyokong dua jenis tag:

1. **Tag ringan**: Hanyalah nama (alias) untuk commit tertentu - ia ialah sejenis "nama rujukan"
2. **Tag beranotasi**: Disimpan sebagai objek Git penuh dengan metadata tambahan

Seperti yang disebutkan dalam Hari 11 (Memahami Rujukan Objek Git), "rujukan umum" merangkumi "nama tag," dan "nama tag" di sini merujuk kepada "tag ringan." Jadi "tag ringan" boleh dikatakan hanyalah "alias" untuk versi commit tertentu, yang merupakan sejenis "nama relatif."

"Tag beranotasi" ialah sejenis objek Git. Seperti yang disebutkan dalam Hari 06 (Menghurai Struktur Data Git - Struktur Objek), objek Git merangkumi 4 jenis objek: objek Blob, Tree, Commit, dan Tag. "Tag beranotasi" yang disebutkan di sini ialah objek Tag. Objek tag disimpan dalam storan objek Git (disimpan dalam direktori `.git\objects\`) dan dikaitkan dengan objek commit lain. Apabila mencipta "tag beranotasi," anda boleh memasukkan "mesej versi" sama seperti semasa mencipta objek commit. Dalam mekanisme tag terbina dalam Git, anda juga boleh menggunakan kunci GnuPG untuk menandatangani objek Tag bagi memastikan "bukan penafian" mesej.

Walaupun kami mempunyai dua jenis tag ini, dan kedua-duanya kelihatan seperti "alias" untuk objek commit, penggunaan kedua-dua tag ini hanya mempunyai sedikit perbezaan. Dalam kebanyakan kes penggunaan, kami menggunakan "tag beranotasi" untuk mencipta "objek tag" dan menyediakan "mesej versi," kerana jenis "tag" ini ialah "objek kekal" dalam repositori Git. (Objek Git yang disimpan dalam storan objek adalah tidak boleh diubah; hanya indeks yang berubah.)

## Mencipta Tag Ringan

Cara paling mudah untuk mencipta tag:

```
git tag v1.0
```

Ini mencipta tag ringan bernama `v1.0` yang menghala ke commit semasa (HEAD).

Untuk menandakan commit tertentu:

```
git tag v0.9 <commit-hash>
```

**Nota**: Semua fail di bawah `.git\refs\` ialah "nama rujukan."

Penggunaan asas:
* Senaraikan semua tag: `git tag`
* Cipta tag ringan: `git tag [tagname]`
* Padam tag ringan: `git tag [tagname] -d`

Jika anda ingin melihat kandungan "tag ringan," anda boleh menggunakan `git cat-file -p [tagname]`. Jika anda ingin melihat jenis objek "tag ringan," anda boleh menggunakan `git cat-file -t [tagname]`.

**Nota Penting**: Tag ringan bukan objek Git. Daripada perkara di atas, anda boleh lihat bahawa nama tag mendapatkan semula kandungan objek commit, dan jenis objek yang dijumpai oleh nama itu ialah objek commit.

## Mencipta Tag Beranotasi

Tag beranotasi disyorkan untuk kebanyakan kes penggunaan kerana ia menyimpan maklumat tambahan:

```
git tag -a v1.0 -m "Release version 1.0"
```

Bendera `-a` mencipta tag beranotasi, dan `-m` menentukan mesej tag.

Perbezaan daripada tag ringan:
1. Apabila melaksanakan `git tag` untuk menyenaraikan semua tag, semua tag bercampur bersama dan anda tidak dapat melihat jenis tag
2. Mencipta "tag beranotasi" memerlukan parameter `-a`
3. Mencipta "tag beranotasi" mesti memasukkan "mesej versi," sama seperti melaksanakan `git commit`, kedua-duanya mempunyai parameter `-m` yang tersedia

## Menyenaraikan Tag

Untuk melihat semua tag dalam repositori anda:

```
git tag
```

Untuk melihat tag yang sepadan dengan corak:

```
git tag -l "v1.*"
```

## Melihat Maklumat Tag

Untuk tag ringan:

```
git show v1.0
```

Ini menunjukkan commit yang dihala oleh tag.

Untuk tag beranotasi:

```
git show v1.0
```

Ini menunjukkan maklumat tag ditambah butiran commit.

## Menandakan Commit Lama

Anda boleh menandakan commit yang bukan pada HEAD:

```
git log --oneline  # Find the commit hash
git tag -a v0.5 -m "Beta release" <commit-hash>
```

## Menolak Tag ke Jauh

Secara lalai, `git push` tidak memindahkan tag. Anda perlu menolaknya secara eksplisit:

```
# Push a specific tag
git push origin v1.0

# Push all tags
git push origin --tags
```

## Memadam Tag

Untuk memadam tag setempat:

```
git tag -d v1.0
```

Untuk memadam tag jauh:

```
git push origin :refs/tags/v1.0
# or
git push origin --delete v1.0
```

## Checkout Tag

Anda boleh checkout kod pada tag tertentu:

```
git checkout v1.0
```

Ini meletakkan anda dalam keadaan "detached HEAD." Jika anda ingin membuat perubahan, cipta cabang baharu:

```
git checkout -b version-1-fixes v1.0
```

## Ringkasan Hari Ini

Tag ialah bahagian penting dalam kawalan versi, membolehkan anda menandakan titik penting dalam sejarah projek anda. Tag beranotasi amat berguna untuk keluaran kerana ia boleh menyimpan maklumat tambahan seperti nota keluaran, maklumat penanda, dan tandatangan.

Izinkan saya menyusun semula perintah dan parameter Git yang dipelajari hari ini:

* git tag
* git tag -a
* git tag -l
* git show
* git push origin --tags
* git tag -d
* git checkout
