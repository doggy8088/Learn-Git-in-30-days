# วันที่ 19: การตั้งค่ารายการละเว้น .gitignore

เมื่อพัฒนาโปรเจกต์ ไฟล์ใหม่อาจปรากฏขึ้นบ่อยครั้งใน Working Directory (เช่น ไฟล์ชั่วคราวหรือไฟล์แคชที่สร้างขึ้นโดยเครื่องมือพัฒนาอย่าง Visual Studio) ไฟล์เหล่านี้จำนวนมากไม่จำเป็นต้องรวมอยู่ในการควบคุมเวอร์ชัน และควรถูกแยกออกไป เราเรียกสิ่งนี้ว่า "รายการละเว้น (Ignore List)"

## ทำความเข้าใจ .gitignore

ไฟล์ `.gitignore` ระบุไฟล์ที่ยังไม่ถูกติดตามโดยตั้งใจซึ่ง Git ควรละเว้น ใน Git ไฟล์ `.gitignore` ถูกใช้เพื่อกำหนด "รายการละเว้น" วัตถุประสงค์หลักคือการแยกไฟล์ที่ไม่จำเป็นต้องเพิ่มเข้าไปในการควบคุมเวอร์ชันออกไป ไฟล์หรือเส้นทาง (ซึ่งสามารถใช้ Wildcard ได้) ที่ระบุไว้ในไฟล์นี้จะไม่ปรากฏในผลลัพธ์ของ `git status` และโดยธรรมชาติก็จะไม่ถูกเพิ่มเมื่อดำเนินการ `git add`

อย่างไรก็ตาม สิ่งนี้ใช้ได้เฉพาะกับ `Untracked files` เท่านั้น ไฟล์ที่ถูกติดตามโดย Git อยู่แล้ว (`Staged files`) จะไม่ได้รับผลกระทบจากไฟล์ `.gitignore`

## การสร้าง .gitignore ผ่าน GitHub

หากคุณเคยสร้างโปรเจกต์บน GitHub คุณอาจเคยใช้คุณสมบัตินี้ เมื่อสร้าง Repository ใหม่ คุณสามารถเลือกรายการละเว้นที่กำหนดไว้ล่วงหน้าซึ่ง GitHub ช่วยคุณตั้งค่าไว้ รายการละเว้นนี้แท้จริงแล้วเป็นเพียงไฟล์ชื่อ `.gitignore` ซึ่งโดยค่าเริ่มต้นจะถูกวางไว้ในไดเรกทอรีรากของโปรเจกต์

คุณสามารถเลือกจากเทมเพลตต่าง ๆ เช่น:
- Node
- Python
- Java
- C#
- Visual Studio
- และอื่น ๆ อีกมากมาย

## การสร้าง .gitignore ด้วยตนเอง

เพียงสร้างไฟล์ชื่อ `.gitignore` ในรากของ Repository ของคุณ:

```
# On Windows
echo node_modules/ > .gitignore

# On Linux/Mac
echo "node_modules/" > .gitignore
```

หรือสร้างมันด้วยตนเองด้วยโปรแกรมแก้ไขข้อความ

## รูปแบบพื้นฐาน

### ละเว้นไฟล์ที่ระบุ

```
config.local.js
secrets.txt
```

### ละเว้นไฟล์ที่มีนามสกุลที่ระบุ

```
*.log
*.tmp
*.cache
```

### ละเว้นไดเรกทอรี

```
node_modules/
dist/
build/
```

สังเกตเครื่องหมายทับท้ายเพื่อบ่งบอกว่าเป็นไดเรกทอรี

### ละเว้นไฟล์ในไดเรกทอรีใด ๆ

```
# Ignore all .log files in any directory
**/*.log
```

## รูปแบบขั้นสูง

### การปฏิเสธ (ข้อยกเว้น)

ใช้ `!` เพื่อสร้างข้อยกเว้น:

```
# Ignore all .log files
*.log

# But don't ignore important.log
!important.log
```

### ละเว้นไฟล์ในไดเรกทอรีที่ระบุเท่านั้น

```
# Ignore test.txt only in root directory
/test.txt

# Ignore test.txt in any subdirectory, but not root
*/test.txt
```

### หลายนามสกุล

```
# Ignore multiple file types
*.{jpg,png,gif}
```

## รูปแบบ .gitignore ที่ใช้บ่อย

### โปรเจกต์ Node.js

```
node_modules/
npm-debug.log
.env
.DS_Store
dist/
build/
```

### โปรเจกต์ Python

```
__pycache__/
*.py[cod]
*$py.class
.venv/
venv/
*.egg-info/
.pytest_cache/
```

### โปรเจกต์ Java

```
*.class
*.jar
*.war
target/
.gradle/
build/
```

### โปรเจกต์ .NET

```
bin/
obj/
*.user
*.suo
packages/
.vs/
```

## .gitignore ส่วนกลาง (Global)

สำหรับรูปแบบที่คุณต้องการละเว้นในทุก Repository:

```
git config --global core.excludesfile ~/.gitignore_global
```

จากนั้นสร้าง `~/.gitignore_global` พร้อมรูปแบบของคุณ

## การละเว้นไฟล์ที่ถูกติดตามอยู่แล้ว

หากคุณ Commit ไฟล์ที่ควรถูกละเว้นไปโดยไม่ได้ตั้งใจ:

```
# Remove from Git but keep the file
git rm --cached filename

# Remove directory from Git but keep it
git rm -r --cached directory/
```

จากนั้นเพิ่มรูปแบบเข้าไปใน `.gitignore` และ Commit

## การดูไฟล์ที่ถูกละเว้น

ในการดูว่าไฟล์ใดกำลังถูกละเว้นอยู่:

```
git status --ignored
```

## การตรวจสอบว่าทำไมไฟล์จึงถูกละเว้น

ในการดูว่ารูปแบบใดเป็นสาเหตุให้ไฟล์ถูกละเว้น:

```
git check-ignore -v filename
```

## ไฟล์เทมเพลต .gitignore

GitHub มีไฟล์เทมเพลต .gitignore สำหรับภาษาและเฟรมเวิร์กต่าง ๆ:

* https://github.com/github/gitignore

## คอมเมนต์ใน .gitignore

ใช้ `#` สำหรับคอมเมนต์:

```
# This is a comment
*.log  # Inline comment
```

## แนวปฏิบัติที่ดีที่สุด

1. **Commit .gitignore ตั้งแต่เนิ่น ๆ**: เพิ่มมันตั้งแต่เริ่มต้นโปรเจกต์ของคุณ
2. **เจาะจง**: หลีกเลี่ยงรูปแบบที่กว้างเกินไป
3. **บันทึกเหตุผล**: ใช้คอมเมนต์เพื่ออธิบายรูปแบบที่ไม่ชัดเจน
4. **จัดระเบียบให้ดี**: จัดกลุ่มรูปแบบที่เกี่ยวข้องกันไว้ด้วยกัน
5. **ใช้เทมเพลต**: เริ่มต้นด้วยเทมเพลตเฉพาะภาษา
6. **ความแตกต่างเฉพาะเครื่อง**: ใช้ `.git/info/exclude` สำหรับรูปแบบส่วนบุคคล

## .gitignore ในไดเรกทอรีย่อย

คุณสามารถมีไฟล์ `.gitignore` ในไดเรกทอรีย่อยได้ รูปแบบจะสัมพันธ์กับตำแหน่งของไฟล์ `.gitignore`

## สรุปของวันนี้

ไฟล์ `.gitignore` เป็นสิ่งจำเป็นสำหรับการรักษา Repository ของคุณให้สะอาด และหลีกเลี่ยงการ Commit ไฟล์ที่ไม่ควรอยู่ในการควบคุมเวอร์ชันโดยไม่ได้ตั้งใจ การทำความเข้าใจไวยากรณ์ของรูปแบบและแนวปฏิบัติที่ดีที่สุดจะช่วยให้คุณรักษา Repository ที่สะอาดและเป็นมืออาชีพได้

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git rm --cached
* git rm -r --cached
* git status --ignored
* git check-ignore
* git config core.excludesfile
