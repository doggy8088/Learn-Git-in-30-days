# วันที่ 17: แนวคิดพื้นฐานและการใช้งาน Merge

ดังที่กล่าวไว้ในวันที่ 08 (แนวคิดพื้นฐานและการใช้งาน Branch) เราได้เรียนรู้เกี่ยวกับ "Branch" กันไปแล้ว ตอนนี้เราจะมาพูดถึงวิธีดำเนินการ "Merge" กัน เนื่องจาก Git เป็นระบบควบคุมเวอร์ชันแบบกระจายศูนย์ (DVCS) คุณจะดำเนินการแยก Branch และ Merge อยู่ตลอดเวลา ไม่ว่าจะเป็นการ Merge โดยตั้งใจ (`git merge`) หรือการ Merge โดยไม่ตั้งใจ (`git pull`) ก็ตาม พูดสั้น ๆ คือ การดำเนินการ "แยก Branch" และ "Merge" เกิดขึ้นบ่อยครั้งจริง ๆ เมื่อใช้ Git ในการควบคุมเวอร์ชัน บทความนี้จะอธิบายแนวคิดพื้นฐานและการใช้งานการดำเนินการ "Merge"

## ทำความเข้าใจแนวคิดของการ Merge

เมื่อคุณสร้าง Branch ใน Working Directory ของ Git คุณสามารถพัฒนาระบบของคุณตามความต้องการที่แตกต่างกันแยกกันได้โดยไม่ส่งผลกระทบซึ่งกันและกัน ตัวอย่างเช่น คุณสามารถเก็บระบบที่เสถียรอยู่เดิมของคุณไว้ใน Branch `master` เพื่อการพัฒนา และเมื่อคุณต้องการแก้ไขข้อผิดพลาด ก็สร้าง Branch `bugfix` เพิ่มขึ้นมาเพื่อแก้ไขข้อผิดพลาดของซอฟต์แวร์ หลังจากแก้ Bug เสร็จแล้ว คุณสามารถนำการเปลี่ยนแปลงจาก Branch `bugfix` กลับไปใช้กับ `master` ได้อีกครั้งผ่าน "การ Merge" นี่คือหนึ่งในสถานการณ์การใช้งานหลัก

โดยทั่วไป ทุกคนจะพัฒนาบน Branch หลักหรือ Branch เริ่มต้น (`master`) จากนั้นสร้าง Branch ตามความต้องการ (`bugfix`) และสุดท้ายก็ Merge ทั้งสอง Branch ให้เป็นหนึ่งเดียว อันที่จริง เมื่อดำเนินการ "Merge" คุณจะ Merge อีก Branch หนึ่งเข้าไปใน Branch ปัจจุบัน จากนั้นจึงลบอีก Branch หนึ่งออกด้วยตนเอง สิ่งนี้ตรงกับแนวคิดของ "การ Merge สอง Branch ให้เป็นหนึ่งเดียว"

ในทางปฏิบัติ มักจะมีโอกาส Merge สาม สี่ หรือมากกว่านั้น Branch ให้เป็นหนึ่งในนั้น ตัวอย่างเช่น นอกจาก Branch หลัก (`master`) แล้ว คุณยังสร้าง Branch สำหรับการดีบัก (`bugfix`) และ Branch สำหรับการเพิ่มฟีเจอร์ (`feature`) อีกด้วย หลังจากพัฒนาไปถึงระดับหนึ่ง คุณสามารถตัดสินใจได้ว่าจะ Merge ทั้งสอง Branch นี้กลับเข้าไปใน Branch หลัก (`master`) พร้อมกันหรือไม่

เมื่อใช้การ Merge ใน Git มีแนวคิดสำคัญอย่างหนึ่ง: **การดำเนินการ Merge ต้องเกิดขึ้นภายใน Repository เดียวกัน** จำไว้ว่าใน Git Repository ใด ๆ จะต้องมี Initial Commit Object (เวอร์ชันเริ่มต้น) และเวอร์ชันอื่น ๆ ทั้งหมดจะเกี่ยวข้องกับเวอร์ชันนี้ เราเรียกความสัมพันธ์นี้ว่า "Object ที่ถูกติดตามบนหัวของ Branch" ดังนั้นคุณจึงไม่สามารถ Merge Branch ที่ระบุจาก Repository หนึ่งเข้าไปใน Branch ของอีก Repository หนึ่งที่ไม่เกี่ยวข้องกันเลยได้

เมื่อทำการ Merge หากทั้งสอง Branch แก้ไขไฟล์เดียวกัน แต่ตราบใดที่บรรทัดที่แก้ไขแตกต่างกัน Git จะนำ/รวมการเปลี่ยนแปลงทั้งสองนี้ให้คุณโดยอัตโนมัติ แต่หากบังเอิญคุณแก้ไข "ไฟล์เดียวกัน" ที่ "บรรทัดเดียวกัน" ในทั้งสอง Branch เหตุการณ์ Conflict จะเกิดขึ้นระหว่างการ Merge เมื่อเกิด Merge Conflict ขึ้น Git จะไม่ตัดสินใจอะไรแทนคุณ แต่จะส่งมอบงาน "การแก้ไข Conflict" ให้กับ "คุณ" และไฟล์ที่ขัดแย้งกันเหล่านี้ทั้งหมดจะถูกทำเครื่องหมายด้วยสถานะ `unmerged` หลังจากเกิด Merge Conflict คุณสามารถใช้คำสั่ง `git status` เพื่อดูสถานะเหล่านี้ได้

## ประเภทของการ Merge

การ Merge ใน Git มีสองประเภทหลัก:

1. **Fast-forward Merge**: ใช้เมื่อ Branch ปลายทางยังไม่ได้แยกออกจาก Branch ต้นทาง
2. **Three-way Merge**: ใช้เมื่อทั้งสอง Branch มี Commit ใหม่

## Fast-Forward Merge

Fast-forward Merge เกิดขึ้นเมื่อ Branch ปัจจุบันยังไม่ได้แยกออกจาก Branch ที่กำลังถูก Merge Git จะเพียงเลื่อนพอยน์เตอร์ของ Branch ไปข้างหน้า

```
# On master branch
git merge feature-branch
```

หาก `master` ยังไม่มี Commit ใหม่ใด ๆ นับตั้งแต่ `feature-branch` ถูกสร้างขึ้น Git จะดำเนินการ Fast-forward Merge

## Three-Way Merge

เมื่อทั้งสอง Branch มี Commit ใหม่ Git จะดำเนินการ Three-way Merge โดยสร้าง Merge Commit ใหม่ที่รวมการเปลี่ยนแปลงจากทั้งสอง Branch

```
# On master branch
git merge feature-branch
```

สิ่งนี้จะสร้าง Commit ใหม่ที่มี Parent Commit สองตัว

## การป้องกัน Fast-Forward

บางครั้งคุณต้องการเก็บรักษาประวัติของ Branch ไว้แม้ว่า Fast-forward จะเป็นไปได้ก็ตาม:

```
git merge --no-ff feature-branch
```

คำสั่งนี้จะสร้าง Merge Commit เสมอ แม้แต่สำหรับการ Merge แบบ Fast-forward

## Merge Conflict

Conflict เกิดขึ้นเมื่อบรรทัดเดียวกันในไฟล์เดียวกันถูกเปลี่ยนแปลงแตกต่างกันในสอง Branch ที่กำลังถูก Merge เมื่อสิ่งนี้เกิดขึ้น:

1. Git จะหยุดการ Merge ชั่วคราว
2. ทำเครื่องหมายไฟล์ที่ขัดแย้งกัน
3. เพิ่มเครื่องหมาย Conflict ลงในไฟล์
4. รอให้คุณแก้ไข Conflict

## การดูไฟล์ที่ขัดแย้งกัน

ในการดูว่าไฟล์ใดมี Conflict บ้าง:

```
git status
```

ไฟล์ที่มี Conflict จะแสดงรายการเป็น "both modified"

## เครื่องหมาย Conflict

Git จะเพิ่มเครื่องหมายลงในไฟล์ที่ขัดแย้งกัน:

```
<<<<<<< HEAD
Your changes
=======
Their changes
>>>>>>> branch-name
```

* `<<<<<<< HEAD`: ทำเครื่องหมายจุดเริ่มต้นของการเปลี่ยนแปลงของคุณ
* `=======`: แยกสองเวอร์ชันออกจากกัน
* `>>>>>>> branch-name`: ทำเครื่องหมายจุดสิ้นสุดของการเปลี่ยนแปลงที่เข้ามา

## การแก้ไข Conflict

ในการแก้ไข Conflict:

1. เปิดไฟล์ที่ขัดแย้งกัน
2. มองหาเครื่องหมาย Conflict
3. แก้ไขไฟล์เพื่อแก้ไข Conflict
4. ลบเครื่องหมาย Conflict ออก
5. Stage ไฟล์ที่แก้ไขแล้ว: `git add <file>`
6. ทำการ Merge ให้เสร็จสมบูรณ์: `git commit`

## การยกเลิกการ Merge

หากคุณต้องการยกเลิกการ Merge ที่กำลังดำเนินการอยู่:

```
git merge --abort
```

คำสั่งนี้จะคืน Repository ของคุณกลับสู่สถานะก่อนที่การ Merge จะเริ่มต้น

## การดูประวัติการ Merge

ในการดู Merge Commit ในประวัติของคุณ:

```
git log --oneline --graph --all
```

คำสั่งนี้จะแสดงภาพแทนของประวัติ Branch และการ Merge ของคุณ

## กลยุทธ์การ Merge

Git รองรับกลยุทธ์การ Merge ที่แตกต่างกัน:

* **recursive** (ค่าเริ่มต้น): กลยุทธ์การ Merge แบบ Three-way ที่เป็นค่าเริ่มต้น
* **ours**: เลือกเวอร์ชันของเราเสมอเมื่อเกิด Conflict
* **theirs**: เลือกเวอร์ชันของพวกเขาเสมอเมื่อเกิด Conflict

```
git merge -X ours branch-name
git merge -X theirs branch-name
```

## แนวปฏิบัติที่ดีที่สุด

1. **Commit งานของคุณ** ก่อนทำการ Merge
2. **Pull การเปลี่ยนแปลงล่าสุด** จาก Remote ก่อนทำการ Merge
3. **ทดสอบการ Merge** ก่อน Push ไปยัง Branch ที่แชร์กัน
4. **สื่อสาร** กับทีมของคุณเกี่ยวกับการ Merge
5. **ทำให้การ Merge มีขนาดเล็ก** เมื่อเป็นไปได้

## สรุปของวันนี้

การ Merge เป็นการดำเนินการพื้นฐานของ Git ที่ช่วยให้คุณรวมงานจาก Branch ต่าง ๆ เข้าด้วยกัน การทำความเข้าใจว่าการ Merge ทำงานอย่างไร โดยเฉพาะวิธีจัดการกับ Conflict เป็นสิ่งจำเป็นสำหรับการทำงานร่วมกันอย่างมีประสิทธิภาพ ฝึกฝนการ Merge เป็นประจำเพื่อให้คุ้นเคยกับกระบวนการนี้

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git merge
* git merge --no-ff
* git merge --abort
* git merge -X ours
* git merge -X theirs
* git log --graph
* git status
