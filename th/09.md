# วันที่ 09: การเปรียบเทียบความแตกต่างของไฟล์และเวอร์ชัน

ในกระบวนการใช้ซอฟต์แวร์ควบคุมเวอร์ชันใด ๆ คุณมักจำเป็นต้องดูบันทึกประวัติและเปรียบเทียบความแตกต่างระหว่างเวอร์ชัน วิธีเปรียบเทียบใน Git จะเป็นจุดเน้นของบทความนี้

## การเตรียม Working Directory

เรามาสร้าง Git Repository และ Working Directory ที่มีสองไฟล์และบันทึกการเปลี่ยนแปลงสองเวอร์ชันอย่างรวดเร็วผ่านคำสั่งต่อไปนี้:

```
mkdir git-demo
cd git-demo
git init

echo 1 > a.txt
echo 2 > b.txt
git add .
git commit -m "Initial commit"

echo 3 > a.txt
echo 4 > b.txt
git add .
git commit -m "Update a.txt and b.txt to 3 and 4"
```

## แนวคิดพื้นฐานของ git diff

ในการเปรียบเทียบความแตกต่างระหว่างสองเวอร์ชันใน Git โดยปกติคุณจะใช้คำสั่ง `git diff` เรามาดำเนินการคำสั่งง่าย ๆ เพื่อเปรียบเทียบความแตกต่างระหว่างสองเวอร์ชันกันก่อน:

1. ก่อนอื่นดำเนินการ `git log` เพื่อรับข้อมูลเวอร์ชันและรับ ID ของ Commit Object สองรายการล่าสุด
2. เราดำเนินการคำสั่ง `git diff commit1 commit2` เพื่อเปรียบเทียบความแตกต่างระหว่างสองเวอร์ชัน โดย commit1 ควรใช้เวอร์ชันที่เก่ากว่า และ commit2 ควรใช้เวอร์ชันที่ใหม่กว่า

ดังแสดงในรูปต่อไปนี้:

![รูปภาพ](figures/09/01.png)

จากผลลัพธ์ของการดำเนินการ `git diff` เราจะได้รับผลการดำเนินการ เนื่องจากเรามีสองไฟล์ใน Repository ทั้งสองนี้ และทั้งคู่มีการเปลี่ยนแปลงระหว่างสองเวอร์ชันนี้ มันจึงแสดงผลลัพธ์ "การเปรียบเทียบความแตกต่าง" สองส่วน

คุณจะเห็นได้จากรูปข้างต้นว่าแต่ละส่วนเริ่มต้นด้วย `diff --git` ซึ่งแสดงว่า git กำลังเปรียบเทียบสองไฟล์ใด

บรรทัดที่สอง `index 37bcc8b..d855592 100644` แสดงถึง "Header Line" เมื่อ git ทำการเปรียบเทียบนี้ อาจมีหลายบรรทัดตรงนี้ และข้อมูลไม่จำเป็นต้องมีเพียงเท่านี้ ข้อมูลเพิ่มเติมมากมายเกี่ยวกับการเปรียบเทียบความแตกต่างนี้จะถูกทำเครื่องหมายไว้ตรงนี้ ตัวอย่างเช่น บรรทัด index และ Hash ID สองค่าหลังจากนั้น (`37bcc8b..d855592`) แสดงถึง Blob Object ID สองค่าใน Git Object Storage (Object Storage) ที่ใช้เปรียบเทียบ Blob Object สองค่านี้ ส่วน `100644` หลังจากนั้นเป็นแอตทริบิวต์ของ git คล้ายกับแอตทริบิวต์ของไฟล์ในสภาพแวดล้อม Linux เช่น ประกาศว่านี่เป็นไฟล์ ไดเรกทอรี อ่านได้ เขียนได้ รันได้ เป็นต้น ต่อไปนี้คือตัวอย่างแอตทริบิวต์ของ git ที่พบบ่อย:

```
0100000000000000 (040000): Directory
1000000110100100 (100644): Regular non-executable file
1000000110110100 (100664): Regular non-executable group-writeable file
1000000111101101 (100755): Regular executable file
1010000000000000 (120000): Symbolic link
1110000000000000 (160000): Gitlink
```

สำหรับลิงก์ที่เกี่ยวข้อง โปรดอ้างอิงเธรดสนทนาต่อไปนี้:

* [How to read the mode field of git-ls-tree's output](https://stackoverflow.com/a/8347325/910074)

บรรทัดที่สาม `--- a/a.txt` แสดงถึงเวอร์ชันที่ "เก่ากว่า" ของสองเวอร์ชันที่เปรียบเทียบกัน

บรรทัดที่สี่ `+++ b/a.txt` แสดงถึงเวอร์ชันที่ "ใหม่กว่า" ของสองเวอร์ชันที่เปรียบเทียบกัน

บรรทัดที่ห้า `@@ -1 +1 @@` แสดงถึงจำนวนบรรทัดทั้งหมดในเวอร์ชันเก่าและเวอร์ชันใหม่ของไฟล์นี้ -1 หมายถึงเวอร์ชันเก่ามีเพียง 1 บรรทัด และ +1 หมายถึงเวอร์ชันใหม่ก็มีเพียง 1 บรรทัดเช่นกัน

สุดท้าย เนื้อหาที่เปลี่ยนแปลงทั้งหมดจะถูกแสดงไว้ มีรูปแบบการแสดงที่เป็นไปได้สามแบบตรงนี้:

* เริ่มต้นด้วยเครื่องหมายลบ - หมายความว่าบรรทัดนี้ถูกลบออกในกระบวนการจากเวอร์ชันเก่าไปยังเวอร์ชันใหม่
* เริ่มต้นด้วยเครื่องหมายบวก + หมายความว่าบรรทัดนี้ถูกเพิ่มเข้ามาในกระบวนการจากเวอร์ชันเก่าไปยังเวอร์ชันใหม่
* เริ่มต้นด้วยอักขระช่องว่าง หมายความว่าบรรทัดนี้ปรากฏในทั้งสองเวอร์ชันโดยไม่มีการเปลี่ยนแปลงใด ๆ

เท่านี้ก็เสร็จสิ้นการเปรียบเทียบความแตกต่างของ Blob Object แรกในสองเวอร์ชันนี้ จากนั้นมันจะแสดงการเปรียบเทียบความแตกต่างของ Blob Object ที่สองในเวอร์ชันนั้น และต่อไปเรื่อย ๆ

เมื่อใช้ `git diff` ใน Git อันที่จริงแล้ว Tree Object คือหน่วยของการเปรียบเทียบ เราได้เรียนรู้จากแผนภาพและวิดีโอใน [วันที่ 06: วิเคราะห์โครงสร้างข้อมูลของ Git - โครงสร้าง Object] ว่า Commit Object แต่ละตัวจริง ๆ แล้วมี Tree Object ของไดเรกทอรีราก (Root Directory) รวมอยู่ด้วย ดังนั้นเมื่อเราเพิ่งใช้ `git diff` เปรียบเทียบ Commit Object สองตัว เรากำลังเปรียบเทียบ Tree Object ภายใต้ Commit Object เหล่านั้นจริง ๆ และกระบวนการเปรียบเทียบจะดำเนินต่อไปแบบเรียกซ้ำ (Recursively) ลงไปเรื่อย ๆ จากตรงนี้ คุณน่าจะสัมผัสได้ว่ากลไกการเปรียบเทียบ Diff ของ Git นั้นทรงพลังมาก คุณสามารถเปรียบเทียบการเปลี่ยนแปลงระหว่างสองเวอร์ชันใด ๆ ได้อย่างรวดเร็ว

เมื่อใช้คำสั่ง `git diff` ส่วนใหญ่จะมีแหล่งที่มาของ Tree Object อยู่สามแหล่ง:

* Tree Object ที่มีอยู่ในกราฟ Commit ทั้งหมด ซึ่งหมายถึง Tree Object ใด ๆ ในเวอร์ชันใด ๆ
* Index ซึ่งแสดงถึงข้อมูลหลังจากที่คุณส่งสถานะไฟล์ไปยัง "ฐานข้อมูล Index" อันที่จริง Tree Object ถูกสร้างขึ้นแล้วเมื่อใช้คำสั่ง `git add`
* Working Directory ปัจจุบันของคุณ แม้ว่าการเปลี่ยนแปลงใน Working Directory จะยังไม่กลายเป็น Tree Object แต่ก็สามารถใช้ผ่าน `git diff` ได้

## วิธีการเปรียบเทียบพื้นฐานสี่วิธี

ในการเปรียบเทียบสองเวอร์ชันใด ๆ ผ่านคำสั่ง `git diff` โดยปกติจะมีการใช้คำสั่งสี่แบบต่อไปนี้:

1. git diff

   โดยไม่มีพารามิเตอร์ใด ๆ สิ่งที่ถูกเปรียบเทียบคือความแตกต่างระหว่าง "Working Directory" กับ "Index" นี่เป็นคำสั่งที่ใช้กันบ่อยมาก เพราะก่อนที่คุณจะดำเนินการคำสั่ง `git add .` คุณสามารถใช้ `git diff` ก่อนเพื่อดูว่าคุณเปลี่ยนแปลงอะไรไปบ้าง

   **หมายเหตุ**: อันที่จริง ในกระบวนการใช้การควบคุมเวอร์ชันด้วย Git ก่อนที่จะดำเนินการ `git commit` เป็นไปได้จริง ๆ ที่จะดำเนินการคำสั่ง `git add` หลายครั้งเพื่อยืนยันว่าจะเพิ่มไฟล์ใดเข้าไปใน Index และในที่สุดก็ Commit เข้าสู่เวอร์ชัน

2. git diff commit

   หากคุณเพิ่ม Commit ID เพียงค่าเดียวหลังจาก `git diff` สิ่งที่ถูกเปรียบเทียบคือ "Working Directory" กับ "Tree Object ใน Commit Object ที่ระบุ"

   คำสั่งที่ใช้บ่อยที่สุดคือ `git diff HEAD` เพราะนี่แสดงถึงการเปรียบเทียบ "Working Directory" กับ "เวอร์ชันล่าสุดของ Branch ปัจจุบัน" วิธีการเปรียบเทียบนี้จะไม่เปรียบเทียบสถานะ "Index" ดังนั้นคุณต้องแยกแยะให้ชัดเจนว่าคุณกำลังเปรียบเทียบแหล่ง Tree Object ใด

3. git diff --cached commit

   ก่อนที่จะดำเนินการ `git commit` สถานะ Index ควรพร้อมแล้ว ดังนั้นหากคุณต้องการเปรียบเทียบ "สถานะ Index ปัจจุบัน" กับ "Tree Object ใน Commit Object ที่ระบุ" คุณสามารถใช้คำสั่งนี้เพื่อทำงานเปรียบเทียบให้เสร็จสมบูรณ์ได้

   คำสั่งที่ใช้บ่อยที่สุดก็คือ `git diff --cached HEAD` เช่นกัน ซึ่งหมายถึงการเปรียบเทียบ "สถานะ Index ปัจจุบัน" กับ "เวอร์ชันล่าสุดของ Branch ปัจจุบัน" วิธีการเปรียบเทียบนี้จะไม่เปรียบเทียบเนื้อหาไฟล์ของ "Working Directory" แต่เปรียบเทียบความแตกต่างระหว่าง "Index" กับ "เวอร์ชันล่าสุดปัจจุบัน" โดยตรง สิ่งนี้ช่วยให้คุณทราบว่ามีการเปลี่ยนแปลงอะไรบ้างก่อนที่จะดำเนินการ `git commit` ซึ่งหมายถึงการเปลี่ยนแปลงอะไรบ้างที่คุณจะสร้างเป็นเวอร์ชัน

   **หมายเหตุ 1**: `git diff --cached` และ `git diff --staged` มีผลลัพธ์เหมือนกันทุกประการ `--staged` เป็นเพียงนามแฝง (Alias) ของ `--cached` เพื่อให้คุณจดจำได้ง่ายขึ้นเท่านั้น!

   **หมายเหตุ 2**: `git diff --cached` และ `git diff --cached HEAD` ก็มีผลลัพธ์เหมือนกันทุกประการเมื่อดำเนินการ HEAD ตัวสุดท้ายสามารถละไว้ได้

4. git diff commit1 commit2

   แบบสุดท้ายคือการเปรียบเทียบความแตกต่างระหว่างสองเวอร์ชันที่แตกต่างกัน (Commit ID) คำสั่งนี้สามารถข้ามการเปลี่ยนแปลงใด ๆ ใน "Index" และ "Working Directory" และเปรียบเทียบสองเวอร์ชันที่ระบุโดยตรง อันที่จริง Git เปรียบเทียบ Tree Object ใน Commit Object ของสองเวอร์ชันที่ระบุนั้น

   คำสั่งที่ใช้บ่อยที่สุดคือ `git diff HEAD^ HEAD` ซึ่งหมายความว่าคุณต้องการเปรียบเทียบความแตกต่างระหว่าง [เวอร์ชันก่อนหน้าของเวอร์ชันล่าสุด] กับ [เวอร์ชันล่าสุด] ความหมายของ HEAD และ ^ ตรงนี้จะอธิบายในบทความต่อ ๆ ไป

## สรุปของวันนี้

`git diff` ที่แนะนำในวันนี้เป็นคำสั่งที่ใช้กันบ่อยมาก และคุณควรใช้มันอย่างชำนาญ สุดท้ายเรามาทบทวนความแตกต่างระหว่างคำสั่งที่ใช้บ่อยของมันกัน:

```
git diff                 => working directory vs index
git diff HEAD            => working directory vs HEAD
git diff --cached HEAD   => index     vs HEAD
git diff --cached        => index     vs HEAD
git diff HEAD^ HEAD     => HEAD^   vs HEAD
```

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git log
* git diff
* git diff HEAD
* git diff --cached
* git diff --staged
* git diff HEAD^ HEAD
