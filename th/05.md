# วันที่ 05: ทำความเข้าใจความสัมพันธ์ระหว่าง Repository, Working Directory, Objects และ Index

ในกระบวนการใช้การควบคุมเวอร์ชันด้วย Git จะต้องสร้างแนวคิดพื้นฐานบางอย่างให้มั่นคง เพื่อให้คุณเรียนรู้ได้อย่างมีประสิทธิภาพและมีความหมายยิ่งขึ้น ด้วยการสนับสนุนทางแนวคิดที่ชัดเจนและถูกต้อง ไม่เพียงแต่จะช่วยให้คุณเรียนรู้การดำเนินการคำสั่ง Git เท่านั้น แต่ที่สำคัญกว่านั้น การเรียนรู้ความรู้ที่เกี่ยวข้องกับ Git จะกลายเป็นเรื่องง่ายขึ้น

## ทำความเข้าใจ Repository

เมื่อเราใช้ Git ในการควบคุมเวอร์ชัน โดยธรรมชาติแล้ว เราจำเป็นต้องมี "Repository" เพื่อเก็บข้อมูลเวอร์ชันเหล่านี้ คำภาษาอังกฤษว่า Repository ก็หมายถึงสิ่งนี้นั่นเอง ผมคุ้นเคยกับการแปลคำภาษาอังกฤษคำนี้ว่า "儲存庫" (ที่เก็บ) ซึ่งหมายถึงพื้นที่หรือโฟลเดอร์และกลุ่มของไฟล์ที่ใช้เก็บทุกเวอร์ชัน

หากคุณมีประสบการณ์การใช้ Git คุณน่าจะรู้ดีว่ามีหลายวิธีในการสร้าง Repository หากคุณต้องการสร้าง Git Repository ในโฟลเดอร์ใดก็ตาม เพียงป้อนคำสั่งต่อไปนี้ก็สร้างเสร็จสมบูรณ์แล้ว:

    git init

จากแผนภาพกระบวนการสร้าง Git Repository ต่อไปนี้ เราจะเห็นได้อย่างชัดเจนว่าเมื่อเราดำเนินการ git init ในไดเรกทอรี G:\git-demo แล้ว Git จะช่วยเราสร้างสิ่งที่เรียกว่า Git Repository ขึ้นโดยอัตโนมัติในไดเรกทอรี .git ของไดเรกทอรีนั้น ไม่ต้องสงสัยเลย โฟลเดอร์ .git นี้คือ Git Repository ที่สมบูรณ์ ในอนาคต การเปลี่ยนแปลงเวอร์ชันทั้งหมดจะถูกเก็บไว้ในโฟลเดอร์นี้โดยอัตโนมัติ

## ทำความเข้าใจ Working Directory

ในตัวอย่างข้างต้น ไดเรกทอรี G:\git-demo จะกลายเป็น "Working Directory" ของเราโดยอัตโนมัติ ความหมายของ "Working Directory" คือเรากำลังเตรียมพัฒนาไฟล์โปรเจกต์ และงานในอนาคตทั้งหมดจะถูกแก้ไขในไดเรกทอรีนี้ ไม่ว่าจะเป็นการเพิ่มไฟล์ แก้ไขไฟล์ ลบไฟล์ เปลี่ยนชื่อไฟล์ ... และการดำเนินการอื่น ๆ ที่เกี่ยวข้องกับ Git ทั้งหมดจะเสร็จสมบูรณ์ในไดเรกทอรีนี้ ดังนั้นมันจึงถูกเรียกว่า "Working Directory"

เมื่อเราดำเนินการพารามิเตอร์คำสั่งที่เกี่ยวข้องกับ Git เรามักจะดำเนินการใน "Working Directory"

เนื่องจากจะมีสถานการณ์ของ Branch มากมายเมื่อใช้การควบคุมเวอร์ชันด้วย Git Working Directory จึงอาจสลับไปมาระหว่าง Branch ต่าง ๆ คำสั่ง git บางคำสั่งจะอัปเดตไฟล์ใน Working Directory เมื่อถูกดำเนินการ ตัวอย่างเช่น เมื่อคุณใช้ git checkout เพื่อสลับไปยัง Branch อื่น เนื่องจากโครงสร้างไดเรกทอรีของ Branch ปัจจุบันไม่ค่อยเหมือนกับ Branch ที่คุณต้องการสลับไป จึงมีความเป็นไปได้สูงที่จะอัปเดตไฟล์ใน Working Directory ปัจจุบันของคุณ เพื่อให้ไดเรกทอรีและไฟล์ภายใต้ Working Directory ปัจจุบันเหมือนกับไดเรกทอรีและไฟล์ภายใต้ Branch อื่นที่จะสลับไป

ดังนั้น การรักษา Working Directory ให้สะอาดในเวลาที่เหมาะสมจึงเป็นหลักการพื้นฐานในกระบวนการควบคุมเวอร์ชัน โดยเฉพาะอย่างยิ่งเมื่อต้อง Merge ในอนาคต เรื่องนี้สำคัญเป็นพิเศษ ผมจะอธิบายความรู้ที่เกี่ยวข้องเพิ่มเติมในบทความต่อ ๆ ไป

## ทำความเข้าใจโครงสร้างข้อมูลของ Git

ใน Git มีโครงสร้างข้อมูลที่สำคัญอยู่สองอย่าง ได้แก่ "Object" และ "Index"

"Object" ใช้สำหรับบันทึกไฟล์และบันทึกเวอร์ชันทั้งหมดใน Repository ในขณะที่ "Index" ใช้สำหรับบันทึกสถานะของไดเรกทอรีก่อนเข้าสู่ Repository

## เกี่ยวกับ Object

สิ่งที่เรียกว่า "Object" คือ "ไฟล์พิเศษ" ชนิดหนึ่ง กระบวนการสร้างไฟล์นี้มีความน่าสนใจมาก มันนำเนื้อหาของไฟล์มาสร้างค่าแฮช SHA1 จากเนื้อหา จากนั้นตั้งชื่อไฟล์ตามค่าแฮช SHA1 นี้

ในกระบวนการใช้ Git ควบคุมเวอร์ชัน ไดเรกทอรีและไฟล์ทั้งหมดที่จะถูกควบคุม จะถูกแยกออกเป็น "ข้อมูลไดเรกทอรี" และ "เนื้อหาไฟล์" ก่อน ซึ่งเราเรียกว่า Tree Object และ Blob Object

ในจำนวนนั้น Blob Object ใช้ "เนื้อหาไฟล์" ดั้งเดิมเป็นเนื้อหาของไฟล์ Blob (หมายเหตุ: Blob Object จริง ๆ แล้วเป็นไฟล์ทางกายภาพ) จากนั้นทำการแฮช SHA1 กับเนื้อหาของมันเพื่อสร้าง Hash ID ขึ้นมา แล้วใช้ Hash ID นี้เป็นชื่อไฟล์ของไฟล์ Blob จากตรงนี้ เราจะทราบได้ว่า Blob Object คือไฟล์ที่มี "เพียงเนื้อหาเท่านั้น" ชื่อไฟล์ของมันถูกสร้างขึ้นจากเนื้อหา ดังนั้นไฟล์ Blob เพียงไฟล์เดียวมักจะไม่มีประโยชน์ต่อการควบคุมเวอร์ชัน

ส่วน Tree Object อีกชนิดหนึ่งใช้สำหรับเก็บว่าโฟลเดอร์หนึ่ง ๆ ประกอบด้วยไฟล์อะไรบ้าง และชื่อไฟล์ของ Blob Object ที่สอดคล้องกับไฟล์นี้คืออะไร ใน Tree Object นอกจากจะมีชื่อไฟล์และข้อมูลที่เกี่ยวข้องของ Blob Object แล้ว มันยังสามารถมี Tree Object อื่น ๆ อยู่ภายในได้อีกด้วย ดังนั้น Tree Object จริง ๆ แล้วจึงมีความหมายเดียวกันกับ "โฟลเดอร์"

ไม่ว่าจะเป็น Blob Object หรือ Tree Object ทั้งหมดนี้ล้วนเป็น Object และ Object เหล่านี้จะถูกเก็บไว้ในสิ่งที่เรียกว่า "Object Storage" และ "Object Storage" นี้โดยค่าเริ่มต้นจะอยู่ในไดเรกทอรี objects ของ "Repository" ดังแสดงในรูปต่อไปนี้:

![รูปภาพ](figures/05/02.png)

เราจะพูดถึงโครงสร้าง Object โดยละเอียดในบทความที่กำลังจะมาถึง

## เกี่ยวกับ Index

สิ่งที่เรียกว่า "Index" คือไฟล์ชั่วคราวที่เปลี่ยนแปลงบ่อยครั้ง ซึ่งมักจะอยู่ในไฟล์ชื่อ index ในไดเรกทอรี .git พูดง่าย ๆ วัตถุประสงค์ของ "Index" ส่วนใหญ่คือการบันทึกว่า "ไฟล์ใดบ้างที่กำลังจะถูกส่งไปยังเวอร์ชัน Commit ถัดไป" กล่าวอีกนัยหนึ่ง หากคุณต้องการส่งเวอร์ชันไปยัง Git Repository คุณจะต้องอัปเดตสถานะ Index ก่อน และการเปลี่ยนแปลงจึงจะถูกส่งไป

ไฟล์ Index นี้มักจะบันทึกสถานะของเวอร์ชันหนึ่ง ๆ ใน Git Repository สถานะนี้สามารถแสดงได้ด้วย Commit Object และ Tree Object ใด ๆ

โดยปกติเราไม่ได้แก้ไขไฟล์ไบนารี .git\index โดยตรง แต่ดำเนินการกับไฟล์ Index นี้ผ่านคำสั่ง git มาตรฐาน คำสั่งสำหรับดำเนินการกับไฟล์ Index มีคร่าว ๆ ดังนี้:

* git add
* git mv
* git rm
* git status
* git commit
* git ls-files

"Index" ของ Git เป็นสื่อกลางระหว่าง "Object Storage" กับ "Working Directory"

คุณอาจเดาได้แล้วว่า ความสัมพันธ์ระหว่างแนวคิดเหล่านี้ที่บทความนี้ต้องการอธิบาย สามารถอธิบายได้ด้วย 5 ขั้นตอนต่อไปนี้:

* ในการใช้การควบคุมเวอร์ชันด้วย Git คุณต้องสร้าง "Working Directory" และ "Repository" ก่อน (mkdir, git init)
* คุณต้องพัฒนางานใน "Working Directory" ก่อน คุณอาจสร้างไดเรกทอรี สร้างไฟล์ แก้ไขไฟล์ ลบไฟล์ ... และการดำเนินการอื่น ๆ
* จากนั้นเมื่อคุณต้องการส่งเวอร์ชันใหม่ไปยัง "Repository" ของ Git คุณต้องอัปเดตสถานะ "Index" ก่อน (git add, git mv, ...)
* จากนั้น Git จะตัดสินใจว่าจะส่งไฟล์ใดไปยัง "Repository" ของ Git โดยอิงจากสถานะปัจจุบันของ "Index" (git status)
* สุดท้าย เมื่อส่งการเปลี่ยนแปลง (git commit) ข้อมูลเวอร์ชันจะถูกเขียนลงใน "Object Storage" (ในเวลานี้ Commit Object จะถูกเขียนลงไป)

เราจะพูดถึงโครงสร้าง Index โดยละเอียดและการดำเนินการคำสั่งในบทความที่กำลังจะมาถึง

    หมายเหตุ: เนื่องจากแนวคิดของ Tree คล้ายกับ Directory มาก เมื่ออ่านต้นฉบับภาษาต่างประเทศ Working Directory จึงมักถูกเขียนว่า Working Tree!

## สรุปของวันนี้

สิ่งที่สำคัญที่สุดเกี่ยวกับสถาปัตยกรรม Git ที่กล่าวถึงในวันนี้คือความสัมพันธ์ระหว่าง "Object" และ "Index" เพราะหากไม่มีข้อมูล "Index" แล้ว Git จะไม่สามารถสร้างเวอร์ชันได้

จากความแตกต่างระหว่าง "Object" และ "Index" คุณน่าจะพบว่า "Object" เป็นไฟล์ประเภท "เปลี่ยนแปลงไม่ได้ (Immutable)" โดยหลักการแล้ว Object ใด ๆ ที่เขียนลงใน "Object Storage" จะไม่เปลี่ยนแปลงอีก เนื่องจาก Object ทั้งหมดถูกสร้างขึ้นจากเนื้อหาไฟล์ต้นฉบับ เรายังสามารถกล่าวได้ว่านี่คือ "ฐานข้อมูล Object" (Object Database) และฐานข้อมูลนี้มักจะมีแต่เนื้อหาที่เพิ่มขึ้น และมีกรณี "ลบเนื้อหา" หรือ "เปลี่ยนเนื้อหา" น้อยกว่า ข้อมูลจะถูกลบก็ต่อเมื่อดำเนินการ git gc เพื่อล้างข้อมูลขยะเท่านั้น ส่วน "Index" เป็นไฟล์ Index แบบ "เปลี่ยนแปลงได้ (Mutable)" ที่ใช้บันทึกเนื้อหาที่ Working Directory ปัจจุบันพร้อมจะ Commit

เมื่อคุณค่อย ๆ เข้าใกล้แก่นของ Git ทีละขั้นตอน ค่อย ๆ เปลี่ยนแนวคิดนามธรรมที่คลุมเครือและไม่ชัดเจนให้กลายเป็นความรู้เชิงแนวคิดที่เป็นรูปธรรม คุณจะไม่รู้สึกไม่สบายใจกับ Git อีกต่อไป โปรดพยายามเรียนรู้ต่อไปเรื่อย ๆ ความสำเร็จอยู่ข้างหน้าแล้ว
