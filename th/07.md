# วันที่ 07: วิเคราะห์โครงสร้างข้อมูลของ Git - โครงสร้าง Index

เรารู้ว่าใน Git มีโครงสร้างข้อมูลที่สำคัญอยู่สองอย่าง ได้แก่ "Object" และ "Index" บทความนี้ใช้เพื่ออธิบายรายละเอียดของ "Index" เป็นหลัก ในระหว่างกระบวนการใช้การควบคุมเวอร์ชันด้วย Git คุณอาจเข้าใจวิธีใช้คำสั่ง git ได้ง่าย แต่ก็ง่ายที่จะตกอยู่ในวังวนของการท่องจำและไม่สามารถใช้ได้อย่างยืดหยุ่น แม้แต่ Linus Torvalds ก็ยังกล่าวไว้ใน Mailing List ว่า: "ก่อนที่ผู้ใช้จะเข้าใจความหมายของ Index พวกเขาจะไม่สามารถเข้าใจความสามารถของ Git ได้อย่างเต็มที่" ดังนั้น การทำความเข้าใจวัตถุประสงค์ของ "Index" จึงมีความสำคัญมาก

## เกี่ยวกับ Index

พูดง่าย ๆ วัตถุประสงค์ของ "Index" ส่วนใหญ่คือการบันทึกว่า "ไฟล์ใดบ้างที่กำลังจะถูกส่งไปยังเวอร์ชัน Commit ถัดไป"

กล่าวอีกนัยหนึ่ง "หากคุณต้องการส่งเวอร์ชันไปยัง Git Repository คุณจะต้องอัปเดตสถานะ Index ก่อน และการเปลี่ยนแปลงจึงจะถูกส่งไป"

"Index" นี้จริง ๆ แล้วมีชื่อเรียกอื่น ๆ มากมายในบทความต่างประเทศหลายชิ้น แต่ทั้งหมดมีความหมายเดียวกัน อย่าสับสนเมื่อคุณเห็นคำที่เกี่ยวข้องในอนาคต

* Index
* Cache
* Directory cache
* Current directory cache
* Staging area
* Staged files

ตัวอย่างเช่น คำสั่ง `git diff --cached` มีความหมายเหมือนกับ `git diff --staged` ทุกประการ

## คำสั่งสำหรับดำเนินการกับ Index

เนื่องจาก "Index" มีความสำคัญต่อ Git มาก คำสั่งส่วนใหญ่จึงมีพารามิเตอร์ที่เกี่ยวข้องกับ Git Index อย่างไรก็ตาม เราจะหยิบยกคำสั่งบางคำสั่งที่เกี่ยวข้องกับ "Index" โดยตรงมาอธิบายคร่าว ๆ

ก่อนที่จะอธิบายคำสั่ง คุณสามารถดูแผนภาพต่อไปนี้ก่อน ซึ่งแสดงวงจรชีวิตของการเปลี่ยนสถานะผ่านคำสั่ง อันที่จริง กระบวนการเปลี่ยนแปลงเหล่านี้ล้วนเป็นกระบวนการอัปเดต "ไฟล์ Index" ทั้งสิ้น:

![รูปภาพ](figures/07/01.png)

ก่อนอื่น ขอแนะนำสถานะของไฟล์สี่สถานะ:

* untracked (ยังไม่ถูกติดตาม หมายถึงสถานะของไฟล์ที่ยังไม่ได้ถูกเพิ่มเข้าไปใน Git Repository)
* unmodified (ยังไม่ถูกแก้ไข หมายถึงสถานะเมื่อไฟล์ถูกเพิ่มเข้ามาเป็นครั้งแรก หรือเนื้อหาไฟล์สอดคล้องกับเนื้อหา HEAD)
* modified (ถูกแก้ไขแล้ว หมายถึงไฟล์ได้รับการแก้ไข หรือเนื้อหาไฟล์ไม่สอดคล้องกับเนื้อหา HEAD)
* staged (รอการ Commit หมายถึงไฟล์เหล่านี้ทั้งหมดจะถูกส่งไปยัง Repository ในครั้งถัดไปที่ดำเนินการ git commit)

### git status

รับสถานะของ **working tree**

เนื่องจากเราได้พูดถึงความสัมพันธ์ระหว่าง Repository, Working Directory, Object และ Index ไปแล้ว เราจึงสามารถอธิบายความสัมพันธ์นี้ได้ในประโยคเดียว:

```txt
Git repository operation is to write data into Git objects by updating the index with changes in the working directory.
```

วัตถุประสงค์ของคำสั่ง `git status` ในที่นี้คือการแสดงความแตกต่างระหว่าง **เวอร์ชันล่าสุด** กับ **ไฟล์ Index** ความแตกต่างในที่นี้รวมถึงความสัมพันธ์ที่ละเอียดอ่อนบางอย่าง เรามาใช้ตัวอย่างเพื่ออธิบายความสัมพันธ์นี้กัน

ต่อไปนี้คือผลลัพธ์ของการดำเนินการ git status:

```sh
G:\git-demo>git status
# On branch master
# Changes to be committed:
#   (use "git reset HEAD <file>..." to unstage)
#
#       new file:   c.txt
#
# Changes not staged for commit:
#   (use "git add <file>..." to update what will be committed)
#   (use "git checkout -- <file>..." to discard changes in working directory)
#
#       modified:   a.txt
#
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#
#       b.txt
```

ตรงนี้คุณจะเห็นกลุ่มที่แตกต่างกันสามกลุ่ม ได้แก่:

* Changes to be committed (การเปลี่ยนแปลงที่พร้อมจะถูกส่ง)
  * มีไฟล์ `new file: c.txt` อยู่ในพื้นที่นี้ ซึ่งหมายความว่า c.txt เป็นไฟล์ใหม่และถูกทำเครื่องหมายว่าพร้อมที่จะ Commit แล้ว
  * สิ่งนี้แสดงถึงหลายสิ่ง:
    1. ไฟล์ c.txt ปัจจุบันมีอยู่ใน **Working Directory**
    2. ไฟล์ c.txt ถูกเพิ่มเข้าไปใน **Index** แล้ว
    3. เนื้อหาของ c.txt ใน **Index** สอดคล้องกับเนื้อหาใน **Working Directory**
    4. เมื่อดำเนินการ git commit เนื้อหาใน **Index** จะถูก Commit (ไม่ใช่เนื้อหาใน Working Directory)

* Changes not staged for commit (การเปลี่ยนแปลงที่ถูกแก้ไขแล้วแต่ยังไม่ได้ Stage เพื่อ Commit)
  * มีไฟล์ `modified: a.txt` อยู่ในพื้นที่นี้ ซึ่งหมายความว่า a.txt เป็นไฟล์ที่ถูกแก้ไขแต่ยังไม่ได้ถูกทำเครื่องหมายว่าพร้อมที่จะ Commit
  * สิ่งนี้แสดงถึงหลายสิ่ง:
    1. ไฟล์ a.txt ปัจจุบันมีอยู่ใน **Working Directory**
    2. ไฟล์ a.txt ถูกเพิ่มเข้าไปใน **Index** แล้ว
    3. เนื้อหาของ a.txt ใน **Index** ไม่สอดคล้องกับเนื้อหาใน **Working Directory**
    4. เมื่อดำเนินการ git commit เฉพาะเนื้อหาใน **Index** เท่านั้นที่จะถูก Commit (ไม่ใช่เนื้อหาใน Working Directory)

* Untracked files (ไฟล์ที่ยังไม่ถูกติดตาม)
  * มีไฟล์ `b.txt` อยู่ในพื้นที่นี้ ซึ่งหมายความว่า b.txt เป็นไฟล์ใหม่และยังไม่ได้ถูกเพิ่มเข้าไปใน Index
  * สิ่งนี้แสดงถึงหลายสิ่ง:
    1. ไฟล์ b.txt ปัจจุบันมีอยู่ใน **Working Directory**
    2. ไฟล์ b.txt ยังไม่ได้ถูกเพิ่มเข้าไปใน **Index**
    3. เมื่อดำเนินการ git commit ไฟล์นี้จะไม่ถูก Commit

### git add

เพิ่มเนื้อหาไฟล์เข้าไปใน Index (Stage ไฟล์สำหรับ Commit ถัดไป)

คำสั่ง `git add` มีการใช้งานมากมาย พูดง่าย ๆ การดำเนินการคำสั่งนี้จะ "อัปเดต Index" แต่วิธีการอัปเดต Index อาจแตกต่างกันไปขึ้นอยู่กับสถานะปัจจุบันของไฟล์:

* หากไฟล์อยู่ในสถานะ **untracked** การดำเนินการ `git add` จะเพิ่มเนื้อหาไฟล์เข้าไปใน Index
* หากไฟล์อยู่ในสถานะ **modified** การดำเนินการ `git add` จะอัปเดตเนื้อหาไฟล์เข้าไปใน Index
* หากไฟล์อยู่ในสถานะ **staged** การดำเนินการ `git add` จะอัปเดตเนื้อหาไฟล์เข้าไปใน Index อีกครั้ง

### git rm

ลบไฟล์ออกจาก Working Tree และออกจาก Index

คำสั่งนี้จะลบไฟล์ออกจากทั้ง **Working Directory** และ **Index** หลังจากลบแล้ว คุณต้องดำเนินการ git commit เพื่อให้การลบนี้เสร็จสมบูรณ์

### git mv

ย้ายหรือเปลี่ยนชื่อไฟล์ ไดเรกทอรี หรือ Symlink

คำสั่งนี้จะย้ายหรือเปลี่ยนชื่อไฟล์ในทั้ง **Working Directory** และ **Index** หลังจากย้ายหรือเปลี่ยนชื่อแล้ว คุณต้องดำเนินการ git commit เพื่อให้การดำเนินการนี้เสร็จสมบูรณ์

### git commit

บันทึกการเปลี่ยนแปลงลงใน Repository

คำสั่งนี้จะเขียนเนื้อหา **Index** ปัจจุบันลงใน **ฐานข้อมูล Object** และสร้าง Commit Object ขึ้นมา

### git ls-files

แสดงข้อมูลเกี่ยวกับไฟล์ใน Index และ Working Tree

คำสั่งนี้สามารถแสดงรายการไฟล์และสถานะใน Index ได้ นี่เป็นคำสั่งที่มีประโยชน์มาก ซึ่งช่วยให้คุณเข้าใจสถานะปัจจุบันของ Index ได้

พารามิเตอร์ที่ใช้บ่อยบางตัว:

* `git ls-files -s` หรือ `git ls-files --stage` : แสดงรายการไฟล์และข้อมูลโดยละเอียดใน Index
* `git ls-files -c` หรือ `git ls-files --cached` : แสดงรายการไฟล์ใน Cache
* `git ls-files -d` หรือ `git ls-files --deleted` : แสดงรายการไฟล์ที่ถูกลบ
* `git ls-files -m` หรือ `git ls-files --modified` : แสดงรายการไฟล์ที่ถูกแก้ไข
* `git ls-files -o` หรือ `git ls-files --others` : แสดงรายการไฟล์ที่ยังไม่ถูกติดตาม

## สรุปของวันนี้

"Index" ใน Git เป็นแนวคิดที่สำคัญมาก ผ่าน Index ทำให้ Git สามารถรู้ได้ว่าไฟล์ใดบ้างที่กำลังจะถูกส่งไปยังเวอร์ชัน Commit ถัดไป ผ่านคำสั่งต่าง ๆ เราสามารถอัปเดตสถานะ Index และควบคุมได้ว่าไฟล์ใดจะถูกส่งไป การทำความเข้าใจ Index สามารถช่วยให้คุณเชี่ยวชาญการควบคุมเวอร์ชันด้วย Git ได้ดียิ่งขึ้น
