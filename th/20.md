# วันที่ 20: แก้ไขประวัติเวอร์ชันที่ Commit แล้ว ตอนที่ 2 (revert)

ในกระบวนการควบคุมเวอร์ชัน มีอีกสถานการณ์หนึ่งที่พบบ่อย: หลังจากดำเนินการ Commit ไปหลายครั้ง คุณค้นพบว่า Commit ก่อนหน้าบางรายการผิดพลาด ตัวอย่างเช่น คุณ Commit โค้ดทดสอบเข้าไปโดยไม่ได้ตั้งใจ ทำให้เกิดปัญหาในเวอร์ชันปัจจุบัน ในกรณีนี้ คุณจำเป็นต้องเข้าใจเนื้อหาที่อธิบายไว้ในบทความนี้

ในวันที่ 18 เราได้เรียนรู้เกี่ยวกับ `git reset` และ `git commit --amend` สำหรับการแก้ไขประวัติ Commit ในเครื่อง อย่างไรก็ตาม คำสั่งเหล่านี้เขียนประวัติใหม่ และไม่ควรใช้กับ Commit ที่ถูก Push ไปยัง Repository ที่แชร์กันแล้ว สำหรับประวัติที่แชร์กัน `git revert` คือทางเลือกที่ปลอดภัย

## ทำความเข้าใจ git revert

`git revert` สร้าง Commit ใหม่ที่ยกเลิกการเปลี่ยนแปลงจาก Commit ก่อนหน้า แตกต่างจาก `reset` ตรงที่มันไม่เขียนประวัติใหม่ แต่มันเพิ่มเข้าไปในประวัติ สิ่งนี้ทำให้มันปลอดภัยสำหรับ Branch ที่แชร์กัน

สมมติว่า ณ จุดนี้คุณค้นพบว่า Commit ก่อนหน้า (เช่น `HEAD~` หรือ `HEAD^` หรือ Hash ของ Commit ที่ระบุ) ทำผิดพลาดไป คุณต้องการ Revert **เวอร์ชันที่ระบุนั้น** เท่านั้น แทนที่จะ Reset กลับไปยังเวอร์ชันแรกแล้วทำทุกอย่างใหม่ ในกรณีนี้ คุณสามารถลองใช้คำสั่ง `git revert` ซึ่งสามารถยกเลิกการเปลี่ยนแปลงของเวอร์ชันหนึ่ง ๆ ผ่านขั้นตอนแบบ "ย้อนกลับ (Reverse)" ได้

"ย้อนกลับ" หมายความว่าอย่างไร? มาลองใช้คำสั่งนี้กันเลย

**ข้อสำคัญ**: ก่อนดำเนินการคำสั่ง `git revert` โปรดแน่ใจว่า Working Directory ของคุณสะอาด! หากคุณมีไฟล์ที่ถูกแก้ไขไปบางส่วน ขอแนะนำให้ใช้ `git stash` เพื่อสร้าง Stash ชั่วคราว

## Revert พื้นฐาน

ในการ Revert Commit ล่าสุด:

```
git revert HEAD
```

คำสั่งนี้จะสร้าง Commit ใหม่ที่ยกเลิกการเปลี่ยนแปลงใน Commit ล่าสุด

## การ Revert Commit ที่ระบุ

สมมติว่าจากประวัติ `git log` คุณพบเวอร์ชันที่มีปัญหา คุณสามารถตรวจสอบบันทึกการเปลี่ยนแปลงของเวอร์ชันนี้ก่อนได้ คุณสามารถใช้ `git log` เพื่อค้นหา Commit ID จากนั้นใช้ `git show [commit_id]` เพื่อดูข้อมูลที่เกี่ยวข้องของเวอร์ชันนั้น

ในการ Revert Commit ที่ระบุ:

```
git revert <commit-hash>
```

ตัวอย่างเช่น:

```
git revert a1b2c3d
```

ในระหว่างการดำเนินการ คุณจะถูกขอให้แก้ไขข้อความ Commit สุดท้าย โดยค่าเริ่มต้น มันจะเพิ่มคำว่า `Revert` และยังเพิ่ม `This reverts commit xxxx` ในบรรทัดที่สาม เพื่อบอกคุณว่าวัตถุประสงค์หลักของเวอร์ชันนี้คือการ Revert จากเวอร์ชัน `xxxx`

## การ Revert หลาย Commit

ในการ Revert ช่วงของ Commit:

```
# Revert commits from HEAD~3 to HEAD~1 (3 commits)
git revert HEAD~3..HEAD
```

หรือ Revert Commit ที่ระบุหลายรายการ:

```
git revert <hash1> <hash2> <hash3>
```

## Revert โดยไม่ Commit

ในการ Stage การเปลี่ยนแปลงจากการ Revert โดยไม่ Commit โดยอัตโนมัติ:

```
git revert --no-commit HEAD
# or
git revert -n HEAD
```

สิ่งนี้มีประโยชน์เมื่อคุณต้องการ Revert หลาย Commit และสร้าง Revert Commit เพียงรายการเดียว:

```
git revert --no-commit HEAD~3..HEAD
git commit -m "Revert last 3 commits"
```

## การจัดการ Conflict

บางครั้งการ Revert Commit อาจทำให้เกิด Conflict:

```
git revert <commit-hash>
# If conflicts occur...
# 1. Resolve conflicts in the files
# 2. Stage the resolved files
git add <resolved-files>
# 3. Continue the revert
git revert --continue
```

ในการยกเลิกการ Revert ที่กำลังดำเนินการอยู่:

```
git revert --abort
```

## การ Revert Merge Commit

การ Revert การ Merge นั้นซับซ้อนกว่า เพราะ Merge Commit มี Parent สองตัว คุณต้องระบุว่าจะ Revert กลับไปยัง Parent ตัวใด:

```
# -m 1 means keep changes from the first parent (usually mainline)
git revert -m 1 <merge-commit-hash>
```

## เมื่อใดควรใช้ Revert กับ Reset

**ใช้ `git revert` เมื่อ:**
* Commit ถูก Push ไปยัง Repository ที่แชร์กันแล้ว
* คุณต้องการเก็บรักษาประวัติไว้
* กำลังทำงานบน Branch สาธารณะ (main, develop เป็นต้น)
* คุณต้องการบันทึกของการดำเนินการยกเลิก

**ใช้ `git reset` เมื่อ:**
* Commit อยู่ใน Local Repository ของคุณเท่านั้น
* คุณต้องการลบ Commit ออกจากประวัติอย่างสมบูรณ์
* กำลังทำงานบน Feature Branch ส่วนตัว
* Commit นั้นเป็นข้อผิดพลาดที่ไม่ควรอยู่ในประวัติ

## การ Revert และการนำการเปลี่ยนแปลงกลับมาใช้ใหม่

บางครั้งคุณ Revert Commit ไป แต่ภายหลังต้องการนำมันกลับมาใช้ใหม่:

```
# First, revert a commit
git revert <commit-hash>

# Later, revert the revert
git revert <revert-commit-hash>
```

## ตัวอย่างการใช้งานจริง

### ตัวอย่างที่ 1: Revert Commit ที่ไม่ดีบน Main Branch

```
# Commit a1b2c3d introduced a bug
git revert a1b2c3d
git push origin main
```

### ตัวอย่างที่ 2: Revert หลาย Commit

```
# Revert the last 5 commits as a single revert commit
git revert --no-commit HEAD~5..HEAD
git commit -m "Revert last 5 commits due to critical bug"
git push origin main
```

### ตัวอย่างที่ 3: Revert แล้วทำการแก้ไข

```
# Revert a problematic commit
git revert a1b2c3d

# Make necessary corrections
# ... edit files ...

# Commit the corrections
git add .
git commit -m "Fix issues from reverted commit"
git push origin main
```

## แนวปฏิบัติที่ดีที่สุด

1. **เขียนข้อความให้ชัดเจน**: อธิบายว่าทำไมคุณจึง Revert
   ```
   git revert a1b2c3d -m "Revert feature X due to performance issues"
   ```

2. **ทดสอบก่อน Push**: ให้แน่ใจว่าการ Revert ไม่ทำให้อะไรเสียหาย

3. **สื่อสาร**: แจ้งให้ทีมของคุณทราบเมื่อคุณ Revert Commit

4. **พิจารณาทางเลือกอื่น**: บางครั้งการแก้ไขไปข้างหน้าก็ดีกว่าการ Revert

5. **บันทึกเหตุผล**: อ้างอิงหมายเลข Issue หรือให้บริบทประกอบ

## การดูประวัติการ Revert

ในการดู Revert Commit ในประวัติของคุณ:

```
git log --oneline --grep="Revert"
```

## สรุปของวันนี้

`git revert` เป็นวิธีที่ปลอดภัยในการยกเลิกการเปลี่ยนแปลงใน Repository ที่แชร์กัน มันรักษาความสมบูรณ์ของประวัติไว้ในขณะที่ยกเลิกการเปลี่ยนแปลงที่ไม่ต้องการ การทำความเข้าใจว่าเมื่อใดควรใช้ `revert` กับ `reset` เป็นสิ่งสำคัญสำหรับการทำงานร่วมกันอย่างมีประสิทธิภาพ และการรักษาประวัติโปรเจกต์ที่สะอาดและเข้าใจได้

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git revert
* git revert HEAD
* git revert <commit-hash>
* git revert --no-commit
* git revert -n
* git revert -m
* git revert --continue
* git revert --abort
