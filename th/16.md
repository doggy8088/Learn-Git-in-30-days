# วันที่ 16: ใช้ git reflog ติดตามประวัติการเปลี่ยนแปลง

การเรียนรู้คำสั่งควบคุมเวอร์ชันของ Git นั้นไม่ยาก แต่การทำความเข้าใจว่า Git ทำอะไรกับ Repository ของคุณจริง ๆ นั้นค่อนข้างท้าทายทีเดียว เมื่อคุณค่อย ๆ เข้าใจแนวคิดหลักและหลักการทำงานของ Git คุณจะสามารถควบคุมการเปลี่ยนแปลงเวอร์ชันใน Git Repository ของคุณได้อย่างมีประสิทธิภาพ บทความนี้จะอธิบายว่า Git บันทึกประวัติการเปลี่ยนแปลงของทุกเวอร์ชันอย่างไร

## ทำความเข้าใจ git reflog

`git reflog` (Reference Log) เป็นกลไกที่บันทึกว่าเมื่อใดที่ปลายของ Branch และการอ้างอิงอื่น ๆ ได้รับการอัปเดตใน Local Repository ก่อนที่คุณจะเข้าใจหลักการพื้นฐานและโครงสร้าง Object ของ Git อย่างถ่องแท้ คุณจะไม่สามารถเข้าใจกระบวนการบันทึกเวอร์ชันได้อย่างแท้จริง เมื่อคุณไม่เข้าใจกระบวนการบันทึกเวอร์ชัน คุณก็ย่อมกังวลโดยธรรมชาติว่า "เวอร์ชันของผมหายไปไหน?" คุณอาจเคยได้ยินใครบางคนพูดว่า "เราใช้การควบคุมเวอร์ชัน ดังนั้นทุกเวอร์ชันจะถูกเก็บรักษาไว้ แก้ไขโค้ดได้ตามสบายเลย" การรู้เรื่องนี้เป็นเรื่องหนึ่ง การรู้วิธีทำเป็นอีกเรื่องหนึ่ง และคุณจะทำได้จริงหรือไม่ก็เป็นอีกเรื่องหนึ่ง

โชคดีที่ Git มีกลไกการบันทึก Log ที่เข้มงวด และกลไกนี้เปิดกว้างมาก ไฟล์ Log ทั้งหมดอยู่ในรูปแบบข้อความและเข้าใจได้ค่อนข้างง่าย มาอธิบายกระบวนการบันทึกเวอร์ชันนี้กัน

Reflog มีประโยชน์อย่างยิ่งสำหรับ:

* การค้นหา Commit ที่ไม่สามารถเข้าถึงได้จาก Branch ใด ๆ อีกต่อไป
* การกู้คืนจาก Reset หรือ Rebase ที่ผิดพลาด
* การทำความเข้าใจว่าคุณทำอะไรไปบ้างใน Repository ของคุณ
* การยกเลิกการเปลี่ยนแปลงที่เกิดขึ้นโดยไม่ได้ตั้งใจ

## ไดเรกทอรี logs

หากคุณเข้าไปในโฟลเดอร์ `.git/` ของ Working Directory ของ Git ใด ๆ คุณจะเห็นไดเรกทอรี `logs` โฟลเดอร์ `logs` นี้มีไฟล์ `HEAD` ที่บันทึกประวัติการเปลี่ยนแปลงเวอร์ชันของ "Branch ปัจจุบัน"

เนื้อหาของไฟล์มีลักษณะดังนี้ (Object ID ถูกย่อไว้เพื่อความสะดวกในการอ่าน):

```
0000000 f5685e0 Will <xxxx@gmail.com> 1381718394 +0800	commit (initial): Initial commit
f5685e0 38d924f Will <xxxx@gmail.com> 1381718395 +0800	commit: a.txt: set 1 as content
38d924f efa1e0c Will <xxxx@gmail.com> 1381734238 +0800	commit: test
efa1e0c af493e5 Will <xxxx@gmail.com> 1381837967 +0800	commit: Add c.txt
```

## การใช้งานพื้นฐาน

ในการดู Reflog:

```
git reflog
```

คำสั่งนี้จะแสดงรายการการดำเนินการล่าสุดในลำดับย้อนเวลาจากล่าสุดไปเก่าสุด จากไฟล์ข้อความ คุณจะเห็น "เวอร์ชันแรก" อยู่ด้านบน แต่ผ่าน `git reflog` "เวอร์ชันล่าสุด" จะแสดงเป็นอันดับแรก และ "เวอร์ชันแรก" จะแสดงเป็นอันดับสุดท้าย

แต่ละรายการจะแสดง:
* Hash ของ Commit
* การอ้างอิง (โดยปกติคือ HEAD)
* การดำเนินการที่ทำไป
* ข้อความ Commit

## รูปแบบของ Reflog

ผลลัพธ์มีลักษณะดังนี้:

```
a1b2c3d HEAD@{0}: commit: Add new feature
e4f5g6h HEAD@{1}: checkout: moving from master to feature-branch
i7j8k9l HEAD@{2}: reset: moving to HEAD~1
```

สัญกรณ์ `HEAD@{n}` หมายถึงค่าก่อนหน้าลำดับที่ n ของ HEAD ตรงนี้ แต่ละเวอร์ชันใน Log ประวัติจะมีหมายเลขที่แทนตำแหน่งของเวอร์ชันนี้ในไฟล์ Log `HEAD@{0}` แทน "เวอร์ชันล่าสุด" ของ Branch ปัจจุบันเสมอ กล่าวอีกนัยหนึ่ง คือการดำเนินการ Git ล่าสุดที่คุณทำบน "Branch" นี้ การเปลี่ยนแปลงเวอร์ชันใด ๆ ที่คุณทำกับ Git จะถูกบันทึกไว้อย่างสมบูรณ์

## การกู้คืนจากการเปลี่ยนแปลงโดยไม่ได้ตั้งใจ

เมื่อผู้เริ่มต้นใช้ Git เป็นครั้งแรก พวกเขาอาจดำเนินการคำสั่งที่ไม่ถูกต้องโดยไม่ได้ตั้งใจ เช่น เกิด Conflict ระหว่าง `git merge` หรือเกิดข้อผิดพลาดเมื่อดำเนินการ `git pull` เพื่อรับเวอร์ชันล่าสุดจาก Remote Repository ในสถานการณ์เช่นนี้ คุณสามารถใช้ "ชื่ออ้างอิง" พิเศษ `HEAD@{n}` เพื่อ "ระบุตำแหน่ง" เวอร์ชันนี้ และกู้คืนเวอร์ชัน Git Repository ปัจจุบันกลับไปยังเวอร์ชันก่อนหน้าได้

ตัวอย่างเช่น หากเราต้องการ "ยกเลิก" บันทึกเวอร์ชันล่าสุด เราสามารถใช้ `git reset HEAD@{1} --hard` เพื่อกู้คืนการเปลี่ยนแปลงได้ ซึ่งหมายความว่าการเปลี่ยนแปลงที่เดิมอยู่ที่ `HEAD@{0}` จะถูกลบออก อย่างไรก็ตาม ใน Git การเปลี่ยนแปลงทั้งหมดจะถูกบันทึกไว้ รวมถึงการดำเนินการ `git reset "HEAD@{1}" --hard` ของคุณด้วย

สิ่งนี้หมายความว่าอย่างไร? มันหมายความว่าเมื่อดำเนินการคำสั่ง Git ใด ๆ คุณไม่จำเป็นต้องกังวลอีกต่อไปว่าข้อมูลใด ๆ ของคุณจะสูญหาย ไม่ว่าคำสั่งที่คุณป้อนจะผิดพลาดเพียงใด ไฟล์ทั้งหมดที่อยู่ใน Repository แล้วจะถูกเก็บรักษาไว้ โดยไม่มีโอกาสสูญหายเลย ดังนั้น หากคุณต้องการยกเลิกการดำเนินการ `git reset "HEAD@{1}" --hard` ที่คุณเพิ่งดำเนินการไป ก็เพียงดำเนินการ `git reset "HEAD@{1}" --hard` อีกครั้ง ยอดเยี่ยมไปเลยใช่ไหม!

## การดู Reflog โดยละเอียด

สำหรับข้อมูลที่ละเอียดยิ่งขึ้น:

```
git reflog show --all
```

ในการดู Reflog สำหรับ Branch ที่ระบุ:

```
git reflog show branch-name
```

## การใช้ Reflog เพื่อกู้คืน Commit

หากคุณ Reset หรือทำ Commit หายโดยไม่ได้ตั้งใจ คุณสามารถกู้คืนพวกมันได้โดยใช้ Reflog:

```
# Find the commit you want to recover
git reflog

# Reset to that commit
git reset --hard HEAD@{2}
```

หรือใช้ Hash ของ Commit โดยตรง:

```
git reset --hard a1b2c3d
```

## การกู้คืน Branch ที่ถูกลบ

หากคุณลบ Branch ไปโดยไม่ได้ตั้งใจ:

```
# Find the commit where the branch was deleted
git reflog

# Recreate the branch
git branch branch-name HEAD@{3}
# or
git branch branch-name <commit-hash>
```

## การหมดอายุของ Reflog

โดยค่าเริ่มต้น รายการ Reflog จะหมดอายุหลังจาก 90 วันสำหรับ Commit ที่เข้าถึงได้ และ 30 วันสำหรับ Commit ที่เข้าถึงไม่ได้ คุณสามารถกำหนดค่านี้ได้:

```
git config gc.reflogExpire "90 days"
git config gc.reflogExpireUnreachable "30 days"
```

## การล้าง Reflog

ในการล้างรายการ Reflog ด้วยตนเอง:

```
# Remove old reflog entries
git reflog expire --expire=now --all

# Run garbage collection
git gc --prune=now
```

## ข้อจำกัดของ Reflog

ประเด็นสำคัญที่ต้องจำ:

* Reflog เป็นแบบโลคัลเท่านั้น ไม่ได้ถูกแชร์กับผู้อื่น
* Reflog ติดตามการเปลี่ยนแปลงของ Repository ของคุณ ไม่ใช่ไฟล์
* มันสามารถช่วยคุณกู้คืน Commit ได้ แต่ไม่สามารถกู้คืนการเปลี่ยนแปลงที่ยังไม่ได้ Commit ได้

## ตัวอย่างการใช้งานจริง

### ตัวอย่างที่ 1: การยกเลิก Hard Reset

```
# You accidentally reset
git reset --hard HEAD~3

# Find the old position
git reflog

# Restore to the old position
git reset --hard HEAD@{1}
```

### ตัวอย่างที่ 2: การกู้คืนหลังจาก Rebase ที่ผิดพลาด

```
# After a problematic rebase
git reflog

# Find the commit before the rebase (usually labeled "rebase finished")
git reset --hard HEAD@{5}
```

## สรุปของวันนี้

`git reflog` เป็นคุณสมบัติด้านความปลอดภัยที่ทรงพลัง ซึ่งสามารถช่วยคุณจากความผิดพลาดของ Git ได้มากมาย มันมีคุณค่าอย่างยิ่งเมื่อคุณต้องการกู้คืนจากการดำเนินการต่าง ๆ เช่น Reset, Rebase หรือการลบ Branch แม้มันจะไม่ใช่สิ่งทดแทนการสำรองข้อมูลเป็นประจำ แต่ก็เป็นเครื่องมืออันล้ำค่าสำหรับการกู้คืนในเครื่อง

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git reflog
* git reflog show
* git reflog show --all
* git reset --hard HEAD@{n}
* git branch branch-name HEAD@{n}
* git reflog expire
* git gc
