# วันที่ 13: การเก็บพักการเปลี่ยนแปลงใน Working Directory และ Index (Stash)

คุณเคยเจอสถานการณ์แบบนี้ไหม: คุณกำลังพัฒนาระบบไปได้ครึ่งทาง จู่ ๆ เจ้านายหรือลูกค้าก็มี "คำสั่งด่วน" ให้คุณแก้ Bug ในระบบที่มีอยู่อย่างเร่งด่วนหรือเพิ่มฟีเจอร์บางอย่าง? โปรแกรมตรงหน้าคุณใกล้จะเสร็จสมบูรณ์แล้ว และ "เรื่องด่วน" ของเจ้านายก็เลื่อนออกไปไม่ได้ สถานะการพัฒนาซอฟต์แวร์ที่ยังไม่เสร็จสมบูรณ์บวกกับความต้องการปรับเปลี่ยนอย่างเร่งด่วน นับเป็นบททดสอบคุณภาพซอฟต์แวร์ครั้งใหญ่เลยทีเดียว หากคุณมีปัญหานี้ Git สามารถช่วยคุณทำภารกิจให้สำเร็จได้อย่างสวยงาม

## ทำความเข้าใจคำสั่ง git stash

เราทราบว่าเมื่อใช้การควบคุมเวอร์ชันด้วย Git จะมีความแตกต่างระหว่าง "Working Directory" และ "Index" ใน Working Directory จะมีไฟล์ที่คุณเปลี่ยนแปลงไปได้ครึ่งทางและยังไม่เสร็จ (ยังไม่ได้เพิ่มเข้าไปใน Index) และยังมีไฟล์ใหม่ที่ยังไม่ได้เพิ่ม (ยังไม่ได้เพิ่มเข้าไปใน Index) ด้วย ข้อมูลที่วางไว้ใน Index คือเนื้อหาที่คุณวางแผนจะสร้างเวอร์ชัน (สร้าง Commit Object) ผ่าน `git commit`

เมื่อคุณกำลังพัฒนาฟีเจอร์ไปได้ครึ่งทางแล้วถูกขัดจังหวะอย่างเร่งด่วน คุณจะต้องรีบร้อนอย่างแน่นอน โดยเฉพาะอย่างยิ่งไม่รู้ว่าจะทำอย่างไรกับโปรแกรมที่เขียนแก้ไปได้ครึ่งทางเหล่านั้นในมือ ใน Git มีคำสั่ง `git stash` ที่สามารถช่วยคุณสร้าง "เวอร์ชันพิเศษ" (ซึ่งก็เป็น Commit Object เช่นกัน) ให้กับไฟล์ที่เขียนไปได้ครึ่งทางเหล่านั้นโดยอัตโนมัติ เราเรียกเวอร์ชันเหล่านี้ว่าเวอร์ชัน Stash หรือคุณจะเรียกมันโดยตรงว่า "เวอร์ชันเก็บพัก" ก็ได้

## การสร้างเวอร์ชัน Stash

ไฟล์ที่เราเปลี่ยนแปลงไปได้ครึ่งทางอาจมีสถานะดังต่อไปนี้:

* ไฟล์ใหม่ (ไฟล์ที่ยังไม่ถูกติดตาม - Untracked)
* ไฟล์ใหม่ (ไฟล์ที่เพิ่มเข้าไปใน Index แล้ว) (ไฟล์ที่ถูกติดตาม/Stage แล้ว)
* ไฟล์ที่แก้ไข (ไฟล์ที่ยังไม่ได้เพิ่มเข้าไปใน Index) (ไฟล์ที่ถูกติดตาม/ยังไม่ Stage)
* ไฟล์ที่แก้ไข (ไฟล์ที่เพิ่มเข้าไปใน Index แล้ว) (ไฟล์ที่ถูกติดตาม/Stage แล้ว)
* ไฟล์ที่ลบ (ไฟล์ที่ยังไม่ได้เพิ่มเข้าไปใน Index) (ไฟล์ที่ถูกติดตาม/ยังไม่ Stage)
* ไฟล์ที่ลบ (ไฟล์ที่เพิ่มเข้าไปใน Index แล้ว) (ไฟล์ที่ถูกติดตาม/Stage แล้ว)

หากคุณต้องการสร้าง "เวอร์ชันเก็บพัก" สำหรับไฟล์ที่พัฒนาไปได้ครึ่งทางเหล่านี้ คุณมีสองทางเลือก:

* `git stash` จะสร้างเวอร์ชันเก็บพักสำหรับไฟล์ที่ถูกติดตามทั้งหมด
* `git stash -u` จะรวมไฟล์ที่ถูกติดตามหรือยังไม่ถูกติดตามทั้งหมด ทุกไฟล์จะถูกสร้างเป็นเวอร์ชันเก็บพัก

**หมายเหตุ**: `git stash` สามารถเขียนเป็น `git stash save` ได้เช่นกัน ผลลัพธ์ของทั้งสองคำสั่งเหมือนกัน เพียงแต่พารามิเตอร์ `save` สามารถละไว้ได้

### ตัวอย่างขั้นตอนการทำงาน

นี่คือตัวอย่างการใช้งานจริงอย่างง่าย:

```bash
# You're working on features
echo "new feature" > feature.txt
git add feature.txt

# Suddenly need to fix a bug
# Stash your work-in-progress
git stash

# Now working directory is clean
# Fix the bug on another branch
git checkout main
# ... make fixes ...
git commit -m "Fix urgent bug"

# Return to your feature work
git checkout feature-branch
git stash pop  # Restore your work
```

## การกู้คืนการเปลี่ยนแปลงที่เก็บพักไว้

หลังจากเก็บพักการเปลี่ยนแปลงของคุณแล้ว คุณสามารถสลับไปยัง Branch อื่นหรือทำงานด่วนนั้นได้ เมื่อคุณพร้อมที่จะทำงานเดิมต่อ คุณสามารถกู้คืนการเปลี่ยนแปลงที่เก็บพักไว้ได้โดยใช้:

* `git stash pop` - นำ Stash ล่าสุดมาใช้และนำมันออกจากรายการ Stash
* `git stash apply` - นำ Stash ล่าสุดมาใช้แต่ยังคงมันไว้ในรายการ Stash

## การแสดงรายการการเปลี่ยนแปลงที่เก็บพักไว้

ในการดูว่าคุณเก็บพักอะไรไว้บ้าง ให้ใช้:

```
git stash list
```

คำสั่งนี้จะแสดงการเปลี่ยนแปลงที่เก็บพักไว้ทั้งหมดพร้อมกับการอ้างอิง Stash ของพวกมัน (stash@{0}, stash@{1} เป็นต้น)

## การนำ Stash ที่ระบุไปใช้

หากคุณมี Stash หลายรายการ คุณสามารถนำรายการที่ระบุไปใช้ได้โดยอ้างอิงหมายเลขของมัน:

```
git stash apply stash@{2}
```

## การทิ้ง Stash

ในการนำ Stash ที่ระบุออกจากรายการ:

```
git stash drop stash@{0}
```

ในการนำ Stash ทั้งหมดออก:

```
git stash clear
```

## การเก็บพักไฟล์ที่ยังไม่ถูกติดตาม

โดยค่าเริ่มต้น `git stash` จะเก็บพักเฉพาะไฟล์ที่ถูกติดตามเท่านั้น ในการเก็บพักไฟล์ที่ยังไม่ถูกติดตามด้วย:

```
git stash -u
```

หรือในการเก็บพักทุกอย่างรวมถึงไฟล์ที่ถูกละเว้น:

```
git stash -a
```

## การสร้าง Stash ที่มีชื่อ

คุณสามารถตั้งข้อความอธิบายให้กับ Stash ของคุณได้:

```
git stash save "Work in progress on feature X"
```

วิธีนี้ทำให้ระบุ Stash ได้ง่ายขึ้นในภายหลัง

## การดูเนื้อหาของ Stash

ในการดูว่ามีอะไรอยู่ใน Stash ที่ระบุโดยไม่ต้องนำไปใช้:

```
git stash show stash@{0}
```

สำหรับ Diff โดยละเอียด:

```
git stash show -p stash@{0}
```

## สรุปของวันนี้

คำสั่ง `git stash` เป็นเครื่องมือที่มีประโยชน์ในทางปฏิบัติมาก ซึ่งช่วยให้คุณวางงานปัจจุบันไว้ชั่วคราวโดยไม่ต้อง Commit มัน สิ่งนี้มีประโยชน์อย่างยิ่งเมื่อคุณต้องการสลับบริบทอย่างรวดเร็วเพื่อไปทำงานอย่างอื่น กลไก Stash ช่วยให้มั่นใจได้ว่าการเปลี่ยนแปลงที่อยู่ระหว่างดำเนินการของคุณจะถูกเก็บไว้อย่างปลอดภัย และสามารถกู้คืนได้ในภายหลัง

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git stash
* git stash save
* git stash -u
* git stash list
* git stash pop
* git stash apply
* git stash drop
* git stash clear
* git stash show
