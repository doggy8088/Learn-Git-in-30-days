# วันที่ 21: แก้ไขประวัติเวอร์ชันที่ Commit แล้ว ตอนที่ 3 (cherry-pick)

ในกระบวนการควบคุมเวอร์ชัน มีอีกสถานการณ์หนึ่งที่พบบ่อย: คุณพัฒนาใน Branch หนึ่งมาสักระยะหนึ่งแล้ว แต่ภายหลังตัดสินใจว่าไม่ต้องการ Branch ทั้งหมดนั้นอีกต่อไป อย่างไรก็ตาม ในนั้นมี Commit บางรายการที่คุณยังอยากเก็บไว้ ในกรณีนี้ คุณจะลบ Branch ทิ้งก็ไม่ได้ แต่การ Merge Branch ทั้งหมดกลับมาก็ไม่เหมาะสมเช่นกัน แล้วควรทำอย่างไร? บทความนี้จะอธิบายวิธีใช้คำสั่ง `git cherry-pick` เพื่อ "เลือกด้วยตนเอง" เฉพาะการเปลี่ยนแปลงที่คุณต้องการนำไปใช้

## ทำความเข้าใจ git cherry-pick

บางครั้งคุณต้องการนำ Commit ที่ระบุจาก Branch หนึ่งไปใช้กับอีก Branch หนึ่ง โดยไม่ต้อง Merge Branch ทั้งหมด คำสั่ง `cherry-pick` ของ Git ช่วยให้คุณทำสิ่งนั้นได้อย่างตรงจุด นั่นคือเลือก Commit เฉพาะรายการและนำไปใช้กับ Branch ปัจจุบันของคุณ

`git cherry-pick` นำการเปลี่ยนแปลงที่เกิดขึ้นใน Commit ที่มีอยู่ไปใช้กับ Branch ปัจจุบันของคุณ มันสร้าง Commit ใหม่ที่มีการเปลี่ยนแปลงเดียวกัน แต่มี Hash ของ Commit ต่างกัน

## Cherry-Pick พื้นฐาน

ในการ Cherry-Pick Commit รายการเดียว:

```
# Switch to the target branch
git checkout main

# Cherry-pick the commit
git cherry-pick <commit-hash>
```

สิ่งนี้จะสร้าง Commit ใหม่บน Branch ปัจจุบันที่มีการเปลี่ยนแปลงเดียวกันกับ Commit ที่ระบุ

## การ Cherry-Pick หลาย Commit

ในการ Cherry-Pick หลาย Commit:

```
# Cherry-pick several commits
git cherry-pick <hash1> <hash2> <hash3>
```

ในการ Cherry-Pick ช่วงของ Commit:

```
# Cherry-pick commits from commit1 to commit2 (exclusive of commit1)
git cherry-pick commit1..commit2

# Cherry-pick commits from commit1 to commit2 (inclusive of commit1)
git cherry-pick commit1^..commit2
```

## Cherry-Pick โดยไม่ Commit

ในการนำการเปลี่ยนแปลงไปใช้โดยไม่สร้าง Commit โดยอัตโนมัติ:

```
git cherry-pick --no-commit <commit-hash>
# or
git cherry-pick -n <commit-hash>
```

สิ่งนี้มีประโยชน์เมื่อคุณต้องการ Cherry-Pick หลาย Commit และสร้าง Commit เพียงรายการเดียว

## การจัดการ Conflict

หากเกิด Conflict ขึ้นระหว่างการ Cherry-Pick:

```
# Resolve conflicts in the files
# Stage the resolved files
git add <resolved-files>

# Continue the cherry-pick
git cherry-pick --continue
```

ในการยกเลิกการ Cherry-Pick ที่กำลังดำเนินการอยู่:

```
git cherry-pick --abort
```

ในการข้าม Commit ปัจจุบันและดำเนินการต่อไปยังรายการถัดไป:

```
git cherry-pick --skip
```

## Cherry-Pick พร้อมการแก้ไข

ในการแก้ไขข้อความ Commit ขณะ Cherry-Pick:

```
git cherry-pick -e <commit-hash>
# or
git cherry-pick --edit <commit-hash>
```

## Cherry-Pick และการ Sign-off

ในการเพิ่มบรรทัด Sign-off ลงในข้อความ Commit:

```
git cherry-pick -s <commit-hash>
# or
git cherry-pick --signoff <commit-hash>
```

## กรณีการใช้งานจริง

### กรณีที่ 1: นำ Hotfix ไปใช้กับหลาย Branch

```
# Fix created on main branch (commit abc123)
git checkout release-1.0
git cherry-pick abc123

git checkout release-2.0
git cherry-pick abc123
```

### กรณีที่ 2: การรวม Feature แบบเลือกเฉพาะบางส่วน

```
# Feature branch has commits A, B, C, D
# You only want B and C on main

git checkout main
git cherry-pick <hash-B> <hash-C>
```

### กรณีที่ 3: การกู้คืน Commit ที่สูญหาย

```
# Find the lost commit using reflog
git reflog

# Cherry-pick it to current branch
git cherry-pick <lost-commit-hash>
```

## Cherry-Pick เทียบกับ Merge เทียบกับ Rebase

**Cherry-pick**:
* นำ Commit ที่ระบุไปใช้แบบเลือกเฉพาะ
* สร้าง Hash ของ Commit ใหม่
* เหมาะสำหรับการรวมแบบเลือกเฉพาะบางส่วน

**Merge**:
* รวม Branch ทั้งหมดเข้าด้วยกัน
* รักษาประวัติไว้อย่างสมบูรณ์
* เหมาะที่สุดสำหรับการรวม Feature Branch

**Rebase**:
* เล่น Commit ซ้ำบน Base ใหม่
* ประวัติเป็นเส้นตรง
* เหมาะสำหรับการเก็บกวาดประวัติ

## แนวปฏิบัติที่ดีที่สุด

1. **ใช้อย่างประหยัด**: Cherry-Pick อาจทำให้ประวัติสับสนได้หากใช้มากเกินไป
2. **บันทึกเหตุผล**: อธิบายว่าทำไมคุณจึง Cherry-Pick ไว้ในข้อความ Commit
3. **หลีกเลี่ยงการซ้ำซ้อน**: อย่า Cherry-Pick Commit ที่ภายหลังจะถูก Merge อยู่แล้ว
4. **ตรวจสอบสิ่งที่ต้องพึ่งพา**: ให้แน่ใจว่า Commit นั้นไม่ได้พึ่งพา Commit อื่น
5. **ทดสอบหลัง Cherry-Pick**: ตรวจสอบว่าการเปลี่ยนแปลงทำงานได้ในบริบทใหม่

## การติดตาม Commit ที่ถูก Cherry-Pick

Git สามารถติดตาม Commit ที่ถูก Cherry-Pick ได้:

```
# Cherry-pick with -x flag
git cherry-pick -x <commit-hash>
```

สิ่งนี้จะเพิ่มบรรทัดหนึ่งลงในข้อความ Commit: "(cherry picked from commit ...)"

## ข้อผิดพลาดทั่วไปที่ควรหลีกเลี่ยง

1. **การ Cherry-Pick Merge Commit**: มักทำให้เกิดปัญหา
2. **การ Cherry-Pick จาก Feature ไปยัง Main**: อาจสร้าง Commit ซ้ำซ้อนเมื่อทำการ Merge
3. **ไม่ทดสอบ**: การเปลี่ยนแปลงอาจทำงานต่างไปใน Branch ที่ต่างกัน
4. **ละเลยสิ่งที่ต้องพึ่งพา**: Commit ที่ถูก Cherry-Pick อาจต้องใช้ Commit อื่นจึงจะทำงานได้

## สรุปของวันนี้

`git cherry-pick` เป็นเครื่องมือที่ทรงพลังสำหรับการนำ Commit จาก Branch หนึ่งไปใช้กับอีก Branch หนึ่งแบบเลือกเฉพาะ มันมีประโยชน์อย่างยิ่งสำหรับการนำ Hotfix ไปใช้กับ Release Branch หลาย Branch หรือการเลือก Feature ที่ระบุจาก Development Branch อย่างไรก็ตาม ควรใช้มันอย่างรอบคอบ เพราะมันอาจทำให้ประวัติซับซ้อนได้หากใช้มากเกินไป

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git cherry-pick <commit>
* git cherry-pick <commit1> <commit2>
* git cherry-pick commit1..commit2
* git cherry-pick --no-commit
* git cherry-pick -n
* git cherry-pick --continue
* git cherry-pick --abort
* git cherry-pick --skip
* git cherry-pick -e
* git cherry-pick -x
* git cherry-pick --signoff
