# วันที่ 11: ทำความเข้าใจการอ้างอิง Git Object และการอ้างอิงเชิงสัญลักษณ์

หลังจากทำความเข้าใจ "ชื่อสัมบูรณ์" ของ Git Object แล้ว ต่อไปเราจะมาแนะนำ "ชื่ออ้างอิง" ที่ใช้กันบ่อยที่สุดในกระบวนการควบคุมเวอร์ชันด้วย Git

## ทำความเข้าใจชื่ออ้างอิงของ Object

ชื่ออ้างอิง (Reference Name หรือ ref) พูดง่าย ๆ ก็คือ "พอยน์เตอร์" ที่ชี้ไปยัง Git Object หรือเป็น "ชื่อที่จำง่ายกว่า" อีกชื่อหนึ่งเมื่อเทียบกับ "ชื่อสัมบูรณ์" โดยใช้ชื่อที่กำหนดไว้ล่วงหน้าหรือชื่อที่ผู้ใช้กำหนดเองเพื่อแทน Git Object ตัวใดตัวหนึ่งโดยเฉพาะ

"ชื่อ Branch" ที่เราเรียนรู้กันก่อนหน้านี้ HEAD ที่เราใช้กันอยู่ (แทนเวอร์ชันล่าสุด) หรือ "ชื่อ Tag" ที่เราจะได้เรียนรู้ต่อไป ล้วนเป็น "ชื่ออ้างอิง" ทั้งสิ้น ซึ่งโดยพื้นฐานแล้วถูกสร้างขึ้นเพื่อให้จดจำได้ง่ายขึ้น

เราจะใช้ "ชื่อ Branch" เป็นตัวอย่างเพื่ออธิบายว่าโครงสร้างทางกายภาพของ "ชื่ออ้างอิง" คืออะไร ในรูปต่อไปนี้ เราใช้ `git branch` เพื่อรับชื่อ Branch ทั้งหมด คุณจะเห็นว่าปัจจุบันเรามีสาม Branch อย่างไรก็ตาม ชื่อ Branch ทั้งสามนี้แท้จริงแล้วคือ "ชื่ออ้างอิง" ซึ่งหมายความว่า "ชื่ออ้างอิง" ทั้งสามนี้สอดคล้องกับ Commit Object สามตัวใน Git Object Repository ในรูปต่อไปนี้ คุณยังจะเห็นได้ว่าชื่ออ้างอิงของ Branch เหล่านี้แท้จริงแล้วเป็นเพียงไฟล์เท่านั้น ชื่ออ้างอิงของ "Local Branch" ทั้งหมดจะอยู่ในไดเรกทอรี `.git\refs\heads`:

![รูปภาพ](figures/11/01.png)

จากนั้นผมจะใช้รูปต่อไปนี้เพื่อพิสูจน์ว่าไฟล์นี้เชื่อมโยงกับ "ชื่อสัมบูรณ์" อย่างไร ผมใช้ `git branch` เพื่อรับชื่อ Branch ทั้งหมดก่อน และพบว่า "Working Directory" ปัจจุบันชี้ไปยัง Branch `newbranch1` ในเวลานี้ เราสามารถรับบันทึกเวอร์ชันทั้งหมดของ Branch นี้ได้ผ่าน `git log --pretty=oneline` โดยค่าเริ่มต้น ชื่ออ้างอิงของ Branch เหล่านี้จะชี้ไปยัง "เวอร์ชันล่าสุด" ของ Branch นั้น เราเพียงแค่เปิดเนื้อหาของไฟล์ `.git\refs\heads\newbranch1` ก็จะเห็นว่านี่เป็นเพียงไฟล์ข้อความธรรมดาที่ชี้ไปยัง "เวอร์ชันล่าสุด" ในประวัติเวอร์ชัน สุดท้าย ใช้ `git cat-file -p 0bd0` เพื่อรับเนื้อหาของ Commit Object นั้น และใช้ `git show 0bd0` เพื่อรับบันทึกการเปลี่ยนแปลงของเวอร์ชันนั้น ซึ่งพิสูจน์ได้ว่าไฟล์เหล่านี้คือวัตถุประสงค์หลักของ "ชื่ออ้างอิง"

![รูปภาพ](figures/11/02.png)

จากนั้นเราใช้คำสั่งเพื่อดูเนื้อหาของการอ่าน Commit Object ตัวใดตัวหนึ่งโดยใช้ "ชื่อสัมบูรณ์" และ "ชื่ออ้างอิง" เพื่อพิสูจน์ว่าผลลัพธ์ของทั้งสองคำสั่งนี้เหมือนกัน:

![รูปภาพ](figures/11/03.png)

ในกรณีส่วนใหญ่ "ชื่ออ้างอิง" มักจะชี้ไปยัง Commit Object แต่ก็ไม่จำเป็นเสมอไป คุณยังสามารถชี้ไปยัง Git Object ประเภทอื่น ๆ ได้ เช่น Blob Object, Tree Object, Tag Object เป็นต้น

## เกี่ยวกับไดเรกทอรี .git/refs/

จากตัวอย่างข้างต้น คุณจะเห็นได้จริง ๆ ว่า "ชื่ออ้างอิง" ทั้งหมดเป็นไฟล์ และทั้งหมดถูกวางไว้ในไดเรกทอรี `git/refs/` ตำแหน่งไดเรกทอรีที่ชื่ออ้างอิงของ Git ถูกวางไว้มีอยู่สามแห่งหลัก ๆ:

* Local Branch: `.git/refs/heads/`
* Remote Branch: `.git/refs/remotes/`
* Tag: `.git/refs/tags/`

ขอยกตัวอย่างง่าย ๆ ให้ดู หากคุณสร้าง Branch ชื่อ `f2e` ในเวลานี้คุณจะทราบว่า "ชื่ออ้างอิง" ของ Local Branch จะสร้างไฟล์ `.git/refs/heads/f2e` ขึ้นมา ดังแสดงในรูปต่อไปนี้:

![รูปภาพ](figures/11/04.png)

อันที่จริง "ชื่อเต็ม" ของ `f2e` นี้ควรเรียกว่า `refs/heads/f2e` เพียงแต่ Git อนุญาตให้คุณป้อนชื่อย่อได้เพื่อความสะดวกในการป้อนชื่ออ้างอิงอย่างรวดเร็ว ดังแสดงในรูปต่อไปนี้ วิธีการใช้ "ชื่ออ้างอิง" ทั้งสามวิธีนี้ล้วนใช้ได้ทั้งสิ้น:

![รูปภาพ](figures/11/05.png)

อย่างไรก็ตาม เมื่อคุณป้อน "ชื่อย่อ" ของชื่ออ้างอิง Git จะค้นหาชื่ออ้างอิงที่เหมาะสมตามลำดับต่อไปนี้โดยค่าเริ่มต้น ทันทีที่พบไฟล์ที่สอดคล้องกัน มันจะส่งคืน "ชื่อสัมบูรณ์ของ Object" ของเนื้อหาไฟล์นั้นทันที:

* `.git/<reference abbreviation>`
* `.git/refs/<reference abbreviation>`
* `.git/refs/tags/<reference abbreviation; tag name>`
* `.git/refs/heads/<reference abbreviation; local branch name>`
* `.git/refs/remotes/<reference abbreviation>`
* `.git/refs/remotes/<reference abbreviation; remote branch name>/HEAD`

ตัวอย่างเช่น เมื่อคุณป้อนคำสั่ง `git cat-file -p f2e` Git จะค้นหา "ไฟล์ชื่ออ้างอิง" ที่เกี่ยวข้องตามลำดับต่อไปนี้ และดึงเนื้อหาของไฟล์นั้นออกมา (นั่นคือชื่อสัมบูรณ์ของ Git Object):

* `.git/f2e` --> ไม่พบไฟล์
* `.git/refs/f2e` --> ไม่พบไฟล์
* `.git/refs/tags/f2e` --> ไม่พบไฟล์
* `.git/refs/heads/f2e` --> **พบชื่ออ้างอิง ไม่ค้นหาต่อ**
* `.git/refs/remotes/f2e`
* `.git/refs/remotes/f2e/HEAD`

## ทำความเข้าใจชื่ออ้างอิงเชิงสัญลักษณ์ของ Object (symref)

ชื่ออ้างอิงเชิงสัญลักษณ์ (Symbolic Reference Name หรือ symref) แท้จริงแล้วก็เป็นชื่ออ้างอิง (ref) ประเภทหนึ่ง เพียงแต่เนื้อหาแตกต่างกัน เราสามารถเห็นความแตกต่างของเนื้อหาได้จากรูปต่อไปนี้ "การอ้างอิงเชิงสัญลักษณ์" จะชี้ไปยัง "ชื่ออ้างอิง" อีกชื่อหนึ่ง และเนื้อหาจะขึ้นต้นด้วย `ref:`:

![รูปภาพ](figures/11/06.png)

ในเครื่องมือ Git มีการอ้างอิงเชิงสัญลักษณ์พิเศษบางอย่างที่ถูกดูแลไว้โดยค่าเริ่มต้น เพื่ออำนวยความสะดวกในการเข้าถึง Commit Object ที่ใช้บ่อยอย่างรวดเร็ว และ Object เหล่านี้จะถูกเก็บไว้ในไดเรกทอรี `.git/` โดยค่าเริ่มต้น การอ้างอิงเชิงสัญลักษณ์เหล่านี้มีอยู่สี่รายการดังต่อไปนี้:

* HEAD
* จะชี้ไปยัง "เวอร์ชันล่าสุด" ใน "Branch" ที่ตั้งไว้ใน "Working Directory" เสมอ
* ดังนั้นเมื่อคุณดำเนินการ `git commit` ใน Branch นี้ การอ้างอิงเชิงสัญลักษณ์ `HEAD` นี้ก็จะถูกอัปเดตไปยัง Commit Object ของเวอร์ชันล่าสุดของ Branch นี้ด้วย
* ORIG_HEAD
* พูดง่าย ๆ ก็คือ "เวอร์ชันก่อนหน้า" ของ HEAD Commit Object มักใช้เพื่อกู้คืนการเปลี่ยนแปลงของเวอร์ชันก่อนหน้า
* FETCH_HEAD
* เมื่อใช้ Remote Repository คุณอาจใช้คำสั่ง `git fetch` เพื่อดึง Object ทั้งหมดจาก Remote Repository การอ้างอิงเชิงสัญลักษณ์ FETCH_HEAD นี้จะบันทึก "ชื่อสัมบูรณ์" ของ HEAD (เวอร์ชันล่าสุด) ของแต่ละ Branch ใน Remote Repository
* MERGE_HEAD
* เมื่อคุณดำเนินการ Merge (หัวข้อเรื่องการ Merge จะกล่าวถึงในบทความต่อไป) ชื่อสัมบูรณ์ของ Commit Object จาก "ต้นทางของการ Merge" จะถูกบันทึกไว้ในการอ้างอิงเชิงสัญลักษณ์ MERGE_HEAD นี้

## การใช้งานการอ้างอิงทั่วไปและการอ้างอิงเชิงสัญลักษณ์

เราทราบว่า "ชื่ออ้างอิง" มีวัตถุประสงค์พิเศษ และมักใช้ในสถานการณ์ต่าง ๆ เช่น "Local Branch", "Remote Branch" และ "Tag" แต่ในความเป็นจริง คุณสามารถสร้าง "ชื่ออ้างอิงแบบกำหนดเอง" ได้ไม่จำกัดจำนวน คุณสามารถสร้าง "การอ้างอิงทั่วไป" ได้อย่างอิสระผ่าน `git update-ref`

ผมจะลองสร้างการอ้างอิงทั่วไปชื่อ `InitialCommit` และชี้ไปยังเวอร์ชันแรกใน Git Repository โปรดดูรูปต่อไปนี้สำหรับลำดับการดำเนินการคำสั่งเพื่อเรียนรู้วิธีสร้างการอ้างอิงทั่วไป:

![รูปภาพ](figures/11/07.png)

หลังจากสร้างแล้ว ไฟล์เริ่มต้นจะถูกวางไว้ในโฟลเดอร์ `.git` และในเวลานี้ คุณสามารถเข้าถึงเนื้อหาของ Git Object ที่ระบุได้ทั้งด้วย "ชื่อสัมบูรณ์" และ "ชื่ออ้างอิง":

![รูปภาพ](figures/11/08.png)

**หมายเหตุ**: โปรดจำไว้ว่าชื่ออ้างอิงสามารถชี้ไปยัง Git Object ใด ๆ ก็ได้ และไม่ได้จำกัดอยู่แค่ Commit Object เท่านั้น

ในการสร้างชื่ออ้างอิงที่เป็นทางการมากขึ้น ควรเพิ่มคำนำหน้า `refs/` เช่น: `git update-ref refs/InitialCommit [object_id]`

ในการลบการอ้างอิงทั่วไป คุณสามารถใช้ตัวเลือก `-d` ดังแสดงในรูปต่อไปนี้:

![รูปภาพ](figures/11/09.png)

ในการแสดงการอ้างอิงทั้งหมด คุณสามารถใช้คำสั่ง `git show-ref` ดังแสดงในรูปต่อไปนี้:

![รูปภาพ](figures/11/10.png)

ในการสร้างและลบ "การอ้างอิงเชิงสัญลักษณ์" คุณสามารถดูรูปต่อไปนี้สำหรับการใช้งาน `git symbolic-ref` โปรดดูรูปแล้วเล่าเรื่องราว หลังจากทำความเข้าใจแล้ว คุณจะพบจริง ๆ ว่า Git มีความยืดหยุ่นและทรงพลังมากในการใช้การอ้างอิง นอกจากนี้ การดำเนินการ `git show-ref` จะแสดงเฉพาะการอ้างอิงเหล่านั้นในไดเรกทอรี `.git\refs` เท่านั้น และใช้ได้เหมือนกันทั้งกับ "การอ้างอิงทั่วไป" และ "การอ้างอิงเชิงสัญลักษณ์":

![รูปภาพ](figures/11/11.png)

ก่อนหน้านี้ในบทความนี้ ได้กล่าวไว้ว่าคุณสามารถสร้างการอ้างอิงไปยังไดเรกทอรีต่อไปนี้:

* `.git/<reference abbreviation>`
* `.git/refs/<reference abbreviation>`
* `.git/refs/tags/<reference abbreviation; tag name>`
* `.git/refs/heads/<reference abbreviation; local branch name>`
* `.git/refs/remotes/<reference abbreviation>`
* `.git/refs/remotes/<reference abbreviation; remote branch name>/HEAD`

การอ้างอิงแบบกำหนดเองมักถูกสร้างขึ้นในสองเส้นทางแรก เพื่อหลีกเลี่ยงความสับสนกับการใช้งาน "Local Branch", "Remote Branch" และ "Tag" ของเรา อย่างไรก็ตาม คุณสามารถใช้ `git update-ref` เพื่อสร้างการอ้างอิงแบบกำหนดเองใด ๆ ได้จริง หากคุณสร้างการอ้างอิงแบบกำหนดเองใน `refs/heads/Will` ก็เทียบเท่ากับการสร้าง Branch ชื่อ `Will` Git นั้นเรียบง่ายจริง ๆ ยิ่งคุณเข้าใจโครงสร้างภายในของ Git มากเท่าไร คุณก็จะยิ่งรักคุณสมบัติต่าง ๆ ของ Git มากขึ้นเท่านั้น

## สรุปของวันนี้

เราทราบว่า "ชื่ออ้างอิง (ref)" พูดง่าย ๆ ก็คือ "พอยน์เตอร์" ที่ชี้ไปยัง Git Object ซึ่งใช้เพื่อชี้ไปยัง Git Object ที่ระบุ ดังนั้นคุณสามารถจินตนาการว่า "ชื่ออ้างอิง" เป็นนามแฝงของชื่อสัมบูรณ์ของ Git Object ที่ใช้เพื่อช่วยในการจดจำ ใน Git มีกลไกมากมายที่ช่วยให้คุณควบคุมโปรเจกต์ได้ เช่น "Branch", "Tag" เป็นต้น กลไกเหล่านี้แท้จริงแล้วสำเร็จได้ด้วย "การอ้างอิง" ภายใต้เบื้องหลัง

ชื่ออ้างอิงของ Git ยังแบ่งออกเป็น "การอ้างอิงทั่วไป" และ "การอ้างอิงเชิงสัญลักษณ์" ทั้งสองมีวัตถุประสงค์เดียวกัน ต่างกันเพียงเนื้อหาเล็กน้อย "การอ้างอิงเชิงสัญลักษณ์" จะชี้ไปยัง "การอ้างอิงทั่วไป" อีกอันหนึ่ง ในขณะที่ "การอ้างอิงทั่วไป" จะชี้ไปยัง "ชื่อสัมบูรณ์" ของ Git Object

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git branch
* git log --pretty=oneline
* git log --oneline
* git cat-file -p [ref or object_id]
* git show [ref or object_id]
* git update-ref
* git symbolic-ref
* git show-ref
