# วันที่ 12: ทำความเข้าใจชื่อสัมพัทธ์ของ Git Object

หลังจากทำความเข้าใจ "ชื่อสัมบูรณ์" และ "ชื่ออ้างอิง" ของ Git Object แล้ว ต่อไปเราจะมาแนะนำ "ชื่อสัมพัทธ์" ซึ่งก็ใช้กันบ่อยในกระบวนการควบคุมเวอร์ชันด้วย Git เช่นกัน

ขอทบทวนกันอีกครั้ง ในการควบคุมเวอร์ชันด้วย Git แต่ละเวอร์ชันแทน Commit Object หนึ่งตัว Commit Object แต่ละตัวมี "ชื่อสัมบูรณ์" ซึ่งเป็นสตริง 40 อักขระที่ได้จากการแฮชเนื้อหาด้วย SHA1 คุณสามารถใช้อักขระ 4 ถึง 40 ตัวแรกเป็นชื่อระบุตัวตนของ Commit Object นั้นได้ ในระหว่างการควบคุมเวอร์ชัน คุณยังสามารถใช้ "ชื่ออ้างอิง" เพื่อแทน Commit Object ตัวใดตัวหนึ่งโดยเฉพาะได้ "ชื่ออ้างอิง" แต่ละชื่อในที่สุดจะสอดคล้องกับ "ชื่อสัมบูรณ์" ของ Object หนึ่งตัว "ชื่ออ้างอิง" ยังแบ่งออกเป็น "การอ้างอิงทั่วไป" และ "การอ้างอิงเชิงสัญลักษณ์" โดย "การอ้างอิงทั่วไป" จะสอดคล้องกับ "ชื่อสัมบูรณ์" โดยตรง ในขณะที่ "การอ้างอิงเชิงสัญลักษณ์" จะสอดคล้องกับ "การอ้างอิงทั่วไป" อีกอันหนึ่ง

สิ่งที่บทความนี้จะแนะนำคือการใช้สัญกรณ์ "ชื่อสัมพัทธ์" ซึ่งช่วยให้คุณค้นหา "Commit Object" อื่น ๆ ได้โดยอิงจากตำแหน่งสัมพัทธ์ของพวกมัน หลังจากค้นพบ Commit Object ตัวใดตัวหนึ่งแล้ว

## สัญกรณ์ชื่อสัมพัทธ์

การใช้ชื่อสัมพัทธ์นั้นจริง ๆ แล้วง่ายมาก มีสัญลักษณ์พิเศษสองตัวที่คุณต้องจำไว้ ตัวหนึ่งคือ `^` และอีกตัวคือ `~`

ในการค้นหาเวอร์ชันก่อนหน้าของ `HEAD` เราจะใช้ `HEAD~` หรือ `HEAD~1` เพื่อแทน "เวอร์ชันก่อนหน้าของ HEAD Commit Object" **หมายเหตุ**: ตรงนี้คุณควรทราบดีอยู่แล้วว่า `HEAD` คือ "ชื่ออ้างอิงเชิงสัญลักษณ์" ที่มีอยู่ในตัว Git ซึ่งแทนเวอร์ชันล่าสุดของ Branch ปัจจุบัน

หากคุณต้องการค้นหาสองเวอร์ชันก่อนหน้า Branch `f2e` อีก Branch หนึ่ง (ไม่รวมเวอร์ชัน `HEAD` ของ `f2e`) คุณสามารถใช้ `f2e~2` หรือ `f2e~~` เพื่อแทนมันได้ นี่คือวิธีการแทนที่พื้นฐานที่สุด

ใน Repository ที่ไม่มี Branch และการ Merge ความหมายที่แสดงโดย `^1` และ `~1` จะเหมือนกันทุกประการ ทั้งคู่แทน "เวอร์ชันก่อนหน้า" แต่ในความเป็นจริง ใน Repository ที่มี Branch และการ Merge พวกมันมีความหมายแตกต่างกัน ส่วนนี้จะอธิบายในภายหลัง

นี่คือสัญกรณ์ "ชื่อสัมพัทธ์" ที่พื้นฐานที่สุด

## การเชื่อมโยงระหว่าง Commit Object

ใน Git Repository ทั่วไป โดยค่าเริ่มต้นจะมี "Root Commit Object" เพียงตัวเดียว ซึ่งเป็นเวอร์ชันแรกที่เราสร้างขึ้น หรือที่รู้จักกันในชื่อ "Initial Commit" คุณยังต้องมี Commit Object ตัวแรกเป็นอย่างน้อยก่อนจึงจะเริ่มแยก Branch ได้ ดังนั้นเราจึงกล่าวได้ว่า: "ใน Git Repository ในบรรดา Commit Object ทั้งหมด ยกเว้น Commit Object ตัวแรก Commit Object ตัวอื่น ๆ ทุกตัวจะต้องมี Parent Commit Object หนึ่งตัวหรือมากกว่า" ทำไมจึงอาจมี Parent Commit Object "มากกว่าหนึ่งตัว"? เพราะเป็นไปได้มากว่าคุณจะ Merge สอง Branch หรือมากกว่านั้นเข้าไปในอีก Branch หนึ่ง ดังนั้น Commit Object หลังจากการ Merge จึงจะมี Parent Commit Object หลายตัว

ขอใช้ตัวอย่างง่าย ๆ เพื่อพิสูจน์เรื่องนี้ เราใช้ `git cat-file -p [object_id]` เพื่อรับเนื้อหาของ Commit Object สองตัวแรก ซึ่งจะทำให้เข้าใจว่า Commit Object แต่ละตัวจะมีแอตทริบิวต์ Parent ที่ชี้ไปยังชื่อสัมบูรณ์ของ Parent Commit Object จริง ๆ ยกเว้น Commit Object ตัวแรกที่จะไม่มีแอตทริบิวต์ Parent ดังแสดงในรูปต่อไปนี้:

## ทำความเข้าใจความแตกต่างระหว่าง `^` และ `~` ในสัญกรณ์ชื่อสัมพัทธ์

ความหมายของ `~` แทน "Parent Commit Object ตัวแรก"

ความหมายที่ `^` แทนคือ "เมื่อมี Parent Commit Object หลายตัว จะแทน Parent Object รุ่นแรกตัวที่เท่าใด"

หากคุณมี "ชื่ออ้างอิง" ชื่อ `C` ในการค้นหา Parent Commit Object ตัวแรกของมัน คุณสามารถเขียนได้ดังต่อไปนี้:

* `C^`
* `C^1`
* `C~`
* `C~1`

หากคุณต้องการค้นหา Parent Commit Object ตัวที่สองของมัน (โดยไม่มีการ Merge) คุณสามารถเขียนได้ดังต่อไปนี้:

* `C^^`
* `C^1^1`
* `C~2`
* `C~~`
* `C~1~1`

แต่คุณไม่สามารถใช้ `C^2` เพื่อแสดง "Parent Commit Object ตัวที่สอง" ได้! เหตุผลก็คือ หากไม่มีการ Merge `C` ตัวนี้จะมี Parent Object เพียงตัวเดียวเท่านั้น คุณสามารถใช้ `C^2` เพื่อแทน "Parent Object ตัวที่สองของ Object ในชั้นก่อนหน้า" ได้เท่านั้น

ข้างต้นอาจฟังดูค่อนข้างเป็นนามธรรมและพันกันไปมา ผมวาดแผนภาพไว้ให้คุณดูเป็นพิเศษ ผ่านแผนภาพนี้ อาจจะชัดเจนยิ่งขึ้น ดังแสดงในรูปต่อไปนี้ เราต้องการค้นหา Commit Object อื่น ๆ (Parent Object) ในเส้นทางสัมพัทธ์ของ Commit Object `C` เนื่องจาก Commit Object `C` ตัวนี้มี Parent Object สามตัว นั่นหมายความว่า Commit Object ตัวนี้ถูกสร้างขึ้นผ่านการ Merge ดังนั้นในการค้นหาแต่ละเส้นทางผ่าน "ชื่อสัมพัทธ์" คุณจะต้องใช้ทักษะการผสมผสานระหว่าง `^` และ `~` เพื่อระบุตำแหน่งของแต่ละเวอร์ชันที่คุณต้องการเปิด

## แนะนำคำสั่ง `git rev-parse`

ในเครื่องมือ Git for Windows มีคำสั่ง `git rev-parse` อยู่ ผ่านคำสั่งนี้ คุณสามารถแยกวิเคราะห์ "ชื่ออ้างอิง" หรือ "ชื่อสัมพัทธ์" ใด ๆ ให้กลายเป็น "ชื่อสัมบูรณ์" ได้ แม้เครื่องมือนี้จะไม่ค่อยได้ใช้บ่อยนัก แต่ก็ค่อนข้างมีประโยชน์ในทางปฏิบัติเมื่อสอน Git ตัวอย่างการใช้งานมีดังต่อไปนี้:

* git rev-parse master
* git rev-parse HEAD
* git rev-parse ORIG_HEAD
* git rev-parse HEAD^
* git rev-parse HEAD~5

## สรุปของวันนี้

หลังจากทำความเข้าใจ "ชื่อสัมพัทธ์" แล้ว วิธีการแทน Commit Object แบบต่าง ๆ ใน Git ก็ได้รับการอธิบายครบถ้วน ผมเชื่อว่าคุณน่าจะสามารถควบคุมการดำเนินการระหว่างเวอร์ชันต่าง ๆ ของ Git ได้ดียิ่งขึ้น

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git log
* git cat-file -p [object_id]
* git rev-parse
