# วันที่ 15: Tag - การทำเครื่องหมายเหตุการณ์สำคัญในการควบคุมเวอร์ชัน

เมื่อใช้ Git ในการควบคุมเวอร์ชัน จะมีเวอร์ชันจำนวนมากถูกสร้างขึ้น เมื่อเวลาผ่านไป ในบรรดาเวอร์ชันมากมายเหล่านี้ จะต้องมีเวอร์ชันสำคัญบางเวอร์ชันที่คุ้มค่าแก่การบันทึกไว้อย่างแน่นอน นี่คือสิ่งที่ "Tag" สามารถช่วยเราทำได้

## ทำความเข้าใจ Tag - แนวคิดพื้นฐาน

โดยพื้นฐานแล้ว วัตถุประสงค์ของ Tag คือการทำเครื่องหมาย "เวอร์ชัน" หรือ "Commit Object" ที่ระบุด้วย "ชื่อที่จำง่าย" เพื่อช่วยให้เราจดจำเวอร์ชันใดเวอร์ชันหนึ่งได้

Tag คือการอ้างอิงที่ชี้ไปยัง Commit ที่ระบุในประวัติ Git ของคุณ Tag แตกต่างจาก Branch ตรงที่ Tag จะไม่เคลื่อนที่เมื่อคุณสร้าง Commit ใหม่ มันจะชี้ไปยัง Commit เดิมเสมอ สิ่งนี้ทำให้ Tag เหมาะอย่างยิ่งสำหรับการทำเครื่องหมายจุด Release หรือหลักชัยสำคัญอื่น ๆ

Git รองรับ Tag สองประเภท:

1. **Lightweight Tag**: เป็นเพียงชื่อ (นามแฝง) สำหรับ Commit ที่ระบุ ซึ่งเป็น "ชื่ออ้างอิง" ประเภทหนึ่ง
2. **Annotated Tag**: ถูกจัดเก็บเป็น Git Object เต็มรูปแบบพร้อมเมทาดาทาเพิ่มเติม

ดังที่กล่าวไว้ในวันที่ 11 (ทำความเข้าใจการอ้างอิง Git Object) "การอ้างอิงทั่วไป" ประกอบด้วย "ชื่อ Tag" และ "ชื่อ Tag" ในที่นี้หมายถึง "Lightweight Tag" ดังนั้นจึงอาจกล่าวได้ว่า "Lightweight Tag" เป็นเพียง "นามแฝง" สำหรับ Commit เวอร์ชันใดเวอร์ชันหนึ่ง ซึ่งเป็น "ชื่อสัมพัทธ์" ประเภทหนึ่ง

"Annotated Tag" เป็น Git Object ประเภทหนึ่ง ดังที่กล่าวไว้ในวันที่ 06 (วิเคราะห์โครงสร้างข้อมูลของ Git - โครงสร้าง Object) Git Object ประกอบด้วย Object 4 ประเภท ได้แก่ Blob, Tree, Commit และ Tag Object "Annotated Tag" ที่กล่าวถึงในที่นี้คือ Tag Object นั่นเอง Tag Object จะถูกจัดเก็บไว้ในที่จัดเก็บ Object ของ Git (จัดเก็บไว้ในไดเรกทอรี `.git\objects\`) และเชื่อมโยงกับ Commit Object อีกตัวหนึ่ง เมื่อสร้าง "Annotated Tag" คุณสามารถใส่ "ข้อความเวอร์ชัน" ได้เช่นเดียวกับเมื่อสร้าง Commit Object ในกลไก Tag ที่มีอยู่ในตัว Git คุณยังสามารถใช้กุญแจ GnuPG เพื่อลงนาม Tag Object เพื่อให้มั่นใจใน "การไม่สามารถปฏิเสธความรับผิด (Non-repudiation)" ของข้อความได้อีกด้วย

แม้เราจะมี Tag สองประเภทนี้ และทั้งคู่ดูเหมือน "นามแฝง" สำหรับ Commit Object แต่การใช้งาน Tag ทั้งสองนี้มีความแตกต่างกันเพียงเล็กน้อย ในกรณีการใช้งานส่วนใหญ่ เราใช้ "Annotated Tag" เพื่อสร้าง "Tag Object" และให้ "ข้อความเวอร์ชัน" เพราะ "Tag" ประเภทนี้เป็น "Object ถาวร" ใน Git Repository (Git Object ที่จัดเก็บไว้ในที่จัดเก็บ Object นั้นเปลี่ยนแปลงไม่ได้ มีเพียง Index เท่านั้นที่เปลี่ยนแปลง)

## การสร้าง Lightweight Tag

วิธีที่ง่ายที่สุดในการสร้าง Tag:

```
git tag v1.0
```

คำสั่งนี้จะสร้าง Lightweight Tag ชื่อ `v1.0` ที่ชี้ไปยัง Commit ปัจจุบัน (HEAD)

ในการ Tag Commit ที่ระบุ:

```
git tag v0.9 <commit-hash>
```

**หมายเหตุ**: ไฟล์ทั้งหมดภายใต้ `.git\refs\` คือ "ชื่ออ้างอิง"

การใช้งานพื้นฐาน:
* แสดงรายการ Tag ทั้งหมด: `git tag`
* สร้าง Lightweight Tag: `git tag [tagname]`
* ลบ Lightweight Tag: `git tag [tagname] -d`

หากคุณต้องการดูเนื้อหาของ "Lightweight Tag" คุณสามารถใช้ `git cat-file -p [tagname]` ได้ หากคุณต้องการดูประเภท Object ของ "Lightweight Tag" คุณสามารถใช้ `git cat-file -t [tagname]` ได้

**ข้อสำคัญ**: Lightweight Tag ไม่ใช่ Git Object จากข้างต้น คุณจะเห็นว่าชื่อ Tag จะดึงเนื้อหาของ Commit Object มา และประเภท Object ที่ค้นพบจากชื่อนั้นคือ Commit Object

## การสร้าง Annotated Tag

Annotated Tag เป็นที่แนะนำสำหรับกรณีการใช้งานส่วนใหญ่ เพราะมันจัดเก็บข้อมูลเพิ่มเติม:

```
git tag -a v1.0 -m "Release version 1.0"
```

แฟล็ก `-a` จะสร้าง Annotated Tag และ `-m` จะระบุข้อความของ Tag

ความแตกต่างจาก Lightweight Tag:
1. เมื่อดำเนินการ `git tag` เพื่อแสดงรายการ Tag ทั้งหมด Tag ทั้งหมดจะปะปนกันอยู่ และคุณไม่สามารถเห็นประเภทของ Tag ได้
2. การสร้าง "Annotated Tag" ต้องใช้พารามิเตอร์ `-a`
3. การสร้าง "Annotated Tag" ต้องใส่ "ข้อความเวอร์ชัน" ด้วย เช่นเดียวกับการดำเนินการ `git commit` ทั้งคู่มีพารามิเตอร์ `-m` ให้ใช้

## การแสดงรายการ Tag

ในการดู Tag ทั้งหมดใน Repository ของคุณ:

```
git tag
```

ในการดู Tag ที่ตรงกับรูปแบบ:

```
git tag -l "v1.*"
```

## การดูข้อมูลของ Tag

สำหรับ Lightweight Tag:

```
git show v1.0
```

คำสั่งนี้จะแสดง Commit ที่ Tag ชี้ไป

สำหรับ Annotated Tag:

```
git show v1.0
```

คำสั่งนี้จะแสดงข้อมูลของ Tag พร้อมรายละเอียดของ Commit

## การ Tag Commit เก่า

คุณสามารถ Tag Commit ที่ไม่ได้อยู่ที่ HEAD ได้:

```
git log --oneline  # Find the commit hash
git tag -a v0.5 -m "Beta release" <commit-hash>
```

## การ Push Tag ไปยัง Remote

โดยค่าเริ่มต้น `git push` จะไม่ถ่ายโอน Tag คุณต้อง Push พวกมันอย่างชัดเจน:

```
# Push a specific tag
git push origin v1.0

# Push all tags
git push origin --tags
```

## การลบ Tag

ในการลบ Tag ในเครื่อง:

```
git tag -d v1.0
```

ในการลบ Tag บน Remote:

```
git push origin :refs/tags/v1.0
# or
git push origin --delete v1.0
```

## การ Checkout Tag

คุณสามารถ Checkout โค้ดที่ Tag ที่ระบุได้:

```
git checkout v1.0
```

สิ่งนี้จะทำให้คุณอยู่ในสถานะ "Detached HEAD" หากคุณต้องการทำการเปลี่ยนแปลง ให้สร้าง Branch ใหม่:

```
git checkout -b version-1-fixes v1.0
```

## สรุปของวันนี้

Tag เป็นส่วนสำคัญของการควบคุมเวอร์ชัน ซึ่งช่วยให้คุณทำเครื่องหมายจุดสำคัญในประวัติโปรเจกต์ของคุณได้ Annotated Tag มีประโยชน์อย่างยิ่งสำหรับ Release เพราะมันสามารถจัดเก็บข้อมูลเพิ่มเติมได้ เช่น บันทึกประจำรุ่น ข้อมูลผู้ Tag และลายเซ็น

ขอผมเรียบเรียงคำสั่งและพารามิเตอร์ Git ที่เรียนรู้ในวันนี้อีกครั้ง:

* git tag
* git tag -a
* git tag -l
* git show
* git push origin --tags
* git tag -d
* git checkout
