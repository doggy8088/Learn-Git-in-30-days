# Day 13: ワーキングディレクトリとインデックスの変更を退避する（stash）

こんな状況に遭遇したことはありませんか。システムの開発が半分ほど進んだところで、突然上司や顧客から「緊急命令」が下り、既存システムのバグを至急修正したり、機能を追加したりするよう求められるのです。目の前のプログラムは完成間近で、上司の「急用」も先延ばしにはできません。未完成のソフトウェア開発状態に緊急の調整要求が重なるのは、ソフトウェア品質に対する大きな試練と言えます。こんな悩みがあるなら、Git がそのタスクを美しく完了する手助けをしてくれます。

## git stash コマンドを理解する

Git のバージョン管理を使う際、「ワーキングディレクトリ」と「インデックス」の区別があることは分かっています。ワーキングディレクトリには、途中まで変更して完成していないファイル（まだインデックスに追加されていない）や、まだ追加されていない新規ファイル（まだインデックスに追加されていない）があります。インデックスに置かれたデータは、`git commit` を通じてバージョンを作成（commit オブジェクトを作成）する予定の内容です。

機能開発が半分ほど進んだところで急に中断されると、慌ててしまうのは当然です。特に、手元にある書きかけのプログラムをどう扱えばよいか分からないときはなおさらです。Git には `git stash` コマンドがあり、書きかけのファイルに対して自動的に「特殊なバージョン」（これも commit オブジェクトです）を作成する手助けをしてくれます。私たちはこれらのバージョンを stash バージョンと呼びます。あるいは直接「退避バージョン」と呼んでもよいでしょう。

## stash バージョンを作成する

途中まで変更したファイルには、以下のような状態がありえます。

* 新規ファイル（追跡されていないファイル）
* 新規ファイル（すでにインデックスに追加されたファイル）（追跡済み／ステージ済みファイル）
* 変更されたファイル（まだインデックスに追加されていないファイル）（追跡済み／未ステージのファイル）
* 変更されたファイル（すでにインデックスに追加されたファイル）（追跡済み／ステージ済みファイル）
* 削除されたファイル（まだインデックスに追加されていないファイル）（追跡済み／未ステージのファイル）
* 削除されたファイル（すでにインデックスに追加されたファイル）（追跡済み／ステージ済みファイル）

これらの開発途中のファイルに対して「退避バージョン」を作成したい場合、選択肢は 2 つあります。

* `git stash` はすべての追跡済みファイルに対して退避バージョンを作成します
* `git stash -u` は追跡済み・未追跡を問わず、すべてのファイルを退避バージョンとして作成します

**注意**：`git stash` は `git stash save` と書くこともできます。2 つのコマンドの結果は同じで、`save` パラメータが省略できるだけです。

### ワークフローの例

簡単な実践例を挙げます。

```bash
# You're working on features
echo "new feature" > feature.txt
git add feature.txt

# Suddenly need to fix a bug
# Stash your work-in-progress
git stash

# Now working directory is clean
# Fix the bug on another branch
git checkout main
# ... make fixes ...
git commit -m "Fix urgent bug"

# Return to your feature work
git checkout feature-branch
git stash pop  # Restore your work
```

## 退避した変更を復元する

変更を退避したら、別のブランチに切り替えたり、緊急のタスクに取り組んだりできます。元の作業を続ける準備ができたら、以下の方法で退避した変更を復元できます。

* `git stash pop` - 最新の stash を適用し、stash リストから削除します
* `git stash apply` - 最新の stash を適用しますが、stash リストには残します

## 退避した変更を一覧表示する

何を退避したかを確認するには、以下を使います。

```
git stash list
```

これにより、stash 参照（stash@{0}、stash@{1} など）とともに、退避したすべての変更が表示されます。

## 特定の stash を適用する

stash が複数ある場合は、その番号を参照して特定のものを適用できます。

```
git stash apply stash@{2}
```

## stash を破棄する

リストから特定の stash を削除するには、以下を使います。

```
git stash drop stash@{0}
```

すべての stash を削除するには、以下を使います。

```
git stash clear
```

## 追跡されていないファイルを退避する

デフォルトでは、`git stash` は追跡済みファイルのみを退避します。追跡されていないファイルも退避するには、以下を使います。

```
git stash -u
```

無視されるファイルも含めてすべてを退避するには、以下を使います。

```
git stash -a
```

## 名前付き stash を作成する

stash に分かりやすいメッセージを付けることができます。

```
git stash save "Work in progress on feature X"
```

これにより、後で stash を識別しやすくなります。

## stash の内容を表示する

特定の stash を適用せずに中身を確認するには、以下を使います。

```
git stash show stash@{0}
```

詳細な差分を見るには、以下を使います。

```
git stash show -p stash@{0}
```

## 本日のまとめ

`git stash` コマンドは非常に実用的なツールで、現在の作業をコミットすることなく一時的に脇に置いておくことができます。これは、別の作業をするために素早くコンテキストを切り替える必要がある場合に特に便利です。stash の仕組みにより、作業途中の変更は安全に保存され、後で復元できます。

本日学んだ Git コマンドとパラメータを整理しておきます。

* git stash
* git stash save
* git stash -u
* git stash list
* git stash pop
* git stash apply
* git stash drop
* git stash clear
* git stash show
