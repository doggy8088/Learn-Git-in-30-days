# Day 24: GitHub リモートリポジトリを使う - 入門編

GitHub は現在、世界で最も広く採用されている Git のオンライン管理プラットフォームです。完全な Git リモートリポジトリの実装、包括的な課題追跡の仕組みとレポートを備え、数千ものオープンソースプロジェクトが Git バージョン管理に GitHub を使っています。多くの企業でも、GitHub が主要な Git プラットフォームとして採用されています。本記事では、GitHub の最も基本的な使い方を案内します。

## GitHub とは

GitHub は Web ベースのプラットフォームで、以下の機能を提供します。
* クラウドで Git リポジトリをホストします
* コラボレーションツール（Issue、プルリクエスト、プロジェクトボード）を提供します
* GitHub Actions による CI/CD を提供します
* コードレビューとディスカッションを可能にします
* オープンソースプロジェクト向けに無料のホスティングを提供します
* 開発者とオープンソースプロジェクトのためのソーシャルプラットフォームとして機能します

## GitHub アカウントを作成する

1. https://github.com にアクセスします
2. 「Sign up」をクリックします
3. 登録手順に従います
4. メールアドレスを確認します

## GitHub で新しいリポジトリを作成する

GitHub リポジトリを作成する際には、主に 2 つのアプローチがあります。

1. **空のリポジトリ（初期コミットなし）**：プッシュしたい既存のローカルリポジトリがある場合に最適です
2. **初期化されたリポジトリ（初期コミットあり）**：GitHub が README、.gitignore、ライセンスファイルを作成してくれます

### 空のリポジトリを作成する

1. 右上の「+」アイコンをクリックします
2. 「New repository」を選択します
3. 以下を入力します。
   * **Repository name**
   * **Description**（任意）
   * **Public or Private**
   * 「Initialize this repository with a README」には**チェックを入れないでください**
   * .gitignore とライセンスは「None」のままにします
4. 「Create repository」をクリックします

作成後、GitHub には既存のリポジトリをプッシュする手順が表示されます。

### 初期化されたリポジトリを作成する

1. 上記の手順 1～3 に従います
2. 「Initialize this repository with a README」に**チェックを入れます**
3. 任意で以下を選択します。
   * 言語に合った **.gitignore テンプレート**
   * プロジェクトの**ライセンス**
4. 「Create repository」をクリックします

GitHub が、選択したファイルを含む初期コミットを作成します。

## ローカルリポジトリを GitHub に接続する

### オプション 1：既存のリポジトリをプッシュする

```
# Add remote
git remote add origin https://github.com/username/repo-name.git

# Push to GitHub
git push -u origin main
```

### オプション 2：GitHub からクローンする

```
# Clone the repository
git clone https://github.com/username/repo-name.git

# Navigate to the directory
cd repo-name
```

## リモートを理解する

リモートとは、別の場所でホストされているリポジトリへの参照です。よく使うコマンドは以下のとおりです。

```
# List remotes
git remote -v

# Add a remote
git remote add <name> <url>

# Remove a remote
git remote remove <name>

# Rename a remote
git remote rename <old> <new>

# Change remote URL
git remote set-url origin <new-url>
```

## GitHub にプッシュする

コミットを GitHub にプッシュします。

```
# Push to the default branch
git push origin main

# Push all branches
git push --all

# Push tags
git push --tags
```

`-u` フラグはアップストリームの追跡を設定します。

```
git push -u origin main
# After this, you can just use:
git push
```

## GitHub からプルする

GitHub から更新を取得します。

```
# Fetch changes
git fetch origin

# Fetch and merge
git pull origin main

# If upstream is set
git pull
```

## 認証方法

### HTTPS

ユーザー名とパスワード／トークンが必要です。

```
https://github.com/username/repo-name.git
```

### SSH

SSH キーの設定が必要です。

```
git@github.com:username/repo-name.git
```

SSH キーを設定するには、以下のようにします。

```
# Generate SSH key
ssh-keygen -t ed25519 -C "your.email@example.com"

# Add to ssh-agent
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# Copy public key
cat ~/.ssh/id_ed25519.pub
# Add this key to GitHub settings
```

### Personal Access Token

HTTPS 認証用です。

1. GitHub Settings > Developer settings > Personal access tokens に移動します
2. 新しいトークンを生成します
3. プッシュ時にトークンをパスワードとして使います

## GitHub の機能

### Issues

バグ、機能拡張、タスクを追跡します。

* 分かりやすいタイトルを作成します
* バグについては再現手順を提供します
* 整理のためにラベルを使います
* コミットやプルリクエストを参照します

### Wiki

プロジェクトのドキュメントです。

* 入門ガイド
* API ドキュメント
* FAQ
* アーキテクチャ図

### Projects

カンバンボードで作業を整理します。

* To Do
* In Progress
* Done

### Releases

重要なマイルストーンを記録します。

1. 「Releases」に移動します
2. 「Draft a new release」をクリックします
3. タグを選択します
4. リリースノートを追加します
5. 必要に応じてバイナリを添付します

## GitHub ワークフローのベストプラクティス

1. **頻繁にコミットする**：小さく論理的なコミットを作成します
2. **良いメッセージを書く**：何をしたかだけでなく、なぜしたかを説明します
3. **プッシュする前にプルする**：常に最新の変更を先に取得します
4. **ブランチを使う**：main に直接コミットしないでください
5. **コードをレビューする**：変更にはプルリクエストを使います

## よくある作業

### リポジトリをフォークする

1. リポジトリページで「Fork」をクリックします
2. フォークをクローンします。
   ```
   git clone https://github.com/your-username/repo-name.git
   ```
3. アップストリームリモートを追加します。
   ```
   git remote add upstream https://github.com/original-owner/repo-name.git
   ```

### フォークを同期する

```
git fetch upstream
git checkout main
git merge upstream/main
git push origin main
```
