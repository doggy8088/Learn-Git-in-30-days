# Day 20: コミット済み履歴の修正 Part 2（revert）

バージョン管理プロセスでは、もう 1 つよくある状況があります。複数のコミットを実行した後、以前のコミットの一部が間違っていたことに気づく場合です。たとえば、誤ってテストコードをコミットしてしまい、現在のバージョンに問題が生じるような場合です。この場合、本記事で説明する内容を理解する必要があります。

Day 18 では、ローカルのコミット履歴を修正するための `git reset` と `git commit --amend` について学びました。しかし、これらのコマンドは履歴を書き換えるため、共有リポジトリにプッシュされたコミットには使うべきではありません。共有履歴については、`git revert` が安全な代替手段です。

## git revert を理解する

`git revert` は、以前のコミットの変更を取り消す新しいコミットを作成します。`reset` とは異なり、履歴を書き換えるのではなく、履歴に追加します。このため、共有ブランチに対して安全です。

この時点で、以前のコミット（`HEAD~` や `HEAD^`、または特定のコミットハッシュなど）が誤って行われたことに気づいたとします。最初のバージョンにリセットしてすべてやり直すのではなく、**その特定のバージョンだけ**を元に戻したいとします。この場合、`git revert` コマンドを試すことができます。これは「逆方向」の手順を通じて、あるバージョンの変更を取り消すことができます。

「逆方向」とはどういう意味でしょうか。すぐにこのコマンドを試してみましょう。

**重要な注意**：`git revert` コマンドを実行する前に、ワーキングディレクトリがクリーンであることを確認してください！部分的に変更されたファイルがある場合は、`git stash` を使って一時的な stash を作成することをお勧めします。

## 基本的な revert

最新のコミットを元に戻すには、以下を使います。

```
git revert HEAD
```

これにより、最新コミットの変更を取り消す新しいコミットが作成されます。

## 特定のコミットを元に戻す

`git log` 履歴から問題のあるバージョンを見つけたとします。まず、このバージョンの変更記録を確認できます。`git log` を使ってコミット ID を見つけ、その後 `git show [commit_id]` を使ってそのバージョンの関連情報を見ることができます。

特定のコミットを元に戻すには、以下を使います。

```
git revert <commit-hash>
```

たとえば、以下のとおりです。

```
git revert a1b2c3d
```

実行中、最終的なコミットメッセージの編集を求められます。デフォルトでは、`Revert` という単語が追加され、3 行目に `This reverts commit xxxx` が追加され、このバージョンの主な目的が `xxxx` バージョンを元に戻すことであることを示します。

## 複数のコミットを元に戻す

コミットの範囲を元に戻すには、以下を使います。

```
# Revert commits from HEAD~3 to HEAD~1 (3 commits)
git revert HEAD~3..HEAD
```

または、複数の特定のコミットを元に戻します。

```
git revert <hash1> <hash2> <hash3>
```

## コミットせずに元に戻す

自動的にコミットせずに、revert の変更をステージするには、以下を使います。

```
git revert --no-commit HEAD
# or
git revert -n HEAD
```

これは、複数のコミットを元に戻して 1 つの revert コミットを作成したい場合に便利です。

```
git revert --no-commit HEAD~3..HEAD
git commit -m "Revert last 3 commits"
```

## 競合を処理する

コミットを元に戻すと、競合が発生することがあります。

```
git revert <commit-hash>
# If conflicts occur...
# 1. Resolve conflicts in the files
# 2. Stage the resolved files
git add <resolved-files>
# 3. Continue the revert
git revert --continue
```

進行中の revert を中止するには、以下を使います。

```
git revert --abort
```

## マージコミットを元に戻す

マージを元に戻すのはより複雑です。マージコミットには 2 つの親があるためです。どの親に戻すかを指定しなければなりません。

```
# -m 1 means keep changes from the first parent (usually mainline)
git revert -m 1 <merge-commit-hash>
```

## revert と reset をいつ使うか

**`git revert` を使う場合：**
* コミットが共有リポジトリにプッシュされている場合
* 履歴を保持したい場合
* 公開ブランチ（main、develop など）で作業している場合
* 元に戻す操作の記録が必要な場合

**`git reset` を使う場合：**
* コミットがローカルリポジトリにのみ存在する場合
* コミットを履歴から完全に削除したい場合
* プライベートな機能ブランチで作業している場合
* コミットが履歴に残すべきでないミスだった場合

## 変更を元に戻して再適用する

コミットを元に戻した後、後になって再適用したいことがあります。

```
# First, revert a commit
git revert <commit-hash>

# Later, revert the revert
git revert <revert-commit-hash>
```

## 実践例

### 例 1：メインブランチの悪いコミットを元に戻す

```
# Commit a1b2c3d introduced a bug
git revert a1b2c3d
git push origin main
```

### 例 2：複数のコミットを元に戻す

```
# Revert the last 5 commits as a single revert commit
git revert --no-commit HEAD~5..HEAD
git commit -m "Revert last 5 commits due to critical bug"
git push origin main
```

### 例 3：元に戻してから修正する

```
# Revert a problematic commit
git revert a1b2c3d

# Make necessary corrections
# ... edit files ...

# Commit the corrections
git add .
git commit -m "Fix issues from reverted commit"
git push origin main
```

## ベストプラクティス

1. **明確なメッセージを書く**：なぜ元に戻すのかを説明します
   ```
   git revert a1b2c3d -m "Revert feature X due to performance issues"
   ```

2. **プッシュする前にテストする**：revert が何も壊さないことを確認します

3. **コミュニケーションを取る**：コミットを元に戻した際はチームに知らせます

4. **代替手段を検討する**：前方修正の方が revert より良い場合もあります

5. **理由を文書化する**：Issue 番号を参照したり、コンテキストを提供したりします

## revert 履歴を表示する

履歴内の revert コミットを見るには、以下を使います。

```
git log --oneline --grep="Revert"
```

## 本日のまとめ

`git revert` は、共有リポジトリで変更を取り消すための安全な方法です。不要な変更を取り消しながら、履歴の整合性を維持します。`revert` と `reset` のどちらを使うべきかを理解することは、効果的なコラボレーションと、クリーンで分かりやすいプロジェクト履歴の維持にとって極めて重要です。

本日学んだ Git コマンドとパラメータを整理しておきます。

* git revert
* git revert HEAD
* git revert <commit-hash>
* git revert --no-commit
* git revert -n
* git revert -m
* git revert --continue
* git revert --abort
