# Day 09: ファイルとバージョンの差分を比較する

どのようなバージョン管理ソフトウェアを使う過程でも、履歴記録を表示したり、バージョン間の差分を比較したりする必要がよくあります。Git でどのように比較するかが本記事の焦点です。

## ワーキングディレクトリの準備

以下のコマンドで、2 つのファイルと 2 件のバージョン変更記録を持つ Git リポジトリとワーキングディレクトリを素早く作成します。

```
mkdir git-demo
cd git-demo
git init

echo 1 > a.txt
echo 2 > b.txt
git add .
git commit -m "Initial commit"

echo 3 > a.txt
echo 4 > b.txt
git add .
git commit -m "Update a.txt and b.txt to 3 and 4"
```

## git diff の基本概念

Git で 2 つのバージョン間の差分を比較するには、通常 `git diff` コマンドを使います。まず簡単なコマンドを実行して、2 つのバージョン間の差分を比較してみましょう。

1. まず `git log` を実行してバージョン情報を取得し、最後の 2 つの commit オブジェクトの ID を取得します
2. `git diff commit1 commit2` コマンドを実行して 2 つのバージョン間の差分を比較します。ここで commit1 には古いバージョンを、commit2 には新しいバージョンを使う必要があります。

`git diff` の実行出力から、実行結果が得られます。これら 2 つのリポジトリには 2 つのファイルがあり、どちらもこれら 2 つのバージョンの間で変更されているため、「差分比較」の結果が 2 セグメント分リストされます。

上記の図から分かるように、各セグメントは `diff --git` で始まり、git がどの 2 つのファイルを比較しているかを表します。

2 行目の `index 37bcc8b..d855592 100644` は、git がこの比較を実行する際の「ヘッダー行（Header Line）」を表します。ここには数行ある場合があり、情報は必ずしもこれだけとは限りません。この差分比較に関する多くの追加情報がここに記されます。たとえば index 行、その後ろの 2 つのハッシュ ID（`37bcc8b..d855592`）は、比較対象の 2 つの blob オブジェクトを表す、Git オブジェクトストレージ（object storage）内の 2 つの blob オブジェクト ID です。その後ろの `100644` は git の属性であり、Linux 環境のファイル属性のようなもので、これはファイルか、ディレクトリか、読み取り可能か、書き込み可能か、実行可能かなどを宣言します。git 属性の一般的な例をいくつか挙げます。

```
0100000000000000 (040000): Directory
1000000110100100 (100644): Regular non-executable file
1000000110110100 (100664): Regular non-executable group-writeable file
1000000111101101 (100755): Regular executable file
1010000000000000 (120000): Symbolic link
1110000000000000 (160000): Gitlink
```

関連リンクについては、以下のディスカッションスレッドを参照してください。

* [How to read the mode field of git-ls-tree's output](https://stackoverflow.com/a/8347325/910074)

3 行目の `--- a/a.txt` は、比較される 2 つのバージョンのうち「古い」バージョンを表します。

4 行目の `+++ b/a.txt` は、比較される 2 つのバージョンのうち「新しい」バージョンを表します。

5 行目の `@@ -1 +1 @@` は、このファイルの旧バージョンと新バージョンの総行数を表します。-1 は旧バージョンが 1 行のみであることを表し、+1 は新バージョンも 1 行のみであることを表します。

最後に、変更された内容がすべてリストされます。ここには 3 つの可能な表現があります。

* マイナス記号 - で始まる場合、その行が旧バージョンから新バージョンへの過程で削除されたことを意味します。
* プラス記号 + で始まる場合、その行が旧バージョンから新バージョンへの過程で追加されたことを意味します。
* 空白文字で始まる場合、その行が両方のバージョンに変更なく現れることを意味します。

これで、これら 2 つのバージョンにおける最初の blob オブジェクトの差分比較が完了し、次にそのバージョンにおける 2 番目の blob オブジェクトの差分比較が表示され、以下同様に続きます。

Git で `git diff` を使う場合、実際には tree オブジェクトが比較の単位となります。[Day 06: Git のデータ構造を解析する - オブジェクト構造] の図と動画で学んだように、各 commit オブジェクトには実際にはルートディレクトリの tree オブジェクトが含まれています。そのため、先ほど `git diff` を使って 2 つの commit オブジェクトを比較したとき、実際にはそれらの commit オブジェクト配下の tree オブジェクトを比較していたのであり、比較プロセスは再帰的に下へ続いていきます。これにより、Git の diff 比較の仕組みが非常に強力であることを感じられるはずです。任意の 2 つのバージョン間の変更を素早く比較できます。

`git diff` コマンドを使う際、tree オブジェクトのソースは主に 3 つあります。

* すべてのコミットグラフに存在する tree オブジェクト。つまり、任意のバージョンにおける任意の tree オブジェクトを意味します。
* Index。ファイルの状態を「インデックスデータベース」に送った後の情報を表します。実際、tree オブジェクトは `git add` コマンドを使うときにすでに作成されています。
* 現在のワーキングディレクトリ。ワーキングディレクトリへの変更はまだ tree オブジェクトになっていませんが、`git diff` を通じて使うことができます。

## 4 つの基本的な比較方法

`git diff` コマンドで任意の 2 つのバージョンを比較するには、通常、次の 4 つのコマンドの使い方があります。

1. git diff

   パラメータなしの場合、比較されるのは「ワーキングディレクトリ」と「インデックス」の差分です。これは非常によく使われるコマンドです。`git add .` コマンドを実行する前に、まず `git diff` を使って自分が何を変更したかを確認できるためです。

   **注記**： 実際、Git バージョン管理を使う過程では、`git commit` を実行する前に、`git add` コマンドを数回実行して、どのファイルをインデックスに追加するかを確認し、最終的にバージョンにコミットすることは確かに可能です。

2. git diff commit

   `git diff` の後に commit ID を 1 つだけ追加した場合、比較されるのは「ワーキングディレクトリ」と「指定された commit オブジェクト内の tree オブジェクト」です。

   最もよく使われるコマンドは `git diff HEAD` です。これは「ワーキングディレクトリ」と「現在のブランチの最新バージョン」を比較することを表すためです。この比較方法は「インデックス」の状態を比較しないため、自分がどの tree オブジェクトのソースを比較しているのかを明確に区別しなければなりません。

3. git diff --cached commit

   `git commit` を実行する前には、インデックスの状態が準備できているはずです。そのため、「現在のインデックスの状態」と「指定された commit オブジェクト内の tree オブジェクト」を比較したい場合は、このコマンドを使って比較タスクを完了できます。

   最もよく使われるコマンドはやはり `git diff --cached HEAD` であり、「現在のインデックスの状態」と「現在のブランチの最新バージョン」を比較することを意味します。この比較方法は「ワーキングディレクトリ」のファイル内容を比較せず、「インデックス」と「現在の最新バージョン」の差分を直接比較します。これにより、`git commit` を実行する前にどのような変更があるか、つまりどのような変更をバージョンとして作成することになるかを知ることができます。

   **注記 1**： `git diff --cached` と `git diff --staged` はまったく同じ結果になります。`--staged` は `--cached` の別名にすぎず、覚えやすくするためのものです！

   **注記 2**： `git diff --cached` と `git diff --cached HEAD` も実行結果はまったく同じです。最後の HEAD は省略できます。

4. git diff commit1 commit2

   最後は、異なる 2 つのバージョン（commit ID）間の差分を比較するものです。このコマンドは「インデックス」と「ワーキングディレクトリ」の変更をすべてスキップし、2 つの特定のバージョンを直接比較できます。実際、Git はそれら 2 つの特定のバージョンの commit オブジェクト内の tree オブジェクトを比較します。

   最もよく使われるコマンドは `git diff HEAD^ HEAD` であり、[最新バージョンの 1 つ前のバージョン] と [最新バージョン] の差分を比較したいことを意味します。ここでの HEAD と ^ の意味は、今後の記事で説明します。

## 本日のまとめ

本日紹介した `git diff` は非常によく使われるコマンドであり、熟練して使えるようになるべきです。最後に、そのよく使われるコマンドの差分を復習しましょう。

```
git diff                 => working directory vs index
git diff HEAD            => working directory vs HEAD
git diff --cached HEAD   => index     vs HEAD
git diff --cached        => index     vs HEAD
git diff HEAD^ HEAD     => HEAD^   vs HEAD
```

* git log
* git diff
* git diff HEAD
* git diff --cached
* git diff --staged
* git diff HEAD^ HEAD
