# Day 05: リポジトリ、ワーキングディレクトリ、オブジェクト、インデックスの関係を理解する

Git バージョン管理を使う過程では、より効率的かつ有意義に学べるよう、いくつかの非常に基本的な概念を確立しなければなりません。明確で正しい概念に支えられていれば、Git のコマンド操作を学ぶ助けになるだけでなく、より重要なことに、Git 関連の知識を学ぶことが容易になります。

## リポジトリを理解する

Git をバージョン管理に使うとき、当然ながら、このバージョン情報を格納するための「リポジトリ」が必要です。英語の Repository という単語がこれを意味します。私はこの英語の単語を「儲存庫」と訳すことに慣れています。これは、すべてのバージョンを格納するために使われる空間、あるいはフォルダとファイルの集合を表します。

Git を使った経験がある方なら、リポジトリを作成する方法がたくさんあることをよくご存じのはずです。任意のフォルダに Git リポジトリを作成したい場合は、次のコマンドを入力するだけで作成が完了します。

    git init

Git リポジトリを作成するプロセスを表した以下の図を通じて、G:\git-demo ディレクトリで git init を実行すると、Git がそのディレクトリの .git ディレクトリにいわゆる Git リポジトリを自動的に作成してくれることが明確に分かります。疑う余地はありません。この .git フォルダが完全な Git リポジトリです。今後、すべてのバージョン変更は自動的にこのフォルダに保存されます。

## ワーキングディレクトリを理解する

上記の例では、ディレクトリ G:\git-demo が自動的に私たちの「ワーキングディレクトリ」になります。「ワーキングディレクトリ」の意味は、プロジェクトファイルの開発を準備する場所であり、今後のすべての作業はこのディレクトリで編集されます。ファイルの追加、ファイルの変更、ファイルの削除、ファイルの名前変更など、Git 関連の操作はすべてこのディレクトリで完結するため、「ワーキングディレクトリ」と呼ばれます。

Git 関連のコマンドパラメータを操作するときは、通常「ワーキングディレクトリ」で実行します。

Git バージョン管理を使う際にはブランチの状況が多く発生するため、ワーキングディレクトリは異なるブランチの間で切り替わることがあります。git コマンドの中には、実行されるとワーキングディレクトリ内のファイルを更新するものがあります。たとえば、git checkout を使って別のブランチに切り替える場合、現在のブランチのディレクトリ構造は切り替え先のブランチとまったく同じではないため、現在のワーキングディレクトリ内のファイルが更新され、現在のワーキングディレクトリ配下のディレクトリとファイルが、切り替え先の別ブランチ配下のディレクトリとファイルと同じになる可能性が非常に高いです。

そのため、適切なタイミングでワーキングディレクトリをクリーンに保つことは、バージョン管理プロセスにおける基本原則であり、特に将来マージを行う際には重要です。関連知識については、今後の記事でさらに説明します。

## Git のデータ構造を理解する

Git には 2 つの重要なデータ構造があります。すなわち「オブジェクト」と「インデックス」です。

「オブジェクト」はリポジトリ内のすべてのファイルとバージョン記録を保存するために使われ、「インデックス」はリポジトリに入る前のディレクトリの状態を保存するために使われます。

## オブジェクトについて

いわゆる「オブジェクト」は「特殊なファイル」です。このファイルの生成プロセスは非常に興味深いものです。ファイルの内容を取り、その内容から SHA1 ハッシュ値を生成し、その SHA1 ハッシュ値に従ってファイルに名前を付けます。

Git をバージョン管理に使う過程では、管理対象となるすべてのディレクトリとファイルは、まず「ディレクトリ情報」と「ファイルの内容」に区別されます。これらを tree オブジェクトと blob オブジェクトと呼びます。

そのうち、blob オブジェクトは元の「ファイルの内容」を blob ファイルの内容として使用し（注：blob オブジェクトは実際には物理ファイルです）、その内容に対して SHA1 ハッシュ演算を実行してハッシュ ID を生成し、そのハッシュ ID を blob ファイルのファイル名として使用します。これにより、blob オブジェクトは「内容のみ」を持つファイルであることが分かります。そのファイル名は内容から生成されるため、単一の blob ファイルだけでは通常、バージョン管理の助けにはなりません。

もう一方の tree オブジェクトは、特定のフォルダにどのファイルが含まれているか、そのファイルに対応する blob オブジェクトのファイル名は何かを格納するために使われます。tree オブジェクトには、blob オブジェクトのファイル名と関連情報が含まれるだけでなく、他の tree オブジェクトも含めることができます。そのため、tree オブジェクトは実際には「フォルダ」の同義語です。

blob オブジェクトと tree オブジェクトのいずれであっても、これらはすべてオブジェクトであり、これらのオブジェクトは「オブジェクトストレージ」（object storage）と呼ばれる場所に保存されます。この「オブジェクトストレージ」は、デフォルトでは「リポジトリ」の objects ディレクトリにあります。以下の図のとおりです。

## インデックスについて

いわゆる「インデックス」は頻繁に変更される一時ファイルであり、通常は .git ディレクトリ内の index という名前のファイルにあります。簡単に言えば、「インデックス」の目的は主に「次のコミットバージョンに提出されるファイルはどれか」を記録することです。言い換えれば、Git リポジトリにバージョンを提出したい場合は、まずインデックスの状態を更新しなければならず、その変更が提出されます。

このインデックスファイルは通常、Git リポジトリ内の特定のバージョンの状態を保存します。この状態は、任意のコミットオブジェクトと tree オブジェクトで表すことができます。

通常、私たちは .git\index バイナリファイルを直接編集することはなく、標準の git コマンドを通じてこのインデックスファイルを操作します。インデックスファイルを操作するコマンドは、おおよそ以下のとおりです。

* git add
* git mv
* git rm
* git status
* git commit
* git ls-files

Git の「インデックス」は、「オブジェクトストレージ」（object storage）と「ワーキングディレクトリ」（working directory）の間の媒体です。

本記事が詳しく説明したいこれらの概念の関係は、以下の 5 つのステップで説明できることにお気づきかもしれません。

* Git バージョン管理を使うには、まず「ワーキングディレクトリ」と「リポジトリ」を作成しなければなりません。（mkdir、git init）
* まず「ワーキングディレクトリ」で開発しなければなりません。ディレクトリの作成、ファイルの作成、ファイルの変更、ファイルの削除などの操作を行うことがあります。
* 次に、Git の「リポジトリ」に新しいバージョンを提出したい場合は、まず「インデックス」の状態を更新しなければなりません。（git add、git mv など）
* 次に Git は、「インデックス」の現在の状態に基づいて、どのファイルを Git の「リポジトリ」に提出するかを決定します。（git status）
* 最後に、変更を提出する（git commit）と、バージョン情報が「オブジェクトストレージ」に書き込まれます（このとき、コミットオブジェクトが書き込まれます）。

インデックスの詳細な構造とコマンド操作については、今後の記事で取り上げます。

    Note: tree の概念はディレクトリと非常に似ているため、外国の原文を読む際、working directory はしばしば working tree と書かれます！

## 本日のまとめ

本日議論した Git アーキテクチャで最も重要なことは、「オブジェクト」と「インデックス」の関係です。「インデックス」情報がなければ、Git はバージョンを作成できないためです。

「オブジェクト」と「インデックス」の違いに基づけば、「オブジェクト」は「不変の（immutable）」ファイルタイプであることが分かるはずです。原則として、「オブジェクトストレージ」に書き込まれたオブジェクトは二度と変更されません。すべてのオブジェクトは元のファイルの内容から生成されるためです。これは「オブジェクトデータベース」（object database）とも言えます。このデータベースは通常、内容が増える一方で、「内容を削除する」や「内容を変更する」ケースは少なくなります。データが削除されるのは、git gc を実行してガベージデータをクリーンアップするときだけです。「インデックス」は「変更可能な（mutable）」インデックスファイルであり、現在のワーキングディレクトリがコミットする準備のできている内容を記録するために使われます。

一歩一歩 Git の核心に近づき、曖昧で不明確な抽象概念を具体的な概念的知識へとゆっくり変換していくことで、Git に対して不安を感じることはなくなります。成功は目の前です。引き続き学習に励んでください。
