# Day 21: コミット済み履歴の修正 Part 3（cherry-pick）

バージョン管理プロセスでは、もう 1 つよくある状況があります。あるブランチでしばらく開発を進めてきたものの、後になってそのブランチ全体はもう不要だと判断する場合です。しかし、その中には残しておきたいコミットがいくつか含まれています。この場合、ブランチを削除することはできず、かといってブランチ全体をマージして戻すのも適切ではありません。どうすればよいでしょうか。本記事では、`git cherry-pick` コマンドを使って、適用したい変更を「手動で選択」する方法を説明します。

## git cherry-pick を理解する

ブランチ全体をマージすることなく、あるブランチの特定のコミットを別のブランチに適用したい場合があります。Git の `cherry-pick` コマンドを使えば、まさにそれが可能になります。コミットを選択して、現在のブランチに適用できます。

`git cherry-pick` は、既存のコミットで導入された変更を現在のブランチに適用します。同じ変更内容を持つ新しいコミットが作成されますが、コミットハッシュは異なります。

## 基本的な cherry-pick

単一のコミットを cherry-pick するには、以下を使います。

```
# Switch to the target branch
git checkout main

# Cherry-pick the commit
git cherry-pick <commit-hash>
```

これにより、指定したコミットと同じ変更内容を持つ新しいコミットが、現在のブランチに作成されます。

## 複数のコミットを cherry-pick する

複数のコミットを cherry-pick するには、以下を使います。

```
# Cherry-pick several commits
git cherry-pick <hash1> <hash2> <hash3>
```

コミットの範囲を cherry-pick するには、以下を使います。

```
# Cherry-pick commits from commit1 to commit2 (exclusive of commit1)
git cherry-pick commit1..commit2

# Cherry-pick commits from commit1 to commit2 (inclusive of commit1)
git cherry-pick commit1^..commit2
```

## コミットせずに cherry-pick する

自動的にコミットを作成せずに変更を適用するには、以下を使います。

```
git cherry-pick --no-commit <commit-hash>
# or
git cherry-pick -n <commit-hash>
```

これは、複数のコミットを cherry-pick して 1 つのコミットにまとめたい場合に便利です。

## 競合を処理する

cherry-pick 中に競合が発生した場合は、以下のようにします。

```
# Resolve conflicts in the files
# Stage the resolved files
git add <resolved-files>

# Continue the cherry-pick
git cherry-pick --continue
```

進行中の cherry-pick を中止するには、以下を使います。

```
git cherry-pick --abort
```

現在のコミットをスキップして次のコミットに進むには、以下を使います。

```
git cherry-pick --skip
```

## 編集しながら cherry-pick する

cherry-pick しながらコミットメッセージを編集するには、以下を使います。

```
git cherry-pick -e <commit-hash>
# or
git cherry-pick --edit <commit-hash>
```

## cherry-pick とサインオフ

コミットメッセージにサインオフ行を追加するには、以下を使います。

```
git cherry-pick -s <commit-hash>
# or
git cherry-pick --signoff <commit-hash>
```

## 実践的なユースケース

### ユースケース 1：ホットフィックスを複数のブランチに適用する

```
# Fix created on main branch (commit abc123)
git checkout release-1.0
git cherry-pick abc123

git checkout release-2.0
git cherry-pick abc123
```

### ユースケース 2：機能を選択的に統合する

```
# Feature branch has commits A, B, C, D
# You only want B and C on main

git checkout main
git cherry-pick <hash-B> <hash-C>
```

### ユースケース 3：失われたコミットを復旧する

```
# Find the lost commit using reflog
git reflog

# Cherry-pick it to current branch
git cherry-pick <lost-commit-hash>
```

## cherry-pick、Merge、Rebase の比較

**Cherry-pick**：
* 特定のコミットを選択的に適用します
* 新しいコミットハッシュを作成します
* 選択的な統合に適しています

**Merge**：
* ブランチ全体を結合します
* 完全な履歴を保持します
* 機能ブランチの統合に最適です

**Rebase**：
* 新しいベースの上にコミットを再生します
* 線形な履歴になります
* 履歴の整理に適しています

## ベストプラクティス

1. **控えめに使う**：cherry-pick を多用すると履歴が分かりにくくなります
2. **理由を記録する**：コミットメッセージに cherry-pick した理由を説明します
3. **重複を避ける**：後でマージされる予定のコミットは cherry-pick しないでください
4. **依存関係を確認する**：そのコミットが他のコミットに依存していないことを確認します
5. **cherry-pick 後にテストする**：新しいコンテキストで変更が正しく動作することを確認します

## cherry-pick したコミットを追跡する

Git では cherry-pick したコミットを追跡できます。

```
# Cherry-pick with -x flag
git cherry-pick -x <commit-hash>
```

これにより、コミットメッセージに「(cherry picked from commit ...)」という行が追加されます。

## 避けるべきよくあるミス

1. **マージコミットを cherry-pick する**：通常、問題の原因になります
2. **機能ブランチから main へ cherry-pick する**：マージ時に重複したコミットが作成されることがあります
3. **テストしない**：変更がブランチによって異なる動作をする場合があります
4. **依存関係を無視する**：cherry-pick したコミットが動作するには他のコミットが必要な場合があります

## 本日のまとめ

`git cherry-pick` は、あるブランチから別のブランチへコミットを選択的に適用するための強力なツールです。ホットフィックスを複数のリリースブランチに適用したり、開発ブランチから特定の機能だけを選んだりする場合に特に便利です。ただし、多用すると履歴が複雑になるため、慎重に使うべきです。

本日学んだ Git コマンドとパラメータを整理しておきます。

* git cherry-pick <commit>
* git cherry-pick <commit1> <commit2>
* git cherry-pick commit1..commit2
* git cherry-pick --no-commit
* git cherry-pick -n
* git cherry-pick --continue
* git cherry-pick --abort
* git cherry-pick --skip
* git cherry-pick -e
* git cherry-pick -x
* git cherry-pick --signoff
