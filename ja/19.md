# Day 19: .gitignore の除外リストを設定する

プロジェクトを開発していると、ワーキングディレクトリに新しいファイルが頻繁に現れることがあります（Visual Studio などの開発ツールが生成する一時ファイルやキャッシュファイルなど）。これらのファイルの多くはバージョン管理に含める必要がなく、除外すべきです。私たちはこれを「除外リスト」と呼びます。

## .gitignore を理解する

`.gitignore` ファイルは、Git が無視すべき、意図的に追跡されていないファイルを指定します。Git では、`.gitignore` ファイルを使って「除外リスト」を定義します。主な目的は、バージョン管理に追加する必要のないファイルを除外することです。このファイルに記載されたファイルやパス（ワイルドカードを含むことができます）は `git status` の結果に表示されず、当然、`git add` を実行した際にも追加されません。

ただし、これは `Untracked files` にのみ適用されます。すでに Git によって追跡されているファイル（`Staged files`）は、`.gitignore` ファイルの影響を受けません。

## GitHub を通じて .gitignore を作成する

GitHub でプロジェクトを作成したことがある方は、この機能を使ったことがあるかもしれません。新しいリポジトリを作成する際、GitHub がセットアップを手伝ってくれる、事前に定義された除外リストを選択できます。この除外リストは、実際には `.gitignore` という名前のファイルにすぎず、デフォルトでプロジェクトのルートディレクトリに配置されます。

以下のようなさまざまなテンプレートから選択できます。
- Node
- Python
- Java
- C#
- Visual Studio
- その他多数

## .gitignore を手動で作成する

リポジトリのルートに `.gitignore` という名前のファイルを単に作成します。

```
# On Windows
echo node_modules/ > .gitignore

# On Linux/Mac
echo "node_modules/" > .gitignore
```

または、テキストエディタで手動で作成します。

## 基本的なパターン

### 特定のファイルを無視する

```
config.local.js
secrets.txt
```

### 特定の拡張子を持つファイルを無視する

```
*.log
*.tmp
*.cache
```

### ディレクトリを無視する

```
node_modules/
dist/
build/
```

ディレクトリであることを示す末尾のスラッシュに注意してください。

### 任意のディレクトリ内のファイルを無視する

```
# Ignore all .log files in any directory
**/*.log
```

## 高度なパターン

### 否定（例外）

`!` を使って例外を作ります。

```
# Ignore all .log files
*.log

# But don't ignore important.log
!important.log
```

### 特定のディレクトリ内のファイルのみを無視する

```
# Ignore test.txt only in root directory
/test.txt

# Ignore test.txt in any subdirectory, but not root
*/test.txt
```

### 複数の拡張子

```
# Ignore multiple file types
*.{jpg,png,gif}
```

## グローバルな .gitignore

すべてのリポジトリで無視したいパターンについては、以下を使います。

```
git config --global core.excludesfile ~/.gitignore_global
```

その後、パターンを記載した `~/.gitignore_global` を作成します。

## すでに追跡されているファイルを無視する

無視すべきファイルを誤ってコミットしてしまった場合は、以下を使います。

```
# Remove from Git but keep the file
git rm --cached filename

# Remove directory from Git but keep it
git rm -r --cached directory/
```

その後、パターンを `.gitignore` に追加してコミットします。

## 無視されているファイルを表示する

どのファイルが無視されているかを確認するには、以下を使います。

```
git status --ignored
```

## ファイルが無視される理由を確認する

どのパターンが原因でファイルが無視されているかを確認するには、以下を使います。

```
git check-ignore -v filename
```

## テンプレートの .gitignore ファイル

GitHub は、さまざまな言語やフレームワーク向けのテンプレート .gitignore ファイルを提供しています。

* https://github.com/github/gitignore

## .gitignore 内のコメント

コメントには `#` を使います。

```
# This is a comment
*.log  # Inline comment
```

## ベストプラクティス

1. **.gitignore を早めにコミットする**：プロジェクトの開始時に追加します
2. **具体的にする**：広すぎるパターンは避けます
3. **理由を文書化する**：自明でないパターンを説明するためにコメントを使います
4. **整理しておく**：関連するパターンをグループ化します
5. **テンプレートを使う**：言語固有のテンプレートから始めます
6. **ローカルのバリエーション**：個人的なパターンには `.git/info/exclude` を使います

## サブディレクトリの .gitignore

サブディレクトリにも `.gitignore` ファイルを置くことができます。パターンは `.gitignore` ファイルの場所からの相対パスです。

## 本日のまとめ

`.gitignore` ファイルは、リポジトリをクリーンに保ち、バージョン管理に属さないファイルを誤ってコミットすることを避けるために不可欠です。パターンの構文とベストプラクティスを理解することで、クリーンでプロフェッショナルなリポジトリを維持するのに役立ちます。

本日学んだ Git コマンドとパラメータを整理しておきます。

* git rm --cached
* git rm -r --cached
* git status --ignored
* git check-ignore
* git config core.excludesfile
