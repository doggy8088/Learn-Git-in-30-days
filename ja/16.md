# Day 16: git reflog で変更履歴を追跡する

Git のバージョン管理コマンドを学ぶこと自体は難しくありませんが、Git が実際にリポジトリに対して何をしているのかを理解するのは、かなり難しい場合があります。Git の核となる概念と動作原理を徐々に理解していくことで、Git リポジトリ内のバージョン変更を効果的に制御できるようになります。本記事では、Git が各バージョンの変更履歴をどのように記録するかを説明します。

## git reflog を理解する

`git reflog`（reference log）は、ローカルリポジトリ内のブランチの先端やその他の参照がいつ更新されたかを記録する仕組みです。Git の基本原理とオブジェクト構造を十分に理解するまでは、バージョンの記録プロセスを真に理解することはできません。バージョンの記録プロセスが分からなければ、「自分のバージョンはどこへ行ったのか」と不安になるのは当然です。「バージョン管理を使っているのだから、すべてのバージョンは保存されている。自由にコードを変更してよい」という言葉を聞いたことがあるかもしれません。これを知っていることと、やり方を知っていることは別問題であり、実際にできるかどうかはまた別の問題です。

幸いなことに、Git には厳密なログの仕組みがあり、この仕組みは非常にオープンです。ログファイルはすべてテキスト形式で、かなり理解しやすくなっています。このバージョン記録プロセスを説明しましょう。

reflog は特に以下の用途で役立ちます。

* どのブランチからも到達できなくなったコミットを見つける
* 誤った reset や rebase から復旧する
* リポジトリで自分が何をしたかを把握する
* 誤った変更を取り消す

## logs ディレクトリ

任意の Git ワーキングディレクトリの `.git/` フォルダに入ると、`logs` ディレクトリが見えます。この `logs` フォルダには、「現在のブランチ」のバージョン変更履歴を記録する `HEAD` ファイルが含まれています。

ファイルの内容は以下のようになっています（読みやすさのため、オブジェクト ID は省略されています）。

```
0000000 f5685e0 Will <xxxx@gmail.com> 1381718394 +0800	commit (initial): Initial commit
f5685e0 38d924f Will <xxxx@gmail.com> 1381718395 +0800	commit: a.txt: set 1 as content
38d924f efa1e0c Will <xxxx@gmail.com> 1381734238 +0800	commit: test
efa1e0c af493e5 Will <xxxx@gmail.com> 1381837967 +0800	commit: Add c.txt
```

## 基本的な使い方

reflog を表示するには、以下を使います。

```
git reflog
```

これにより、最近のアクションが新しい順に一覧表示されます。テキストファイルでは一番上に「最初のバージョン」が見えますが、`git reflog` を通すと「最新バージョン」が最初に表示され、「最初のバージョン」は最後に表示されます。

各エントリには以下が表示されます。

* コミットハッシュ
* 参照（通常は HEAD）
* 実行されたアクション
* コミットメッセージ

## reflog の形式

出力は以下のようになります。

```
a1b2c3d HEAD@{0}: commit: Add new feature
e4f5g6h HEAD@{1}: checkout: moving from master to feature-branch
i7j8k9l HEAD@{2}: reset: moving to HEAD~1
```

`HEAD@{n}` 表記は、HEAD の n 個前の値を指します。ここで、履歴ログ内の各バージョンには、ログファイル内でのこのバージョンの位置を表す番号があります。`HEAD@{0}` は常に現在のブランチの「最新バージョン」、言い換えれば、この「ブランチ」に対してあなたが最後に行った Git 操作を表します。Git に対して行ったあらゆるバージョン変更は完全に記録されます。

## 誤った変更から復旧する

Git を使い始めたばかりの初心者は、誤って間違ったコマンドを実行することがあります。たとえば、`git merge` 中に競合が発生したり、リモートリポジトリから最新バージョンを取得するために `git pull` を実行した際にミスが起きたりといった場合です。このような状況では、特殊な「参照名」`HEAD@{n}` を使ってこのバージョンを「特定」し、現在の Git リポジトリのバージョンを以前のバージョンに復元できます。

たとえば、最新のバージョン記録を「取り消し」たい場合は、`git reset HEAD@{1} --hard` を使って変更を復元できます。これは、もともと `HEAD@{0}` にあった変更が削除されることを意味します。しかし、Git では、あなたが `git reset "HEAD@{1}" --hard` を実行したアクションも含め、すべての変更が記録されます。

これは何を意味するのでしょうか。つまり、どんな Git コマンドを実行する際も、データが失われる心配はもう要らないということです。入力したコマンドがどれほど間違っていても、すでにリポジトリに入っているすべてのファイルは保存され、失われる可能性は絶対にありません。そのため、たった今実行した `git reset "HEAD@{1}" --hard` アクションを取り消したい場合は、もう一度 `git reset "HEAD@{1}" --hard` を実行するだけです。素晴らしいと思いませんか。

## 詳細な reflog を表示する

より詳細な情報を見るには、以下を使います。

```
git reflog show --all
```

特定のブランチの reflog を見るには、以下を使います。

```
git reflog show branch-name
```

## reflog を使ってコミットを復旧する

誤って reset したり、コミットを失ったりした場合は、reflog を使って復旧できます。

```
# Find the commit you want to recover
git reflog

# Reset to that commit
git reset --hard HEAD@{2}
```

または、コミットハッシュを直接使うこともできます。

```
git reset --hard a1b2c3d
```

## 削除されたブランチを復旧する

誤ってブランチを削除した場合は、以下を使います。

```
# Find the commit where the branch was deleted
git reflog

# Recreate the branch
git branch branch-name HEAD@{3}
# or
git branch branch-name <commit-hash>
```

## reflog の有効期限

デフォルトでは、reflog エントリは到達可能なコミットについては 90 日、到達不可能なコミットについては 30 日で期限切れになります。これは以下のように設定できます。

```
git config gc.reflogExpire "90 days"
git config gc.reflogExpireUnreachable "30 days"
```

## reflog をクリーンアップする

reflog エントリを手動でクリーンアップするには、以下を使います。

```
# Remove old reflog entries
git reflog expire --expire=now --all

# Run garbage collection
git gc --prune=now
```

## reflog の制限事項

覚えておくべき重要なポイントは以下のとおりです。

* reflog はローカルのみであり、他の人とは共有されません
* reflog はリポジトリに対する変更を追跡するもので、ファイルを追跡するものではありません
* コミットの復旧には役立ちますが、コミットされていない変更は復旧できません

## 実践例

### 例 1：ハードリセットを取り消す

```
# You accidentally reset
git reset --hard HEAD~3

# Find the old position
git reflog

# Restore to the old position
git reset --hard HEAD@{1}
```

### 例 2：誤った rebase からの復旧

```
# After a problematic rebase
git reflog

# Find the commit before the rebase (usually labeled "rebase finished")
git reset --hard HEAD@{5}
```

## 本日のまとめ

`git reflog` は強力な安全機能であり、多くの Git のミスからあなたを救ってくれます。reset、rebase、ブランチの削除といった操作から復旧する必要がある場合に特に価値があります。定期的なバックアップの代わりにはなりませんが、ローカルでの復旧には欠かせないツールです。

本日学んだ Git コマンドとパラメータを整理しておきます。

* git reflog
* git reflog show
* git reflog show --all
* git reset --hard HEAD@{n}
* git branch branch-name HEAD@{n}
* git reflog expire
* git gc
