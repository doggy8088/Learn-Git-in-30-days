# Day 25: GitHub リモートリポジトリを使う - 概念編

Day 24 の基礎を踏まえ、本記事では GitHub リモートリポジトリを扱う際の重要な概念とワークフローを探ります。

## リモート追跡ブランチを理解する

リモート追跡ブランチは、リモートブランチの状態への参照です。`<remote>/<branch>` という命名パターンに従います。

```
# List all branches including remote tracking branches
git branch -a

# Example output:
# * main
#   feature
#   remotes/origin/main
#   remotes/origin/feature
```

## Fetch と Pull の違い

### Fetch

別のリポジトリからオブジェクトと参照をダウンロードしますが、マージはしません。

```
git fetch origin
```

これによりリモート追跡ブランチが更新されますが、ワーキングディレクトリは変更されません。

### Pull

Fetch と Merge を 1 つのコマンドで行います。

```
git pull origin main
# Equivalent to:
git fetch origin
git merge origin/main
```

または Rebase を使います。

```
git pull --rebase origin main
```

## アップストリームブランチ

アップストリームの追跡を設定すると、プッシュ／プルがシンプルになります。

```
# Set upstream when pushing
git push -u origin feature-branch

# Now you can just use:
git push
git pull
```

アップストリームの設定を確認するには、以下を使います。

```
git branch -vv
```

## リモートブランチを追跡する

### リモートからローカルブランチを作成する

```
# Option 1: Automatic tracking
git checkout feature-branch
# If feature-branch exists on remote, Git auto-creates and tracks it

# Option 2: Explicit tracking
git checkout -b feature-branch origin/feature-branch

# Option 3: Using track flag
git checkout --track origin/feature-branch
```

### リモートブランチの追跡を解除する

```
git branch --unset-upstream
```

## 異なるブランチ名でプッシュする

ローカルブランチを異なる名前でリモートにプッシュします。

```
git push origin local-branch:remote-branch
```

## リモートブランチを削除する

リモートブランチを削除するには、以下を使います。

```
# Method 1
git push origin --delete branch-name

# Method 2
git push origin :branch-name
```

## 複数のリモートを扱う

複数のリモートを持つことができます（例：origin と upstream）。

```
# Add upstream remote
git remote add upstream https://github.com/original/repo.git

# Fetch from upstream
git fetch upstream

# Merge upstream changes
git merge upstream/main

# Push to your origin
git push origin main
```

## git push の動作を理解する

さまざまなプッシュモードがあります。

```
# Push current branch to matching branch on remote
git config push.default simple  # Default in Git 2.0+

# Push all matching branches
git config push.default matching

# Push current branch to branch with same name
git config push.default current

# No push without explicit ref spec
git config push.default nothing
```

## 強制プッシュとその危険性

### 強制プッシュすべき場合

* 機能ブランチを Rebase した場合
* そのブランチで作業しているのが自分だけの場合
* プッシュ済みコミットのミスを修正する必要がある場合

### 強制プッシュの方法

```
# Standard force push (dangerous!)
git push -f origin feature-branch

# Safer: force push with lease
git push --force-with-lease origin feature-branch
```

`--force-with-lease` は、最後にフェッチしてからリモートが変更されていない場合にのみ成功します。

### 強制プッシュのベストプラクティス

1. **main／master には決して強制プッシュしない**
2. 共有ブランチを強制プッシュする前に**コミュニケーションを取る**
3. -f の代わりに **--force-with-lease を使う**
4. 強制プッシュする前に**バックアップブランチを作成する**
5. **自分の機能ブランチだけを強制プッシュする**

## 分岐したブランチを処理する

ローカルとリモートが分岐した場合は、以下のようにします。

```
# Check the situation
git status

# Option 1: Merge remote changes
git pull origin main

# Option 2: Rebase on remote changes
git pull --rebase origin main

# Option 3: Force push (if appropriate)
git push --force-with-lease origin feature-branch
```

## リモート追跡参照をクリーンアップする

古くなったリモート追跡ブランチを削除します。

```
# See stale branches
git remote prune origin --dry-run

# Remove stale branches
git remote prune origin

# Or during fetch
git fetch --prune
```

## ベアリポジトリと非ベアリポジトリ

### 非ベア（ワーキングリポジトリ）

* ワーキングディレクトリがあります
* 開発に使われます
* 通常クローンする形式です

### ベアリポジトリ

* ワーキングディレクトリがありません
* Git データのみです
* サーバーで使われます

```
# Create bare repository
git clone --bare project project.git

# Or init as bare
git init --bare project.git
```

## Git ワークフローのパターン

### 集中型ワークフロー

全員が main ブランチで作業します。

```
git pull origin main
# Make changes
git add .
git commit -m "Changes"
git push origin main
```

### 機能ブランチワークフロー

各機能に専用のブランチを用意します。

```
git checkout -b feature-x
# Work on feature
git push origin feature-x
# Create pull request
# After merge, delete branch
git branch -d feature-x
git push origin --delete feature-x
```

### Gitflow ワークフロー

複数の長期間存続するブランチを使います。

* **main**：本番環境に対応できるコード
* **develop**：統合ブランチ
* **feature/**：機能開発
* **release/**：リリース準備
* **hotfix/**：緊急修正

## プルリクエストのワークフロー

1. リポジトリを**フォーク**します（オープンソースの場合）
2. フォークを**クローン**します
3. **機能ブランチを作成**します
   ```
   git checkout -b feature-name
   ```
4. **変更してコミット**します
5. **フォークにプッシュ**します
   ```
   git push origin feature-name
   ```
6. GitHub で**プルリクエストを作成**します
7. コードについて**議論しレビュー**します
8. **要求された変更を行います**
9. **承認されたらマージ**します

## フォークを最新に保つ

```
# Add upstream remote (once)
git remote add upstream https://github.com/original/repo.git

# Fetch upstream changes
git fetch upstream

# Merge upstream/main into your main
git checkout main
git merge upstream/main

# Push to your fork
git push origin main
```

## プルリクエストの競合を解決する

```
# Update your branch with target branch
git fetch origin
git checkout feature-branch
git merge origin/main

# Resolve conflicts
# ... edit files ...
git add .
git commit -m "Resolve conflicts"

# Push updated branch
git push origin feature-branch
```

## 本日のまとめ

リモートリポジトリの概念を理解することは、効果的なコラボレーションにとって極めて重要です。チームで作業する場合も、オープンソースに貢献する場合も、リモートの管理、ブランチの追跡、競合の処理の方法を知ることで、より効果的な Git ユーザーになれます。

本日学んだ Git コマンドとパラメータを整理しておきます。

* git fetch origin
* git pull origin main
* git pull --rebase
* git push -u origin branch
* git push origin --delete branch
* git push --force-with-lease
* git branch -vv
* git branch --unset-upstream
* git remote prune origin
* git fetch --prune
* git clone --bare
