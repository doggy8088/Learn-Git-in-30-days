# Day 28: GitHub のフォークとプルリクエストのワークフローを理解する

フォークとプルリクエストは、GitHub におけるオープンソースコラボレーションの基本です。本記事では、書き込み権限のないプロジェクトに貢献する方法を説明します。

## フォークを理解する

フォークとは、自分の GitHub アカウント配下に作成されるリポジトリの完全なコピーです。フォークを使うと、以下のことができます。
* 元のプロジェクトに影響を与えずに自由に実験できます
* プルリクエストを通じて変更を提案できます
* プロジェクトを自分のニーズに合わせてカスタマイズできます

## フォーク、クローン、ブランチの違い

* **フォーク**：GitHub 上でリポジトリをコピーします（自分のアカウント）
* **クローン**：リポジトリをローカルマシンにコピーします
* **ブランチ**：分岐した開発ラインを作成します

## リポジトリをフォークする

### GitHub 上で

1. リポジトリに移動します
2. 「Fork」ボタン（右上）をクリックします
3. フォーク先（自分のアカウントまたは組織）を選択します
4. GitHub がフォークを作成するのを待ちます

### フォークをクローンする

```
# Clone your fork
git clone https://github.com/your-username/repo-name.git

# Navigate to directory
cd repo-name

# Add upstream remote
git remote add upstream https://github.com/original-owner/repo-name.git

# Verify remotes
git remote -v
# origin    https://github.com/your-username/repo-name.git (fetch)
# origin    https://github.com/your-username/repo-name.git (push)
# upstream  https://github.com/original-owner/repo-name.git (fetch)
# upstream  https://github.com/original-owner/repo-name.git (push)
```

## 完全なプルリクエストのワークフロー

### ステップ 1：フォークを同期する

```
# Fetch upstream changes
git fetch upstream

# Checkout your main branch
git checkout main

# Merge upstream changes
git merge upstream/main

# Push to your fork
git push origin main
```

### ステップ 2：機能ブランチを作成する

```
# Create and checkout feature branch
git checkout -b fix-typo-in-readme

# Make your changes
# Edit files...

# Stage changes
git add README.md

# Commit changes
git commit -m "Fix typo in installation instructions"
```

### ステップ 3：フォークにプッシュする

```
# Push branch to your fork
git push origin fix-typo-in-readme
```

### ステップ 4：プルリクエストを作成する

1. GitHub で自分のフォークに移動します
2. 「Compare & pull request」ボタンをクリックします
3. PR の詳細を入力します。
   * **タイトル**：明確で簡潔な説明
   * **説明**：何を、なぜ、どのように
   * 該当する場合は Issue を参照します
4. 「Create pull request」をクリックします

### ステップ 5：フィードバックに対応する

```
# Make requested changes
# Edit files...

# Commit changes
git add .
git commit -m "Address review feedback"

# Push updates
git push origin fix-typo-in-readme
# PR automatically updates!
```

### ステップ 6：マージ後

```
# Switch to main
git checkout main

# Pull merged changes
git pull upstream main

# Push to your fork
git push origin main

# Delete feature branch
git branch -d fix-typo-in-readme
git push origin --delete fix-typo-in-readme
```

## フォークを最新に保つ

### 定期的な同期

```
# Fetch and merge in one command
git checkout main
git pull upstream main
git push origin main
```

### 自動同期

フォークのページにある GitHub の「Fetch upstream」ボタンを使うか、GitHub Actions を設定します。

```yaml
# .github/workflows/sync-upstream.yml
name: Sync Fork
on:
  schedule:
    - cron: '0 0 * * *'  # Daily
  workflow_dispatch:
jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: TobKed/github-forks-sync-action@v1
        with:
          upstream: original-owner/repo-name
          target: your-username/repo-name
```

## 1 つの PR に複数のコミットを含める

### 方法 1：インタラクティブ Rebase

```
# Squash commits
git rebase -i HEAD~3

# In editor, change 'pick' to 'squash' for commits to combine
# Save and edit commit message

# Force push (since you're rewriting history)
git push -f origin feature-branch
```

### 方法 2：ソフトリセット

```
# Reset to before your commits
git reset --soft HEAD~3

# Create single commit
git commit -m "Complete feature implementation"

# Force push
git push -f origin feature-branch
```

## PR のマージ競合に対処する

```
# Sync with upstream
git fetch upstream

# Rebase on upstream/main
git rebase upstream/main

# Resolve conflicts
# Edit conflicting files
git add resolved-files
git rebase --continue

# Force push
git push -f origin feature-branch
```

## ドラフトプルリクエスト

早期のフィードバックを得るためにドラフト PR を作成します。

1. PR を作成する際に、「Create pull request」のドロップダウンをクリックします
2. 「Create draft pull request」を選択します
3. 完成したら準備完了としてマークします

利点：
* 早期のフィードバックが得られます
* 作業中であることを示せます
* 誤ってマージされるのを防ぎます

## プルリクエストのベストプラクティス

### PR を作成する前に

- [ ] コードが動作し、テストされている
- [ ] プロジェクトのスタイルガイドラインに従っている
- [ ] ドキュメントが更新されている
- [ ] コミットがクリーンで論理的である
- [ ] ブランチが main と同期している

### 良い PR を書く

**タイトル**：
```
❌ Fix stuff
✅ Fix null pointer exception in user login
```

**説明**：
```
## What
Fixes a null pointer exception that occurs when users login with empty passwords.

## Why
Bug #123 reported crashes on invalid login attempts.

## How
Added null check before password validation.

## Testing
- Tested with empty password
- Tested with valid password
- Tested with invalid password

Closes #123
```

### レビュー中

* すべてのコメントに返信します
* 不明な点があれば質問します
* 要求された変更には速やかに対応します
* 提案に対してオープンでいます
* レビュアーに感謝します

## オープンソースに貢献する

### プロジェクトを見つける

1. **GitHub Explore**：https://github.com/explore
2. **First Timers Only**：https://www.firsttimersonly.com/
3. **Good First Issue**：GitHub で検索します
4. **Up For Grabs**：https://up-for-grabs.net/

### 貢献する前に

1. `CONTRIBUTING.md` を読みます
2. オープンな Issue を確認します
3. 既存の PR を見ます
4. 行動規範を理解します
5. 開発環境をセットアップします

### 初めての PR

小さなことから始めます。
* タイプミスを修正する
* ドキュメントを改善する
* テストを追加する
* 明らかなバグを修正する

### 評判を築く

1. ドキュメントから始めます
2. 良いバグ報告をします
3. Issue で他の人を助けます
4. 質の高い PR を提出します
5. 忍耐強く、敬意を持って接します

## 避けるべきよくあるミス

1. **フォークを同期しない**：PR を作成する前に常に更新します
2. **変更が多すぎる**：PR は焦点を絞ってください
3. **説明がない**：何を、なぜ変更したかを説明します
4. **main への強制プッシュ**：決してしないでください
5. **メンテナーと議論する**：敬意を持って接します
6. **テストしない**：変更は常にテストします

## 本日のまとめ

フォークとプルリクエストは、大規模なオープンソースコラボレーションを可能にします。このワークフローを理解することで、貢献できる何千ものプロジェクトへの扉が開きます。小さなことから始めて、忍耐強く取り組みましょう。そして、経験豊富なコントリビューターも、かつては初心者だったことを忘れないでください。

本日学んだ Git コマンドとパラメータを整理しておきます。

* git clone <fork-url>
* git remote add upstream <original-url>
* git fetch upstream
* git merge upstream/main
* git push origin branch-name
* git push -f origin branch-name
* git rebase -i HEAD~n
* git reset --soft HEAD~n
