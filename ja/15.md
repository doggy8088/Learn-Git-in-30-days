# Day 15: タグ - バージョン管理における重要なイベントの記録

Git を使ってバージョン管理を行うと、大量のバージョンが生成されます。時が経つにつれ、これら多くのバージョンの中には、記録する価値のある重要なバージョンが必ず存在します。これこそが「タグ」の助けを借りてできることです。

## タグを理解する - 基本概念

基本的に、タグの目的は、特定の「バージョン」または「commit オブジェクト」に「覚えやすい名前」でマークを付け、特定のバージョンを思い出す手助けをすることです。

タグは、Git 履歴内の特定のコミットを指す参照です。ブランチとは異なり、タグは新しいコミットを作成しても移動せず、常に同じコミットを指し続けます。このため、タグはリリースポイントやその他の重要なマイルストーンをマークするのに最適です。

Git は 2 種類のタグをサポートしています。

1. **軽量タグ**：特定のコミットに対する単なる名前（エイリアス）であり、「参照名」の一種です
2. **注釈付きタグ**：追加のメタデータとともに完全な Git オブジェクトとして保存されます

Day 11（Git オブジェクトの参照とシンボリック参照を理解する）で述べたように、「一般参照」には「タグ名」が含まれ、ここでいう「タグ名」とは「軽量タグ」を指します。そのため、「軽量タグ」は特定のコミットバージョンに対する単なる「エイリアス」であり、「相対名」の一種であると言えます。

「注釈付きタグ」は Git オブジェクトの一種です。Day 06（Git のデータ構造を解析する - オブジェクト構造）で述べたように、Git オブジェクトには Blob、Tree、Commit、Tag オブジェクトの 4 つのオブジェクトタイプがあります。ここで述べる「注釈付きタグ」が Tag オブジェクトです。Tag オブジェクトは Git のオブジェクトストレージに保存され（`.git\objects\` ディレクトリに保存されます）、別の commit オブジェクトに関連付けられます。「注釈付きタグ」を作成する際は、commit オブジェクトを作成する際と同様に「バージョンメッセージ」を含めることができます。Git に組み込まれたタグの仕組みでは、GnuPG キーを使って Tag オブジェクトに署名し、メッセージの「否認防止」を確保することもできます。

この 2 種類のタグがあり、どちらも commit オブジェクトの「エイリアス」のように見えますが、2 つのタグの使い方はわずかに異なるだけです。ほとんどのユースケースでは、「注釈付きタグ」を使って「tag オブジェクト」を作成し、「バージョンメッセージ」を提供します。このタイプの「タグ」は Git リポジトリ内の「恒久的なオブジェクト」だからです。（オブジェクトストレージに保存された Git オブジェクトは不変であり、変わるのはインデックスだけです。）

## 軽量タグを作成する

タグを作成する最も簡単な方法は以下のとおりです。

```
git tag v1.0
```

これにより、現在のコミット（HEAD）を指す `v1.0` という名前の軽量タグが作成されます。

特定のコミットにタグを付けるには、以下を使います。

```
git tag v0.9 <commit-hash>
```

**注意**：`.git\refs\` 配下のすべてのファイルは「参照名」です。

基本的な使い方：
* すべてのタグを一覧表示する：`git tag`
* 軽量タグを作成する：`git tag [tagname]`
* 軽量タグを削除する：`git tag [tagname] -d`

「軽量タグ」の内容を見たい場合は、`git cat-file -p [tagname]` を使います。「軽量タグ」のオブジェクトタイプを見たい場合は、`git cat-file -t [tagname]` を使います。

**重要な注意**：軽量タグは Git オブジェクトではありません。上記から分かるように、タグ名は commit オブジェクトの内容を取得し、その名前で見つかるオブジェクトタイプは commit オブジェクトです。

## 注釈付きタグを作成する

注釈付きタグは、追加情報を保存できるため、ほとんどのユースケースで推奨されます。

```
git tag -a v1.0 -m "Release version 1.0"
```

`-a` フラグは注釈付きタグを作成し、`-m` はタグメッセージを指定します。

軽量タグとの違い：
1. `git tag` を実行してすべてのタグを一覧表示すると、すべてのタグが混在して表示され、タグのタイプは分かりません
2. 「注釈付きタグ」の作成には `-a` パラメータが必要です
3. 「注釈付きタグ」の作成には「バージョンメッセージ」が必須であり、`git commit` を実行するのと同様に、どちらも `-m` パラメータが使えます

## タグを一覧表示する

リポジトリ内のすべてのタグを見るには、以下を使います。

```
git tag
```

パターンに一致するタグを見るには、以下を使います。

```
git tag -l "v1.*"
```

## タグ情報を表示する

軽量タグについては、以下を使います。

```
git show v1.0
```

これにより、タグが指すコミットが表示されます。

注釈付きタグについては、以下を使います。

```
git show v1.0
```

これにより、タグ情報に加えてコミットの詳細が表示されます。

## 古いコミットにタグを付ける

HEAD にないコミットにもタグを付けることができます。

```
git log --oneline  # Find the commit hash
git tag -a v0.5 -m "Beta release" <commit-hash>
```

## タグをリモートにプッシュする

デフォルトでは、`git push` はタグを転送しません。明示的にプッシュする必要があります。

```
# Push a specific tag
git push origin v1.0

# Push all tags
git push origin --tags
```

## タグを削除する

ローカルタグを削除するには、以下を使います。

```
git tag -d v1.0
```

リモートタグを削除するには、以下を使います。

```
git push origin :refs/tags/v1.0
# or
git push origin --delete v1.0
```

## タグをチェックアウトする

特定のタグのコードをチェックアウトできます。

```
git checkout v1.0
```

これにより「detached HEAD」状態になります。変更を加えたい場合は、新しいブランチを作成してください。

```
git checkout -b version-1-fixes v1.0
```

## 本日のまとめ

タグはバージョン管理に不可欠な要素であり、プロジェクト履歴の重要なポイントにマークを付けることができます。注釈付きタグは、リリースノート、タグ付けした人の情報、署名などの追加情報を保存できるため、リリースにおいて特に便利です。

本日学んだ Git コマンドとパラメータを整理しておきます。

* git tag
* git tag -a
* git tag -l
* git show
* git push origin --tags
* git tag -d
* git checkout
