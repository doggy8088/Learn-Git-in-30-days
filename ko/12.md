# Day 12: Git 개체 상대 이름 이해하기

Git 개체의 "절대 이름"과 "참조 이름"을 이해한 다음에는, Git 버전 관리 과정에서 역시 흔히 사용되는 "상대 이름"을 소개하겠습니다.

다시 복습해 보겠습니다. Git 버전 관리에서 각 버전은 커밋 개체를 나타냅니다. 각 커밋 개체에는 "절대 이름", 즉 내용을 SHA1 해싱하여 얻은 40자 문자열이 있습니다. 처음 4자부터 40자까지를 해당 커밋 개체의 식별 이름으로 사용할 수 있습니다. 버전 관리 중에는 "참조 이름"을 사용해 특정 커밋 개체를 나타낼 수도 있습니다. 각 "참조 이름"은 궁극적으로 개체의 "절대 이름"에 대응합니다. "참조 이름"은 "일반 참조"와 "심볼릭 참조"로 나뉩니다. 그중 "일반 참조"는 "절대 이름"에 직접 대응하는 반면, "심볼릭 참조"는 또 다른 "일반 참조"에 대응합니다.

이 글에서 소개할 것은 "상대 이름" 표기법의 사용법으로, 이를 사용하면 특정 커밋 개체를 찾은 뒤 상대적인 위치를 기준으로 다른 "커밋 개체"를 찾을 수 있습니다.

## 상대 이름 표기법

상대 이름을 사용하는 것은 사실 매우 간단합니다. 기억해야 할 특수 기호가 두 가지 있는데, 하나는 `^`이고 다른 하나는 `~`입니다.

`HEAD`의 이전 버전을 찾으려면 `HEAD~` 또는 `HEAD~1`을 사용해 "HEAD 커밋 개체의 이전 버전"을 나타냅니다. **참고**: 여기서 `HEAD`는 Git에 내장된 "심볼릭 참조 이름"으로, 현재 브랜치의 최신 버전을 나타낸다는 것을 이미 잘 알고 있어야 합니다.

또 다른 `f2e` 브랜치보다 두 버전 앞선 버전을 찾고 싶다면(`f2e`의 `HEAD` 버전은 포함하지 않음), `f2e~2` 또는 `f2e~~`를 사용해 나타낼 수 있습니다. 이것이 가장 기본적인 표현 방법입니다.

브랜치와 병합이 없는 리포지토리에서는 `^1`과 `~1`이 나타내는 의미가 완전히 동일하며, 둘 다 "이전 버전"을 나타냅니다. 하지만 실제로는 브랜치와 병합이 있는 리포지토리에서는 서로 다른 의미를 가집니다. 이 부분은 나중에 설명하겠습니다.

이것이 가장 기본적인 "상대 이름" 표기법입니다.

## 커밋 개체 사이의 연결

보다 일반적인 Git 리포지토리에서는 기본적으로 "루트 커밋 개체"가 하나만 존재하는데, 이는 우리가 만든 첫 번째 버전으로 "Initial Commit"이라고도 합니다. 또한 브랜치를 시작하려면 최소한 첫 번째 커밋 개체가 있어야 합니다. 따라서 "Git 리포지토리에서 모든 커밋 개체 중 첫 번째 커밋 개체를 제외한 다른 모든 커밋 개체는 반드시 하나 이상의 부모 커밋 개체를 가진다"고 말할 수 있습니다. 왜 부모 커밋 개체가 "하나 이상"일 수 있을까요? 두 개 이상의 브랜치를 다른 브랜치로 병합할 가능성이 매우 높기 때문입니다. 따라서 병합 후의 커밋 개체는 여러 개의 부모 커밋 개체를 가지게 됩니다.

간단한 예를 들어 이를 증명해 보겠습니다. `git cat-file -p [object_id]`를 사용해 처음 두 커밋 개체의 내용을 가져오면, 각 커밋 개체에는 실제로 부모 커밋 개체의 절대 이름을 가리키는 부모 속성이 있으며, 첫 번째 커밋 개체만 부모 속성이 없다는 것을 이해할 수 있습니다. 다음 그림과 같습니다.

## 상대 이름 표기법에서 `^`와 `~`의 차이 이해하기

`~`가 나타내는 의미는 "첫 번째 부모 커밋 개체"입니다.

`^`가 나타내는 의미는 "부모 커밋 개체가 여러 개일 때, 몇 번째 1세대 부모 개체를 나타낼 것인가"입니다.

`C`라는 "참조 이름"이 있을 때, 그 첫 번째 부모 커밋 개체를 찾으려면 다음과 같은 표현을 사용할 수 있습니다.

* `C^`
* `C^1`
* `C~`
* `C~1`

두 번째 부모 커밋 개체를 찾고 싶다면(병합 없이), 다음과 같은 표현을 사용할 수 있습니다.

* `C^^`
* `C^1^1`
* `C~2`
* `C~~`
* `C~1~1`

하지만 "두 번째 부모 커밋 개체"를 표현하는 데 `C^2`를 사용할 수는 없습니다! 병합이 없으면 이 `C`에는 부모 개체가 하나만 있기 때문입니다. `C^2`는 "이전 단계 개체의 두 번째 부모 개체"를 나타내는 데만 사용할 수 있습니다.

위의 설명이 조금 추상적이고 말하기 어려울 수 있습니다. 여러분이 볼 수 있도록 특별히 다이어그램을 그렸습니다. 다이어그램을 통하면 더 명확해질 수 있습니다. 다음 그림과 같이, `C` 커밋 개체의 상대 경로에서 다른 커밋 개체(부모 개체)를 찾고자 합니다. 이 `C` 커밋 개체에는 부모 개체가 세 개 있으므로, 이는 이 커밋 개체가 병합을 통해 만들어졌다는 의미입니다. 따라서 "상대 이름"으로 각 경로를 찾으려면 `^`와 `~`를 조합하는 기술을 사용해 열고 싶은 각 버전을 찾아야 합니다.

## `git rev-parse` 명령어 소개

Git for Windows 도구에는 `git rev-parse` 명령어가 있습니다. 이 명령어를 통해 어떤 "참조 이름"이나 "상대 이름"도 "절대 이름"으로 파싱할 수 있습니다. 이 도구는 자주 사용되지는 않지만, Git을 가르칠 때 상당히 실용적입니다. 사용 예시는 다음과 같습니다.

* git rev-parse master
* git rev-parse HEAD
* git rev-parse ORIG_HEAD
* git rev-parse HEAD^
* git rev-parse HEAD~5

## 오늘의 요약

"상대 이름"을 이해한 뒤에는 Git에서 커밋 개체를 나타내는 다양한 방법이 모두 설명되었습니다. 이제 Git의 다양한 버전 사이의 작업을 더 잘 제어할 수 있을 것이라 믿습니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git log
* git cat-file -p [object_id]
* git rev-parse
