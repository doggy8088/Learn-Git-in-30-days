# Day 03: 리포지토리 만들기

Git을 사용하기 시작하려면 가장 중요한 것은 먼저 Git 리포지토리를 갖는 것입니다. 그런데 이 리포지토리는 어디서 오는 것일까요? 이 글에서는 리포지토리를 만드는 다양한 방법을 소개하겠습니다.

리포지토리를 만드는 방법은 사실 여러 가지가 있습니다. 예를 들면 다음과 같습니다.

* 로컬 머신에 로컬 리포지토리 만들기
* 로컬 머신에 공유 리포지토리 만들기
* GitHub나 다른 Git 플랫폼에 원격 리포지토리 만들기

어느 경우든 리포지토리는 항상 필요합니다. 각각에 대해 다음과 같이 설명하겠습니다.

## 로컬 머신에 로컬 리포지토리 만들기

먼저 [GitHub for Windows](https://windows.github.com/)의 Git Shell 도구를 열어 보겠습니다. 이 도구는 실제로 Windows PowerShell 인터페이스이지만, Git 관련 환경 변수와 명령 프롬프트 설정이 일부 추가되어 있습니다.

![이미지](figures/03/01.png)

열면 기본적으로 `%USERPROFILE%\Documents\GitHub` 폴더가 됩니다. 이곳은 [GitHub for Windows](https://windows.github.com/)의 기본 프로젝트 루트 디렉터리로, [GitHub for Windows](https://windows.github.com/)를 통해 GitHub에서 복제한 모든 프로젝트가 기본적으로 이 디렉터리에 배치된다는 의미입니다.

따라서 여기에 새 디렉터리를 만들어 "작업 디렉터리"로 사용할 수 있습니다. `mkdir git-demo` 명령어를 입력하여 디렉터리를 만든 다음, `cd git-demo`를 사용하여 해당 디렉터리로 들어갈 수 있습니다.

이곳은 빈 디렉터리이고 Git 리포지토리가 포함되어 있지 않으므로, `git init` 명령어를 사용하여 리포지토리를 만들 수 있습니다. 기본적으로 리포지토리는 작업 디렉터리 아래의 `.git` 디렉터리에 배치됩니다.

전체 작업 단계는 다음 그림과 같습니다.

![이미지](figures/03/02.png)

만든 후에는 Git Shell의 명령 프롬프트에서 뭔가 달라진 것을 확인할 수 있습니다. 현재 경로 뒤에 강조 표시된 `[master]`가 추가됩니다. 이 프롬프트는 현재 `작업 디렉터리`의 다양한 상태를 표시합니다. 이해할 수 있다면 매우 유용한 정보원으로, 명령줄 도구로 Git을 사용할 때 현재 작업 디렉터리의 상태를 조회하기 위해 `git status` 명령어를 많이 입력하지 않아도 됩니다. 이 부분은 다음 글에서 구체적으로 설명하겠습니다.

## 로컬 머신에 공유 리포지토리 만들기

공유 리포지토리란 작업 디렉터리 없이 Git 리포지토리를 만드는 것을 말합니다. 이러한 상황은 Linux 운영 체제에서 더 흔합니다. Linux 운영 체제는 보통 같은 Linux 호스트를 여러 사람이 사용하기 때문입니다. Windows 운영 체제에서도 사용할 수 있지만, 우리의 개발 환경은 대부분 Windows 클라이언트 환경이며, 여러 사람이 컴퓨터를 공유하는 경우는 드뭅니다.

공유 리포지토리를 만들려면 다음 그림과 같이 `git init --bare` 명령어를 사용하여 만들 수 있습니다. `git init`에 `--bare` 매개변수를 사용하면 현재 디렉터리에 Git 리포지토리 관련 파일과 폴더가 모두 생성되는 것을 볼 수 있습니다. 이 폴더는 개발 목적으로 직접 사용할 수 없다는 점에 특히 주의해야 합니다. Git 관련 정보를 저장하는 데만 사용할 수 있습니다. 대부분의 경우 이 폴더 안의 어떤 파일도 수동으로 편집해서는 안 됩니다. git 명령어를 통해 작업하는 것이 가장 좋습니다.

![이미지](figures/03/03.png)

이것은 "작업 디렉터리가 없는 순수 리포지토리"이므로, 공유 리포지토리는 "베어 리포지토리(bare repository)"라는 별칭도 가지고 있습니다.

Git은 "분산 버전 관리"이며 모두가 완전한 리포지토리를 가지고 있다는 것을 다시 한번 강조해야 합니다. 즉, "작업 디렉터리"를 만들려면 먼저 이 "베어 리포지토리"의 내용을 가져와야 합니다. 이때 `git clone [REPO_URI]` 명령어를 사용하여 사본을 "복제(clone)"해 와야 합니다. `git clone` 과정을 거치면 작업 디렉터리가 자동으로 생성될 뿐만 아니라, 이 "베어 리포지토리"도 완전히 복제됩니다. 이 복제 과정은 "완전한 백업"과 같아서, Git 리포지토리의 모든 버전 기록, 모든 버전의 파일 등 모든 데이터를 완전히 복사해 옵니다. 전체 명령어 작업 과정은 다음 그림을 참고하세요.

![이미지](figures/03/04.png)

실제로 "공유 리포지토리" 또는 "베어 리포지토리"를 사용하는 방법은 여러 가지가 있을 수 있습니다.

* 여러 사람이 사용하는 머신에서 협업 개발을 할 때, 대부분의 사람에게는 이 "베어 리포지토리 폴더"에 대한 읽기 전용 권한을 부여하고, 한 사람이나 소수의 사람에게만 쓰기 권한을 부여할 수 있습니다.
* 어떤 사람들은 베어 리포지토리를 Dropbox에 올려서, 자신의 여러 컴퓨터와 이 베어 리포지토리를 동기화합니다.

주의하세요: "작업 디렉터리" 아래의 `.git` 디렉터리도 "리포지토리"이지만, 작업 디렉터리 아래의 리포지토리에는 작업 디렉터리의 인덱스 정보도 일부 포함되어 있어 작업 디렉터리의 상태 정보를 기록합니다. 이 상태 정보는 "공유 리포지토리"에는 나타나지 않으며, 공유 리포지토리에는 버전 정보(즉, Git 개체 정보)만 포함됩니다.

## GitHub나 다른 Git 플랫폼에 원격 리포지토리 만들기

사실 "원격 리포지토리"와 "공유 리포지토리"는 거의 같습니다. 차이점은 "공유 리포지토리"는 대부분 파일에 직접 접근하는 방식을 사용하는 반면, "원격 리포지토리"는 보통 SSH, Git 프로토콜, HTTP 등의 프로토콜을 사용하여 Git 리포지토리에 "원격으로" 접근한다는 점뿐입니다. 그 밖의 사용 방법은 기본적으로 같습니다.

다음은 GitHub를 통해 리포지토리를 만들고 그 리포지토리를 로컬로 복제하는 과정을 보여 줍니다.

* 먼저 GitHub에 로그인한 다음, 새 리포지토리를 만듭니다

![이미지](figures/03/05.png)

* GitHub 프로젝트의 관련 정보를 설정하고 리포지토리를 만듭니다

![이미지](figures/03/06.png)

* 만든 후에는 프로젝트를 가져오는 방법이나 로컬의 기존 프로젝트를 GitHub로 가져오는 방법을 안내합니다

![이미지](figures/03/07.png)

* 위와 같이, Quick setup 섹션에서 "Set up in Desktop"을 클릭할 수 있습니다. 컴퓨터가 자동으로 GitHub for Windows 도구를 열고, 이 리포지토리를 자동으로 복제하여 작업 디렉터리를 만듭니다.

* 원격 Git 리포지토리의 URL을 복사한 다음, `git clone [REPO_URL]`을 실행하여 사본을 복제해 올 수도 있습니다.

![이미지](figures/03/08.png)

## 오늘의 요약

이상이 Git 리포지토리를 만드는 세 가지 방법입니다. 오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git init
* git init --bare
* git clone \[REPOSITORY\_URI]
