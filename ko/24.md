# Day 24: GitHub 원격 리포지토리 사용하기 - 시작하기

GitHub는 현재 전 세계에서 가장 널리 사용되는 Git 온라인 관리 플랫폼입니다. 완전한 Git 원격 리포지토리 구현, 포괄적인 이슈 추적 메커니즘과 보고서, 그리고 Git 버전 관리에 GitHub를 사용하는 수천 개의 오픈 소스 프로젝트를 갖추고 있습니다. 많은 기업에서도 GitHub를 주요 Git 플랫폼으로 채택하고 있습니다. 이 글에서는 GitHub의 가장 기본적인 사용법을 안내하겠습니다.

## GitHub란 무엇인가요?

GitHub는 다음을 제공하는 웹 기반 플랫폼입니다.
* 클라우드에 Git 리포지토리를 호스팅합니다
* 협업 도구(이슈, 풀 리퀘스트, 프로젝트 보드)를 제공합니다
* GitHub Actions를 통한 CI/CD를 제공합니다
* 코드 리뷰와 토론을 가능하게 합니다
* 오픈 소스 프로젝트에 무료 호스팅을 제공합니다
* 개발자와 오픈 소스 프로젝트를 위한 소셜 플랫폼 역할을 합니다

## GitHub 계정 만들기

1. https://github.com 으로 이동합니다
2. "Sign up"을 클릭합니다
3. 등록 절차를 따릅니다
4. 이메일 주소를 인증합니다

## GitHub에 새 리포지토리 만들기

GitHub 리포지토리를 만들 때는 크게 두 가지 방식이 있습니다.

1. **빈 리포지토리(초기 커밋 없음)**: push할 기존 로컬 리포지토리가 있을 때 가장 좋습니다
2. **초기화된 리포지토리(초기 커밋 있음)**: GitHub가 README, .gitignore, 라이선스 파일을 대신 만들어 줍니다

### 빈 리포지토리 만들기

1. 오른쪽 상단의 "+" 아이콘을 클릭합니다
2. "New repository"를 선택합니다
3. 다음을 입력합니다.
   * **Repository name**
   * **Description**(선택 사항)
   * **Public 또는 Private**
   * "Initialize this repository with a README"를 **체크하지 마세요**
   * .gitignore와 license는 "None"으로 둡니다
4. "Create repository"를 클릭합니다

생성 후에는 GitHub가 기존 리포지토리를 push하는 방법을 안내합니다.

### 초기화된 리포지토리 만들기

1. 위의 1~3단계를 따릅니다
2. "Initialize this repository with a README"를 **체크합니다**
3. 선택적으로 다음을 선택합니다.
   * 사용하는 언어의 **.gitignore 템플릿**
   * 프로젝트의 **License**
4. "Create repository"를 클릭합니다

GitHub가 선택한 파일들로 초기 커밋을 만들어 줍니다.

## 로컬 리포지토리를 GitHub에 연결하기

### 옵션 1: 기존 리포지토리 Push하기

```
# Add remote
git remote add origin https://github.com/username/repo-name.git

# Push to GitHub
git push -u origin main
```

### 옵션 2: GitHub에서 Clone하기

```
# Clone the repository
git clone https://github.com/username/repo-name.git

# Navigate to the directory
cd repo-name
```

## 리모트 이해하기

리모트(remote)란 다른 곳에 호스팅된 리포지토리에 대한 참조입니다. 흔히 사용하는 명령어는 다음과 같습니다.

```
# List remotes
git remote -v

# Add a remote
git remote add <name> <url>

# Remove a remote
git remote remove <name>

# Rename a remote
git remote rename <old> <new>

# Change remote URL
git remote set-url origin <new-url>
```

## GitHub에 Push하기

커밋을 GitHub에 push합니다.

```
# Push to the default branch
git push origin main

# Push all branches
git push --all

# Push tags
git push --tags
```

`-u` 플래그는 업스트림 추적을 설정합니다.

```
git push -u origin main
# After this, you can just use:
git push
```

## GitHub에서 Pull하기

GitHub에서 업데이트를 가져옵니다.

```
# Fetch changes
git fetch origin

# Fetch and merge
git pull origin main

# If upstream is set
git pull
```

## 인증 방법

### HTTPS

사용자 이름과 비밀번호/토큰이 필요합니다.

```
https://github.com/username/repo-name.git
```

### SSH

SSH 키 설정이 필요합니다.

```
git@github.com:username/repo-name.git
```

SSH 키 설정 방법은 다음과 같습니다.

```
# Generate SSH key
ssh-keygen -t ed25519 -C "your.email@example.com"

# Add to ssh-agent
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# Copy public key
cat ~/.ssh/id_ed25519.pub
# Add this key to GitHub settings
```

### Personal Access Token

HTTPS 인증을 위해서는 다음을 수행합니다.

1. GitHub Settings > Developer settings > Personal access tokens로 이동합니다
2. 새 토큰을 생성합니다
3. push할 때 토큰을 비밀번호로 사용합니다

## README.md

좋은 README에는 다음이 포함되어야 합니다.

* 프로젝트 설명
* 설치 방법
* 사용 예시
* 기여 가이드라인
* 라이선스 정보

예시는 다음과 같습니다.

```markdown
# Project Name

Brief description of the project.

## Installation

\`\`\`bash
npm install
\`\`\`

## Usage

\`\`\`javascript
const example = require('example');
\`\`\`

## Contributing

Pull requests are welcome!

## License

MIT
```

## GitHub 기능

### Issues

버그, 개선 사항, 작업을 추적합니다.

* 설명이 명확한 제목을 작성하세요
* 버그에 대해서는 재현 단계를 제공하세요
* 정리를 위해 라벨을 사용하세요
* 커밋과 풀 리퀘스트를 참조하세요

### Wiki

프로젝트 문서를 작성합니다.

* 시작하기 가이드
* API 문서
* FAQ
* 아키텍처 다이어그램

### Projects

칸반 보드로 작업을 정리합니다.

* To Do
* In Progress
* Done

### Releases

중요한 마일스톤을 표시합니다.

1. "Releases"로 이동합니다
2. "Draft a new release"를 클릭합니다
3. 태그를 선택합니다
4. 릴리스 노트를 추가합니다
5. 필요하면 바이너리를 첨부합니다

## GitHub 워크플로 모범 사례

1. **자주 커밋하세요**: 작고 논리적인 커밋을 만드세요
2. **좋은 메시지를 작성하세요**: 무엇을 했는지가 아니라 왜 했는지 설명하세요
3. **push하기 전에 pull하세요**: 항상 최신 변경 사항을 먼저 가져오세요
4. **브랜치를 사용하세요**: main에 직접 커밋하지 마세요
5. **코드를 리뷰하세요**: 변경 사항에는 풀 리퀘스트를 사용하세요

## 흔한 작업

### 리포지토리 Fork하기

1. 리포지토리 페이지에서 "Fork"를 클릭합니다
2. 포크를 clone합니다.
   ```
   git clone https://github.com/your-username/repo-name.git
   ```
3. upstream 리모트를 추가합니다.
   ```
   git remote add upstream https://github.com/original-owner/repo-name.git
   ```

### Fork 동기화하기

```
git fetch upstream
git checkout main
git merge upstream/main
git push origin main
```

## 오늘의 요약

GitHub는 Git 리포지토리를 호스팅하고 다른 사람들과 협업할 수 있는 강력한 플랫폼을 제공합니다. 로컬 리포지토리를 GitHub에 연결하고, 변경 사항을 push하고 pull하며, GitHub의 기능을 사용하는 방법을 이해하는 것은 현대 소프트웨어 개발에 필수적입니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git remote add
* git remote -v
* git remote remove
* git remote rename
* git push -u origin main
* git push --all
* git push --tags
* git pull origin main
* git fetch origin
* git clone
