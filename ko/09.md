# Day 09: 파일 및 버전 차이 비교하기

어떤 버전 관리 소프트웨어를 사용하는 과정에서든, 이력 기록을 보고 버전 사이의 차이를 비교해야 할 때가 자주 있습니다. Git에서 어떻게 비교하는지가 이 글의 초점입니다.

## 작업 디렉터리 준비하기

다음 명령어를 통해 파일 두 개와 버전 변경 기록 두 개가 있는 Git 리포지토리와 작업 디렉터리를 빠르게 만들겠습니다.

```
mkdir git-demo
cd git-demo
git init

echo 1 > a.txt
echo 2 > b.txt
git add .
git commit -m "Initial commit"

echo 3 > a.txt
echo 4 > b.txt
git add .
git commit -m "Update a.txt and b.txt to 3 and 4"
```

## git diff의 기본 개념

Git에서 두 버전 사이의 차이를 비교하려면 보통 `git diff` 명령어를 사용합니다. 먼저 간단한 명령어를 실행하여 두 버전 사이의 차이를 비교해 보겠습니다.

1. 먼저 `git log`를 실행하여 버전 정보를 가져오고, 마지막 두 커밋 개체의 ID를 가져옵니다
2. `git diff commit1 commit2` 명령어를 실행하여 두 버전 사이의 차이를 비교합니다. 여기서 commit1은 오래된 버전을, commit2는 더 새로운 버전을 사용해야 합니다.

다음 그림과 같습니다.

![이미지](figures/09/01.png)

`git diff` 실행 출력에서 실행 결과를 얻을 수 있습니다. 이 두 리포지토리에는 파일이 두 개 있고, 두 버전 사이에 둘 다 변경되었으므로, "차이 비교" 결과가 두 구간으로 나열됩니다.

위 그림에서 볼 수 있듯이, 각 구간은 `diff --git`으로 시작하며, git이 어떤 두 파일을 비교하는지를 나타냅니다.

두 번째 줄 `index 37bcc8b..d855592 100644`는 git이 이 비교를 수행할 때의 "헤더 줄(Header Line)"을 나타냅니다. 여기에는 여러 줄이 있을 수 있으며, 정보가 반드시 이것만 있는 것은 아닙니다. 이 차이 비교에 대한 많은 추가 정보가 여기에 표시됩니다. 예를 들어 index 줄, 그 뒤의 두 해시 ID(`37bcc8b..d855592`)는 Git 개체 저장소(object storage)에 있는 두 blob 개체 ID를 나타내며, 이 두 blob 개체를 비교하는 데 사용됩니다. 그 뒤의 `100644`는 git 속성으로, Linux 환경의 파일 속성과 비슷하며, 이것이 파일인지, 디렉터리인지, 읽기 가능한지, 쓰기 가능한지, 실행 가능한지 등을 선언합니다. 다음은 git 속성의 몇 가지 흔한 예입니다.

```
0100000000000000 (040000): Directory
1000000110100100 (100644): Regular non-executable file
1000000110110100 (100664): Regular non-executable group-writeable file
1000000111101101 (100755): Regular executable file
1010000000000000 (120000): Symbolic link
1110000000000000 (160000): Gitlink
```

관련 링크는 다음 토론 스레드를 참고하세요.

* [How to read the mode field of git-ls-tree's output](https://stackoverflow.com/a/8347325/910074)

세 번째 줄 `--- a/a.txt`는 비교되는 두 버전 중 "더 오래된" 버전을 나타냅니다.

네 번째 줄 `+++ b/a.txt`는 비교되는 두 버전 중 "더 새로운" 버전을 나타냅니다.

다섯 번째 줄 `@@ -1 +1 @@`는 이 파일의 이전 버전과 새 버전의 전체 줄 수를 나타냅니다. -1은 이전 버전에 1줄만 있음을 나타내고, +1은 새 버전에도 1줄만 있음을 나타냅니다.

마지막으로, 변경된 모든 내용이 나열됩니다. 여기에는 세 가지 가능한 표현이 있습니다.

* 마이너스 기호 -로 시작하면, 이 줄이 이전 버전에서 새 버전으로 가는 과정에서 삭제되었음을 의미합니다.
* 플러스 기호 +로 시작하면, 이 줄이 이전 버전에서 새 버전으로 가는 과정에서 추가되었음을 의미합니다.
* 공백 문자로 시작하면, 이 줄이 두 버전 모두에 변경 없이 나타남을 의미합니다.

이로써 이 두 버전에 있는 첫 번째 blob 개체의 차이 비교가 완료되고, 그 버전의 두 번째 blob 개체의 차이 비교가 표시되는 식으로 계속됩니다.

Git에서 `git diff`를 사용할 때, 실제로 비교 단위는 트리 개체입니다. [Day 06: Git 데이터 구조 파헤치기 - 개체 구조]의 다이어그램과 영상에서 배웠듯이, 각 커밋 개체에는 실제로 루트 디렉터리의 트리 개체가 포함되어 있습니다. 따라서 방금 `git diff`를 사용하여 두 커밋 개체를 비교했을 때, 실제로는 그 커밋 개체 아래의 트리 개체를 비교한 것이며, 비교 과정은 재귀적으로 계속 아래로 진행됩니다. 이를 통해 Git의 diff 비교 메커니즘이 매우 강력하다는 것을 느낄 수 있을 것입니다. 어떤 두 버전 사이의 변경 사항도 빠르게 비교할 수 있습니다.

`git diff` 명령어를 사용할 때, 트리 개체의 출처는 주로 세 가지입니다.

* 모든 커밋 그래프에 존재하는 트리 개체로, 어떤 버전의 어떤 트리 개체든 해당합니다.
* 인덱스(Index)로, 파일을 "인덱스 데이터베이스"에 보낸 후의 정보를 나타냅니다. 실제로 트리 개체는 `git add` 명령어를 사용할 때 이미 만들어졌습니다.
* 현재 작업 디렉터리로, 작업 디렉터리의 변경 사항이 아직 트리 개체가 되지 않았지만, `git diff`를 통해 사용할 수 있습니다.

## 네 가지 기본 비교 방법

`git diff` 명령어를 통해 어떤 두 버전이든 비교하려면, 보통 다음 네 가지 명령어 사용법이 있습니다.

1. git diff

   매개변수가 없으면, 비교되는 것은 "작업 디렉터리"와 "인덱스" 사이의 차이입니다. 이것은 매우 흔히 사용되는 명령어입니다. `git add .` 명령어를 실행하기 전에, 먼저 `git diff`를 사용하여 무엇을 변경했는지 볼 수 있기 때문입니다.

   **참고**: 사실 Git 버전 관리를 사용하는 과정에서, `git commit`을 실행하기 전에, 어떤 파일을 인덱스에 추가할지 확인하기 위해 `git add` 명령어를 여러 번 실행한 다음, 최종적으로 버전에 커밋하는 것이 가능합니다.

2. git diff commit

   `git diff` 뒤에 커밋 ID를 하나만 추가하면, 비교되는 것은 "작업 디렉터리"와 "지정한 커밋 개체에 있는 트리 개체"입니다.

   가장 흔히 사용되는 명령어는 `git diff HEAD`입니다. 이것은 "작업 디렉터리"와 "현재 브랜치의 최신 버전"을 비교하는 것을 나타내기 때문입니다. 이 비교 방법은 "인덱스" 상태를 비교하지 않으므로, 어떤 트리 개체 출처를 비교하고 있는지 명확히 구분해야 합니다.

3. git diff --cached commit

   `git commit`을 실행하기 전에 인덱스 상태가 준비되어 있어야 합니다. 따라서 "현재 인덱스 상태"와 "지정한 커밋 개체에 있는 트리 개체"를 비교하려면 이 명령어를 사용하여 비교 작업을 완료할 수 있습니다.

   가장 흔히 사용되는 명령어 역시 `git diff --cached HEAD`로, "현재 인덱스 상태"와 "현재 브랜치의 최신 버전"을 비교하는 것을 의미합니다. 이 비교 방법은 "작업 디렉터리"의 파일 내용을 비교하지 않고, "인덱스"와 "현재 최신 버전" 사이의 차이를 직접 비교합니다. 이는 `git commit`을 실행하기 전에 어떤 변경 사항이 있는지, 즉 어떤 변경 사항을 버전으로 만들 것인지를 파악하는 데 도움이 됩니다.

   **참고 1**: `git diff --cached`와 `git diff --staged`는 완전히 같은 결과입니다. `--staged`는 단지 기억하기 쉽도록 만든 `--cached`의 별칭일 뿐입니다!

   **참고 2**: `git diff --cached`와 `git diff --cached HEAD`도 실행하면 완전히 같은 결과입니다. 마지막의 HEAD는 생략할 수 있습니다.

4. git diff commit1 commit2

   마지막은 서로 다른 두 버전(커밋 ID) 사이의 차이를 비교하는 것입니다. 이 명령어는 "인덱스"와 "작업 디렉터리"의 어떤 변경 사항도 건너뛰고, 두 개의 특정 버전을 직접 비교할 수 있습니다. 실제로 Git은 그 두 특정 버전 커밋 개체에 있는 트리 개체를 비교합니다.

   가장 흔히 사용되는 명령어는 `git diff HEAD^ HEAD`로, [최신 버전의 이전 버전]과 [최신 버전] 사이의 차이를 비교하겠다는 의미입니다. 여기서 HEAD와 ^의 의미는 향후 글에서 설명하겠습니다.

## 오늘의 요약

오늘 소개한 `git diff`는 매우 흔히 사용되는 명령어이므로 능숙하게 사용할 수 있어야 합니다. 마지막으로 흔히 사용되는 명령어들의 차이를 복습하겠습니다.

```
git diff                 => working directory vs index
git diff HEAD            => working directory vs HEAD
git diff --cached HEAD   => index     vs HEAD
git diff --cached        => index     vs HEAD
git diff HEAD^ HEAD     => HEAD^   vs HEAD
```

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git log
* git diff
* git diff HEAD
* git diff --cached
* git diff --staged
* git diff HEAD^ HEAD
