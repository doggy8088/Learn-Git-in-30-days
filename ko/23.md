# Day 23: 커밋된 버전 이력 수정하기 Part 5 (rebase 2)

이전 글에서는 Rebase가 이미 존재하는 두 브랜치에 대해 "베이스 버전을 다시 지정"하는 데 사용된다고 설명했습니다. Rebase를 실행하면 원래 브랜치의 시작점(브랜치 지점)도 이동하여 버전 그래프가 변경됩니다. 하지만 Rebase는 이것만 할 수 있는 것이 아닙니다. 특정 브랜치 라인에 있는 임의 버전의 버전 정보를 수정하는 데도 사용할 수 있습니다.

이 글에서는 `git rebase` 탐구를 이어가며, 브랜치의 커밋 정보 수정을 포함해 rebase를 효과적으로 사용하는 고급 기법과 실용적인 워크플로를 더 깊이 살펴보겠습니다.

## 고급 대화형 Rebase 기법

### 커밋 나누기

하나의 커밋을 여러 개로 나누려면 다음을 사용합니다.

```
git rebase -i HEAD~3

# Mark the commit to split with "edit"
# When Git stops at that commit:
git reset HEAD^
git add file1
git commit -m "First part"
git add file2
git commit -m "Second part"
git rebase --continue
```

### 결합과 순서 바꾸기

한 번의 작업으로 커밋의 순서를 바꾸면서 결합할 수도 있습니다.

```
git rebase -i HEAD~5

# In the editor:
pick abc123 Feature A
squash def456 Fix for A
pick jkl012 Feature C  # Moved before B
pick ghi789 Feature B  # Moved after C
fixup mno345 Typo fix for B
```

## Exec와 함께 Rebase하기

rebase 중 각 커밋 뒤에 명령어를 실행합니다.

```
git rebase -i --exec "npm test" HEAD~5
```

이렇게 하면 각 커밋을 적용한 뒤 `npm test`가 실행되어, 어떤 커밋이 테스트를 깨뜨렸는지 찾는 데 도움이 됩니다.

## 특정 커밋 위로 Rebase하기

브랜치 이름 대신 특정 커밋 위로 rebase할 수도 있습니다.

```
git rebase --onto <new-base-commit> <old-base-commit> <branch>
```

사용 사례 예시 - 이력 중간에서 커밋 제거하기:

```
# Remove commits between B and D
#     A---B---C---D---E feature
# Becomes:
#     A---B---D'---E' feature

git rebase --onto B D feature
```

## 전략 옵션과 함께 Rebase하기

rebase 중 병합 전략을 사용합니다.

```
# Always prefer our version in conflicts
git rebase -X ours main

# Always prefer their version
git rebase -X theirs main
```

## 병합 커밋 보존하기

기본적으로 rebase는 병합 커밋을 평탄화합니다. 병합 커밋을 보존하려면 다음을 사용합니다.

```
git rebase -p main
# or
git rebase --preserve-merges main
```

참고: `-p`는 더 이상 권장되지 않습니다. 대신 `--rebase-merges`를 사용하세요.

```
git rebase --rebase-merges main
```

## Fork-Point와 함께 Rebase하기

분기점을 자동으로 찾습니다.

```
git rebase --fork-point main
```

이는 원격 브랜치가 강제 push되었을 때 유용합니다.

## 워크플로: 기능 브랜치를 최신 상태로 유지하기

기능 브랜치를 main과 최신 상태로 유지하는 흔한 워크플로는 다음과 같습니다.

```
# On feature branch
git fetch origin
git rebase origin/main

# Or in one command
git pull --rebase origin main
```

## 워크플로: 풀 리퀘스트 준비하기

풀 리퀘스트를 만들기 전에 커밋을 정리합니다.

```
# 1. Interactive rebase to clean history
git rebase -i main

# 2. Squash fixup commits, reword messages
# 3. Force push to update your branch
git push -f origin feature-branch
```

## 워크플로: 코드 리뷰 후 업데이트하기

코드 리뷰 피드백을 받은 뒤에는 다음을 수행합니다.

```
# Make changes
git add .
git commit --fixup <original-commit>

# Rebase with autosquash
git rebase -i --autosquash main

# Force push the updated branch
git push -f origin feature-branch
```

## 강제 Push 처리하기

작업 중인 브랜치를 누군가가 강제 push하면 다음을 수행합니다.

```
# Fetch the updated branch
git fetch origin

# Rebase your work onto the new history
git rebase --onto origin/feature-branch old-commit feature-branch
```

또는 간단히 다음을 사용합니다.

```
git pull --rebase origin feature-branch
```

## 정리 작업: Rebase vs Reset

push하기 전에 로컬 커밋을 정리할 때는 다음을 고려합니다.

**Rebase**(권장):
* 시간 순서를 보존합니다
* 대화형으로 제어할 수 있습니다
* 커밋을 cherry-pick할 수 있습니다

**Reset**(더 간단하지만 유연성은 떨어집니다):
* 커밋을 완전히 제거합니다
* 깨끗한 상태에서 다시 시작합니다
* 개별 커밋에 대한 제어가 적습니다

## 흔한 Rebase 패턴

### 패턴 1: 모든 커밋 합치기

```
git rebase -i --root
# Mark all but first commit as "squash"
```

### 패턴 2: 모든 커밋 메시지 다시 쓰기

```
git rebase -i HEAD~10
# Mark all commits as "reword"
```

### 패턴 3: 특정 커밋 제거하기

```
git rebase -i HEAD~10
# Mark unwanted commits as "drop"
```

## Rebase 안전 점검표

rebase하기 전에 확인하세요.

- [ ] 이 커밋이 공유 브랜치에 push되었나요?
- [ ] 다른 사람이 이 커밋을 기반으로 작업했나요?
- [ ] 백업(브랜치 또는 태그)이 있나요?
- [ ] 팀과 소통했나요?
- [ ] 강제 push할 준비가 되었나요?

## Rebase 재앙에서 복구하기

문제가 생기면 다음을 수행합니다.

```
# Step 1: Stay calm
# Step 2: Find the old state
git reflog

# Step 3: Reset to before the rebase
git reset --hard HEAD@{5}

# Step 4: Try again more carefully
```

## Rebase와 지속적 통합

rebase와 함께 CI/CD를 사용할 때는 다음을 따릅니다.

1. **push하기 전에 로컬에서 rebase**하세요
2. **rebase 후 테스트를 실행**하세요
3. **본인의 브랜치만 강제 push**하세요
4. **병합 전에 CI를 기다리**세요
5. **병합 후에는 절대로 rebase하지 마**세요

## 모범 사례 요약

1. **로컬에서만**: push되지 않은 커밋만 rebase하세요
2. **작게 rebase**: 큰 충돌을 피하기 위해 자주 rebase하세요
3. **철저히 테스트**: rebase 후 테스트를 실행하세요
4. **소통**: 강제 push하기 전에 팀에게 경고하세요
5. **백업**: 대규모 rebase 전에 백업 브랜치를 만드세요
6. **-f 사용에 주의**: 강제 push하기 전에 다시 한 번 확인하세요

## 오늘의 요약

고급 rebase 기법은 깔끔하고 이해하기 쉬운 커밋 이력을 유지하기 위한 강력한 도구를 제공합니다. 이러한 기능은 워크플로를 크게 개선할 수 있지만, 연습과 신중한 사용이 필요합니다. 핵심은 rebase를 사용해야 할 때와 병합 같은 더 안전한 대안을 고수해야 할 때를 아는 것입니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git rebase --exec
* git rebase --onto
* git rebase -X
* git rebase --preserve-merges
* git rebase --rebase-merges
* git rebase --fork-point
* git rebase --root
* git pull --rebase
* git push -f
