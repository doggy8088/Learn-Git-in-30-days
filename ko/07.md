# Day 07: Git 데이터 구조 파헤치기 - 인덱스 구조

Git에는 두 가지 중요한 데이터 구조, 즉 "개체"와 "인덱스"가 있다는 것을 알고 있습니다. 이 글은 주로 "인덱스"의 세부 사항을 설명하는 데 사용됩니다. Git 버전 관리를 사용하는 과정에서는 git 명령어의 사용법을 쉽게 이해할 수 있지만, 기계적인 암기에 빠져 유연하게 사용하지 못하기 쉽습니다. Linus Torvalds조차 메일링 리스트에서 "사용자가 인덱스의 의미를 이해하기 전에는 Git의 기능을 완전히 이해할 수 없다"고 언급했습니다. 따라서 "인덱스"의 목적을 이해하는 것은 매우 중요합니다.

## 인덱스에 대하여

간단히 말해, "인덱스"의 목적은 주로 "어떤 파일이 다음 커밋 버전에 제출될 것인지"를 기록하는 것입니다.

다시 말해, "Git 리포지토리에 버전을 제출하려면 먼저 인덱스 상태를 업데이트해야 하며, 그래야 변경 사항이 제출됩니다."

이 "인덱스"는 실제로 많은 외국 글에서 많은 별칭을 가지고 있지만, 모두 같은 의미입니다. 앞으로 관련 단어를 보더라도 혼동하지 마세요.

* Index
* Cache
* Directory cache
* Current directory cache
* Staging area
* Staged files

예를 들어, `git diff --cached` 명령어는 `git diff --staged`와 완전히 동의어입니다.

## 인덱스를 조작하는 명령어

"인덱스"는 Git에 매우 중요하므로, 대부분의 명령어에는 Git 인덱스와 관련된 매개변수가 있습니다. 그러나 여기서는 "인덱스"와 직접 관련된 몇 가지 명령어를 대략 나열하여 설명하겠습니다.

명령어를 설명하기 전에, 먼저 다음 다이어그램을 보세요. 이 다이어그램은 명령어를 통해 상태가 변경되는 생명 주기를 보여 줍니다. 사실 이러한 변경 과정은 모두 "인덱스 파일"을 업데이트하는 과정입니다.

![이미지](figures/07/01.png)

먼저 네 가지 파일 상태를 소개하겠습니다.

* untracked(추적되지 않음, 아직 Git 리포지토리에 추가되지 않은 파일의 상태를 나타냅니다)
* unmodified(수정되지 않음, 파일이 처음 추가될 때의 상태, 또는 파일 내용이 HEAD 내용과 일치하는 상태를 나타냅니다)
* modified(이미 수정됨, 파일이 편집되었거나 파일 내용이 HEAD 내용과 일치하지 않는 상태를 나타냅니다)
* staged(커밋 대기 중, 다음에 git commit이 실행될 때 이 파일들이 모두 리포지토리로 보내질 것임을 나타냅니다)

### git status

**작업 트리**(working tree)의 상태를 가져옵니다.

이미 리포지토리, 작업 디렉터리, 개체, 인덱스 사이의 관계에 대해 이야기했으므로, 이 관계를 한 문장으로 설명할 수 있습니다.

```txt
Git repository operation is to write data into Git objects by updating the index with changes in the working directory.
```

여기서 `git status` 명령어의 목적은 **최신 버전**과 **인덱스 파일** 사이의 차이를 표시하는 것입니다. 여기에는 몇 가지 미묘한 관계가 포함되어 있습니다. 예시를 들어 이 관계를 설명하겠습니다.

다음은 git status를 실행한 결과입니다.

```sh
G:\git-demo>git status
# On branch master
# Changes to be committed:
#   (use "git reset HEAD <file>..." to unstage)
#
#       new file:   c.txt
#
# Changes not staged for commit:
#   (use "git add <file>..." to update what will be committed)
#   (use "git checkout -- <file>..." to discard changes in working directory)
#
#       modified:   a.txt
#
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#
#       b.txt
```

여기서는 세 가지 서로 다른 그룹을 볼 수 있습니다.

* Changes to be committed(제출할 준비가 된 변경 사항)
  * 이 영역에는 `new file: c.txt` 파일이 있는데, 이는 c.txt가 새 파일이며 커밋할 준비가 된 것으로 표시되었음을 의미합니다.
  * 이는 몇 가지를 나타냅니다.
    1. c.txt 파일은 현재 **작업 디렉터리**에 존재합니다
    2. c.txt 파일이 **인덱스**에 추가되었습니다
    3. **인덱스**에 있는 c.txt의 내용이 **작업 디렉터리**의 내용과 일치합니다
    4. git commit을 실행하면 **인덱스**의 내용이 커밋됩니다(작업 디렉터리의 내용이 아닙니다)

* Changes not staged for commit(수정되었지만 아직 커밋을 위해 스테이징되지 않은 변경 사항)
  * 이 영역에는 `modified: a.txt` 파일이 있는데, 이는 a.txt가 수정된 파일이지만 커밋할 준비가 된 것으로 표시되지 않았음을 의미합니다.
  * 이는 몇 가지를 나타냅니다.
    1. a.txt 파일은 현재 **작업 디렉터리**에 존재합니다
    2. a.txt 파일이 **인덱스**에 추가되었습니다
    3. **인덱스**에 있는 a.txt의 내용이 **작업 디렉터리**의 내용과 일치하지 않습니다
    4. git commit을 실행하면 **인덱스**의 내용만 커밋됩니다(작업 디렉터리의 내용이 아닙니다)

* Untracked files(추적되지 않는 파일)
  * 이 영역에는 `b.txt` 파일이 있는데, 이는 b.txt가 새 파일이며 인덱스에 추가되지 않았음을 의미합니다.
  * 이는 몇 가지를 나타냅니다.
    1. b.txt 파일은 현재 **작업 디렉터리**에 존재합니다
    2. b.txt 파일이 **인덱스**에 추가되지 않았습니다
    3. git commit을 실행하면 이 파일은 커밋되지 않습니다

### git add

파일 내용을 인덱스에 추가합니다(다음 커밋을 위해 파일을 스테이징합니다).

`git add` 명령어에는 많은 용도가 있습니다. 간단히 말해, 이 명령어를 실행하면 "인덱스를 업데이트"하지만, 현재 파일 상태에 따라 인덱스가 업데이트되는 방식이 다를 수 있습니다.

* 파일이 **untracked** 상태이면, `git add`를 실행하면 파일 내용이 인덱스에 추가됩니다
* 파일이 **modified** 상태이면, `git add`를 실행하면 파일 내용이 인덱스로 업데이트됩니다
* 파일이 **staged** 상태이면, `git add`를 실행하면 파일 내용이 인덱스로 다시 업데이트됩니다

### git rm

작업 트리와 인덱스에서 파일을 제거합니다.

이 명령어는 **작업 디렉터리**와 **인덱스** 모두에서 파일을 삭제합니다. 삭제한 후에는 git commit을 실행하여 이 삭제 작업을 완료해야 합니다.

### git mv

파일, 디렉터리 또는 심볼릭 링크를 이동하거나 이름을 변경합니다.

이 명령어는 **작업 디렉터리**와 **인덱스** 모두에서 파일을 이동하거나 이름을 변경합니다. 이동하거나 이름을 변경한 후에는 git commit을 실행하여 이 작업을 완료해야 합니다.

### git commit

변경 사항을 리포지토리에 기록합니다.

이 명령어는 현재 **인덱스** 내용을 **개체 데이터베이스**에 기록하고 커밋 개체를 생성합니다.

### git ls-files

인덱스와 작업 트리에 있는 파일에 대한 정보를 표시합니다.

이 명령어는 인덱스의 파일 목록과 상태를 표시할 수 있습니다. 이것은 인덱스의 현재 상태를 이해하는 데 도움이 되는 매우 유용한 명령어입니다.

몇 가지 흔한 매개변수는 다음과 같습니다.

* `git ls-files -s` 또는 `git ls-files --stage` : 인덱스의 파일 목록과 상세 정보 표시
* `git ls-files -c` 또는 `git ls-files --cached` : 캐시된 파일 목록 표시
* `git ls-files -d` 또는 `git ls-files --deleted` : 삭제된 파일 목록 표시
* `git ls-files -m` 또는 `git ls-files --modified` : 수정된 파일 목록 표시
* `git ls-files -o` 또는 `git ls-files --others` : 추적되지 않는 파일 목록 표시

## 오늘의 요약

Git에서 "인덱스"는 매우 중요한 개념입니다. 인덱스를 통해 Git은 어떤 파일이 다음 커밋 버전에 제출될 것인지를 알 수 있습니다. 다양한 명령어를 통해 인덱스 상태를 업데이트하고 어떤 파일이 제출될지를 제어할 수 있습니다. 인덱스를 이해하면 Git 버전 관리를 더 잘 마스터하는 데 도움이 됩니다.
