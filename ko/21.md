# Day 21: 커밋된 버전 이력 수정하기 Part 3 (cherry-pick)

버전 관리 과정에는 또 다른 흔한 상황이 있습니다. 어떤 브랜치에서 한동안 개발을 진행했지만, 나중에 그 브랜치 전체는 더 이상 필요 없다고 판단하는 경우입니다. 그런데 그 안에 있는 몇 개의 커밋은 여전히 유지하고 싶습니다. 이 경우 브랜치를 삭제할 수도 없고, 브랜치 전체를 병합하는 것도 적절하지 않습니다. 어떻게 해야 할까요? 이 글에서는 `git cherry-pick` 명령어를 사용해 원하는 변경 사항을 "수동으로 선택"하여 적용하는 방법을 설명하겠습니다.

## git cherry-pick 이해하기

때로는 브랜치 전체를 병합하지 않고 한 브랜치의 특정 커밋만 다른 브랜치에 적용하고 싶을 수 있습니다. Git의 `cherry-pick` 명령어를 사용하면 바로 그렇게 할 수 있습니다. 커밋을 선택적으로 골라 현재 브랜치에 적용하는 것입니다.

`git cherry-pick`은 기존 커밋이 도입한 변경 사항을 현재 브랜치에 적용합니다. 동일한 변경 사항을 담은 새 커밋을 만들지만 커밋 해시는 달라집니다.

## 기본 Cherry-Pick

커밋 하나를 cherry-pick하려면 다음을 사용합니다.

```
# Switch to the target branch
git checkout main

# Cherry-pick the commit
git cherry-pick <commit-hash>
```

이렇게 하면 지정한 커밋과 동일한 변경 사항을 담은 새 커밋이 현재 브랜치에 만들어집니다.

## 여러 커밋 Cherry-Pick하기

여러 커밋을 cherry-pick하려면 다음을 사용합니다.

```
# Cherry-pick several commits
git cherry-pick <hash1> <hash2> <hash3>
```

커밋 범위를 cherry-pick하려면 다음을 사용합니다.

```
# Cherry-pick commits from commit1 to commit2 (exclusive of commit1)
git cherry-pick commit1..commit2

# Cherry-pick commits from commit1 to commit2 (inclusive of commit1)
git cherry-pick commit1^..commit2
```

## 커밋하지 않고 Cherry-Pick하기

자동으로 커밋을 만들지 않고 변경 사항만 적용하려면 다음을 사용합니다.

```
git cherry-pick --no-commit <commit-hash>
# or
git cherry-pick -n <commit-hash>
```

이는 여러 커밋을 cherry-pick한 뒤 하나의 커밋으로 만들고 싶을 때 유용합니다.

## 충돌 처리하기

cherry-pick 중 충돌이 발생하면 다음을 수행합니다.

```
# Resolve conflicts in the files
# Stage the resolved files
git add <resolved-files>

# Continue the cherry-pick
git cherry-pick --continue
```

진행 중인 cherry-pick을 중단하려면 다음을 사용합니다.

```
git cherry-pick --abort
```

현재 커밋을 건너뛰고 다음 커밋으로 계속 진행하려면 다음을 사용합니다.

```
git cherry-pick --skip
```

## 편집하며 Cherry-Pick하기

cherry-pick하면서 커밋 메시지를 편집하려면 다음을 사용합니다.

```
git cherry-pick -e <commit-hash>
# or
git cherry-pick --edit <commit-hash>
```

## Cherry-Pick과 Sign-off

커밋 메시지에 sign-off 줄을 추가하려면 다음을 사용합니다.

```
git cherry-pick -s <commit-hash>
# or
git cherry-pick --signoff <commit-hash>
```

## 실용적인 사용 사례

### 사용 사례 1: 여러 브랜치에 핫픽스 적용하기

```
# Fix created on main branch (commit abc123)
git checkout release-1.0
git cherry-pick abc123

git checkout release-2.0
git cherry-pick abc123
```

### 사용 사례 2: 선택적 기능 통합

```
# Feature branch has commits A, B, C, D
# You only want B and C on main

git checkout main
git cherry-pick <hash-B> <hash-C>
```

### 사용 사례 3: 유실된 커밋 복구하기

```
# Find the lost commit using reflog
git reflog

# Cherry-pick it to current branch
git cherry-pick <lost-commit-hash>
```

## Cherry-Pick vs Merge vs Rebase

**Cherry-pick**:
* 특정 커밋을 선택적으로 적용합니다
* 새 커밋 해시를 만듭니다
* 선택적 통합에 적합합니다

**Merge**:
* 브랜치 전체를 결합합니다
* 전체 이력을 보존합니다
* 기능 브랜치를 통합할 때 가장 좋습니다

**Rebase**:
* 새 베이스 위에 커밋을 재생합니다
* 선형 이력을 만듭니다
* 이력을 정리할 때 좋습니다

## 모범 사례

1. **아껴서 사용하세요**: Cherry-pick을 과도하게 사용하면 이력이 혼란스러워질 수 있습니다
2. **이유를 문서화하세요**: 커밋 메시지에 cherry-pick한 이유를 설명하세요
3. **중복을 피하세요**: 나중에 병합될 커밋은 cherry-pick하지 마세요
4. **의존성을 확인하세요**: 커밋이 다른 커밋에 의존하지 않는지 확인하세요
5. **cherry-pick 후 테스트하세요**: 변경 사항이 새 맥락에서 동작하는지 확인하세요

## Cherry-Pick한 커밋 추적하기

Git은 cherry-pick한 커밋을 추적할 수 있습니다.

```
# Cherry-pick with -x flag
git cherry-pick -x <commit-hash>
```

이렇게 하면 커밋 메시지에 "(cherry picked from commit ...)"라는 줄이 추가됩니다.

## 피해야 할 흔한 실수

1. **병합 커밋 cherry-pick하기**: 보통 문제를 일으킵니다
2. **기능 브랜치에서 main으로 cherry-pick하기**: 병합할 때 중복 커밋이 생길 수 있습니다
3. **테스트하지 않기**: 변경 사항이 다른 브랜치에서는 다르게 동작할 수 있습니다
4. **의존성 무시하기**: cherry-pick한 커밋이 동작하려면 다른 커밋이 필요할 수 있습니다

## 오늘의 요약

`git cherry-pick`은 한 브랜치에서 다른 브랜치로 커밋을 선택적으로 적용할 수 있는 강력한 도구입니다. 여러 릴리스 브랜치에 핫픽스를 적용하거나 개발 브랜치에서 특정 기능만 선택할 때 특히 유용합니다. 다만 과도하게 사용하면 이력이 복잡해질 수 있으므로 신중하게 사용해야 합니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git cherry-pick <commit>
* git cherry-pick <commit1> <commit2>
* git cherry-pick commit1..commit2
* git cherry-pick --no-commit
* git cherry-pick -n
* git cherry-pick --continue
* git cherry-pick --abort
* git cherry-pick --skip
* git cherry-pick -e
* git cherry-pick -x
* git cherry-pick --signoff
