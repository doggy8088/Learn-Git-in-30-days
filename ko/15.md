# Day 15: 태그 - 버전 관리의 중요한 이벤트 표시하기

Git을 사용해 버전 관리를 하다 보면 수많은 버전이 생성됩니다. 시간이 지나면서 이 많은 버전 중에는 분명 기록할 가치가 있는 중요한 버전이 생기기 마련입니다. 이것이 바로 "태그"가 우리를 도와줄 수 있는 일입니다.

## 태그 이해하기 - 기본 개념

기본적으로 태그의 목적은 특정 "버전" 또는 "커밋 개체"에 "기억하기 쉬운 이름"을 표시하여 특정 버전을 기억하는 데 도움을 주는 것입니다.

태그는 Git 기록의 특정 커밋을 가리키는 참조입니다. 브랜치와 달리 태그는 새 커밋을 만들어도 이동하지 않으며, 항상 같은 커밋을 가리킵니다. 이 덕분에 태그는 릴리스 지점이나 기타 중요한 마일스톤을 표시하는 데 이상적입니다.

Git은 두 가지 유형의 태그를 지원합니다.

1. **경량 태그(Lightweight tags)**: 특정 커밋에 대한 단순한 이름(별칭)으로, "참조 이름"의 한 종류입니다
2. **주석 태그(Annotated tags)**: 추가 메타데이터와 함께 완전한 Git 개체로 저장됩니다

Day 11(Git 개체 참조 이해하기)에서 언급했듯이, "일반 참조"에는 "태그 이름"이 포함되며, 여기서의 "태그 이름"은 "경량 태그"를 가리킵니다. 따라서 "경량 태그"는 어떤 커밋 버전에 대한 "별칭"에 불과하며, "참조 이름"의 한 종류라고 말할 수 있습니다.

"주석 태그"는 Git 개체의 한 종류입니다. Day 06(Git 데이터 구조 파헤치기 - 개체 구조)에서 언급했듯이, Git 개체에는 Blob, Tree, Commit, Tag 개체의 4가지 개체 유형이 있습니다. 여기서 언급하는 "주석 태그"가 바로 Tag 개체입니다. Tag 개체는 Git의 개체 저장소(`.git\objects\` 디렉터리에 저장됨)에 저장되며 또 다른 커밋 개체와 연결됩니다. "주석 태그"를 만들 때는 커밋 개체를 만들 때와 마찬가지로 "버전 메시지"를 포함할 수 있습니다. Git에 내장된 태그 메커니즘에서는 GnuPG 키를 사용해 Tag 개체에 서명함으로써 메시지의 "부인 방지"를 보장할 수도 있습니다.

이 두 가지 태그 유형이 있고, 둘 다 커밋 개체의 "별칭"처럼 보이지만, 이 두 태그의 사용법에는 약간의 차이만 있습니다. 대부분의 사용 사례에서는 "주석 태그"를 사용해 "태그 개체"를 만들고 "버전 메시지"를 제공하는데, 이는 이 유형의 "태그"가 Git 리포지토리의 "영구 개체"이기 때문입니다. (개체 저장소에 저장된 Git 개체는 변경할 수 없으며, 인덱스만 변경됩니다.)

## 경량 태그 만들기

태그를 만드는 가장 간단한 방법입니다.

```
git tag v1.0
```

이렇게 하면 현재 커밋(HEAD)을 가리키는 `v1.0`이라는 이름의 경량 태그가 만들어집니다.

특정 커밋에 태그를 달려면 다음을 사용합니다.

```
git tag v0.9 <commit-hash>
```

**참고**: `.git\refs\` 아래의 모든 파일은 "참조 이름"입니다.

기본 사용법:
* 모든 태그 나열: `git tag`
* 경량 태그 만들기: `git tag [tagname]`
* 경량 태그 삭제: `git tag [tagname] -d`

"경량 태그"의 내용을 보고 싶다면 `git cat-file -p [tagname]`을 사용할 수 있습니다. "경량 태그"의 개체 유형을 보고 싶다면 `git cat-file -t [tagname]`을 사용할 수 있습니다.

**중요 참고 사항**: 경량 태그는 Git 개체가 아닙니다. 위에서 볼 수 있듯이 태그 이름은 커밋 개체의 내용을 가져오며, 이름으로 찾은 개체 유형은 커밋 개체입니다.

## 주석 태그 만들기

주석 태그는 추가 정보를 저장하므로 대부분의 사용 사례에 권장됩니다.

```
git tag -a v1.0 -m "Release version 1.0"
```

`-a` 플래그는 주석 태그를 만들고, `-m`은 태그 메시지를 지정합니다.

경량 태그와의 차이점:
1. `git tag`를 실행해 모든 태그를 나열하면 모든 태그가 섞여 표시되어 태그 유형을 볼 수 없습니다
2. "주석 태그"를 만들려면 `-a` 매개변수가 필요합니다
3. "주석 태그"를 만들 때는 `git commit`을 실행할 때와 마찬가지로 "버전 메시지"를 반드시 포함해야 하며, 둘 다 `-m` 매개변수를 사용할 수 있습니다

## 태그 나열하기

리포지토리의 모든 태그를 보려면 다음을 사용합니다.

```
git tag
```

패턴과 일치하는 태그를 보려면 다음을 사용합니다.

```
git tag -l "v1.*"
```

## 태그 정보 보기

경량 태그의 경우:

```
git show v1.0
```

이렇게 하면 태그가 가리키는 커밋이 표시됩니다.

주석 태그의 경우:

```
git show v1.0
```

이렇게 하면 태그 정보와 함께 커밋 세부 정보가 표시됩니다.

## 오래된 커밋에 태그 달기

HEAD에 있지 않은 커밋에도 태그를 달 수 있습니다.

```
git log --oneline  # Find the commit hash
git tag -a v0.5 -m "Beta release" <commit-hash>
```

## 태그를 원격에 Push하기

기본적으로 `git push`는 태그를 전송하지 않습니다. 명시적으로 push해야 합니다.

```
# Push a specific tag
git push origin v1.0

# Push all tags
git push origin --tags
```

## 태그 삭제하기

로컬 태그를 삭제하려면 다음을 사용합니다.

```
git tag -d v1.0
```

원격 태그를 삭제하려면 다음을 사용합니다.

```
git push origin :refs/tags/v1.0
# or
git push origin --delete v1.0
```

## 태그 체크아웃하기

특정 태그의 코드를 체크아웃할 수 있습니다.

```
git checkout v1.0
```

이렇게 하면 "분리된 HEAD(detached HEAD)" 상태가 됩니다. 변경 작업을 하고 싶다면 새 브랜치를 만드세요.

```
git checkout -b version-1-fixes v1.0
```

## 오늘의 요약

태그는 버전 관리의 필수적인 부분으로, 프로젝트 기록의 중요한 지점을 표시할 수 있게 해 줍니다. 주석 태그는 릴리스 노트, 태그 작성자 정보, 서명과 같은 추가 정보를 저장할 수 있어 릴리스에 특히 유용합니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git tag
* git tag -a
* git tag -l
* git show
* git push origin --tags
* git tag -d
* git checkout
