# Day 13: 작업 디렉터리와 인덱스의 변경 사항 스태시하기

이런 상황을 겪어 본 적이 있으신가요? 시스템 개발을 절반쯤 진행하고 있는데, 갑자기 상사나 고객이 "긴급 명령"을 내려 기존 시스템의 버그를 긴급히 수정하거나 기능을 추가해 달라고 요청하는 경우 말입니다. 눈앞의 프로그램은 거의 완성 단계에 있고, 상사의 "긴급한 일"은 미룰 수 없습니다. 완성되지 않은 소프트웨어 개발 상태에 긴급 조정 요구까지 더해지면, 이는 소프트웨어 품질에 대한 큰 시험이 됩니다. 이런 고민이 있다면 Git이 작업을 멋지게 완수할 수 있도록 도와줄 수 있습니다.

## git stash 명령어 이해하기

Git 버전 관리를 사용할 때는 "작업 디렉터리"와 "인덱스"가 구분된다는 것을 알고 있습니다. 작업 디렉터리에는 절반쯤 변경하고 아직 끝내지 않은 파일(아직 인덱스에 추가되지 않음)도 있고, 새로 만들었지만 아직 추가되지 않은 파일(아직 인덱스에 추가되지 않음)도 있습니다. 인덱스에 놓인 데이터는 `git commit`을 통해 버전(커밋 개체 생성)을 만들 계획인 내용입니다.

기능 개발을 절반쯤 진행하다가 긴급히 중단되면 분명 당황하게 되며, 특히 손에 들고 있는 절반쯤 다시 쓴 프로그램들을 어떻게 해야 할지 모르게 됩니다. Git에는 `git stash`라는 명령어가 있어, 절반쯤 작성한 파일들에 대해 자동으로 "특수 버전"(이것도 커밋 개체)을 만들어 줄 수 있습니다. 이러한 버전을 스태시 버전이라고 부르거나, 직접 "스테이징 버전"이라고 불러도 됩니다.

## 스태시 버전 만들기

절반쯤 변경한 파일은 다음과 같은 상태를 가질 수 있습니다.

* 새 파일(추적되지 않는 파일)
* 새 파일(이미 인덱스에 추가된 파일)(추적됨/스테이징된 파일)
* 수정된 파일(아직 인덱스에 추가되지 않은 파일)(추적됨/스테이징되지 않은 파일)
* 수정된 파일(이미 인덱스에 추가된 파일)(추적됨/스테이징된 파일)
* 삭제된 파일(아직 인덱스에 추가되지 않은 파일)(추적됨/스테이징되지 않은 파일)
* 삭제된 파일(이미 인덱스에 추가된 파일)(추적됨/스테이징된 파일)

이렇게 절반쯤 개발한 파일들에 대해 "스테이징 버전"을 만들고 싶다면 두 가지 선택지가 있습니다.

* `git stash`는 추적되는 모든 파일에 대해 스테이징 버전을 만듭니다
* `git stash -u`는 추적되거나 추적되지 않는 모든 파일을 포함하며, 모두 스테이징 버전으로 만들어집니다

**참고**: `git stash`는 `git stash save`라고 쓸 수도 있습니다. 두 명령어의 결과는 동일하며, 단지 `save` 매개변수를 생략할 수 있을 뿐입니다.

### 예시 워크플로

다음은 간단한 실습 예시입니다.

```bash
# You're working on features
echo "new feature" > feature.txt
git add feature.txt

# Suddenly need to fix a bug
# Stash your work-in-progress
git stash

# Now working directory is clean
# Fix the bug on another branch
git checkout main
# ... make fixes ...
git commit -m "Fix urgent bug"

# Return to your feature work
git checkout feature-branch
git stash pop  # Restore your work
```

## 스태시한 변경 사항 복원하기

변경 사항을 스태시한 후에는 다른 브랜치로 전환하거나 긴급한 작업을 처리할 수 있습니다. 원래 작업을 계속할 준비가 되면, 다음을 사용해 스태시한 변경 사항을 복원할 수 있습니다.

* `git stash pop` - 가장 최근의 스태시를 적용하고 스태시 목록에서 제거합니다
* `git stash apply` - 가장 최근의 스태시를 적용하지만 스태시 목록에 유지합니다

## 스태시한 변경 사항 목록 보기

스태시한 내용이 무엇인지 보려면 다음을 사용합니다.

```
git stash list
```

이렇게 하면 스태시 참조(stash@{0}, stash@{1} 등)와 함께 스태시한 모든 변경 사항이 표시됩니다.

## 특정 스태시 적용하기

스태시가 여러 개 있는 경우, 번호를 참조하여 특정 스태시를 적용할 수 있습니다.

```
git stash apply stash@{2}
```

## 스태시 삭제하기

목록에서 특정 스태시를 제거하려면 다음을 사용합니다.

```
git stash drop stash@{0}
```

모든 스태시를 제거하려면 다음을 사용합니다.

```
git stash clear
```

## 추적되지 않는 파일 스태시하기

기본적으로 `git stash`는 추적되는 파일만 스태시합니다. 추적되지 않는 파일도 함께 스태시하려면 다음을 사용합니다.

```
git stash -u
```

또는 무시되는 파일을 포함해 모든 것을 스태시하려면 다음을 사용합니다.

```
git stash -a
```

## 이름이 있는 스태시 만들기

스태시에 설명적인 메시지를 붙일 수 있습니다.

```
git stash save "Work in progress on feature X"
```

이렇게 하면 나중에 스태시를 식별하기가 더 쉬워집니다.

## 스태시 내용 보기

특정 스태시를 적용하지 않고 그 안에 무엇이 들어 있는지 보려면 다음을 사용합니다.

```
git stash show stash@{0}
```

자세한 diff를 보려면 다음을 사용합니다.

```
git stash show -p stash@{0}
```

## 오늘의 요약

`git stash` 명령어는 현재 작업을 커밋하지 않고도 일시적으로 따로 보관할 수 있게 해 주는 매우 실용적인 도구입니다. 이는 다른 작업을 하기 위해 빠르게 컨텍스트를 전환해야 할 때 특히 유용합니다. 스태시 메커니즘은 작업 중인 변경 사항이 안전하게 저장되고 나중에 복원될 수 있도록 보장합니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git stash
* git stash save
* git stash -u
* git stash list
* git stash pop
* git stash apply
* git stash drop
* git stash clear
* git stash show
