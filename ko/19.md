# Day 19: .gitignore 무시 목록 설정하기

프로젝트를 개발하다 보면 작업 디렉터리에 새 파일이 자주 나타날 수 있습니다(Visual Studio 같은 개발 도구가 생성하는 임시 파일이나 캐시 파일 등). 이러한 파일 중 상당수는 버전 관리에 포함할 필요가 없으므로 제외해야 합니다. 우리는 이것을 "무시 목록"이라고 부릅니다.

## .gitignore 이해하기

`.gitignore` 파일은 Git이 무시해야 하는, 의도적으로 추적되지 않는 파일을 지정합니다. Git에서 `.gitignore` 파일은 "무시 목록"을 정의하는 데 사용됩니다. 주된 목적은 버전 관리에 추가할 필요가 없는 파일을 제외하는 것입니다. 이 파일에 나열된 파일이나 경로(와일드카드를 포함할 수 있음)는 `git status` 결과에 나타나지 않으며, 당연히 `git add`를 실행할 때도 추가되지 않습니다.

그러나 이는 `Untracked files`에만 적용됩니다. 이미 Git이 추적하고 있는 파일(`Staged files`)은 `.gitignore` 파일의 영향을 받지 않습니다.

## GitHub를 통해 .gitignore 만들기

GitHub에서 프로젝트를 만들어 본 적이 있다면 이 기능을 사용해 보았을 것입니다. 새 리포지토리를 만들 때 GitHub가 설정을 도와주는 미리 정의된 무시 목록을 선택할 수 있습니다. 이 무시 목록은 사실 `.gitignore`라는 이름의 파일일 뿐이며, 기본적으로 프로젝트 루트 디렉터리에 놓입니다.

다음과 같은 다양한 템플릿 중에서 선택할 수 있습니다.
- Node
- Python
- Java
- C#
- Visual Studio
- 그 외 다수

## .gitignore 수동으로 만들기

리포지토리 루트에 `.gitignore`라는 이름의 파일을 만들면 됩니다.

```
# On Windows
echo node_modules/ > .gitignore

# On Linux/Mac
echo "node_modules/" > .gitignore
```

또는 텍스트 편집기로 수동으로 만듭니다.

## 기본 패턴

### 특정 파일 무시하기

```
config.local.js
secrets.txt
```

### 특정 확장자를 가진 파일 무시하기

```
*.log
*.tmp
*.cache
```

### 디렉터리 무시하기

```
node_modules/
dist/
build/
```

디렉터리를 나타내는 끝의 슬래시에 주목하세요.

### 모든 디렉터리의 파일 무시하기

```
# Ignore all .log files in any directory
**/*.log
```

## 고급 패턴

### 부정(예외)

`!`를 사용해 예외를 만듭니다.

```
# Ignore all .log files
*.log

# But don't ignore important.log
!important.log
```

### 특정 디렉터리의 파일만 무시하기

```
# Ignore test.txt only in root directory
/test.txt

# Ignore test.txt in any subdirectory, but not root
*/test.txt
```

### 여러 확장자

```
# Ignore multiple file types
*.{jpg,png,gif}
```

## 전역 .gitignore

모든 리포지토리에 걸쳐 무시하고 싶은 패턴에 대해서는 다음을 사용합니다.

```
git config --global core.excludesfile ~/.gitignore_global
```

그런 다음 패턴을 담은 `~/.gitignore_global`을 만듭니다.

## 이미 추적되는 파일 무시하기

무시해야 할 파일을 실수로 커밋한 경우:

```
# Remove from Git but keep the file
git rm --cached filename

# Remove directory from Git but keep it
git rm -r --cached directory/
```

그런 다음 패턴을 `.gitignore`에 추가하고 커밋합니다.

## 무시된 파일 보기

어떤 파일이 무시되고 있는지 보려면 다음을 사용합니다.

```
git status --ignored
```

## 파일이 무시되는 이유 확인하기

어떤 패턴 때문에 파일이 무시되는지 보려면 다음을 사용합니다.

```
git check-ignore -v filename
```

## 템플릿 .gitignore 파일

GitHub는 다양한 언어와 프레임워크를 위한 템플릿 .gitignore 파일을 제공합니다.

* https://github.com/github/gitignore

## .gitignore의 주석

주석에는 `#`를 사용합니다.

```
# This is a comment
*.log  # Inline comment
```

## 모범 사례

1. **.gitignore를 일찍 커밋하세요**: 프로젝트 시작 시점에 추가하세요
2. **구체적으로 작성하세요**: 지나치게 광범위한 패턴은 피하세요
3. **이유를 문서화하세요**: 주석을 사용해 명확하지 않은 패턴을 설명하세요
4. **정리된 상태를 유지하세요**: 관련 패턴을 함께 그룹화하세요
5. **템플릿을 사용하세요**: 언어별 템플릿으로 시작하세요
6. **로컬 변형**: 개인 패턴에는 `.git/info/exclude`를 사용하세요

## 하위 디렉터리 .gitignore

하위 디렉터리에도 `.gitignore` 파일을 둘 수 있습니다. 패턴은 `.gitignore` 파일의 위치를 기준으로 상대적입니다.

## 오늘의 요약

`.gitignore` 파일은 리포지토리를 깨끗하게 유지하고, 버전 관리에 속하지 않는 파일을 실수로 커밋하는 것을 피하는 데 필수적입니다. 패턴 구문과 모범 사례를 이해하면 깨끗하고 전문적인 리포지토리를 유지하는 데 도움이 됩니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git rm --cached
* git rm -r --cached
* git status --ignored
* git check-ignore
* git config core.excludesfile
