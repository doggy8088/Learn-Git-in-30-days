# Day 20: 커밋된 버전 이력 수정하기 Part 2 (revert)

버전 관리 과정에는 또 다른 흔한 상황이 있습니다. 여러 번 커밋을 실행한 후에 이전의 일부 커밋이 잘못되었음을 발견하는 경우입니다. 예를 들어 테스트 코드를 실수로 커밋하여 현재 버전에 문제가 생긴 경우입니다. 이럴 때는 이 글에서 설명하는 내용을 이해해야 합니다.

Day 18에서는 로컬 커밋 이력을 수정하기 위한 `git reset`과 `git commit --amend`에 대해 배웠습니다. 그러나 이 명령어들은 이력을 다시 쓰므로, 공유 리포지토리에 push된 커밋에는 사용해서는 안 됩니다. 공유된 이력에 대해서는 `git revert`가 안전한 대안입니다.

## git revert 이해하기

`git revert`는 이전 커밋의 변경 사항을 되돌리는 새 커밋을 만듭니다. `reset`과 달리 이력을 다시 쓰지 않고 이력에 추가합니다. 이 덕분에 공유 브랜치에서도 안전합니다.

이 시점에 이전의 어떤 커밋(예를 들어 `HEAD~`나 `HEAD^`, 또는 특정 커밋 해시)이 잘못 수행되었음을 발견했다고 가정해 보겠습니다. 첫 번째 버전으로 reset하고 모든 것을 다시 하는 것이 아니라, **그 특정 버전만** 되돌리고 싶을 것입니다. 이 경우 `git revert` 명령어를 사용해 볼 수 있는데, 이는 "역방향" 단계를 통해 어떤 버전의 변경 사항을 되돌릴 수 있습니다.

"역방향"이란 무엇을 의미할까요? 바로 이 명령어를 사용해 보겠습니다.

**중요 참고 사항**: `git revert` 명령어를 실행하기 전에 작업 디렉터리가 깨끗한지 확인하세요! 부분적으로 수정된 파일이 있다면, `git stash`를 사용해 임시 스태시를 만드는 것을 권장합니다.

## 기본 Revert

가장 최근의 커밋을 되돌리려면 다음을 사용합니다.

```
git revert HEAD
```

이렇게 하면 마지막 커밋의 변경 사항을 되돌리는 새 커밋이 만들어집니다.

## 특정 커밋 되돌리기

`git log` 이력에서 문제가 있는 버전을 발견했다고 가정해 보겠습니다. 먼저 이 버전의 변경 기록을 확인할 수 있습니다. `git log`를 사용해 커밋 ID를 찾은 다음, `git show [commit_id]`를 사용해 해당 버전의 관련 정보를 볼 수 있습니다.

특정 커밋을 되돌리려면 다음을 사용합니다.

```
git revert <commit-hash>
```

예를 들면 다음과 같습니다.

```
git revert a1b2c3d
```

실행 중에는 최종 커밋 메시지를 편집하라는 요청을 받게 됩니다. 기본적으로 `Revert`라는 단어가 추가되고, 세 번째 줄에는 `This reverts commit xxxx`가 추가되어 이 버전의 주된 목적이 `xxxx` 버전을 되돌리는 것임을 알려 줍니다.

## 여러 커밋 되돌리기

커밋 범위를 되돌리려면 다음을 사용합니다.

```
# Revert commits from HEAD~3 to HEAD~1 (3 commits)
git revert HEAD~3..HEAD
```

또는 여러 개의 특정 커밋을 되돌립니다.

```
git revert <hash1> <hash2> <hash3>
```

## 커밋하지 않고 되돌리기

자동으로 커밋하지 않고 revert 변경 사항을 스테이징하려면 다음을 사용합니다.

```
git revert --no-commit HEAD
# or
git revert -n HEAD
```

이는 여러 커밋을 되돌리고 하나의 revert 커밋을 만들고 싶을 때 유용합니다.

```
git revert --no-commit HEAD~3..HEAD
git commit -m "Revert last 3 commits"
```

## 충돌 처리하기

때로는 커밋을 되돌리면 충돌이 발생할 수 있습니다.

```
git revert <commit-hash>
# If conflicts occur...
# 1. Resolve conflicts in the files
# 2. Stage the resolved files
git add <resolved-files>
# 3. Continue the revert
git revert --continue
```

진행 중인 revert를 중단하려면 다음을 사용합니다.

```
git revert --abort
```

## 병합 커밋 되돌리기

병합 커밋에는 부모가 두 개 있으므로 병합을 되돌리는 것은 더 복잡합니다. 어느 부모로 되돌릴지 지정해야 합니다.

```
# -m 1 means keep changes from the first parent (usually mainline)
git revert -m 1 <merge-commit-hash>
```

## Revert와 Reset 중 무엇을 사용할 것인가

**다음의 경우 `git revert`를 사용하세요:**
* 커밋이 공유 리포지토리에 push되었을 때
* 이력을 보존하고 싶을 때
* 공개 브랜치(main, develop 등)에서 작업할 때
* 되돌리기 작업의 기록이 필요할 때

**다음의 경우 `git reset`을 사용하세요:**
* 커밋이 로컬 리포지토리에만 있을 때
* 이력에서 커밋을 완전히 제거하고 싶을 때
* 비공개 기능 브랜치에서 작업할 때
* 커밋이 이력에 남아서는 안 되는 실수였을 때

## 변경 사항 되돌렸다가 다시 적용하기

때로는 커밋을 되돌린 뒤 나중에 다시 적용하고 싶을 수 있습니다.

```
# First, revert a commit
git revert <commit-hash>

# Later, revert the revert
git revert <revert-commit-hash>
```

## 실용적인 예시

### 예시 1: Main 브랜치의 잘못된 커밋 되돌리기

```
# Commit a1b2c3d introduced a bug
git revert a1b2c3d
git push origin main
```

### 예시 2: 여러 커밋 되돌리기

```
# Revert the last 5 commits as a single revert commit
git revert --no-commit HEAD~5..HEAD
git commit -m "Revert last 5 commits due to critical bug"
git push origin main
```

### 예시 3: 되돌린 뒤 수정하기

```
# Revert a problematic commit
git revert a1b2c3d

# Make necessary corrections
# ... edit files ...

# Commit the corrections
git add .
git commit -m "Fix issues from reverted commit"
git push origin main
```

## 모범 사례

1. **명확한 메시지를 작성하세요**: 되돌리는 이유를 설명하세요
   ```
   git revert a1b2c3d -m "Revert feature X due to performance issues"
   ```

2. **push하기 전에 테스트하세요**: revert가 아무것도 깨뜨리지 않는지 확인하세요

3. **소통하세요**: 커밋을 되돌릴 때 팀에게 알리세요

4. **대안을 고려하세요**: 때로는 앞으로 수정하는 것이 revert보다 낫습니다

5. **이유를 문서화하세요**: 이슈 번호를 참조하거나 맥락을 제공하세요

## Revert 이력 보기

이력에서 revert 커밋을 보려면 다음을 사용합니다.

```
git log --oneline --grep="Revert"
```

## 오늘의 요약

`git revert`는 공유 리포지토리에서 변경 사항을 되돌리는 안전한 방법입니다. 원치 않는 변경 사항을 되돌리면서도 이력의 무결성을 유지합니다. `revert`와 `reset` 중 무엇을 언제 사용할지 이해하는 것은 효과적인 협업과 깨끗하고 이해하기 쉬운 프로젝트 이력을 유지하는 데 매우 중요합니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git revert
* git revert HEAD
* git revert <commit-hash>
* git revert --no-commit
* git revert -n
* git revert -m
* git revert --continue
* git revert --abort
