# Day 14: Git for Windows 구성 옵션

Git for Windows 명령줄 도구를 사용하는 것은 GUI 도구를 통해 작업하는 것보다 확실히 더 효율적입니다. 그 이유는 명령어를 통해 반복적인 버전 관리 작업의 상당 부분을 자동화하거나, 복잡한 표준 작업 절차(SOP)를 간단한 명령어 작업으로 바꿀 수 있기 때문입니다. 이 글에서는 Git for Windows 명령줄 도구를 사용하는 몇 가지 팁을 공유하겠습니다.

## Git 명령줄 도구 구성 옵션 소개

Git 명령줄 도구에는 설정할 수 있는 "옵션"이 많이 있는데, 이는 GUI 도구를 사용할 때 보통 [도구] -> [기본 설정]에서 명령어 실행 시의 일부 동작을 미세 조정하는 것과 같습니다. 가장 흔한 것은 물론 Git for Windows를 처음 사용할 때 반드시 설정해야 하는 `user.name`과 `user.email` 옵션입니다. 이 두 옵션이 설정되어 있지 않으면 `git commit`을 실행할 권한조차 없습니다.

Git for Windows 도구에 현재 설정된 모든 옵션을 나열하려면 `git config --list` 명령어를 사용할 수 있습니다.

**참고**: 인터넷에 있는 대부분의 Git 글은 Linux나 Mac 환경을 설정하는 방법을 소개하므로, 이 글에서는 Windows 플랫폼 구성에 중점을 두겠습니다. 하지만 저장 경로가 다를 뿐, 명령어 사용법은 실제로 동일합니다.

어떤 "옵션"을 사용할 수 있는지 확인하고 싶다면, 명령 프롬프트에서 `git help config`를 실행해 전체 문서를 표시하거나 [git-config(1) Manual Page](https://www.kernel.org/pub/software/scm/git/docs/git-config.html)를 방문하면 됩니다.

## Git 구성 수준 이해하기

Git에는 세 가지 구성 수준이 있습니다.

1. **시스템 수준** (`--system`): 시스템의 모든 사용자에게 적용됩니다
   * 위치: `C:\Program Files\Git\etc\gitconfig`
   * **Windows에서 중요**: UAC가 활성화되어 있으면 설정이 `%LOCALAPPDATA%\VirtualStore\Program Files\Git\etc\gitconfig`로 리디렉션될 수 있습니다
   * **권장 사항**: 시스템 수준 옵션을 설정할 때는 항상 관리자 권한으로 명령 프롬프트를 실행하세요
   
2. **전역 수준** (`--global`): 현재 사용자에게 적용됩니다
   * 위치: `C:\Users\[username]\.gitconfig` 또는 `%USERPROFILE%\.gitconfig`
   * `user.name`, `user.email`, 개인 기본 설정에 흔히 사용됩니다
   
3. **로컬 수준** (`--local`): 현재 리포지토리에만 적용됩니다
   * 위치: 리포지토리의 `.git\config`
   * 리포지토리를 초기화하거나 클론할 때 자동으로 만들어집니다

낮은 수준의 구성이 높은 수준의 구성을 재정의합니다(로컬 > 전역 > 시스템).

## 구성 보기

현재의 모든 구성을 보려면 다음을 사용합니다.

```
git config --list
```

특정 수준의 구성을 보려면 다음을 사용합니다.

```
git config --global --list
git config --local --list
git config --system --list
```

## 사용자 신원 설정하기

가장 기본적인 구성은 사용자 이름과 이메일을 설정하는 것입니다.

```
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
```

이 설정은 여러분이 만드는 모든 커밋에 사용됩니다.

## 기본 편집기 구성하기

커밋 메시지에 사용할 선호하는 텍스트 편집기를 설정합니다.

```
git config --global core.editor "code --wait"  # VS Code
git config --global core.editor "notepad"      # Notepad
git config --global core.editor "vim"          # Vim
```

## 줄 끝 구성

이는 크로스 플랫폼 개발에서 중요합니다.

```
# Windows (convert LF to CRLF on checkout, CRLF to LF on commit)
git config --global core.autocrlf true

# Linux/Mac (convert CRLF to LF on commit, no conversion on checkout)
git config --global core.autocrlf input

# No conversion
git config --global core.autocrlf false
```

### 중요: Windows UAC와 VirtualStore

사용자 계정 컨트롤(UAC)이 활성화된 Windows Vista 이상에서는 시스템 수준 구성을 설정할 때 중요한 고려 사항이 있습니다.

**문제점**: Windows VirtualStore 기술은 관리자 권한이 없는 프로세스가 시스템 디렉터리에 쓰려고 할 때 파일 쓰기를 리디렉션합니다. 이는 다음을 의미합니다.
- 일반 명령 프롬프트로 만든 설정은 `%LOCALAPPDATA%\VirtualStore\Program Files\Git\etc\gitconfig`로 이동합니다
- 관리자 명령 프롬프트로 만든 설정은 `C:\Program Files\Git\etc\gitconfig`로 이동합니다
- 이 두 위치는 동기화되지 않아 예상치 못한 동작을 일으킵니다

**해결 방법**: 시스템 수준 옵션(`--system`)을 설정할 때는 설정이 시스템 전체에 적용되도록 항상 관리자 권한으로 명령 프롬프트를 실행하세요.

자세한 정보: [VirtualStore - Inside Windows Vista User Account Control](https://learn.microsoft.com/en-us/previous-versions/technet-magazine/cc138019(v=msdn.10))

## 별칭 구성하기

자주 사용하는 명령어에 대한 바로 가기를 만듭니다.

```
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.st status
git config --global alias.lg "log --oneline --graph --all"
```

그러면 `git checkout` 대신 `git co`를 사용하는 식으로 쓸 수 있습니다.

## 색상 출력

가독성을 높이기 위해 색상 출력을 활성화합니다.

```
git config --global color.ui auto
```

## 기본 브랜치 이름

새 리포지토리의 기본 브랜치 이름을 설정합니다.

```
git config --global init.defaultBranch main
```

## 병합 및 Diff 도구

선호하는 병합 및 diff 도구를 구성합니다.

```
git config --global merge.tool vimdiff
git config --global diff.tool vimdiff
```

## 자격 증명 도우미

비밀번호를 반복해서 입력하지 않도록 자격 증명을 저장합니다.

```
# Windows
git config --global credential.helper wincred

# Cache credentials for 1 hour
git config --global credential.helper 'cache --timeout=3600'
```

## Push 동작

기본 push 동작을 구성합니다.

```
# Push only the current branch
git config --global push.default simple

# Push all matching branches
git config --global push.default matching
```

## 구성 해제하기

구성을 제거하려면 다음을 사용합니다.

```
git config --global --unset user.name
git config --global --unset-all user.email
```

## 구성 파일 직접 편집하기

구성 파일을 직접 편집할 수도 있습니다.

```
git config --global --edit
git config --local --edit
```

## 오늘의 요약

Git을 이해하고 올바르게 구성하는 것은 원활한 워크플로를 위해 필수적입니다. 구성 시스템은 유연하고 강력하여, 여러분의 선호와 작업 환경에 맞게 Git을 사용자 지정할 수 있습니다.

오늘 배운 Git 명령어와 매개변수를 다시 정리하겠습니다.

* git config --list
* git config --global user.name
* git config --global user.email
* git config --global core.editor
* git config --global core.autocrlf
* git config --global alias.*
* git config --global --edit
* git config --global --unset
