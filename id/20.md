# Hari 20: Memperbaiki Riwayat Versi yang Sudah Di-commit Bagian 2 (revert)

Dalam proses kontrol versi, ada situasi umum lainnya: setelah menjalankan beberapa commit, Anda menemukan bahwa beberapa commit sebelumnya salah. Sebagai contoh, Anda secara tidak sengaja melakukan commit kode pengujian, menyebabkan masalah pada versi saat ini. Dalam kasus ini, Anda perlu memahami konten yang dijelaskan dalam artikel ini.

Pada Hari 18, kita mempelajari tentang `git reset` dan `git commit --amend` untuk memperbaiki riwayat commit lokal. Namun, perintah-perintah ini menulis ulang riwayat dan tidak boleh digunakan untuk commit yang telah di-push ke repositori bersama. Untuk riwayat bersama, `git revert` adalah alternatif yang aman.

## Memahami git revert

`git revert` membuat commit baru yang membatalkan perubahan dari commit sebelumnya. Tidak seperti `reset`, perintah ini tidak menulis ulang riwayat — perintah ini menambahkannya. Hal ini membuatnya aman untuk branch bersama.

Misalkan pada titik ini Anda menemukan bahwa commit sebelumnya (seperti `HEAD~` atau `HEAD^` atau hash commit tertentu) dilakukan secara tidak benar. Anda ingin me-revert **versi spesifik itu** saja, daripada mereset ke versi pertama dan mengulang semuanya. Dalam kasus ini, Anda dapat mencoba perintah `git revert`, yang dapat membatalkan perubahan versi tertentu melalui langkah-langkah "terbalik".

Apa arti "terbalik"? Mari kita segera coba perintah ini.

**Catatan Penting**: Sebelum menjalankan perintah `git revert`, pastikan direktori kerja Anda bersih! Jika Anda memiliki file yang dimodifikasi sebagian, disarankan untuk menggunakan `git stash` untuk membuat stash sementara.

## Revert Dasar

Untuk me-revert commit terbaru:

```
git revert HEAD
```

Ini membuat commit baru yang membatalkan perubahan pada commit terakhir.

## Me-revert Commit Tertentu

Misalkan dari riwayat `git log`, Anda menemukan versi yang bermasalah. Anda pertama-tama dapat memeriksa catatan perubahan versi ini. Anda dapat menggunakan `git log` untuk menemukan ID commit, kemudian menggunakan `git show [commit_id]` untuk melihat informasi yang relevan dari versi tersebut.

Untuk me-revert commit tertentu:

```
git revert <commit-hash>
```

Sebagai contoh:

```
git revert a1b2c3d
```

Selama eksekusi, Anda akan diminta untuk mengedit pesan commit akhir. Secara default, pesan ini menambahkan kata `Revert` dan juga menambahkan `This reverts commit xxxx` pada baris ketiga untuk memberi tahu Anda bahwa tujuan utama versi ini adalah me-revert dari versi `xxxx`.

## Me-revert Beberapa Commit

Untuk me-revert rentang commit:

```
# Revert commits from HEAD~3 to HEAD~1 (3 commits)
git revert HEAD~3..HEAD
```

Atau me-revert beberapa commit tertentu:

```
git revert <hash1> <hash2> <hash3>
```

## Revert Tanpa Commit

Untuk me-stage perubahan revert tanpa melakukan commit secara otomatis:

```
git revert --no-commit HEAD
# or
git revert -n HEAD
```

Ini berguna ketika Anda ingin me-revert beberapa commit dan membuat satu commit revert tunggal:

```
git revert --no-commit HEAD~3..HEAD
git commit -m "Revert last 3 commits"
```

## Menangani Konflik

Terkadang me-revert commit dapat menyebabkan konflik:

```
git revert <commit-hash>
# If conflicts occur...
# 1. Resolve conflicts in the files
# 2. Stage the resolved files
git add <resolved-files>
# 3. Continue the revert
git revert --continue
```

Untuk membatalkan revert yang sedang berlangsung:

```
git revert --abort
```

## Me-revert Commit Merge

Me-revert merge lebih kompleks karena commit merge memiliki dua induk. Anda harus menentukan induk mana yang akan di-revert:

```
# -m 1 means keep changes from the first parent (usually mainline)
git revert -m 1 <merge-commit-hash>
```

## Kapan Menggunakan Revert vs Reset

**Gunakan `git revert` ketika:**
* Commit telah di-push ke repositori bersama
* Anda ingin mempertahankan riwayat
* Bekerja pada branch publik (main, develop, dan sebagainya)
* Anda memerlukan catatan operasi pembatalan

**Gunakan `git reset` ketika:**
* Commit hanya berada di repositori lokal Anda
* Anda ingin sepenuhnya menghapus commit dari riwayat
* Bekerja pada branch fitur pribadi
* Commit tersebut adalah kesalahan yang tidak seharusnya berada dalam riwayat

## Me-revert dan Menerapkan Kembali Perubahan

Terkadang Anda me-revert sebuah commit tetapi kemudian ingin menerapkannya kembali:

```
# First, revert a commit
git revert <commit-hash>

# Later, revert the revert
git revert <revert-commit-hash>
```

## Contoh Praktis

### Contoh 1: Me-revert Commit Buruk pada Branch Main

```
# Commit a1b2c3d introduced a bug
git revert a1b2c3d
git push origin main
```

### Contoh 2: Me-revert Beberapa Commit

```
# Revert the last 5 commits as a single revert commit
git revert --no-commit HEAD~5..HEAD
git commit -m "Revert last 5 commits due to critical bug"
git push origin main
```

### Contoh 3: Me-revert Kemudian Membuat Koreksi

```
# Revert a problematic commit
git revert a1b2c3d

# Make necessary corrections
# ... edit files ...

# Commit the corrections
git add .
git commit -m "Fix issues from reverted commit"
git push origin main
```

## Praktik Terbaik

1. **Tulis pesan yang jelas**: Jelaskan mengapa Anda melakukan revert
   ```
   git revert a1b2c3d -m "Revert feature X due to performance issues"
   ```

2. **Uji sebelum mendorong**: Pastikan revert tidak merusak apa pun

3. **Berkomunikasi**: Beri tahu tim Anda ketika Anda me-revert commit

4. **Pertimbangkan alternatif**: Terkadang perbaikan ke depan lebih baik daripada revert

5. **Dokumentasikan alasannya**: Rujuk nomor issue atau berikan konteks

## Melihat Riwayat Revert

Untuk melihat commit revert dalam riwayat Anda:

```
git log --oneline --grep="Revert"
```

## Ringkasan Hari Ini

`git revert` adalah cara yang aman untuk membatalkan perubahan di repositori bersama. Perintah ini mempertahankan integritas riwayat sambil membatalkan perubahan yang tidak diinginkan. Memahami kapan menggunakan `revert` versus `reset` sangat penting untuk kolaborasi yang efektif dan mempertahankan riwayat proyek yang bersih dan dapat dipahami.

* git revert <commit-hash>
* git revert --no-commit
* git revert -n
* git revert -m
* git revert --continue
* git revert --abort
