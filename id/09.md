# Hari 09: Membandingkan Perbedaan File dan Versi

Dalam proses menggunakan perangkat lunak kontrol versi apa pun, Anda sering perlu melihat catatan historis dan membandingkan perbedaan antara versi. Cara membandingkan di Git akan menjadi fokus artikel ini.

## Menyiapkan Direktori Kerja

Kami dengan cepat membuat repositori Git dan direktori kerja dengan dua file dan dua catatan perubahan versi melalui perintah berikut:

```
mkdir git-demo
cd git-demo
git init

echo 1 > a.txt
echo 2 > b.txt
git add .
git commit -m "Initial commit"

echo 3 > a.txt
echo 4 > b.txt
git add .
git commit -m "Update a.txt and b.txt to 3 and 4"
```

## Konsep Dasar git diff

Untuk membandingkan perbedaan antara dua versi di Git, Anda biasanya menggunakan perintah `git diff`. Mari kita pertama-tama menjalankan perintah sederhana untuk membandingkan perbedaan antara dua versi:

1. Pertama jalankan `git log` untuk mendapatkan informasi versi dan mendapatkan id dari dua objek commit terakhir
2. Kami menjalankan perintah `git diff commit1 commit2` untuk membandingkan perbedaan antara kedua versi, di mana commit1 harus menggunakan versi yang lebih lama dan commit2 harus menggunakan versi yang lebih baru.

Seperti yang ditunjukkan pada gambar berikut:

![gambar](figures/09/01.png)

Dari output eksekusi `git diff`, kita bisa mendapatkan hasil eksekusi. Karena kami memiliki dua file dalam kedua repositori ini, dan keduanya telah berubah di antara kedua versi ini, ia akan mencantumkan dua segmen hasil "perbandingan perbedaan".

Anda dapat melihat dari gambar di atas bahwa setiap segmen dimulai dengan `diff --git`, yang mewakili dua file mana yang dibandingkan oleh git.

Baris kedua `index 37bcc8b..d855592 100644` mewakili "Header Line" ketika git melakukan perbandingan ini. Mungkin ada beberapa baris di sini, dan informasinya tidak harus hanya ini. Banyak informasi tambahan tentang perbandingan perbedaan ini akan ditandai di sini. Misalnya, baris index, dua hash id setelahnya (`37bcc8b..d855592`) mewakili dua id objek blob dalam penyimpanan objek Git (object storage), yang digunakan untuk membandingkan kedua objek blob ini. `100644` setelahnya adalah atribut git, agak seperti atribut file dalam lingkungan Linux, seperti menyatakan ini adalah file, direktori, dapat dibaca, dapat ditulis, dapat dieksekusi, dan lain-lain. Berikut adalah beberapa contoh umum atribut git:

```
0100000000000000 (040000): Directory
1000000110100100 (100644): Regular non-executable file
1000000110110100 (100664): Regular non-executable group-writeable file
1000000111101101 (100755): Regular executable file
1010000000000000 (120000): Symbolic link
1110000000000000 (160000): Gitlink
```

Untuk tautan terkait, silakan merujuk ke utas diskusi berikut:

* [How to read the mode field of git-ls-tree's output](https://stackoverflow.com/a/8347325/910074)

Baris ketiga `--- a/a.txt` mewakili versi yang "lebih lama" dari dua versi yang dibandingkan.

Baris keempat `+++ b/a.txt` mewakili versi yang "lebih baru" dari dua versi yang dibandingkan.

Baris kelima `@@ -1 +1 @@` mewakili jumlah total baris dalam versi lama dan versi baru dari file ini. -1 mewakili versi lama hanya memiliki 1 baris, dan +1 mewakili versi baru juga hanya memiliki 1 baris.

Terakhir, semua isi yang diubah dicantumkan. Ada tiga kemungkinan representasi di sini:

* Dimulai dengan tanda minus -, itu berarti baris ini dihapus dalam proses dari versi lama ke versi baru.
* Dimulai dengan tanda plus +, itu berarti baris ini ditambahkan dalam proses dari versi lama ke versi baru.
* Dimulai dengan karakter spasi, itu berarti baris ini muncul di kedua versi tanpa perubahan apa pun.

Ini menyelesaikan perbandingan perbedaan objek blob pertama dalam kedua versi ini, dan kemudian ia akan menampilkan perbandingan perbedaan objek blob kedua dalam versi tersebut, dan seterusnya.

Ketika menggunakan `git diff` di Git, sebenarnya, objek tree adalah unit perbandingan. Kami belajar dari diagram dan video di [Hari 06: Mengurai Struktur Data Git - Struktur Objek] bahwa setiap objek commit sebenarnya mencakup objek tree dari direktori root. Jadi ketika kami baru saja menggunakan `git diff` untuk membandingkan dua objek commit, kami sebenarnya membandingkan objek tree di bawah objek commit tersebut, dan proses perbandingan akan berlanjut secara rekursif ke bawah. Dari sini, Anda seharusnya dapat merasakan bahwa mekanisme perbandingan diff Git sangat kuat. Anda dapat dengan cepat membandingkan perubahan antara dua versi mana pun.

Ketika menggunakan perintah `git diff`, ada terutama tiga sumber objek tree:

* Objek tree yang ada dalam semua grafik commit, yang berarti objek tree mana pun dalam versi mana pun.
* Index, mewakili informasi setelah Anda mengirim status file ke "basis data indeks." Sebenarnya, objek tree telah dibuat ketika menggunakan perintah `git add`.
* Direktori kerja Anda saat ini, meskipun perubahan pada direktori kerja belum menjadi objek tree, mereka dapat digunakan melalui `git diff`.

## Empat Metode Perbandingan Dasar

Untuk membandingkan dua versi mana pun melalui perintah `git diff`, biasanya ada empat penggunaan perintah berikut:

1. git diff

   Tanpa parameter apa pun, yang dibandingkan adalah perbedaan antara "direktori kerja" dan "indeks." Ini adalah perintah yang sangat umum digunakan karena sebelum Anda menjalankan perintah `git add .`, Anda dapat terlebih dahulu menggunakan `git diff` untuk melihat apa yang telah Anda ubah.

   **Catatan**: Sebenarnya, dalam proses menggunakan kontrol versi Git, sebelum menjalankan `git commit`, memang dimungkinkan untuk menjalankan perintah `git add` beberapa kali untuk mengonfirmasi file mana yang akan ditambahkan ke indeks, dan akhirnya melakukan commit ke versi.

2. git diff commit

   Jika Anda hanya menambahkan id commit setelah `git diff`, yang dibandingkan adalah "direktori kerja" dan "objek tree dalam objek commit yang ditentukan."

   Perintah yang paling umum digunakan adalah `git diff HEAD` karena ini mewakili membandingkan "direktori kerja" dengan "versi terbaru dari branch saat ini." Metode perbandingan ini tidak akan membandingkan keadaan "indeks", jadi Anda harus membedakan dengan jelas sumber objek tree mana yang Anda bandingkan.

3. git diff --cached commit

   Sebelum menjalankan `git commit`, keadaan indeks seharusnya sudah siap. Jadi jika Anda ingin membandingkan "keadaan indeks saat ini" dengan "objek tree dalam objek commit yang ditentukan," Anda dapat menggunakan perintah ini untuk menyelesaikan tugas perbandingan.

   Perintah yang paling umum digunakan juga adalah `git diff --cached HEAD`, yang berarti membandingkan "keadaan indeks saat ini" dengan "versi terbaru dari branch saat ini." Metode perbandingan ini tidak akan membandingkan isi file dari "direktori kerja," tetapi secara langsung membandingkan perbedaan antara "indeks" dan "versi terbaru saat ini." Ini membantu Anda mengetahui perubahan apa yang ada sebelum menjalankan `git commit`, yang berarti perubahan apa yang akan Anda buat sebagai sebuah versi.

   **Catatan 1**: `git diff --cached` dan `git diff --staged` memiliki hasil yang persis sama. `--staged` hanyalah alias untuk `--cached` agar lebih mudah Anda ingat!

   **Catatan 2**: `git diff --cached` dan `git diff --cached HEAD` juga memiliki hasil yang persis sama ketika dijalankan. HEAD terakhir dapat dihilangkan.

4. git diff commit1 commit2

   Yang terakhir adalah membandingkan perbedaan antara dua versi yang berbeda (id commit). Perintah ini dapat melewati perubahan apa pun dalam "indeks" dan "direktori kerja" dan secara langsung membandingkan dua versi tertentu. Sebenarnya, Git membandingkan objek tree dalam objek commit dua versi tertentu tersebut.

   Perintah yang paling umum digunakan adalah `git diff HEAD^ HEAD`, yang berarti Anda ingin membandingkan perbedaan antara [versi sebelumnya dari versi terbaru] dan [versi terbaru]. Arti HEAD dan ^ di sini akan dijelaskan dalam artikel-artikel mendatang.

## Ringkasan Hari Ini

`git diff` yang diperkenalkan hari ini adalah perintah yang sangat umum digunakan, dan Anda harus menggunakannya dengan mahir. Mari terakhir tinjau perbedaan antara perintah-perintahnya yang umum digunakan:

```
git diff                 => working directory vs index
git diff HEAD            => working directory vs HEAD
git diff --cached HEAD   => index     vs HEAD
git diff --cached        => index     vs HEAD
git diff HEAD^ HEAD     => HEAD^   vs HEAD
```

Izinkan saya menyusun kembali perintah dan parameter Git yang dipelajari hari ini:

* git log
* git diff
* git diff HEAD
* git diff --cached
* git diff --staged
* git diff HEAD^ HEAD
