# Hari 26: Banyak Orang Bekerja di Repositori Remote yang Sama

Ketika banyak orang bekerja dalam repositori yang sama, koordinasi dan pemahaman tentang alur kerja Git menjadi sangat penting. Artikel ini mengeksplorasi praktik terbaik dan skenario umum untuk kolaborasi tim.

## Tantangan Umum dalam Kolaborasi Tim

1. **Konflik merge**: Banyak orang mengedit file yang sama
2. **Branch yang berdivergensi**: Lokal dan remote menjadi tidak sinkron
3. **Commit yang hilang**: Secara tidak sengaja menimpa pekerjaan orang lain
4. **Kesenjangan komunikasi**: Tidak mengetahui apa yang sedang dikerjakan orang lain

## Alur Kerja Tim Dasar

### Alur Kerja Harian

```
# Morning: Get latest changes
git pull origin main

# Create feature branch
git checkout -b feature-name

# Work and commit frequently
git add .
git commit -m "Progress on feature"

# Before finishing: update with latest main
git checkout main
git pull origin main
git checkout feature-name
git merge main

# Resolve any conflicts

# Push your branch
git push origin feature-name

# Create pull request for review
```

### Tetap Terkini

Lakukan fetch perubahan secara berkala:

```
# Check what's changed
git fetch origin

# View remote changes
git log main..origin/main

# Merge if appropriate
git merge origin/main
```

## Menangani Pekerjaan Bersamaan

### Skenario 1: File yang Sama, Baris Berbeda

Biasanya di-merge secara otomatis:

```
git pull origin main
# If auto-merge succeeds, you're done!
```

### Skenario 2: File yang Sama, Baris yang Sama

Memerlukan penyelesaian manual:

```
git pull origin main
# Conflict!

# Edit conflicting files
# Remove markers: <<<<<<<, =======, >>>>>>>
# Keep the correct changes

# Stage resolved files
git add resolved-file.txt

# Complete the merge
git commit
```

### Skenario 3: Seseorang Melakukan Rebase

Dapat menyebabkan masalah besar jika branch digunakan bersama:

```
# If someone rebased a shared branch
git fetch origin

# You need to rebase your work
git rebase origin/feature-branch

# Or start fresh
git reset --hard origin/feature-branch
```

## Proses Code Review

### Membuat Pull Request yang Baik

1. **Judul deskriptif**: "Add user authentication feature"
2. **Deskripsi terperinci**:
   * Apa yang dilakukan PR ini?
   * Mengapa perubahan ini diperlukan?
   * Bagaimana cara mengujinya?
3. **Jaga agar tetap kecil**: Lebih mudah di-review
4. **Satu hal per PR**: Jangan mencampurkan fitur dan perbaikan
5. **Perbarui dengan main**: Pastikan PR dapat di-merge dengan bersih

### Mereview Pull Request

1. **Periksa kode** logika dan gayanya
2. **Uji secara lokal** jika memungkinkan
3. **Berikan umpan balik yang konstruktif**
4. **Setujui atau minta perubahan**
5. **Merge ketika siap**

## Menyelesaikan Konflik Tim

### Komunikasi Terlebih Dahulu

* **Bicarakan dengan tim Anda**: Sering kali mencegah masalah
* **Gunakan komentar PR**: Ajukan pertanyaan, diskusikan pendekatan
* **Dokumentasikan keputusan**: Perbarui deskripsi atau komentar PR

### Solusi Teknis

#### Menyelesaikan Konflik

```
# Update your branch
git fetch origin
git merge origin/main

# Resolve conflicts in files
# Stage changes
git add .

# Complete merge
git commit
```

#### Membatalkan dan Memulai Kembali

```
# If resolution is too complex
git merge --abort

# Talk to the other developer
# Coordinate who makes what changes
```

## Aturan Perlindungan Branch

Di GitHub, lindungi branch penting:

1. **Mewajibkan review pull request**
2. **Mewajibkan pemeriksaan status** (CI/CD)
3. **Menegakkan riwayat linear**
4. **Sertakan administrator**

Konfigurasikan di: Settings > Branches > Branch protection rules

## Continuous Integration

Gunakan CI untuk menangkap masalah sejak dini:

```yaml
# Example .github/workflows/test.yml
name: Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      - run: npm install
      - run: npm test
```

## Alat Komunikasi

### Pesan Commit

Ikuti konvensi:

```
<type>(<scope>): <subject>

<body>

<footer>
```

Contoh:

```
feat(auth): add user login functionality

Implement JWT-based authentication with email and password.
Includes password hashing with bcrypt and token refresh.

Closes #123
```

### Template Pull Request

Buat `.github/pull_request_template.md`:

```markdown
## Description
<!-- Describe your changes -->

## Type of Change
- [ ] Bug fix
- [ ] New feature
- [ ] Breaking change

## Testing
<!-- How was this tested? -->

## Checklist
- [ ] Tests pass
- [ ] Documentation updated
- [ ] No merge conflicts
```

## Menangani Tim Besar

### Feature Flag

Deploy kode yang belum siap:

```javascript
if (featureFlags.newUI) {
  return <NewUI />;
} else {
  return <OldUI />;
}
```

### Branch Rilis

Memisahkan pengembangan dari rilis:

```
main (production)
├── release/v2.0
├── release/v1.9
└── develop (integration)
    ├── feature/login
    ├── feature/dashboard
    └── feature/reports
```

## Ringkasan Praktik Terbaik

1. **Pull sebelum push**: Selalu dapatkan perubahan terbaru terlebih dahulu
2. **Sering commit**: Commit kecil dan logis
3. **Push secara berkala**: Bagikan pekerjaan Anda, dapatkan umpan balik
4. **Gunakan branch**: Jaga main tetap stabil
5. **Tulis pengujian**: Tangkap masalah sebelum orang lain mengalaminya
6. **Review kode**: Belajar satu sama lain
7. **Berkomunikasi**: Berkomunikasilah secara berlebihan jika diperlukan
8. **Dokumentasikan**: README, wiki, komentar
9. **Bersabar**: Konflik terjadi, selesaikan bersama
10. **Bantu orang lain**: Keberhasilan tim adalah keberhasilan Anda

## Ringkasan Hari Ini

Kolaborasi tim yang sukses dengan Git memerlukan keterampilan teknis dan komunikasi yang baik. Memahami alur kerja umum, menangani konflik dengan anggun, dan menggunakan alat seperti pull request dan CI/CD akan membantu tim Anda bekerja sama dengan lancar.

Izinkan saya menyusun kembali perintah dan parameter Git yang dipelajari hari ini:

* git pull origin main
* git fetch origin
* git merge origin/main
* git rebase origin/branch
* git push origin branch
* git log main..origin/main
