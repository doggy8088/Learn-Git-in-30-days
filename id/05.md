# Hari 05: Memahami Hubungan antara Repositori, Direktori Kerja, Objek, dan Indeks

Dalam proses menggunakan kontrol versi Git, beberapa konsep yang sangat dasar harus dibangun agar Anda dapat belajar dengan lebih efisien dan bermakna. Dengan dukungan konseptual yang jelas dan benar, ini tidak hanya akan membantu Anda mempelajari operasi perintah Git, tetapi yang lebih penting, mempelajari pengetahuan terkait Git akan menjadi lebih mudah.

## Memahami Repositori

Ketika kita menggunakan Git untuk kontrol versi, secara alami, kita memerlukan "repositori" untuk menyimpan informasi versi ini. Kata bahasa Inggris Repository berarti hal ini. Saya biasa menerjemahkan kata bahasa Inggris ini sebagai "Repositori", yang mewakili sebuah ruang atau folder beserta sekumpulan file yang digunakan untuk menyimpan semua versi.

Jika Anda memiliki pengalaman menggunakan Git, Anda seharusnya tahu dengan baik bahwa ada banyak cara untuk membuat repositori. Jika Anda ingin membuat repositori Git di folder mana pun, cukup masukkan perintah berikut untuk menyelesaikan pembuatan:

    git init

Melalui diagram proses pembuatan repositori Git berikut, kita dapat mengetahui dengan jelas bahwa ketika kita menjalankan git init di direktori G:\git-demo, Git akan secara otomatis membantu kita membuat apa yang disebut repositori Git di direktori .git dari direktori tersebut. Jangan ragu, folder .git ini adalah repositori Git yang lengkap. Di masa depan, semua perubahan versi akan secara otomatis disimpan di folder ini.

## Memahami Direktori Kerja

Pada contoh di atas, direktori G:\git-demo akan secara otomatis menjadi "direktori kerja" kita. Arti dari "direktori kerja" adalah kita bersiap untuk mengembangkan file proyek, dan semua pekerjaan di masa depan akan diedit di direktori ini, baik itu menambahkan file, memodifikasi file, menghapus file, mengganti nama file, ... dan semua operasi terkait Git lainnya akan diselesaikan di direktori ini, jadi disebut "direktori kerja".

Ketika kita mengoperasikan parameter perintah terkait Git, kita biasanya menjalankannya di "direktori kerja".

Karena akan ada banyak situasi branch ketika menggunakan kontrol versi Git, direktori kerja dapat beralih di antara branch yang berbeda. Beberapa perintah git akan memperbarui file di direktori kerja ketika dijalankan. Misalnya, ketika Anda menggunakan git checkout untuk beralih ke branch yang berbeda, karena struktur direktori branch saat ini tidak sama persis dengan branch yang ingin Anda tuju, sangat mungkin perintah itu memperbarui file di direktori kerja Anda saat ini sehingga direktori dan file di bawah direktori kerja saat ini sama dengan direktori dan file di bawah branch lain yang dituju.

Oleh karena itu, menjaga direktori kerja tetap bersih pada waktu yang tepat adalah prinsip dasar dalam proses kontrol versi, terutama saat melakukan merging di masa depan. Ini sangat penting. Saya akan menjelaskan lebih lanjut pengetahuan terkait dalam artikel-artikel mendatang.

## Memahami Struktur Data Git

Ada dua struktur data penting dalam Git, yaitu "objek" dan "indeks".

"Objek" digunakan untuk menyimpan semua file dan catatan versi dalam repositori, sedangkan "indeks" digunakan untuk menyimpan keadaan direktori sebelum masuk ke repositori.

## Tentang Objek

Yang disebut "objek" adalah sebuah "file khusus". Proses pembuatan file ini sangat menarik. Ia mengambil isi sebuah file, menghasilkan nilai hash SHA1 melalui isi tersebut, dan kemudian menamai sebuah file menurut nilai hash SHA1 ini.

Dalam proses menggunakan Git untuk kontrol versi, semua direktori dan file yang akan dikontrol pertama-tama akan dibedakan antara "informasi direktori" dan "isi file", yang kita sebut objek tree dan objek blob.

Di antaranya, objek blob menggunakan "isi file" asli sebagai isi file blob (catatan: objek blob sebenarnya adalah file fisik), dan kemudian melakukan operasi hash SHA1 pada isinya untuk menghasilkan hash id, dan kemudian menggunakan hash id ini sebagai nama file dari file blob. Dari sini, kita dapat mengetahui bahwa objek blob adalah file yang "hanya berisi isi". Nama filenya dihasilkan dari isi, jadi satu file blob tunggal biasanya tidak membantu untuk kontrol versi.

Objek tree lainnya digunakan untuk menyimpan file apa saja yang termasuk dalam folder tertentu dan apa nama file dari objek blob yang sesuai dengan file ini. Dalam objek tree, selain berisi nama file dan informasi terkait dari objek blob, ia juga dapat berisi objek tree lainnya. Jadi objek tree sebenarnya sinonim dengan "folder".

Terlepas dari objek blob dan objek tree, ini semua adalah objek, dan objek-objek ini akan disimpan dalam apa yang disebut "penyimpanan objek" (object storage), dan "penyimpanan objek" ini secara default berada di direktori objects dari "repositori", seperti yang ditunjukkan pada gambar berikut:

Kita akan membicarakan struktur objek secara terperinci dalam artikel-artikel mendatang.

## Tentang Indeks

Yang disebut "indeks" adalah file sementara yang sering berubah, yang biasanya terletak di file bernama index dalam direktori .git. Sederhananya, tujuan dari "indeks" terutama adalah untuk mencatat "file mana saja yang akan dikirimkan ke versi commit berikutnya". Dengan kata lain, jika Anda ingin mengirimkan sebuah versi ke repositori Git, maka Anda harus terlebih dahulu memperbarui status indeks, dan perubahan akan dikirimkan.

File indeks ini biasanya menyimpan keadaan versi tertentu dalam repositori Git. Keadaan ini dapat diwakili oleh objek commit dan objek tree mana pun.

Kita biasanya tidak secara langsung mengedit file biner .git\index, tetapi mengoperasikan file indeks ini melalui perintah git standar. Perintah untuk mengoperasikan file indeks kira-kira sebagai berikut:

* git add
* git mv
* git rm
* git status
* git commit
* git ls-files

"Indeks" Git adalah media antara "penyimpanan objek" (object storage) dan "direktori kerja" (working directory).

Anda mungkin sudah dapat menebak bahwa hubungan antara konsep-konsep yang ingin diuraikan dalam artikel ini dapat dijelaskan dengan 5 langkah berikut:

* Untuk menggunakan kontrol versi Git, Anda harus terlebih dahulu membuat "direktori kerja" dan "repositori". (mkdir, git init)
* Anda harus terlebih dahulu mengembangkan di "direktori kerja", Anda dapat membuat direktori, membuat file, memodifikasi file, menghapus file, ... dan operasi lainnya.
* Kemudian ketika Anda ingin mengirimkan versi baru ke "repositori" Git, Anda harus terlebih dahulu memperbarui status "indeks". (git add, git mv, ...)
* Kemudian Git akan memutuskan file mana yang akan dikirimkan ke "repositori" Git berdasarkan keadaan "indeks" saat ini. (git status)
* Terakhir, ketika mengirimkan perubahan (git commit), informasi versi akan ditulis ke "penyimpanan objek" (pada saat ini, sebuah objek commit akan ditulis).

Kita akan membicarakan struktur indeks dan operasi perintah secara terperinci dalam artikel-artikel mendatang.

    Catatan: Karena konsep tree sangat mirip dengan direktori, ketika membaca teks asli asing, working directory sering ditulis sebagai working tree!

## Ringkasan Hari Ini

Hal terpenting tentang arsitektur Git yang dibahas hari ini adalah hubungan antara "objek" dan "indeks", karena tanpa informasi "indeks", Git tidak dapat membuat versi.

Berdasarkan perbedaan antara "objek" dan "indeks", Anda seharusnya dapat menemukan bahwa "objek" adalah jenis file yang "tidak dapat diubah" (immutable). Pada prinsipnya, objek apa pun yang ditulis ke "penyimpanan objek" tidak akan berubah lagi, karena semua objek dihasilkan dari isi file asli. Kita juga dapat mengatakan ini adalah "basis data objek" (object database), dan basis data ini biasanya hanya menambah isi, dan ada lebih sedikit kasus "menghapus isi" atau "mengubah isi". Data hanya dihapus ketika menjalankan git gc untuk membersihkan data sampah. "Indeks" adalah file indeks yang "dapat diubah" (mutable) yang digunakan untuk mencatat isi yang siap di-commit oleh direktori kerja saat ini.

Ketika Anda selangkah demi selangkah mendekati inti Git, perlahan-lahan mengubah konsep abstrak yang samar dan tidak jelas menjadi pengetahuan konseptual yang konkret, Anda tidak akan lagi merasa gelisah tentang Git. Silakan terus bekerja keras untuk belajar, kesuksesan ada di depan.
