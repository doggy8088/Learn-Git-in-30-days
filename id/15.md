# Hari 15: Tag - Menandai Peristiwa Penting dalam Kontrol Versi

Ketika menggunakan Git untuk kontrol versi, sejumlah besar versi akan dihasilkan. Seiring waktu, di antara banyak versi ini, pasti akan ada beberapa versi penting yang layak dicatat. Inilah yang dapat dibantu oleh "tag" untuk kita lakukan.

## Memahami Tag - Konsep Dasar

Pada dasarnya, tujuan tag adalah untuk menandai "versi" atau "objek commit" tertentu dengan "nama yang mudah diingat" untuk membantu kita mengingat versi tertentu.

Tag adalah referensi yang menunjuk ke commit tertentu dalam riwayat Git Anda. Tidak seperti branch, tag tidak bergerak ketika Anda membuat commit baru — tag selalu menunjuk ke commit yang sama. Hal ini membuat tag ideal untuk menandai titik rilis atau tonggak penting lainnya.

Git mendukung dua jenis tag:

1. **Lightweight tags**: Sederhananya adalah nama (alias) untuk commit tertentu — ini adalah jenis "nama referensi"
2. **Annotated tags**: Disimpan sebagai objek Git lengkap dengan metadata tambahan

Seperti yang disebutkan pada Hari 11 (Memahami Referensi Objek Git), "referensi umum" mencakup "nama tag", dan "nama tag" di sini mengacu pada "lightweight tags". Jadi "lightweight tags" dapat dikatakan hanyalah "alias" untuk versi commit tertentu, yang merupakan jenis "nama relatif".

"Annotated tags" adalah jenis objek Git. Seperti yang disebutkan pada Hari 06 (Mengurai Struktur Data Git - Struktur Objek), objek Git mencakup 4 jenis objek: objek Blob, Tree, Commit, dan Tag. "Annotated tag" yang disebutkan di sini adalah objek Tag. Objek Tag disimpan dalam penyimpanan objek Git (disimpan di direktori `.git\objects\`) dan dikaitkan dengan objek commit lain. Ketika membuat "annotated tags", Anda dapat menyertakan "pesan versi" sama seperti ketika membuat objek commit. Dalam mekanisme tag bawaan Git, Anda bahkan dapat menggunakan kunci GnuPG untuk menandatangani objek Tag guna memastikan "non-repudiation" pesan.

Meskipun kita memiliki dua jenis tag ini, dan keduanya terlihat seperti "alias" untuk objek commit, penggunaan kedua tag ini hanya memiliki sedikit perbedaan. Dalam kebanyakan kasus penggunaan, kami menggunakan "annotated tags" untuk membuat "objek tag" dan menyediakan "pesan versi", karena jenis "tag" ini adalah "objek permanen" dalam repositori Git. (Objek Git yang disimpan dalam penyimpanan objek tidak dapat diubah; hanya indeks yang berubah.)

## Membuat Lightweight Tags

Cara paling sederhana untuk membuat tag:

```
git tag v1.0
```

Ini membuat lightweight tag bernama `v1.0` yang menunjuk ke commit saat ini (HEAD).

Untuk memberi tag pada commit tertentu:

```
git tag v0.9 <commit-hash>
```

**Catatan**: Semua file di bawah `.git\refs\` adalah "nama referensi".

Penggunaan dasar:
* Mencantumkan semua tag: `git tag`
* Membuat lightweight tag: `git tag [tagname]`
* Menghapus lightweight tag: `git tag [tagname] -d`

Jika Anda ingin melihat isi "lightweight tag", Anda dapat menggunakan `git cat-file -p [tagname]`. Jika Anda ingin melihat jenis objek dari "lightweight tag", Anda dapat menggunakan `git cat-file -t [tagname]`.

**Catatan Penting**: Lightweight tag bukanlah objek Git. Dari penjelasan di atas, Anda dapat melihat bahwa nama tag mengambil isi objek commit, dan jenis objek yang ditemukan berdasarkan nama tersebut adalah objek commit.

## Membuat Annotated Tags

Annotated tags direkomendasikan untuk sebagian besar kasus penggunaan karena menyimpan informasi tambahan:

```
git tag -a v1.0 -m "Release version 1.0"
```

Flag `-a` membuat annotated tag, dan `-m` menentukan pesan tag.

Perbedaan dari lightweight tags:
1. Ketika menjalankan `git tag` untuk mencantumkan semua tag, semua tag tercampur bersama dan Anda tidak dapat melihat jenis tag
2. Membuat "annotated tags" memerlukan parameter `-a`
3. Membuat "annotated tags" harus menyertakan "pesan versi", sama seperti menjalankan `git commit`, keduanya memiliki parameter `-m` yang tersedia

## Mencantumkan Tag

Untuk melihat semua tag di repositori Anda:

```
git tag
```

Untuk melihat tag yang cocok dengan pola:

```
git tag -l "v1.*"
```

## Melihat Informasi Tag

Untuk lightweight tag:

```
git show v1.0
```

Ini menunjukkan commit yang ditunjuk oleh tag.

Untuk annotated tag:

```
git show v1.0
```

Ini menunjukkan informasi tag ditambah detail commit.

## Memberi Tag pada Commit Lama

Anda dapat memberi tag pada commit yang tidak berada di HEAD:

```
git log --oneline  # Find the commit hash
git tag -a v0.5 -m "Beta release" <commit-hash>
```

## Mendorong Tag ke Remote

Secara default, `git push` tidak mentransfer tag. Anda perlu mendorongnya secara eksplisit:

```
# Push a specific tag
git push origin v1.0

# Push all tags
git push origin --tags
```

## Menghapus Tag

Untuk menghapus tag lokal:

```
git tag -d v1.0
```

Untuk menghapus tag remote:

```
git push origin :refs/tags/v1.0
# or
git push origin --delete v1.0
```

## Checkout Tag

Anda dapat melakukan checkout kode pada tag tertentu:

```
git checkout v1.0
```

Ini menempatkan Anda dalam keadaan "detached HEAD". Jika Anda ingin membuat perubahan, buat branch baru:

```
git checkout -b version-1-fixes v1.0
```

## Ringkasan Hari Ini

Tag adalah bagian penting dari kontrol versi, memungkinkan Anda menandai titik-titik penting dalam riwayat proyek Anda. Annotated tags sangat berguna untuk rilis karena dapat menyimpan informasi tambahan seperti catatan rilis, informasi tagger, dan tanda tangan.

Izinkan saya menyusun kembali perintah dan parameter Git yang dipelajari hari ini:

* git tag
* git tag -a
* git tag -l
* git show
* git push origin --tags
* git tag -d
* git checkout
