# Hari 24: Menggunakan Repositori Remote GitHub - Memulai

GitHub saat ini adalah platform manajemen Git online yang paling banyak diadopsi di dunia. Platform ini mencakup implementasi repositori remote Git yang lengkap, mekanisme pelacakan issue dan laporan yang komprehensif, dan ribuan proyek open source yang menggunakan GitHub untuk kontrol versi Git. Bahkan di banyak perusahaan, GitHub diadopsi sebagai platform Git utama. Artikel ini akan memandu Anda melalui penggunaan GitHub yang paling dasar.

## Apa itu GitHub?

GitHub adalah platform berbasis web yang:
* Menghosting repositori Git di cloud
* Menyediakan alat kolaborasi (issue, pull request, papan proyek)
* Menawarkan CI/CD melalui GitHub Actions
* Memungkinkan code review dan diskusi
* Menyediakan hosting gratis untuk proyek open source
* Berfungsi sebagai platform sosial untuk pengembang dan proyek open source

## Membuat Akun GitHub

1. Buka https://github.com
2. Klik "Sign up"
3. Ikuti proses pendaftaran
4. Verifikasi alamat email Anda

## Membuat Repositori Baru di GitHub

Ada dua pendekatan utama saat membuat repositori GitHub:

1. **Repositori kosong (tanpa commit awal)**: Terbaik ketika Anda memiliki repositori lokal yang sudah ada untuk di-push
2. **Repositori yang diinisialisasi (dengan commit awal)**: GitHub membuat file README, .gitignore, dan/atau lisensi untuk Anda

### Membuat Repositori Kosong

1. Klik ikon "+" di sudut kanan atas
2. Pilih "New repository"
3. Isi:
   * **Nama repositori**
   * **Deskripsi** (opsional)
   * **Publik atau Privat**
   * **JANGAN centang** "Initialize this repository with a README"
   * Biarkan .gitignore dan lisensi sebagai "None"
4. Klik "Create repository"

Setelah pembuatan, GitHub menampilkan petunjuk untuk melakukan push repositori yang sudah ada.

### Membuat Repositori yang Diinisialisasi

1. Ikuti langkah 1-3 di atas
2. **Centang** "Initialize this repository with a README"
3. Secara opsional pilih:
   * **Template .gitignore** untuk bahasa Anda
   * **Lisensi** untuk proyek Anda
4. Klik "Create repository"

GitHub akan membuat commit awal dengan file yang dipilih.

## Menghubungkan Repositori Lokal ke GitHub

### Opsi 1: Push Repositori yang Sudah Ada

```
# Add remote
git remote add origin https://github.com/username/repo-name.git

# Push to GitHub
git push -u origin main
```

### Opsi 2: Clone dari GitHub

```
# Clone the repository
git clone https://github.com/username/repo-name.git

# Navigate to the directory
cd repo-name
```

## Memahami Remote

Remote adalah referensi ke repositori yang dihosting di tempat lain. Perintah umum:

```
# List remotes
git remote -v

# Add a remote
git remote add <name> <url>

# Remove a remote
git remote remove <name>

# Rename a remote
git remote rename <old> <new>

# Change remote URL
git remote set-url origin <new-url>
```

## Melakukan Push ke GitHub

Push commit Anda ke GitHub:

```
# Push to the default branch
git push origin main

# Push all branches
git push --all

# Push tags
git push --tags
```

Flag `-u` mengatur pelacakan upstream:

```
git push -u origin main
# After this, you can just use:
git push
```

## Melakukan Pull dari GitHub

Dapatkan pembaruan dari GitHub:

```
# Fetch changes
git fetch origin

# Fetch and merge
git pull origin main

# If upstream is set
git pull
```

## Metode Autentikasi

### HTTPS

Memerlukan nama pengguna dan kata sandi/token:

```
https://github.com/username/repo-name.git
```

### SSH

Memerlukan pengaturan kunci SSH:

```
git@github.com:username/repo-name.git
```

Mengatur kunci SSH:

```
# Generate SSH key
ssh-keygen -t ed25519 -C "your.email@example.com"

# Add to ssh-agent
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519

# Copy public key
cat ~/.ssh/id_ed25519.pub
# Add this key to GitHub settings
```

### Personal Access Token

Untuk autentikasi HTTPS:

1. Buka GitHub Settings > Developer settings > Personal access tokens
2. Buat token baru
3. Gunakan token sebagai kata sandi saat melakukan push

## Fitur GitHub

### Issue

Melacak bug, peningkatan, dan tugas:

* Buat judul yang deskriptif
* Berikan langkah reproduksi untuk bug
* Gunakan label untuk pengorganisasian
* Referensikan commit dan pull request

### Wiki

Dokumentasi untuk proyek Anda:

* Panduan memulai
* Dokumentasi API
* FAQ
* Diagram arsitektur

### Proyek

Mengorganisasikan pekerjaan dengan papan Kanban:

* To Do
* In Progress
* Done

### Rilis

Menandai tonggak penting:

1. Buka "Releases"
2. Klik "Draft a new release"
3. Pilih tag
4. Tambahkan catatan rilis
5. Lampirkan biner jika diperlukan

## Praktik Terbaik Alur Kerja GitHub

1. **Sering commit**: Buat commit kecil dan logis
2. **Tulis pesan yang baik**: Jelaskan mengapa, bukan hanya apa
3. **Pull sebelum push**: Selalu dapatkan perubahan terbaru terlebih dahulu
4. **Gunakan branch**: Jangan commit langsung ke main
5. **Review kode**: Gunakan pull request untuk perubahan

## Tugas Umum

### Melakukan Fork pada Repositori

1. Klik "Fork" pada halaman repositori
2. Clone fork Anda:
   ```
   git clone https://github.com/your-username/repo-name.git
   ```
3. Tambahkan remote upstream:
   ```
   git remote add upstream https://github.com/original-owner/repo-name.git
   ```

### Menyinkronkan Fork

```
git fetch upstream
git checkout main
git merge upstream/main
git push origin main
```
