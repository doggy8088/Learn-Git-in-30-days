# Hari 27: Kontrol Versi melalui Branch di Repositori Remote yang Sama

Tim yang berbeda menggunakan strategi branching yang berbeda. Artikel ini mengeksplorasi model branching yang umum dan kapan menggunakan masing-masing model.

## Mengapa Strategi Branching Penting

Tanpa strategi yang jelas:
* Konflik kode meningkat
* Rilis menjadi kacau
* Bug lolos ke produksi
* Koordinasi tim terganggu

## GitHub Flow

**Terbaik untuk**: Aplikasi web, continuous deployment

### Strategi

* Satu branch utama: `main`
* Branch fitur untuk semua perubahan
* Deploy dari `main`

### Alur Kerja

```
1. Create branch from main
   git checkout -b feature-name

2. Work and commit
   git commit -am "Add feature"

3. Push and create PR
   git push origin feature-name

4. Review and discuss

5. Deploy from branch (staging)

6. Merge to main
   # On GitHub: Merge PR

7. Deploy from main (production)
```

### Kelebihan
* Sederhana dan lugas
* Pengembangan yang cepat
* Main selalu dapat di-deploy
* Sangat baik untuk continuous deployment

### Kekurangan
* Tidak ada dukungan rilis jangka panjang
* Memerlukan CI/CD yang baik
* Tidak ideal untuk banyak versi

## Git Flow

**Terbaik untuk**: Perangkat lunak dengan rilis, banyak versi

### Jenis Branch

* **main**: Kode siap produksi
* **develop**: Branch integrasi
* **feature/**: Fitur baru
* **release/**: Persiapan rilis
* **hotfix/**: Perbaikan darurat

### Alur Kerja

```
# Start new feature
git checkout -b feature/login develop

# Work on feature
git commit -am "Implement login"

# Finish feature
git checkout develop
git merge --no-ff feature/login
git branch -d feature/login

# Start release
git checkout -b release/1.0 develop

# Prepare release (bug fixes only)
git commit -am "Bump version to 1.0"

# Finish release
git checkout main
git merge --no-ff release/1.0
git tag -a 1.0

git checkout develop
git merge --no-ff release/1.0
git branch -d release/1.0

# Hotfix
git checkout -b hotfix/1.0.1 main
git commit -am "Fix critical bug"

git checkout main
git merge --no-ff hotfix/1.0.1
git tag -a 1.0.1

git checkout develop
git merge --no-ff hotfix/1.0.1
git branch -d hotfix/1.0.1
```

### Kelebihan
* Pemisahan tanggung jawab yang jelas
* Mendukung banyak versi
* Proses rilis yang terstruktur

### Kekurangan
* Lebih kompleks
* Siklus pengembangan yang lebih lambat
* Beban tambahan untuk proyek sederhana

## GitLab Flow

**Terbaik untuk**: Organisasi dengan lingkungan staging dan produksi

### Strategi

* Branch lingkungan: `main`, `staging`, `production`
* Branch fitur di-merge ke `main`
* Promosi melalui lingkungan

### Alur Kerja

```
# Feature development
git checkout -b feature-name main
# Work and commit
git push origin feature-name
# Create MR to main

# After merge to main
# Deploy to staging
git checkout staging
git merge main
git push origin staging

# After testing in staging
# Deploy to production
git checkout production
git merge staging
git push origin production
```

### Kelebihan
* Deployment berbasis lingkungan
* Jalur promosi yang jelas
* Baik untuk industri yang diatur secara ketat

### Kekurangan
* Lebih banyak branch yang harus dikelola
* Memerlukan otomatisasi
* Dapat menjadi lebih lambat

## Pengembangan Berbasis Trunk (Trunk-Based Development)

**Terbaik untuk**: Tim berkinerja tinggi, continuous deployment

### Strategi

* Trunk tunggal: `main`
* Branch fitur yang sangat berumur pendek (< 1 hari)
* Feature flag untuk fitur yang belum selesai

### Alur Kerja

```
# Create short-lived branch
git checkout -b quick-fix main

# Make small change
git commit -am "Fix button color"

# Merge same day
git checkout main
git merge quick-fix
git push origin main

# Or commit directly to main
# (with CI and feature flags)
```

### Kelebihan
* Integrasi tercepat
* Mengurangi konflik merge
* Mendorong CI/CD
* Kualitas kode yang tinggi

### Kekurangan
* Memerlukan disiplin
* Membutuhkan CI/CD yang baik
* Kompleksitas feature flag

## Release Flow (Microsoft)

**Terbaik untuk**: Perangkat lunak enterprise, rilis terencana

### Strategi

* `main`: Selalu siap rilis
* `release/*`: Branch stabilisasi
* Branch topik: Fitur berumur pendek

### Alur Kerja

```
# Create topic branch
git checkout -b users/name/feature main

# Work and create PR
git push origin users/name/feature

# Create release branch
git checkout -b release/v2.0 main

# Cherry-pick into release
git cherry-pick <commit-hash>

# Release
git checkout main
git merge release/v2.0
git tag v2.0
```

### Kelebihan
* Jadwal rilis yang fleksibel
* Pengembangan dan stabilisasi secara paralel
* Baik untuk enterprise

### Kekurangan
* Dapat menjadi kompleks
* Memerlukan cherry-pick
* Lebih banyak pemeliharaan

## Memilih Strategi

### GitHub Flow Ketika:
* Continuous deployment
* Aplikasi web
* Tim kecil
* Iterasi cepat

### Git Flow Ketika:
* Rilis terjadwal
* Aplikasi desktop/mobile
* Perlu mendukung banyak versi
* Siklus hidup perangkat lunak tradisional

### GitLab Flow Ketika:
* Banyak lingkungan
* Deployment bertahap
* Persyaratan regulasi

### Trunk-Based Ketika:
* Tim berpengalaman
* CI/CD yang sangat baik
* Continuous deployment
* Frekuensi rilis yang tinggi

## Konvensi Penamaan Branch

### Branch Fitur
```
feature/user-authentication
feature/dark-mode
feat/issue-123
```

### Branch Perbaikan Bug
```
fix/login-error
bugfix/issue-456
hotfix/critical-security-patch
```

### Branch Rilis
```
release/1.0
release/2.0.0
release/v1.5
```

### Branch Lainnya
```
docs/update-readme
test/integration-tests
refactor/database-layer
chore/update-dependencies
```

## Perintah Manajemen Branch

### Daftar Branch
```
# Local branches
git branch

# All branches (including remote)
git branch -a

# With last commit
git branch -v

# Merged branches
git branch --merged

# Unmerged branches
git branch --no-merged
```

### Menghapus Branch
```
# Delete local branch
git branch -d feature-name

# Force delete
git branch -D feature-name

# Delete remote branch
git push origin --delete feature-name
```

### Mengganti Nama Branch
```
# Rename current branch
git branch -m new-name

# Rename other branch
git branch -m old-name new-name
```
