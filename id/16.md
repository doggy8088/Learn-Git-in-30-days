# Hari 16: Menggunakan git reflog untuk Melacak Riwayat Perubahan

Mempelajari perintah kontrol versi Git tidaklah sulit, tetapi memahami apa yang sebenarnya dilakukan Git terhadap repositori Anda bisa cukup menantang. Seiring Anda secara bertahap memahami konsep inti dan prinsip operasi Git, Anda dapat secara efektif mengendalikan perubahan versi dalam repositori Git Anda. Artikel ini menjelaskan bagaimana Git mencatat riwayat perubahan untuk setiap versi.

## Memahami git reflog

`git reflog` (reference log) adalah mekanisme yang mencatat kapan ujung branch dan referensi lainnya diperbarui di repositori lokal. Sebelum Anda sepenuhnya memahami prinsip dasar dan struktur objek Git, Anda tidak dapat benar-benar memahami proses pencatatan versi. Ketika Anda tidak memahami proses pencatatan versi, Anda secara alami khawatir "ke mana perginya versi saya?" Anda mungkin pernah mendengar seseorang berkata "Kami menggunakan kontrol versi, jadi semua versi terpelihara, silakan memodifikasi kode dengan bebas." Mengetahui hal ini adalah satu hal, mengetahui cara melakukannya adalah hal lain, dan apakah Anda benar-benar dapat melakukannya adalah hal yang lain lagi.

Untungnya, Git memiliki mekanisme pencatatan yang ketat, dan mekanisme ini sangat terbuka — file log semuanya dalam format teks dan cukup mudah dipahami. Mari kita jelaskan proses pencatatan versi ini.

Reflog sangat berguna untuk:

* Menemukan commit yang tidak lagi dapat dijangkau dari branch mana pun
* Memulihkan dari reset atau rebase yang keliru
* Memahami apa yang telah Anda lakukan di repositori Anda
* Membatalkan perubahan yang tidak disengaja

## Direktori logs

Jika Anda masuk ke folder `.git/` dari direktori kerja Git mana pun, Anda dapat melihat direktori `logs`. Folder `logs` ini berisi file `HEAD` yang mencatat riwayat perubahan versi dari "branch saat ini".

Isi file terlihat seperti ini (id objek disingkat agar mudah dibaca):

```
0000000 f5685e0 Will <xxxx@gmail.com> 1381718394 +0800	commit (initial): Initial commit
f5685e0 38d924f Will <xxxx@gmail.com> 1381718395 +0800	commit: a.txt: set 1 as content
38d924f efa1e0c Will <xxxx@gmail.com> 1381734238 +0800	commit: test
efa1e0c af493e5 Will <xxxx@gmail.com> 1381837967 +0800	commit: Add c.txt
```

## Penggunaan Dasar

Untuk melihat reflog:

```
git reflog
```

Ini menunjukkan daftar tindakan terbaru dalam urutan kronologis terbalik. Dari file teks, Anda dapat melihat "versi pertama" di bagian atas, tetapi melalui `git reflog`, "versi terbaru" ditampilkan terlebih dahulu, dan "versi pertama" terakhir.

Setiap entri menunjukkan:
* Hash commit
* Referensi (biasanya HEAD)
* Tindakan yang dilakukan
* Pesan commit

## Format Reflog

Outputnya terlihat seperti:

```
a1b2c3d HEAD@{0}: commit: Add new feature
e4f5g6h HEAD@{1}: checkout: moving from master to feature-branch
i7j8k9l HEAD@{2}: reset: moving to HEAD~1
```

Notasi `HEAD@{n}` mengacu pada nilai HEAD ke-n sebelumnya. Di sini, setiap versi dalam log riwayat memiliki nomor yang mewakili posisi versi ini dalam file log. `HEAD@{0}` selalu mewakili "versi terbaru" dari branch saat ini, dengan kata lain, operasi Git terbaru yang Anda lakukan pada "branch" ini. Setiap perubahan versi yang Anda buat pada Git akan dicatat secara lengkap.

## Memulihkan dari Perubahan yang Tidak Disengaja

Ketika pemula pertama kali menggunakan Git, mereka mungkin secara tidak sengaja menjalankan perintah yang salah, seperti konflik yang terjadi selama `git merge`, atau kesalahan yang terjadi ketika menjalankan `git pull` untuk mendapatkan versi terbaru dari repositori remote. Dalam situasi seperti itu, Anda dapat menggunakan "nama referensi" khusus `HEAD@{n}` untuk "menemukan" versi ini dan memulihkan versi repositori Git saat ini ke versi sebelumnya.

Sebagai contoh, jika kita ingin "membatalkan" catatan versi terbaru, kita dapat menggunakan `git reset HEAD@{1} --hard` untuk memulihkan perubahan. Ini berarti perubahan yang semula berada di `HEAD@{0}` akan dihapus. Namun, di Git, semua perubahan dicatat, termasuk tindakan Anda menjalankan `git reset "HEAD@{1}" --hard`.

Apa artinya ini? Artinya ketika menjalankan perintah Git apa pun, Anda tidak perlu lagi khawatir data Anda akan hilang. Tidak peduli seberapa salah perintah yang Anda masukkan, semua file yang sudah berada di repositori akan terpelihara, tanpa ada kemungkinan hilang sama sekali. Jadi, jika Anda ingin membatalkan tindakan `git reset "HEAD@{1}" --hard` yang baru saja Anda jalankan, cukup jalankan `git reset "HEAD@{1}" --hard` lagi. Bukankah itu hebat!

## Melihat Reflog Terperinci

Untuk informasi yang lebih terperinci:

```
git reflog show --all
```

Untuk melihat reflog untuk branch tertentu:

```
git reflog show branch-name
```

## Menggunakan Reflog untuk Memulihkan Commit

Jika Anda secara tidak sengaja mereset atau kehilangan commit, Anda dapat memulihkannya menggunakan reflog:

```
# Find the commit you want to recover
git reflog

# Reset to that commit
git reset --hard HEAD@{2}
```

Atau gunakan hash commit secara langsung:

```
git reset --hard a1b2c3d
```

## Memulihkan Branch yang Terhapus

Jika Anda menghapus branch secara tidak sengaja:

```
# Find the commit where the branch was deleted
git reflog

# Recreate the branch
git branch branch-name HEAD@{3}
# or
git branch branch-name <commit-hash>
```

## Kedaluwarsa Reflog

Secara default, entri reflog kedaluwarsa setelah 90 hari untuk commit yang dapat dijangkau dan 30 hari untuk commit yang tidak dapat dijangkau. Anda dapat mengonfigurasinya:

```
git config gc.reflogExpire "90 days"
git config gc.reflogExpireUnreachable "30 days"
```

## Membersihkan Reflog

Untuk membersihkan entri reflog secara manual:

```
# Remove old reflog entries
git reflog expire --expire=now --all

# Run garbage collection
git gc --prune=now
```

## Keterbatasan Reflog

Poin penting untuk diingat:

* Reflog hanya bersifat lokal — tidak dibagikan dengan orang lain
* Reflog melacak perubahan pada repositori Anda, bukan file
* Reflog dapat membantu Anda memulihkan commit, tetapi bukan perubahan yang belum di-commit

## Contoh Praktis

### Contoh 1: Membatalkan Hard Reset

```
# You accidentally reset
git reset --hard HEAD~3

# Find the old position
git reflog

# Restore to the old position
git reset --hard HEAD@{1}
```

### Contoh 2: Memulihkan Setelah Rebase yang Keliru

```
# After a problematic rebase
git reflog

# Find the commit before the rebase (usually labeled "rebase finished")
git reset --hard HEAD@{5}
```

## Ringkasan Hari Ini

`git reflog` adalah fitur keamanan yang kuat yang dapat menyelamatkan Anda dari banyak kesalahan Git. Fitur ini sangat berharga ketika Anda perlu memulihkan dari operasi seperti reset, rebase, atau penghapusan branch. Meskipun bukan pengganti pencadangan rutin, ini adalah alat yang sangat berharga untuk pemulihan lokal.

* git reflog
* git reflog show
* git reflog show --all
* git reset --hard HEAD@{n}
* git branch branch-name HEAD@{n}
* git reflog expire
* git gc
