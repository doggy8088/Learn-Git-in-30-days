# Hari 28: Memahami Alur Kerja Fork dan Pull Request di GitHub

Fork dan pull request adalah hal mendasar dalam kolaborasi open source di GitHub. Artikel ini menjelaskan cara berkontribusi pada proyek yang tidak Anda miliki akses tulisnya.

## Memahami Fork

Fork adalah salinan lengkap dari sebuah repositori di bawah akun GitHub Anda. Fork memungkinkan Anda untuk:
* Bereksperimen secara bebas tanpa memengaruhi proyek asli
* Mengusulkan perubahan melalui pull request
* Menyesuaikan proyek sesuai kebutuhan Anda

## Fork vs Clone vs Branch

* **Fork**: Menyalin repositori di GitHub (akun Anda)
* **Clone**: Menyalin repositori ke mesin lokal
* **Branch**: Membuat garis pengembangan yang berbeda

## Melakukan Fork pada Repositori

### Di GitHub

1. Buka repositori tersebut
2. Klik tombol "Fork" (kanan atas)
3. Pilih tempat fork (akun atau organisasi Anda)
4. Tunggu GitHub membuat fork

### Melakukan Clone pada Fork Anda

```
# Clone your fork
git clone https://github.com/your-username/repo-name.git

# Navigate to directory
cd repo-name

# Add upstream remote
git remote add upstream https://github.com/original-owner/repo-name.git

# Verify remotes
git remote -v
# origin    https://github.com/your-username/repo-name.git (fetch)
# origin    https://github.com/your-username/repo-name.git (push)
# upstream  https://github.com/original-owner/repo-name.git (fetch)
# upstream  https://github.com/original-owner/repo-name.git (push)
```

## Alur Kerja Pull Request Lengkap

### Langkah 1: Sinkronkan Fork Anda

```
# Fetch upstream changes
git fetch upstream

# Checkout your main branch
git checkout main

# Merge upstream changes
git merge upstream/main

# Push to your fork
git push origin main
```

### Langkah 2: Buat Branch Fitur

```
# Create and checkout feature branch
git checkout -b fix-typo-in-readme

# Make your changes
# Edit files...

# Stage changes
git add README.md

# Commit changes
git commit -m "Fix typo in installation instructions"
```

### Langkah 3: Push ke Fork Anda

```
# Push branch to your fork
git push origin fix-typo-in-readme
```

### Langkah 4: Buat Pull Request

1. Buka fork Anda di GitHub
2. Klik tombol "Compare & pull request"
3. Isi detail PR:
   * **Judul**: Deskripsi yang jelas dan ringkas
   * **Deskripsi**: Apa, mengapa, dan bagaimana
   * Referensikan issue jika berlaku
4. Klik "Create pull request"

### Langkah 5: Menanggapi Umpan Balik

```
# Make requested changes
# Edit files...

# Commit changes
git add .
git commit -m "Address review feedback"

# Push updates
git push origin fix-typo-in-readme
# PR automatically updates!
```

### Langkah 6: Setelah Merge

```
# Switch to main
git checkout main

# Pull merged changes
git pull upstream main

# Push to your fork
git push origin main

# Delete feature branch
git branch -d fix-typo-in-readme
git push origin --delete fix-typo-in-readme
```

## Menjaga Fork Tetap Terkini

### Sinkronisasi Berkala

```
# Fetch and merge in one command
git checkout main
git pull upstream main
git push origin main
```

### Sinkronisasi Otomatis

Gunakan tombol "Fetch upstream" di GitHub pada halaman fork Anda, atau atur GitHub Actions:

```yaml
# .github/workflows/sync-upstream.yml
name: Sync Fork
on:
  schedule:
    - cron: '0 0 * * *'  # Daily
  workflow_dispatch:
jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - uses: TobKed/github-forks-sync-action@v1
        with:
          upstream: original-owner/repo-name
          target: your-username/repo-name
```

## Beberapa Commit dalam Satu PR

### Metode 1: Rebase Interaktif

```
# Squash commits
git rebase -i HEAD~3

# In editor, change 'pick' to 'squash' for commits to combine
# Save and edit commit message

# Force push (since you're rewriting history)
git push -f origin feature-branch
```

### Metode 2: Soft Reset

```
# Reset to before your commits
git reset --soft HEAD~3

# Create single commit
git commit -m "Complete feature implementation"

# Force push
git push -f origin feature-branch
```

## Menangani Konflik Merge dalam PR

```
# Sync with upstream
git fetch upstream

# Rebase on upstream/main
git rebase upstream/main

# Resolve conflicts
# Edit conflicting files
git add resolved-files
git rebase --continue

# Force push
git push -f origin feature-branch
```

## Draft Pull Request

Buat draft PR untuk umpan balik awal:

1. Saat membuat PR, klik dropdown pada "Create pull request"
2. Pilih "Create draft pull request"
3. Tandai sebagai siap ketika selesai

Manfaat:
* Mendapatkan umpan balik awal
* Menunjukkan pekerjaan yang sedang berlangsung
* Mencegah merge yang tidak disengaja

## Praktik Terbaik Pull Request

### Sebelum Membuat PR

- [ ] Kode berfungsi dan telah diuji
- [ ] Mengikuti panduan gaya proyek
- [ ] Dokumentasi diperbarui
- [ ] Commit bersih dan logis
- [ ] Branch terkini dengan main

### Menulis PR yang Baik

**Judul**:
```
❌ Fix stuff
✅ Fix null pointer exception in user login
```

**Deskripsi**:
```
## What
Fixes a null pointer exception that occurs when users login with empty passwords.

## Why
Bug #123 reported crashes on invalid login attempts.

## How
Added null check before password validation.

## Testing
- Tested with empty password
- Tested with valid password
- Tested with invalid password

Closes #123
```

### Selama Review

* Tanggapi semua komentar
* Ajukan pertanyaan jika tidak jelas
* Buat perubahan yang diminta dengan segera
* Terbuka terhadap saran
* Ucapkan terima kasih kepada reviewer

## Berkontribusi pada Open Source

### Menemukan Proyek

1. **GitHub Explore**: https://github.com/explore
2. **First Timers Only**: https://www.firsttimersonly.com/
3. **Good First Issue**: Cari di GitHub
4. **Up For Grabs**: https://up-for-grabs.net/

### Sebelum Berkontribusi

1. Baca `CONTRIBUTING.md`
2. Periksa issue yang terbuka
3. Lihat PR yang sudah ada
4. Pahami kode etik (code of conduct)
5. Siapkan lingkungan pengembangan

### PR Pertama Anda

Mulailah dari hal kecil:
* Perbaiki kesalahan ketik
* Tingkatkan dokumentasi
* Tambahkan pengujian
* Perbaiki bug yang jelas

### Membangun Reputasi

1. Mulai dengan dokumentasi
2. Laporkan bug yang baik
3. Bantu orang lain dalam issue
4. Kirimkan PR berkualitas
5. Bersabar dan bersikap hormat

## Kesalahan Umum yang Harus Dihindari

1. **Tidak menyinkronkan fork**: Selalu perbarui sebelum membuat PR
2. **Terlalu banyak perubahan**: Jaga PR tetap fokus
3. **Tidak ada deskripsi**: Jelaskan apa dan mengapa
4. **Force push ke main**: Jangan pernah melakukan ini
5. **Berdebat dengan maintainer**: Bersikaplah hormat
6. **Tidak menguji**: Selalu uji perubahan Anda

## Ringkasan Hari Ini

Fork dan pull request memungkinkan kolaborasi open source dalam skala besar. Memahami alur kerja ini membuka ribuan proyek yang dapat Anda kontribusikan. Mulailah dari hal kecil, bersabarlah, dan ingatlah bahwa setiap kontributor berpengalaman dulunya juga seorang pemula.

Izinkan saya menyusun kembali perintah dan parameter Git yang dipelajari hari ini:

* git clone <fork-url>
* git remote add upstream <original-url>
* git fetch upstream
* git merge upstream/main
* git push origin branch-name
* git push -f origin branch-name
* git rebase -i HEAD~n
* git reset --soft HEAD~n
