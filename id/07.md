# Hari 07: Mengurai Struktur Data Git - Struktur Indeks

Kita tahu ada dua struktur data penting dalam Git, yaitu "objek" dan "indeks". Artikel ini terutama digunakan untuk menjelaskan detail dari "indeks". Selama proses menggunakan kontrol versi Git, Anda mungkin dengan mudah memahami penggunaan perintah git, tetapi mudah jatuh ke dalam hafalan dan tidak dapat menggunakannya secara fleksibel. Bahkan Linus Torvalds menyebutkan dalam Mailing List: "Sebelum pengguna memahami arti indeks, mereka tidak dapat sepenuhnya memahami kemampuan Git." Oleh karena itu, memahami tujuan "indeks" sangatlah penting.

## Tentang Indeks

Sederhananya, tujuan dari "indeks" terutama adalah untuk mencatat "file mana saja yang akan dikirimkan ke versi commit berikutnya".

Dengan kata lain, "jika Anda ingin mengirimkan sebuah versi ke repositori Git, maka Anda harus terlebih dahulu memperbarui status indeks, dan perubahan akan dikirimkan."

"Indeks" ini sebenarnya memiliki banyak alias dalam banyak artikel asing, tetapi semuanya berarti hal yang sama. Jangan bingung ketika Anda melihat kata-kata terkait di masa depan.

* Index
* Cache
* Directory cache
* Current directory cache
* Staging area
* Staged files

Misalnya, perintah `git diff --cached` sepenuhnya sinonim dengan `git diff --staged`.

## Perintah untuk Mengoperasikan Indeks

Karena "indeks" sangat penting bagi Git, sebagian besar perintah memiliki parameter yang terkait dengan indeks Git. Namun, kami secara kasar mencantumkan beberapa perintah yang secara langsung terkait dengan "indeks" untuk penjelasan.

Sebelum menjelaskan perintah-perintah tersebut, Anda dapat terlebih dahulu melihat diagram berikut, yang menggambarkan siklus hidup perubahan keadaan melalui perintah. Sebenarnya, proses perubahan ini semuanya adalah proses memperbarui "file indeks":

![gambar](figures/07/01.png)

Pertama, izinkan saya memperkenalkan empat keadaan file:

* untracked (belum dilacak, mewakili keadaan file yang belum ditambahkan ke repositori Git)
* unmodified (belum dimodifikasi, mewakili keadaan ketika file ditambahkan untuk pertama kalinya, atau isi file konsisten dengan isi HEAD)
* modified (sudah dimodifikasi, mewakili bahwa file telah diedit, atau isi file tidak konsisten dengan isi HEAD)
* staged (menunggu untuk di-commit, mewakili bahwa file-file ini semuanya akan dikirim ke repositori saat git commit dijalankan berikutnya)

### git status

Mendapatkan status dari **working tree** (working tree).

Karena kita telah membicarakan hubungan antara repositori, direktori kerja, objek, dan indeks, kita dapat menjelaskan hubungan ini dalam satu kalimat:

```txt
Git repository operation is to write data into Git objects by updating the index with changes in the working directory.
```

Tujuan dari perintah `git status` di sini adalah untuk menampilkan perbedaan antara **versi terbaru** dan **file indeks**. Perbedaan di sini mencakup beberapa hubungan yang halus. Mari gunakan contoh untuk menjelaskan hubungan ini.

Berikut adalah hasil dari menjalankan git status:

```sh
G:\git-demo>git status
# On branch master
# Changes to be committed:
#   (use "git reset HEAD <file>..." to unstage)
#
#       new file:   c.txt
#
# Changes not staged for commit:
#   (use "git add <file>..." to update what will be committed)
#   (use "git checkout -- <file>..." to discard changes in working directory)
#
#       modified:   a.txt
#
# Untracked files:
#   (use "git add <file>..." to include in what will be committed)
#
#       b.txt
```

Di sini Anda akan melihat tiga kelompok berbeda, yaitu:

* Changes to be committed (perubahan yang siap di-commit)
  * Ada file `new file: c.txt` di area ini, yang berarti c.txt adalah file baru dan telah ditandai sebagai siap untuk di-commit.
  * Ini mewakili beberapa hal:
    1. File c.txt saat ini ada di **direktori kerja**
    2. File c.txt telah ditambahkan ke **indeks**
    3. Isi c.txt di **indeks** konsisten dengan isi di **direktori kerja**
    4. Saat menjalankan git commit, isi di **indeks** yang akan di-commit (bukan isi di direktori kerja)

* Changes not staged for commit (perubahan yang telah dimodifikasi tetapi belum di-stage untuk commit)
  * Ada file `modified: a.txt` di area ini, yang berarti a.txt adalah file yang dimodifikasi tetapi belum ditandai sebagai siap untuk di-commit.
  * Ini mewakili beberapa hal:
    1. File a.txt saat ini ada di **direktori kerja**
    2. File a.txt telah ditambahkan ke **indeks**
    3. Isi a.txt di **indeks** tidak konsisten dengan isi di **direktori kerja**
    4. Saat menjalankan git commit, hanya isi di **indeks** yang akan di-commit (bukan isi di direktori kerja)

* Untracked files (file yang belum dilacak)
  * Ada file `b.txt` di area ini, yang berarti b.txt adalah file baru dan belum ditambahkan ke indeks.
  * Ini mewakili beberapa hal:
    1. File b.txt saat ini ada di **direktori kerja**
    2. File b.txt belum ditambahkan ke **indeks**
    3. Saat menjalankan git commit, file ini tidak akan di-commit

### git add

Menambahkan isi file ke indeks (men-stage file untuk commit berikutnya).

Perintah `git add` memiliki banyak kegunaan. Sederhananya, menjalankan perintah ini akan "memperbarui indeks", tetapi cara indeks diperbarui dapat bervariasi tergantung pada keadaan file saat ini:

* Jika file berada dalam keadaan **untracked**, menjalankan `git add` akan menambahkan isi file ke indeks
* Jika file berada dalam keadaan **modified**, menjalankan `git add` akan memperbarui isi file ke indeks
* Jika file berada dalam keadaan **staged**, menjalankan `git add` akan memperbarui isi file ke indeks lagi

### git rm

Menghapus file dari working tree dan dari indeks.

Perintah ini akan menghapus file dari **direktori kerja** dan **indeks**. Setelah penghapusan, Anda perlu menjalankan git commit untuk menyelesaikan tindakan penghapusan ini.

### git mv

Memindahkan atau mengganti nama file, direktori, atau symlink.

Perintah ini akan memindahkan atau mengganti nama file di **direktori kerja** dan **indeks**. Setelah memindahkan atau mengganti nama, Anda perlu menjalankan git commit untuk menyelesaikan tindakan ini.

### git commit

Mencatat perubahan ke repositori.

Perintah ini akan menulis isi **indeks** saat ini ke **basis data objek** dan menghasilkan objek commit.

### git ls-files

Menampilkan informasi tentang file dalam indeks dan working tree.

Perintah ini dapat menampilkan daftar file dan status dalam indeks. Ini adalah perintah yang sangat berguna yang dapat membantu Anda memahami keadaan indeks saat ini.

Beberapa parameter umum:

* `git ls-files -s` atau `git ls-files --stage` : Menampilkan daftar file dan informasi terperinci dalam indeks
* `git ls-files -c` atau `git ls-files --cached` : Menampilkan daftar file yang di-cache
* `git ls-files -d` atau `git ls-files --deleted` : Menampilkan daftar file yang dihapus
* `git ls-files -m` atau `git ls-files --modified` : Menampilkan daftar file yang dimodifikasi
* `git ls-files -o` atau `git ls-files --others` : Menampilkan daftar file yang belum dilacak

## Ringkasan Hari Ini

"Indeks" dalam Git adalah konsep yang sangat penting. Melalui indeks, Git dapat mengetahui file mana saja yang akan dikirimkan ke versi commit berikutnya. Melalui berbagai perintah, kita dapat memperbarui status indeks dan mengontrol file mana yang akan dikirimkan. Memahami indeks dapat membantu Anda lebih menguasai kontrol versi Git.
