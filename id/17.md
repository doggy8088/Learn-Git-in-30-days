# Hari 17: Konsep Dasar dan Penggunaan Merge

Seperti yang disebutkan pada Hari 08 (Konsep Dasar dan Penggunaan Branch), kita telah mempelajari tentang "branch". Sekarang kita akan membahas cara melakukan "merging". Karena Git adalah sistem kontrol versi terdistribusi (DVCS), Anda akan terus-menerus melakukan operasi branching dan merging, baik merging yang disengaja (`git merge`) maupun merging yang tidak disengaja (`git pull`). Singkatnya, operasi "branching" dan "merging" memang sering terjadi ketika menggunakan Git untuk kontrol versi. Artikel ini akan menjelaskan konsep dasar dan penggunaan operasi "merging".

## Memahami Konsep Merge

Ketika Anda membuat branch di direktori kerja Git, Anda dapat mengembangkan sistem Anda sesuai dengan kebutuhan yang berbeda secara terpisah tanpa saling memengaruhi. Sebagai contoh, Anda dapat menyimpan sistem Anda yang semula stabil di branch `master` untuk pengembangan, dan ketika Anda perlu memperbaiki kesalahan, buat branch `bugfix` tambahan untuk memperbaiki kesalahan perangkat lunak. Setelah bug diperbaiki, Anda dapat menerapkan kembali perubahan dari branch `bugfix` ke `master` melalui "merging". Ini adalah salah satu skenario penggunaan utama.

Umumnya, semua orang mengembangkan pada branch utama atau default (`master`), kemudian membuat branch sesuai kebutuhan (`bugfix`), dan akhirnya menggabungkan kedua branch menjadi satu. Sebenarnya, ketika melakukan operasi "merge", Anda menggabungkan branch lain ke branch saat ini, dan kemudian secara manual menghapus branch lainnya. Ini sesuai dengan konsep "menggabungkan dua branch menjadi satu".

Dalam praktiknya, sering ada kesempatan untuk menggabungkan tiga, empat, atau lebih branch menjadi salah satunya. Sebagai contoh, selain branch utama (`master`), Anda juga membuat branch untuk debugging (`bugfix`) dan branch untuk menambahkan fitur (`feature`). Setelah berkembang sampai tingkat tertentu, Anda dapat memutuskan apakah akan menggabungkan kedua branch ini kembali ke branch utama (`master`) bersama-sama.

Ketika menggunakan merging di Git, ada konsep penting: **tindakan merge harus terjadi dalam repositori yang sama**. Ingatlah bahwa dalam repositori Git mana pun, harus ada objek Initial Commit (versi awal), dan semua versi lainnya akan terkait dengan versi ini. Kami menyebut hubungan ini "objek yang terlacak pada ujung branch", jadi Anda tidak dapat menggabungkan branch tertentu dari satu repositori ke branch dari repositori lain yang sama sekali tidak terkait.

Ketika melakukan merge, jika kedua branch telah memodifikasi file yang sama, tetapi selama baris yang dimodifikasi berbeda, Git akan secara otomatis menerapkan/menggabungkan kedua perubahan ini untuk Anda. Tetapi jika kebetulan Anda memodifikasi "file yang sama" pada "baris yang sama" di kedua branch, peristiwa konflik akan terjadi selama merging. Ketika konflik merge terjadi, Git tidak akan memutuskan apa pun untuk Anda, tetapi akan menyerahkan pekerjaan "menyelesaikan konflik" kepada "Anda", dan file-file yang berkonflik ini semuanya akan ditandai dengan status `unmerged`. Setelah konflik merge, Anda dapat menggunakan perintah `git status` untuk melihat status-status ini.

## Jenis Merge

Ada dua jenis merge utama di Git:

1. **Fast-forward merge**: Digunakan ketika branch target belum menyimpang dari branch sumber
2. **Three-way merge**: Digunakan ketika kedua branch memiliki commit baru

## Fast-Forward Merge

Fast-forward merge terjadi ketika branch saat ini belum menyimpang dari branch yang digabungkan. Git cukup menggerakkan penunjuk branch ke depan.

```
# On master branch
git merge feature-branch
```

Jika `master` belum memiliki commit baru sejak `feature-branch` dibuat, Git melakukan fast-forward merge.

## Three-Way Merge

Ketika kedua branch memiliki commit baru, Git melakukan three-way merge, membuat commit merge baru yang menggabungkan perubahan dari kedua branch.

```
# On master branch
git merge feature-branch
```

Ini membuat commit baru dengan dua commit induk.

## Mencegah Fast-Forward

Terkadang Anda ingin mempertahankan riwayat branch bahkan ketika fast-forward dimungkinkan:

```
git merge --no-ff feature-branch
```

Ini selalu membuat commit merge, bahkan untuk fast-forward merge.

## Konflik Merge

Konflik terjadi ketika baris yang sama dalam file yang sama telah diubah secara berbeda di kedua branch yang digabungkan. Ketika ini terjadi:

1. Git menjeda merge
2. Menandai file yang berkonflik
3. Menambahkan penanda konflik ke file
4. Menunggu Anda menyelesaikan konflik

## Melihat File yang Berkonflik

Untuk melihat file mana yang memiliki konflik:

```
git status
```

File dengan konflik dicantumkan sebagai "both modified".

## Penanda Konflik

Git menambahkan penanda ke file yang berkonflik:

```
<<<<<<< HEAD
Your changes
=======
Their changes
>>>>>>> branch-name
```

* `<<<<<<< HEAD`: Menandai awal perubahan Anda
* `=======`: Memisahkan kedua versi
* `>>>>>>> branch-name`: Menandai akhir perubahan yang masuk

## Menyelesaikan Konflik

Untuk menyelesaikan konflik:

1. Buka file yang berkonflik
2. Cari penanda konflik
3. Edit file untuk menyelesaikan konflik
4. Hapus penanda konflik
5. Stage file yang telah diselesaikan: `git add <file>`
6. Selesaikan merge: `git commit`

## Membatalkan Merge

Jika Anda ingin membatalkan merge yang sedang berlangsung:

```
git merge --abort
```

Ini mengembalikan repositori Anda ke keadaan sebelum merge dimulai.

## Melihat Riwayat Merge

Untuk melihat commit merge dalam riwayat Anda:

```
git log --oneline --graph --all
```

Ini menunjukkan representasi visual dari riwayat branch dan merge Anda.

## Strategi Merge

Git mendukung strategi merge yang berbeda:

* **recursive** (default): Strategi three-way merge default
* **ours**: Selalu memilih versi kita dalam konflik
* **theirs**: Selalu memilih versi mereka dalam konflik

```
git merge -X ours branch-name
git merge -X theirs branch-name
```

## Praktik Terbaik

1. **Commit pekerjaan Anda** sebelum melakukan merge
2. **Tarik perubahan terbaru** dari remote sebelum melakukan merge
3. **Uji merge** sebelum mendorong ke branch bersama
4. **Berkomunikasi** dengan tim Anda tentang merge
5. **Jaga merge tetap kecil** bila memungkinkan

## Ringkasan Hari Ini

Merging adalah operasi Git fundamental yang memungkinkan Anda menggabungkan pekerjaan dari branch yang berbeda. Memahami cara kerja merge, terutama cara menangani konflik, sangat penting untuk kolaborasi yang efektif. Berlatihlah melakukan merge secara teratur agar terbiasa dengan prosesnya.

* git merge
* git merge --no-ff
* git merge --abort

* git merge -X theirs
* git log --graph
* git status
