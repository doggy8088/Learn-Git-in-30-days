# Hari 13: Menyimpan Sementara Perubahan di Direktori Kerja dan Indeks (Stash)

Pernahkah Anda mengalami situasi ini: Anda sedang berada di tengah pengembangan sebuah sistem, dan tiba-tiba atasan atau klien Anda memberi Anda "perintah mendesak", meminta Anda untuk segera memperbaiki bug pada sistem yang ada atau menambahkan fitur? Program di hadapan Anda hampir selesai, dan "urusan mendesak" dari atasan tidak dapat ditunda. Keadaan pengembangan perangkat lunak yang belum selesai ditambah persyaratan penyesuaian darurat benar-benar merupakan ujian besar bagi kualitas perangkat lunak. Jika Anda memiliki masalah ini, Git dapat membantu Anda menyelesaikan tugas dengan baik.

## Memahami Perintah git stash

Kita tahu bahwa ketika menggunakan kontrol versi Git, ada perbedaan antara "direktori kerja" dan "indeks". Di direktori kerja, akan ada file yang telah Anda ubah setengah jalan dan belum selesai (belum ditambahkan ke indeks), dan juga akan ada file baru yang belum ditambahkan (belum ditambahkan ke indeks). Data yang ditempatkan di indeks adalah konten yang Anda rencanakan untuk dibuat versinya (membuat objek commit) melalui `git commit`.

Ketika Anda berada di tengah pengembangan fitur dan tiba-tiba disela secara mendesak, Anda pasti akan terburu-buru, terutama tidak tahu apa yang harus dilakukan dengan program-program yang setengah ditulis ulang itu. Di Git, ada perintah `git stash` yang secara otomatis dapat membantu Anda membuat "versi khusus" (juga merupakan objek commit) untuk file-file yang setengah ditulis itu. Kami menyebut versi ini versi stash, atau Anda dapat langsung menyebutnya "versi simpan sementara".

## Membuat Versi Stash

File yang telah kita ubah setengah jalan mungkin memiliki keadaan berikut:

* File baru (untracked files)
* File baru (file yang sudah ditambahkan ke indeks) (tracked/staged files)
* File yang dimodifikasi (file yang belum ditambahkan ke indeks) (tracked/unstaged files)
* File yang dimodifikasi (file yang sudah ditambahkan ke indeks) (tracked/staged files)
* File yang dihapus (file yang belum ditambahkan ke indeks) (tracked/unstaged files)
* File yang dihapus (file yang sudah ditambahkan ke indeks) (tracked/staged files)

Jika Anda ingin membuat "versi simpan sementara" untuk file-file yang setengah dikembangkan ini, Anda memiliki dua pilihan:

* `git stash` akan membuat versi simpan sementara untuk semua file yang terlacak
* `git stash -u` akan menyertakan semua file yang terlacak atau tidak terlacak, semuanya akan dibuat sebagai versi simpan sementara

**Catatan**: `git stash` juga dapat ditulis sebagai `git stash save`. Hasil kedua perintah ini sama, hanya saja parameter `save` dapat dihilangkan.

### Contoh Alur Kerja

Berikut adalah contoh praktis sederhana:

```bash
# You're working on features
echo "new feature" > feature.txt
git add feature.txt

# Suddenly need to fix a bug
# Stash your work-in-progress
git stash

# Now working directory is clean
# Fix the bug on another branch
git checkout main
# ... make fixes ...
git commit -m "Fix urgent bug"

# Return to your feature work
git checkout feature-branch
git stash pop  # Restore your work
```

## Memulihkan Perubahan yang Di-stash

Setelah menyimpan sementara perubahan Anda, Anda dapat beralih ke branch lain atau mengerjakan tugas mendesak. Ketika Anda siap untuk melanjutkan pekerjaan awal Anda, Anda dapat memulihkan perubahan yang di-stash menggunakan:

* `git stash pop` - Menerapkan stash terbaru dan menghapusnya dari daftar stash
* `git stash apply` - Menerapkan stash terbaru tetapi tetap menyimpannya dalam daftar stash

## Melihat Daftar Perubahan yang Di-stash

Untuk melihat apa yang telah Anda stash, gunakan:

```
git stash list
```

Ini akan menunjukkan kepada Anda semua perubahan yang di-stash beserta referensi stash-nya (stash@{0}, stash@{1}, dan sebagainya).

## Menerapkan Stash Tertentu

Jika Anda memiliki beberapa stash, Anda dapat menerapkan stash tertentu dengan merujuk nomornya:

```
git stash apply stash@{2}
```

## Menghapus Stash

Untuk menghapus stash tertentu dari daftar:

```
git stash drop stash@{0}
```

Untuk menghapus semua stash:

```
git stash clear
```

## Menyimpan Sementara File yang Tidak Terlacak

Secara default, `git stash` hanya menyimpan sementara file yang terlacak. Untuk juga menyimpan sementara file yang tidak terlacak:

```
git stash -u
```

Atau untuk menyimpan sementara semuanya termasuk file yang diabaikan:

```
git stash -a
```

## Membuat Stash Bernama

Anda dapat memberikan pesan deskriptif pada stash Anda:

```
git stash save "Work in progress on feature X"
```

Ini memudahkan untuk mengidentifikasi stash di kemudian hari.

## Melihat Isi Stash

Untuk melihat apa yang ada dalam stash tertentu tanpa menerapkannya:

```
git stash show stash@{0}
```

Untuk diff terperinci:

```
git stash show -p stash@{0}
```

## Ringkasan Hari Ini

Perintah `git stash` adalah alat yang sangat praktis yang memungkinkan Anda menyisihkan pekerjaan Anda saat ini untuk sementara tanpa melakukan commit. Ini sangat berguna ketika Anda perlu dengan cepat beralih konteks untuk mengerjakan hal lain. Mekanisme stash memastikan bahwa perubahan pekerjaan yang sedang berlangsung Anda tersimpan dengan aman dan dapat dipulihkan nanti.

* git stash -u
* git stash list
* git stash pop
* git stash apply
* git stash drop
* git stash clear
* git stash show
