# Hari 25: Menggunakan Repositori Remote GitHub - Konsep

Melanjutkan dasar-dasar dari Hari 24, artikel ini mengeksplorasi konsep dan alur kerja penting saat bekerja dengan repositori remote GitHub.

## Memahami Branch Pelacakan Remote

Branch pelacakan remote (remote tracking branch) adalah referensi terhadap keadaan branch remote. Branch ini mengikuti pola penamaan `<remote>/<branch>`:

```
# List all branches including remote tracking branches
git branch -a

# Example output:
# * main
#   feature
#   remotes/origin/main
#   remotes/origin/feature
```

## Fetch vs Pull

### Fetch

Mengunduh objek dan ref dari repositori lain tetapi tidak melakukan merge:

```
git fetch origin
```

Ini memperbarui branch pelacakan remote Anda tetapi tidak mengubah direktori kerja Anda.

### Pull

Fetch + Merge dalam satu perintah:

```
git pull origin main
# Equivalent to:
git fetch origin
git merge origin/main
```

Atau dengan rebase:

```
git pull --rebase origin main
```

## Branch Upstream

Atur pelacakan upstream untuk menyederhanakan push/pull:

```
# Set upstream when pushing
git push -u origin feature-branch

# Now you can just use:
git push
git pull
```

Periksa konfigurasi upstream:

```
git branch -vv
```

## Melacak Branch Remote

### Membuat Branch Lokal dari Remote

```
# Option 1: Automatic tracking
git checkout feature-branch
# If feature-branch exists on remote, Git auto-creates and tracks it

# Option 2: Explicit tracking
git checkout -b feature-branch origin/feature-branch

# Option 3: Using track flag
git checkout --track origin/feature-branch
```

### Berhenti Melacak Branch Remote

```
git branch --unset-upstream
```

## Push dengan Nama Branch Berbeda

Push branch lokal ke remote dengan nama berbeda:

```
git push origin local-branch:remote-branch
```

## Menghapus Branch Remote

Menghapus branch remote:

```
# Method 1
git push origin --delete branch-name

# Method 2
git push origin :branch-name
```

## Bekerja dengan Beberapa Remote

Anda dapat memiliki beberapa remote (misalnya, origin dan upstream):

```
# Add upstream remote
git remote add upstream https://github.com/original/repo.git

# Fetch from upstream
git fetch upstream

# Merge upstream changes
git merge upstream/main

# Push to your origin
git push origin main
```

## Memahami Perilaku git push

Mode push yang berbeda:

```
# Push current branch to matching branch on remote
git config push.default simple  # Default in Git 2.0+

# Push all matching branches
git config push.default matching

# Push current branch to branch with same name
git config push.default current

# No push without explicit ref spec
git config push.default nothing
```

## Force Push dan Bahayanya

### Kapan Melakukan Force Push

* Anda telah melakukan rebase pada branch fitur Anda
* Anda satu-satunya yang bekerja pada branch tersebut
* Anda perlu memperbaiki kesalahan pada commit yang telah di-push

### Cara Melakukan Force Push

```
# Standard force push (dangerous!)
git push -f origin feature-branch

# Safer: force push with lease
git push --force-with-lease origin feature-branch
```

`--force-with-lease` hanya berhasil jika remote belum berubah sejak terakhir kali Anda melakukan fetch.

### Praktik Terbaik Force Push

1. **Jangan pernah force push ke main/master**
2. **Berkomunikasi** sebelum melakukan force push pada branch bersama
3. **Gunakan --force-with-lease** alih-alih -f
4. **Buat branch cadangan** sebelum melakukan force push
5. **Hanya force push branch fitur Anda sendiri**

## Menangani Branch yang Berdivergensi

Ketika lokal dan remote telah berdivergensi:

```
# Check the situation
git status

# Option 1: Merge remote changes
git pull origin main

# Option 2: Rebase on remote changes
git pull --rebase origin main

# Option 3: Force push (if appropriate)
git push --force-with-lease origin feature-branch
```

## Membersihkan Referensi Pelacakan Remote

Menghapus branch pelacakan remote yang sudah basi:

```
# See stale branches
git remote prune origin --dry-run

# Remove stale branches
git remote prune origin

# Or during fetch
git fetch --prune
```

## Repositori Bare vs Non-Bare

### Non-Bare (Repositori Kerja)

* Memiliki direktori kerja
* Digunakan untuk pengembangan
* Yang Anda clone secara normal

### Repositori Bare

* Tidak memiliki direktori kerja
* Hanya data Git
* Digunakan di server

```
# Create bare repository
git clone --bare project project.git

# Or init as bare
git init --bare project.git
```

## Pola Alur Kerja Git

### Alur Kerja Terpusat

Semua orang bekerja pada branch main:

```
git pull origin main
# Make changes
git add .
git commit -m "Changes"
git push origin main
```

### Alur Kerja Branch Fitur

Setiap fitur mendapatkan branch-nya sendiri:

```
git checkout -b feature-x
# Work on feature
git push origin feature-x
# Create pull request
# After merge, delete branch
git branch -d feature-x
git push origin --delete feature-x
```

### Alur Kerja Gitflow

Menggunakan beberapa branch berumur panjang:

* **main**: Kode siap produksi
* **develop**: Branch integrasi
* **feature/**: Pengembangan fitur
* **release/**: Persiapan rilis
* **hotfix/**: Perbaikan darurat

## Alur Kerja Pull Request

1. **Fork** repositori (untuk open source)
2. **Clone** fork Anda
3. **Buat branch fitur**
   ```
   git checkout -b feature-name
   ```
4. **Buat perubahan dan commit**
5. **Push ke fork Anda**
   ```
   git push origin feature-name
   ```
6. **Buat pull request** di GitHub
7. **Diskusikan dan review** kode
8. **Buat perubahan yang diminta**
9. **Merge ketika disetujui**

## Menjaga Fork Tetap Terkini

```
# Add upstream remote (once)
git remote add upstream https://github.com/original/repo.git

# Fetch upstream changes
git fetch upstream

# Merge upstream/main into your main
git checkout main
git merge upstream/main

# Push to your fork
git push origin main
```

## Menyelesaikan Konflik dalam Pull Request

```
# Update your branch with target branch
git fetch origin
git checkout feature-branch
git merge origin/main

# Resolve conflicts
# ... edit files ...
git add .
git commit -m "Resolve conflicts"

# Push updated branch
git push origin feature-branch
```
