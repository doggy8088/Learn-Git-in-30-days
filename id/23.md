# Hari 23: Memperbaiki Riwayat Versi yang Sudah Di-commit Bagian 5 (rebase 2)

Dalam artikel sebelumnya, kita membahas bahwa Rebase digunakan untuk "menentukan ulang versi base" untuk dua branch yang sudah ada. Setelah menjalankan Rebase, titik awal branch asli juga berubah (titik percabangan dipindahkan), menyebabkan perubahan pada grafik versi. Namun, Rebase dapat melakukan lebih dari sekadar ini - rebase juga dapat digunakan untuk memodifikasi informasi versi dari versi mana pun pada garis branch tertentu.

Artikel ini melanjutkan eksplorasi kita tentang `git rebase`, mendalami teknik-teknik tingkat lanjut dan alur kerja praktis untuk menggunakan rebase secara efektif, termasuk memodifikasi informasi commit pada sebuah branch.

## Teknik Rebase Interaktif Tingkat Lanjut

### Memecah Commit

Untuk memecah satu commit menjadi beberapa commit:

```
git rebase -i HEAD~3

# Mark the commit to split with "edit"
# When Git stops at that commit:
git reset HEAD^
git add file1
git commit -m "First part"
git add file2
git commit -m "Second part"
git rebase --continue
```

### Menggabungkan dan Menyusun Ulang

Anda dapat menyusun ulang sekaligus menggabungkan commit dalam satu operasi:

```
git rebase -i HEAD~5

# In the editor:
pick abc123 Feature A
squash def456 Fix for A
pick jkl012 Feature C  # Moved before B
pick ghi789 Feature B  # Moved after C
fixup mno345 Typo fix for B
```

## Rebase dengan Exec

Menjalankan perintah setelah setiap commit selama rebase:

```
git rebase -i --exec "npm test" HEAD~5
```

Ini menjalankan `npm test` setelah menerapkan setiap commit, membantu Anda menemukan commit mana yang merusak pengujian.

## Rebase ke Commit Tertentu

Alih-alih nama branch, Anda dapat melakukan rebase ke commit tertentu:

```
git rebase --onto <new-base-commit> <old-base-commit> <branch>
```

Contoh kasus penggunaan - menghapus commit dari tengah riwayat:

```
# Remove commits between B and D
#     A---B---C---D---E feature
# Becomes:
#     A---B---D'---E' feature

git rebase --onto B D feature
```

## Rebase dengan Opsi Strategi

Menggunakan strategi merge selama rebase:

```
# Always prefer our version in conflicts
git rebase -X ours main

# Always prefer their version
git rebase -X theirs main
```

## Mempertahankan Commit Merge

Secara default, rebase meratakan (flatten) commit merge. Untuk mempertahankannya:

```
git rebase -p main
# or
git rebase --preserve-merges main
```

Catatan: `-p` sudah tidak digunakan lagi (deprecated); gunakan `--rebase-merges` sebagai gantinya:

```
git rebase --rebase-merges main
```

## Rebase dengan Fork-Point

Secara otomatis menemukan titik fork:

```
git rebase --fork-point main
```

Ini berguna ketika branch remote telah di-force-push.

## Alur Kerja: Menjaga Branch Fitur Tetap Terkini

Alur kerja umum untuk menjaga branch fitur Anda tetap terkini dengan main:

```
# On feature branch
git fetch origin
git rebase origin/main

# Or in one command
git pull --rebase origin main
```

## Alur Kerja: Mempersiapkan Pull Request

Bersihkan commit Anda sebelum membuat pull request:

```
# 1. Interactive rebase to clean history
git rebase -i main

# 2. Squash fixup commits, reword messages
# 3. Force push to update your branch
git push -f origin feature-branch
```

## Alur Kerja: Memperbarui Setelah Code Review

Setelah umpan balik code review:

```
# Make changes
git add .
git commit --fixup <original-commit>

# Rebase with autosquash
git rebase -i --autosquash main

# Force push the updated branch
git push -f origin feature-branch
```

## Menangani Force Push

Ketika seseorang melakukan force push pada branch yang sedang Anda kerjakan:

```
# Fetch the updated branch
git fetch origin

# Rebase your work onto the new history
git rebase --onto origin/feature-branch old-commit feature-branch
```

Atau cukup:

```
git pull --rebase origin feature-branch
```

## Rebase vs Reset untuk Pembersihan

Untuk membersihkan commit lokal sebelum push:

**Rebase** (disarankan):
* Mempertahankan urutan kronologis
* Kendali interaktif
* Dapat melakukan cherry-pick pada commit

**Reset** (lebih sederhana tetapi kurang fleksibel):
* Menghapus commit sepenuhnya
* Memulai kembali dari keadaan bersih
* Kurang kendali atas commit individual

## Pola Rebase yang Umum

### Pola 1: Menggabungkan (Squash) Semua Commit

```
git rebase -i --root
# Mark all but first commit as "squash"
```

### Pola 2: Menulis Ulang Semua Pesan Commit

```
git rebase -i HEAD~10
# Mark all commits as "reword"
```

### Pola 3: Menghapus Commit Tertentu

```
git rebase -i HEAD~10
# Mark unwanted commits as "drop"
```

## Daftar Periksa Keamanan Rebase

Sebelum melakukan rebase:

- [ ] Apakah commit ini sudah di-push ke branch bersama?
- [ ] Apakah orang lain telah mendasarkan pekerjaan pada commit ini?
- [ ] Apakah saya memiliki cadangan (branch atau tag)?
- [ ] Apakah saya sudah berkomunikasi dengan tim?
- [ ] Apakah saya siap untuk melakukan force-push?

## Memulihkan dari Bencana Rebase

Jika terjadi kesalahan:

```
# Step 1: Stay calm
# Step 2: Find the old state
git reflog

# Step 3: Reset to before the rebase
git reset --hard HEAD@{5}

# Step 4: Try again more carefully
```

## Rebase dan Continuous Integration

Ketika menggunakan CI/CD dengan rebase:

1. **Rebase secara lokal** sebelum melakukan push
2. **Jalankan pengujian** setelah rebase
3. **Force push** hanya branch Anda
4. **Tunggu CI** sebelum melakukan merge
5. **Jangan pernah rebase** setelah merge

## Ringkasan Praktik Terbaik

1. **Hanya lokal**: Rebase hanya commit yang belum di-push
2. **Rebase kecil**: Lakukan rebase secara berkala untuk menghindari konflik besar
3. **Uji secara menyeluruh**: Jalankan pengujian setelah rebase
4. **Berkomunikasi**: Beri tahu tim sebelum melakukan force-push
5. **Cadangkan**: Buat branch cadangan sebelum rebase besar
6. **Berhati-hati dengan -f**: Periksa kembali sebelum melakukan force-push

## Ringkasan Hari Ini

Teknik rebase tingkat lanjut memberi Anda alat yang ampuh untuk mempertahankan riwayat commit yang bersih dan mudah dipahami. Meskipun fitur-fitur ini dapat secara signifikan meningkatkan alur kerja Anda, fitur-fitur ini memerlukan latihan dan penggunaan yang hati-hati. Kuncinya adalah mengetahui kapan menggunakan rebase dan kapan tetap menggunakan alternatif yang lebih aman seperti merge.
