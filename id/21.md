# Hari 21: Memperbaiki Riwayat Versi yang Sudah Di-commit Bagian 3 (cherry-pick)

Dalam proses kontrol versi, ada situasi umum lainnya: Anda telah mengembangkan di sebuah branch untuk sementara waktu, tetapi kemudian memutuskan bahwa Anda tidak lagi menginginkan seluruh branch tersebut. Namun, ada beberapa commit di dalamnya yang masih ingin Anda pertahankan. Dalam kasus ini, Anda tidak dapat menghapus branch tersebut, tetapi menggabungkan (merge) seluruh branch kembali juga tidak tepat. Apa yang harus Anda lakukan? Artikel ini akan menjelaskan cara menggunakan perintah `git cherry-pick` untuk "memilih secara manual" perubahan yang ingin Anda terapkan.

## Memahami git cherry-pick

Terkadang Anda ingin menerapkan commit tertentu dari satu branch ke branch lain tanpa menggabungkan seluruh branch. Perintah `cherry-pick` pada Git memungkinkan Anda melakukan hal itu - memilih commit secara selektif dan menerapkannya ke branch Anda saat ini.

`git cherry-pick` menerapkan perubahan yang diperkenalkan oleh commit yang sudah ada ke branch Anda saat ini. Perintah ini membuat commit baru dengan perubahan yang sama tetapi hash commit yang berbeda.

## Cherry-Pick Dasar

Untuk melakukan cherry-pick pada satu commit:

```
# Switch to the target branch
git checkout main

# Cherry-pick the commit
git cherry-pick <commit-hash>
```

Ini membuat commit baru pada branch saat ini dengan perubahan yang sama seperti commit yang ditentukan.

## Melakukan Cherry-Pick pada Beberapa Commit

Untuk melakukan cherry-pick pada beberapa commit:

```
# Cherry-pick several commits
git cherry-pick <hash1> <hash2> <hash3>
```

Untuk melakukan cherry-pick pada rentang commit:

```
# Cherry-pick commits from commit1 to commit2 (exclusive of commit1)
git cherry-pick commit1..commit2

# Cherry-pick commits from commit1 to commit2 (inclusive of commit1)
git cherry-pick commit1^..commit2
```

## Cherry-Pick Tanpa Commit

Untuk menerapkan perubahan tanpa secara otomatis membuat commit:

```
git cherry-pick --no-commit <commit-hash>
# or
git cherry-pick -n <commit-hash>
```

Ini berguna ketika Anda ingin melakukan cherry-pick pada beberapa commit dan membuat satu commit tunggal.

## Menangani Konflik

Jika konflik terjadi selama cherry-pick:

```
# Resolve conflicts in the files
# Stage the resolved files
git add <resolved-files>

# Continue the cherry-pick
git cherry-pick --continue
```

Untuk membatalkan cherry-pick yang sedang berlangsung:

```
git cherry-pick --abort
```

Untuk melewati commit saat ini dan melanjutkan ke commit berikutnya:

```
git cherry-pick --skip
```

## Cherry-Pick dengan Edit

Untuk mengedit pesan commit saat melakukan cherry-pick:

```
git cherry-pick -e <commit-hash>
# or
git cherry-pick --edit <commit-hash>
```

## Cherry-Pick dan Sign-off

Untuk menambahkan baris sign-off ke pesan commit:

```
git cherry-pick -s <commit-hash>
# or
git cherry-pick --signoff <commit-hash>
```

## Kasus Penggunaan Praktis

### Kasus Penggunaan 1: Menerapkan Hotfix ke Beberapa Branch

```
# Fix created on main branch (commit abc123)
git checkout release-1.0
git cherry-pick abc123

git checkout release-2.0
git cherry-pick abc123
```

### Kasus Penggunaan 2: Integrasi Fitur Secara Selektif

```
# Feature branch has commits A, B, C, D
# You only want B and C on main

git checkout main
git cherry-pick <hash-B> <hash-C>
```

### Kasus Penggunaan 3: Memulihkan Commit yang Hilang

```
# Find the lost commit using reflog
git reflog

# Cherry-pick it to current branch
git cherry-pick <lost-commit-hash>
```

## Cherry-Pick vs Merge vs Rebase

**Cherry-pick**:
* Menerapkan commit tertentu secara selektif
* Membuat hash commit baru
* Baik untuk integrasi selektif

**Merge**:
* Menggabungkan seluruh branch
* Mempertahankan riwayat yang lengkap
* Terbaik untuk mengintegrasikan branch fitur

**Rebase**:
* Memainkan ulang commit pada base baru
* Riwayat linear
* Baik untuk membersihkan riwayat

## Praktik Terbaik

1. **Gunakan dengan hemat**: Cherry-pick dapat membuat riwayat membingungkan jika digunakan secara berlebihan
2. **Dokumentasikan alasannya**: Jelaskan mengapa Anda melakukan cherry-pick dalam pesan commit
3. **Hindari duplikasi**: Jangan melakukan cherry-pick pada commit yang nantinya akan di-merge
4. **Periksa dependensi**: Pastikan commit tidak bergantung pada commit lain
5. **Uji setelah cherry-pick**: Verifikasi perubahan berfungsi dalam konteks baru

## Melacak Commit yang Di-cherry-pick

Git dapat melacak commit yang di-cherry-pick:

```
# Cherry-pick with -x flag
git cherry-pick -x <commit-hash>
```

Ini menambahkan baris ke pesan commit: "(cherry picked from commit ...)"

## Kesalahan Umum yang Harus Dihindari

1. **Melakukan cherry-pick pada commit merge**: Biasanya menyebabkan masalah
2. **Melakukan cherry-pick dari branch fitur ke main**: Dapat membuat commit duplikat saat melakukan merge
3. **Tidak menguji**: Perubahan mungkin berperilaku berbeda di branch yang berbeda
4. **Mengabaikan dependensi**: Commit yang di-cherry-pick mungkin memerlukan commit lain agar berfungsi

## Ringkasan Hari Ini

`git cherry-pick` adalah alat yang ampuh untuk menerapkan commit secara selektif dari satu branch ke branch lain. Perintah ini sangat berguna untuk menerapkan hotfix ke beberapa branch rilis atau memilih fitur tertentu dari branch pengembangan. Namun, perintah ini harus digunakan dengan bijaksana karena dapat memperumit riwayat jika digunakan secara berlebihan.

Izinkan saya menyusun kembali perintah dan parameter Git yang dipelajari hari ini:

* git cherry-pick <commit>
* git cherry-pick <commit1> <commit2>
* git cherry-pick commit1..commit2
* git cherry-pick --no-commit
* git cherry-pick -n
* git cherry-pick --continue
* git cherry-pick --abort
* git cherry-pick --skip
* git cherry-pick -e
* git cherry-pick -x
* git cherry-pick --signoff
