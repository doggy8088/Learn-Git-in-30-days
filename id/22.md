# Hari 22: Memperbaiki Riwayat Versi yang Sudah Di-commit Bagian 4 (rebase)

Kita telah membahas tiga metode berbeda untuk memperbaiki versi. Sebenarnya, `git revert` dan `git cherry-pick` tidak benar-benar "memperbaiki catatan riwayat versi" - keduanya menerapkan versi yang telah di-commit sebelumnya, baik "menerapkan ulang" maupun "menerapkan secara terbalik". Artikel ini akan menjelaskan mekanisme Rebase pada Git, yang benar-benar digunakan untuk memodifikasi catatan commit. Fitur ini penting dan ampuh.

## Memahami git rebase

Rebase adalah salah satu fitur Git yang paling ampuh tetapi berpotensi berbahaya. Fitur ini memungkinkan Anda menulis ulang riwayat commit, membuatnya lebih bersih dan lebih linear.

Rebase adalah proses memindahkan atau menggabungkan urutan commit ke commit base baru. Tidak seperti merge, yang mempertahankan riwayat lengkap, rebase menulis ulang riwayat untuk menciptakan progresi yang linear.

## Rebase Dasar

Operasi rebase dasar:

```
# On feature branch
git checkout feature-branch

# Rebase onto main
git rebase main
```

Ini memainkan ulang semua commit dari `feature-branch` di atas `main`.

## Cara Kerja Rebase

Ketika Anda melakukan rebase:

1. Git menemukan ancestor bersama dari branch Anda dan branch target
2. Git menyimpan semua commit dari branch Anda sejak ancestor tersebut
3. Git me-reset branch Anda ke branch target
4. Git menerapkan ulang commit yang Anda simpan satu per satu

## Rebase vs Merge

**Merge**:
* Mempertahankan riwayat lengkap
* Menunjukkan kapan branch bercabang dan digabungkan
* Aman untuk branch bersama
* Membuat commit merge

**Rebase**:
* Menciptakan riwayat linear
* Lebih bersih, lebih mudah dipahami
* Menulis ulang riwayat (berbahaya untuk branch bersama)
* Tidak ada commit merge

Perbandingan visual:

```
# Before rebase
     C---D feature
    /
A---B---E---F main

# After git rebase main (on feature)
             C'---D' feature
            /
A---B---E---F main

# After git merge feature (on main)
     C---D 
    /     A---B---E---F---G main
```

## Menangani Konflik Selama Rebase

Jika konflik terjadi:

```
# Git pauses the rebase
# Resolve conflicts in the files
# Stage the resolved files
git add <resolved-files>

# Continue the rebase
git rebase --continue
```

Untuk membatalkan rebase:

```
git rebase --abort
```

Untuk melewati commit saat ini:

```
git rebase --skip
```

## Rebase Interaktif

Rebase interaktif memberi Anda kendali penuh atas commit:

```
git rebase -i HEAD~3
```

Ini membuka editor tempat Anda dapat:

* **pick**: Mempertahankan commit apa adanya
* **reword**: Mengubah pesan commit
* **edit**: Berhenti untuk mengamend commit
* **squash**: Menggabungkan dengan commit sebelumnya, mempertahankan kedua pesan
* **fixup**: Menggabungkan dengan commit sebelumnya, membuang pesan ini
* **drop**: Menghapus commit sepenuhnya

Contoh editor rebase interaktif:

```
pick abc123 Add feature A
reword def456 Add feature B
squash ghi789 Fix typo in feature B
drop jkl012 Experimental change
```

## Tugas Rebase Interaktif yang Umum

### Menggabungkan Commit (Squashing)

Menggabungkan beberapa commit menjadi satu:

```
git rebase -i HEAD~3

# In the editor, change:
pick abc123 First commit
pick def456 Second commit
pick ghi789 Third commit

# To:
pick abc123 First commit
squash def456 Second commit
squash ghi789 Third commit
```

### Menyusun Ulang Commit

Cukup susun ulang baris-baris dalam editor rebase interaktif.

### Mengedit Commit

```
git rebase -i HEAD~3

# Change "pick" to "edit" for the commit you want to modify
# Git will stop at that commit
# Make your changes
git add .
git commit --amend
git rebase --continue
```

## Rebase ke Branch yang Berbeda

```
git rebase --onto new-base old-base feature-branch
```

Ini memindahkan commit dari `feature-branch` yang berada setelah `old-base` ke `new-base`.

## Autosquash

Secara otomatis menggabungkan (squash) commit fixup:

```
# Create a fixup commit
git commit --fixup <commit-to-fix>

# Later, rebase with autosquash
git rebase -i --autosquash main
```

## Aturan Emas Rebase

**Jangan pernah melakukan rebase pada commit yang telah di-push ke repositori bersama!**

Rebase menulis ulang riwayat, yang dapat menyebabkan masalah besar bagi orang lain yang telah mendasarkan pekerjaan mereka pada commit tersebut.

Aman untuk:
* Commit lokal yang belum di-push
* Branch fitur yang Anda miliki
* Membersihkan sebelum membuat pull request

Berbahaya untuk:
* Branch main/master
* Branch fitur bersama
* Commit apa pun yang mungkin telah menjadi dasar pekerjaan orang lain

## Memulihkan dari Kesalahan Rebase

Jika rebase berjalan salah:

```
# Find the commit before the rebase
git reflog

# Reset to that commit
git reset --hard HEAD@{2}
```

## Praktik Terbaik

1. **Rebase sebelum push**: Bersihkan commit lokal Anda sebelum membagikannya
2. **Jangan rebase riwayat publik**: Hanya rebase commit lokal
3. **Cadangkan sebelum rebase besar**: Buat branch terlebih dahulu
4. **Berkomunikasi**: Beri tahu tim Anda jika Anda harus melakukan rebase pada kode bersama
5. **Berlatih**: Coba rebase pada branch percobaan terlebih dahulu

## Ringkasan Hari Ini

Rebase adalah alat yang ampuh untuk menciptakan riwayat commit yang bersih dan linear. Meskipun sangat baik untuk pekerjaan lokal dan mempersiapkan branch untuk merge, rebase harus digunakan dengan hati-hati untuk menghindari penulisan ulang riwayat bersama. Memahami kapan dan bagaimana menggunakan rebase sangat penting untuk alur kerja Git tingkat lanjut.

* git rebase -i

* git rebase --abort
* git rebase --skip
* git rebase --onto
* git rebase --autosquash
* git commit --fixup
